## 1. 한 장 요약

WaterCare AI는 고객 증상 원문을 구조화하고 명시적 안전 규칙을 먼저 적용한
뒤, 허용된 제품·세대·공식 문서만 pgvector로 검색하여 사용 안내 제안을
반환한다. AI는 문의 상태·권한·최종 EvidenceCard와 DB 저장을 확정하지
않으며, 이 책임은 Django Backend에 있다.

| 구성 | 현재 구현 | 발표 표현 |
| --- | --- | --- |
| 안전 분류 | YAML 명시 규칙·금지 표현 Guard | 규칙 기반 안전 분류 |
| 증상 구조화 | 규칙 기반 최소 구조화 | 사전 정의 구조화, 외부 LLM 아님 |
| Embedding | `BAAI/bge-m3` 고정 Revision | 사전학습 모델 적용, 직접 학습 아님 |
| 검색 | PostgreSQL pgvector Cosine Exact Search | 격리 DB 실증 완료, 팀 DB 재검증 대기 |
| 안내 생성 | 규칙·Template 기반 | 외부 LLM 생성 결과 아님 |
| Backend 연동 | 계약·FastAPI 준비 | Adapter·저장 E2E 대기 |

## 2. 요청·응답 흐름

```text
Django Backend
  └─ Public inquiry UUID, correlation_id, ai_request_id, state_version
       ↓ POST /api/v1/ai/analyze
FastAPI AI
  ├─ 계약 검증
  ├─ 증상 구조화
  ├─ 안전 규칙 우선 판정
  ├─ 허용 범위·공식 근거 검색
  └─ 구조화 결과·위험도·사용 안내·근거 제안
       ↓
Django Backend
  └─ stale·중복 검증 후 상태·저장·EvidenceCard 결정
```

현재 Backend durable dispatch 저장 위치, 실패 재처리 상태, Adapter E2E는
미확정이다. 따라서 위 흐름은 AI 계약과 독립 Runtime까지 검증됐으며 전체
업무 저장 흐름 완료를 의미하지 않는다.

## 5. 발표 시연 시나리오

### 시나리오 A — 위험 우선

```text

```

## 6. 재현 절차

저장소 Root에서 실행한다.

```powershell
.\ai\.venv\Scripts\python.exe --version
.\ai\.venv\Scripts\python.exe -m pip check
.\ai\.venv\Scripts\python.exe -m pytest ai\tests\unit -q
.\ai\.venv\Scripts\python.exe -m uvicorn ai.app.main:app --host 127.0.0.1 --port 8001
```

Health와 Mock 분석:

```text
GET  http://127.0.0.1:8001/health
POST http://127.0.0.1:8001/api/v1/ai/analyze?mode=mock
```

Mock는 계약·화면 시연용이며 실제 pgvector 검색 성공으로 표현하지 않는다.

## 7. 발표 제한사항

- 팀 DB pgvector Migration과 최신 팀 DB 재검증은 남아 있다.
- Backend AI Adapter·Evidence 저장·stale/중복 차단 E2E는 남아 있다.
- 외부 LLM Provider는 현재 공식 기준선이 아니다.
- 평가 범위는 제품 1종, D세대, 승인 청크 7개로 제한된다.
- “학습 완료”, “전체 제품 정확도 100%”, “환각 0%”, “다중 Agent 완성”을
  사용하지 않는다.
