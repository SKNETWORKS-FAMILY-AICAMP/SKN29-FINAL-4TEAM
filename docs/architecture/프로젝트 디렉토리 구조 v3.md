# 프로젝트 디렉토리 관할 분배안

> 기준 문서: `프로젝트 디렉토리 구조 v2.md`
>
> 기준 역할
>
> - 윤승혁: PM·기술 통합·Harness·HITL·Consultation Handoff
> - 양정현: 모바일 앱 개발·MCP·A2A
> - 한예나: 웹 프론트엔드 개발
> - 최지용: 백엔드·데이터베이스
> - 이동윤: Multi-Agent Core·RAG·Evals
> - 김은진: 데이터·Observability·QA·DevOps·Docker 전담

## 1. 편집 권한 규칙

| 구분 | 편집 조건 |
|---|---|
| 주관할 | 타인의 협의·허가 없이 편집 가능 |
| 부관할 | 주관할 팀원과 협의한 뒤 편집 가능 |
| 관할 아님 | 주관할 팀원과 협의하고 PM 허가까지 받은 뒤 편집 가능 |
| 공동 편집 | 별도의 주관할·부관할을 두지 않으며 모든 팀원이 목적에 맞게 편집 가능 |

## 2. 적용 방식

1. 아래 표에서 더 구체적인 경로가 우선한다.
2. 별도 예외가 없는 하위 디렉토리는 가장 가까운 상위 디렉토리의 관할을 상속한다.
3. `/**`는 해당 디렉토리와 모든 하위 디렉토리를 의미한다.
4. 표에 이름이 없는 팀원은 해당 경로의 `관할 아님`으로 본다.
5. `docs/**`는 공동 편집 대상으로 두며 주관할·부관할을 지정하지 않는다.
6. 모든 `Dockerfile*`, Docker Compose 파일, `.dockerignore`는 경로의 상위 관할과 관계없이 **3.1 Docker 전담 공통 예외**를 최우선 적용한다.

### 3.1 Docker 전담 공통 예외

> 이 표는 저장소 안의 모든 현재·향후 Docker 관련 파일에 적용하며, 서비스별 상위 디렉토리 관할보다 우선한다. 각 서비스 담당자는 런타임 요구사항·포트·환경변수·Health Check 조건을 김은진에게 전달하고, Docker 파일의 최종 편집과 통합은 김은진이 맡는다.

| 경로 | 주관할 | 부관할 | 근거 |
|---|---|---|---|
| `Dockerfile*` | 김은진 | 윤승혁 | 저장소 루트 Dockerfile과 변형 파일 전체 |
| `web/Dockerfile*` | 김은진 | 한예나 | Web 이미지 빌드·Nginx 실행 환경 |
| `backend/Dockerfile*` | 김은진 | 최지용 | Django·Gunicorn 이미지 빌드 환경 |
| `ai/Dockerfile*` | 김은진 | 이동윤 | AI Runtime·의존성·서비스 이미지 빌드 환경 |
| `mobile/**/Dockerfile*` | 김은진 | 양정현 | 향후 Mobile 관련 Dockerfile이 생길 경우 적용 |
| `*/Dockerfile*`, `**/Dockerfile*` | 김은진 | 해당 서비스 담당자 | 추가 서비스와 모든 중첩 경로의 Dockerfile까지 동일 원칙 적용 |
| `docker-compose*.yml`, `docker-compose*.yaml` | 김은진 | 윤승혁 | 저장소 루트 Docker Compose 통합 실행 설정 |
| `**/docker-compose*.yml`, `**/docker-compose*.yaml` | 김은진 | 해당 서비스 담당자 | 하위 디렉토리의 Docker Compose 설정 |
| `compose*.yml`, `compose*.yaml`, `**/compose*.yml`, `**/compose*.yaml` | 김은진 | 해당 서비스 담당자 | Compose 최신 파일명과 환경별 변형 설정 |
| `.dockerignore`, `**/.dockerignore` | 김은진 | 해당 서비스 담당자 | Docker Build Context·비밀값·불필요 파일 제외 기준 |

## 15. 충돌 방지용 최종 원칙

1. 자기 관할 디렉토리라도 다른 영역의 계약·상태·공통 코드를 임의로 복제하지 않는다.
2. API·AI·상태 코드 변경은 반드시 `contracts/`의 해당 주관할이 먼저 반영하거나 동시 반영한다.
3. 테스트 실패를 우회하기 위해 `tests/`, `.github/workflows/`, `infra/`를 임의 수정하지 않는다.
4. 공식 원본이 있는 `data/raw/`는 김은진 외 팀원이 직접 수정하지 않는다.
5. `docs/**`는 공동 편집이지만 기계가 검증해야 하는 계약 원본은 `contracts/**`에만 둔다.
6. 관할이 불명확한 새 디렉토리를 만들 때는 최상위 영역의 관할을 우선 적용하고, 둘 이상의 영역에 걸치면 PM이 주관할·부관할을 확정한다.
7. 모든 `Dockerfile*`, Docker Compose 파일, `.dockerignore`의 최종 주관할은 김은진으로 통일하며, 서비스 담당자는 필요한 Runtime 조건을 부관할로 협의한다.
8. Multi-Agent 공통 상태와 Pipeline 계약은 이동윤이 주관하고, Harness·HITL·Handoff는 윤승혁, MCP·A2A는 양정현, Observability 공통 설정은 김은진이 각자 맡은 경로에서 편집한다.
