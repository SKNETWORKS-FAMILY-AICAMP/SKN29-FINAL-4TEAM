# 최종 프로젝트 데일리 스크럼 6주차 요약 보고서 (8/18 ~ 8/21)

* 4팀 대주제 : 다중 에이전트 서빙 기반 고객 피드백 분석 및 맞춤형 응대 자동화 시스템

## 8월 18일 (화) - 6주차 사용자 화면 보완 및 공용 RDS·AI Runtime 검증 준비

* **진행 업무**
  * Web은 상담사 문의 화면의 날짜 정보와 분류별 선택 기능을 보완하고, 목록·상세 화면의 정보 가시성을 개선함
  * Mobile은 고객이 작성하거나 제출한 문의 답변이 화면 전환 뒤 사라지지 않도록 상태·이동 흐름을 보완하고, 로그인 만료 상황의 동작을 검증함
  * Backend·DB는 인증·권한 Migration을 재현 가능한 절차로 정리하면서 RDS 적용을 준비하고, Web·Mobile·AI가 함께 계약을 검증할 경로를 마련함
  * AI·RAG는 3개 역할 기반 Multi-Agent 후보 Runtime의 1차 구현과 실제 연동 비교를 진행하고, pgvector 접속 장애 시 비밀값이 오류·로그에 노출되지 않도록 방어 경계를 보강함
  * QA·DevOps는 RDS 환경 구성과 후속 업무 인계를 진행하고, EC2 배포를 GitHub Actions CI/CD로 자동화하기 위한 후속 작업을 계획함
  * PM은 현재 Backend의 요청 처리·상태 전이·AI 연동 흐름을 팀원들에게 다시 공유하고 6주차 담당자별 업무 범위를 정리함

* **담당자별 주요 작업 내용**
  * **윤승혁 (PM)**
    * 고객 Mobile 문의부터 Backend 상태 저장·AI 처리·상담사 Web 연결까지의 전체 Backend 중심 흐름을 팀원들에게 리마인드함
    * 6주차 담당자별 업무 지침을 정리하고, 구현·실제 Runtime 검증·운영 적용 상태를 구분해 보고하도록 기준을 공유함
  * **최지용 (Backend·DB)**
    * 인증·권한을 포함한 Migration을 동일한 순서로 재현할 수 있도록 실행 흐름과 검증 경계를 정리함
    * 보류 중인 `visits.0005`를 제외하고 승인된 Migration만 적용할 수 있는 Allowlist 경로를 구현·격리 검증함
    * RDS 환경 적용을 준비하면서 Web·Mobile·AI가 같은 계약과 데이터 기준으로 검증할 수 있는 공동 경로를 마련 중임
  * **한예나 (Web Frontend)**
    * 상담사 대시보드와 전체 문의 화면에서 날짜 정보와 문의 분류별 선택·필터 기능을 보완함
    * 문의 목록·상세의 글자, 배지, 상태 정보와 주요 행동 영역이 더 잘 보이도록 화면 가시성과 레이아웃을 개선함
    * 최근 관리일 표시와 존재하지 않는 리소스의 404 처리에 대한 테스트를 보강함
  * **이동윤 (AI·RAG)**
    * 증상 분석·근거 분석·케어 판단의 3개 역할과 Supervisor Handoff를 갖는 Multi-Agent 후보 Runtime을 1차 구현함
    * 후보 Runtime을 실제 OpenAI·Readonly pgvector·Backend 경로에서 검증했으나, 기본 Runtime은 계속 `single_rag`로 유지하고 운영 전환은 승인 전까지 보류함
    * pgvector 연결·권한·검색 오류에서 DSN·Driver 원문 등 비밀값이 응답, 로그, 예외 연쇄에 노출되지 않도록 보호 오류 경계를 보강함
  * **양정현 (Mobile Frontend)**
    * 고객 문의의 추가 답변과 작성 중 입력이 오류·충돌 또는 화면 이동 뒤 사라지지 않도록 상태 보존과 재시도 흐름을 보완함
    * 문의 화면에서 안내 화면으로 이동한 뒤 뒤로 가기 동작이 꼬이지 않도록 Navigation Back Stack을 정리함
    * 로그인 만료 시 사용자 안내와 후속 동작이 정상적으로 처리되는지 관련 테스트로 검증함
  * **김은진 (QA·DevOps)**
    * 공용 RDS 환경 세팅과 팀원이 이어서 실행할 수 있는 작업 인계 절차를 진행 중임
    * RDS 연결·권한·Migration·복구 검증 범위를 정리하고, 환경 구성만으로 전체 E2E 완료로 판정하지 않도록 기준을 유지함
    * EC2 인스턴스 배포를 GitHub Actions CI/CD로 자동화하는 작업은 후속 예정 범위로 분리함
