# 최종 프로젝트 데일리 스크럼 3주차 요약 보고서 (7/27 ~ 7/31)

## 7월 27일 (월) - 담당 영역별 개발 기준 정리 및 핵심 기능 구현 진행
* **진행 업무**
  * 팀원별 업무 범위와 공통 상태·API 규칙 정리
  * 모바일·웹 핵심 화면 구현 및 ERD·API·합성 데이터 정합성 검토
* **주요 작업 내용**
  * PM은 공통 업무 흐름과 완료 기준을 정리하고, 모바일은 카카오맵 경로 및 이동 기능을 구현함
  * 백엔드·DB는 ERD와 API 명세를 수정하고, AI·RAG는 변경 지침을 기반으로 선행 개발 범위를 검토함
  * 데이터·QA·DevOps는 합성 데이터와 E2E 계약 불일치를 수정하고, 웹은 상담사 문의 목록·상세·방문 전환 화면과 공통 로딩 UI를 구현함

## 7월 28일 (화) - 디렉토리 구조 수정 및 충돌사항 수정
* **진행 업무**
  * 팀원별 각자 맡은 업무 진행 및 충돌 수정
* **주요 작업 내용**
  * PM - 모바일 디렉토리 분리, git 충돌 관리
  * 데이터·QA·DevOps - 승인 필요없는 데이터 정리 및 합의 대기중
  * 모바일개발 - 모바일 디렉토리 바꾸면서 JDK 다시 설치. 앱 아이콘 변경
  * 백엔드 - 장고 Postgresql 마이그레이션 할 수 있도록 문서 정리 , state machine 과 충돌하는 부분 수정
  * 프론트 - 상담사 화면 및 기능 구현 완료, 로딩/오류/권한필요/부분실패 상황에 뜨는 화면 구현
  금주 중 관리자 화면 및 기능 구현 예정, 백엔드 준비 후 실제 API, JWT 연동 및 E2E 테스트 예정
  * AI/RAG - 안전 규칙 분류기 & 출력 가드레일 엔진 구축 , FastAPI 실행 환경 , 임베딩과 검색기 구축. RAG 기준선 및 최소 오케스트레이터 프롬프트 작성 . 현재 검증중

## 7월 29일 (수) - 3주차 진행도 점검 및 역할별 기능·데이터 통합
* **진행 업무**
  * 3주차 작업 진행도를 확인하고 팀원별 브랜치의 구현 내용, 코드 계약 및 통합 상태 검토
  * 상담사 Web, 고객·방문기사 Mobile, Backend·DB, Data·QA, AI·RAG 영역별 기능 구현 및 연동 기준 정합화
* **주요 작업 내용**
  * PM - 상태 머신과 데이터 계약을 확정하고 코드 계약 정합성을 검토함. 백엔드·데이터·Web·AI 브랜치 작업을 순차적으로 검토·병합하여 팀 작업을 합성함
  * Web 프론트 - 상담사 화면의 문의 식별자, 재시도 멱등성, 응답 DTO 및 인증 토큰 처리를 API 계약에 맞게 보완함. 상담원 기능과 운영 대시보드 P1·반응형 화면을 구현하고 합성 데이터 계약 호환 및 테스트를 정리함
  * Mobile 프론트 - 고객의 방문기사 호출 화면과 기사 호출 수락 흐름을 구현함. 고객·방문기사 앱의 호출 API 모델을 연결하고 기사 위치 서비스와 실시간 차량 이동 기능을 추가함
  * Backend·DB - 백엔드 구조 리팩토링과 합성 데이터 적재·연결 확인을 진행함. 공통 API·오류·예시 계약, 인증 토큰 만료 응답 및 상태 전환 준비도를 보완하고 Frontend·AI 연동 Gate와 실행 환경 인계 문서를 점검함
  * Data·QA - 업무지침서와 백엔드 인계사항을 반영하여 데이터 카탈로그·설정·스키마·합성 데이터 및 검증 리포트를 정리함. 데이터 계약 정합성과 재현성 검증 테스트를 보완함
  * AI·RAG - AI Backend 기능 구현을 이어가며 증상 분석 요청·오류 코드·역할별 응답 예시와 RAG·안전성 평가 데이터를 수정함. 실행에 필요한 환경 변수와 Python 의존성 누락 항목을 보완함

## 7월 30일 (목) - 역할별 구현 현황 공유 및 개발 환경·연동 오류 개선

* **진행 업무**
  * 역할별 기능 구현 진행 상황과 문서·데이터 검증 상태 공유
  * 모바일·백엔드·AI·RAG 간 연동 오류 및 개발 환경 충돌 사항 점검
  * Web 화면 단순화와 요구사항 정의서·WBS 최신화 진행
* **주요 작업 내용**
  * PM - 팀원별 코드를 검토하고 작업 진행도를 갱신함. 개발 과정에서 확인된 추가 요구사항을 반영하여 요구사항 정의서와 WBS를 업데이트함
  * Data·QA·DevOps - 데이터를 수정하고 데이터 전처리 결과서 작성 및 제출 준비를 진행함. AI·RAG와 Backend 담당자의 피드백을 반영했으며, 최종 문서 작성을 위한 추가 데이터 검증을 진행함. 해시값이 조금만 달라도 GitHub Actions 검증이 실패하는 문제와 매 커밋·푸시마다 전체 데이터를 검증하는 방식의 확장성 개선 필요성을 확인함
  * Web 프론트 - 복잡해 보이는 상담사·운영자 화면을 단순화하고, 주요 정보를 스크롤 없이 확인할 수 있도록 화면 구성을 개선함. 상세 화면의 정보 밀도를 낮추는 방안을 검토하고 있으며, LLM의 정형화된 화면 구성을 줄이기 위해 화면별 디자인 레퍼런스를 추가로 조사함
  * AI·RAG - 데이터와 기능 계약을 수정하고 PostgreSQL 환경에서 pgvector가 정상적으로 동작하는지 개별 검증함. 수집·가공된 데이터의 RAG 활용 적합성을 검토하여 데이터 담당자에게 전달했으며, Backend 구조와 일치하도록 기능을 수정함. 실행 과정에서 발생한 Python 버전 충돌 문제를 점검함
  * Backend·DB - 팀원들이 Backend와 DB 기능을 연동할 수 있도록 인계 문서를 작성해 배포함. 일부 팀원의 환경 및 연동 문제를 해결하고 SQL 작업을 진행했으며, DB 구조 정리가 완료되면 멘토에게 설계와 구현 방향을 검토받을 예정임
  * Mobile 프론트 - Android 앱에서 발생한 오류를 수정하고, Backend API 명세와 일치하지 않는 요청·응답 모델 및 데이터 구조를 보완함. Python과 JDK 버전 충돌로 인해 개발 환경을 다시 설정했으며, 이후 실제 Backend API 연동을 중심으로 고객·방문기사 기능을 통합 테스트할 예정임
