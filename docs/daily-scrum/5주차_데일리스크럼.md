> 작성 기준: 2026년 8월 10일 팀 스크럼 공유 내용, 6명의 5주차 업무 지침서, GitHub `main` 및 담당자 브랜치 게시 내역을 함께 대조함. 브랜치 게시·작성자 테스트와 독립 QA 완료는 구분하여 기록함.

## 8월 10일 (월) - 5주차 필수 범위 확정 및 실제 연동·Runtime 검증 착수

* **진행 업무**
  * PM이 5주차 필수 범위와 의존성을 재정렬하고, 6~7주차 업무 및 조기 E2E 범위를 분리함
  * Backend는 상담사 문의 조회와 상담·방문 Runtime을 구현하고, Web·Mobile이 실제 API를 소비할 수 있도록 계약과 인계 기준을 정리함
  * AI·RAG는 Backend 연동에 필요한 Fixture와 Multi-Agent 선행 작업을 진행함
  * Web·Mobile은 Mock/Fake 경계를 정리하고 실제 API 전환을 위한 화면·Repository·오류 처리 준비를 진행함
  * QA는 Backend·AI 실행 환경과 별도 검증 DB를 준비하고 상담·방문 Runtime을 독립 재현함

* **담당자별 주요 작업 내용**
  * **윤승혁 (PM)**
    * 팀원별 5주차 지침서, WBS, Scope·Dependency를 대조해 이번 주 필수 업무를 우선하도록 범위를 재정리함
    * 대표 E2E 범위를 조건부 업무로 분리하고, 다음 주 일정이 지연되지 않도록 5주차 필수 Gate를 먼저 닫는 방향을 공지함
    * GitHub `main`에서 최지용·한예나 브랜치 작업을 병합하고 팀 기준 작업물을 갱신함
  * **최지용 (Backend·DB)**
    * 상담사 문의 목록·상세 조회 Runtime과 계약 테스트를 구현하고, 한예나가 참고할 Web API 개발·검증 가이드를 게시함
    * 상담 시작·명시 저장·요약 확정·완료 및 방문 검토·생성·불필요·일정 저장·방문일 확정 Runtime과 OpenAPI 계약 회귀를 구현함
    * PM이 확정한 Action 계약, Data CI 해시·생성 보고서를 동기화하고, 추가 질문 답변(`SUBMIT_ANSWERS`)은 검증 전 Runtime 완료로 오인하지 않도록 보류 경계를 문서화함
    * 위 작업은 `jiyong` 브랜치에 게시된 뒤 `main`에 병합되었으나, 방문 Runtime은 PostgreSQL 독립 QA에서 Lock 결함이 확인되어 수정·재검증 전 소비자 연결 완료로 판정하지 않음
  * **한예나 (Web Frontend)**
    * Backend·QA 담당자와 상담사 문의 목록·상세 API 주소, 오류 응답, 개인정보 비노출 범위를 협의함
    * 상담사 API 전환 구조와 화면 가독성을 개선하고, 문의 목록을 확인하기 위한 합성 Mock 데이터를 보강함
    * 상담사·운영자 화면 디자인을 개선했으며, 기각 전환 시나리오에 대한 제안이 채택되지 않아 흐름과 화면 설계를 다시 정비 중임
    * 관련 화면·Mock·협업 회신 작업은 GitHub에 게시되어 `main`에 병합됨
  * **이동윤 (AI·RAG)**
    * Backend↔AI·RAG 연결에 사용할 Fixture를 수집하고, 5주차 지침서에서 다른 담당자 없이 먼저 수행 가능한 우선순위 작업을 진행함
    * Backend AI 단계 작업을 게시하고, 개인 브랜치에는 상담 요약 Generator·Formatter, Safety 규칙·테스트, Runtime Identity, AI Entry Gate 및 Multi-Agent 계약 초안을 추가함
    * 현재 단계는 연동 선행 준비로 기록하며, 실제 Backend HTTP·팀 DB·LLM 통합 완료로 확대 판정하지 않음
  * **양정현 (Mobile Frontend)**
    * 스크럼 공유 시점에는 5주차 지침서에 따른 연동 준비와 Backend 요청사항 정리를 완료했으며, 실제 연동은 대기 상태로 보고함
    * 이후 GitHub 개인 브랜치에는 합성 고객 P0 문의 흐름, Remote Repository, Guidance·Follow-up, 기사 방문 API 경계, 테스트 및 인계 산출물을 게시함
    * 해당 게시물은 아직 팀 `main` 반영 및 방문 Runtime QA 완료와 구분하며, 방문 API는 Backend 결함 수정 전 최종 실연동 완료로 판정하지 않음
  * **김은진 (QA·DevOps)**
    * 본격적인 QA를 위해 Backend·AI 가상환경과 별도 PostgreSQL 검증 환경을 구성하고, 중복 검증 DB 문제와 설치·Runtime 설정 이상을 정리해 담당자에게 인계함
    * Backend 요청사항 반영 결과와 인계 문서를 GitHub에 게시하고 상담·방문 Runtime을 독립 재현함
    * 기본 테스트와 상담 흐름은 통과했으나, 방문 데이터 조회 시 Nullable 기사 관계까지 함께 잠그는 PostgreSQL Row Lock 결함을 확인하여 `CHANGE_REQUEST`로 회신함
    * 시간대 기준과 테스트 환경값 불일치도 별도 보정 대상으로 분리했으며, Backend 수정 전 방문 소비자 배포·연동을 보류함

* **공통 Blocker 및 다음 작업**
  * 최지용은 `VisitRepository`에서 필요한 방문 행만 잠그도록 조회를 수정하고, PostgreSQL 정상·오류·동시성·Rollback 회귀 결과를 김은진에게 재전달함
  * 김은진은 수정본에서 방문 Runtime 실패 Case를 먼저 재현한 뒤 전체 관련 회귀를 다시 수행하고, PASS·FAIL·남은 Blocker를 PM에게 취합 전달함
  * 한예나는 상담사 문의 목록·상세 Remote 연결과 개인정보·오류 처리를 계속 진행하되, 방문 소비는 QA PASS 전까지 차단 상태로 유지함
  * 양정현은 Backend 요청사항과 Mobile 계약 경계를 유지하고, 개인 브랜치 결과를 `main` 반영·실제 API 검증 결과와 분리함
  * 이동윤은 Fixture·Multi-Agent 초안을 실제 Backend HTTP·팀 DB·LLM 검증으로 연결하며, 준비 산출물을 통합 완료로 표시하지 않음
  * 윤승혁은 5주차 필수 업무의 완료 조건과 다음 주 이월 항목을 구분하고, 독립 QA를 통과한 범위만 팀 완료 상태로 갱신함
