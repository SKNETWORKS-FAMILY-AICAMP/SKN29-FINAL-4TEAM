## 1. 계약과 Pydantic 제약

다음 불일치를 Runtime에 반영했다.

- `inquiry_id`: Backend Public UUID로 강제
- `selected_symptoms`: 최대 30개, 항목별 1~200자
- `previous_answers`: 최대 50개
- `question_id`: 1~100자
- `answer_text`: 1~1000자
- 오류 `success`: `false` 상수
- 오류 코드: `AI-FAILED-01`, `AI-VALIDATION-01`, `AI-TIMEOUT-01` Enum
- 오류 메시지: 1~500자
- 오류 Stage: 실패 가능한 Stage만 허용하고 `COMPLETED` 거부
- `risk_level`, `priority`, `verification_status`: Runtime Enum 적용
- 다중 페이지 근거: `page_refs` 보존

Negative Parity 테스트에서 다음 입력을 JSON Schema와 Pydantic이 함께
거부하는 것을 확인했다.

- UUID가 아닌 `inquiry_id`
- 증상 31개
- 빈 증상 또는 201자 증상
- 이전 답변 51개
- 빈 질문 ID 또는 1001자 답변
- 오류 `success=true`
- 미등록 오류 코드
- 501자 오류 메시지
- 오류 Stage `COMPLETED`
- 미등록 근거 검증 상태

## 3. Timeout·Retry·구조화 로그

- HTTP 전체 Timeout 30초 유지
- Backend 자동 재시도 0회 유지
- AI 내부 재시도 상한은 1회지만 현재 Retry Loop는 `enabled=false`
- 실제 `retry_count=0`을 응답·로그에 기록
- Timeout 시 `CancellationToken`을 Worker에 전달
- LangGraph 각 단계 시작 전에 취소 신호 확인
- pgvector 연결 5초, 검색 SQL 5초, UPSERT SQL 10초 제한
- 협력적 Worker 취소 단위 테스트 통과

구조화 로그는 다음 필드만 허용한다.

```text
inquiry_id, correlation_id, ai_request_id, state_version,
stage, status, retry_count, latency_ms, error_code
```

고객 원문을 포함한 임의 필드는 로거에서 제거한다. 테스트에서 고객 원문이
로그에 없고 시작·완료 이벤트의 `correlation_id`가 동일함을 확인했다.

현재 취소 방식은 파이프라인 단계 경계의 협력적 취소다. 이미 실행 중인 로컬
Embedding 함수 자체를 OS 수준에서 강제 종료하지는 않지만, 반환 직후 취소
신호를 재확인해 DB Query와 다음 Stage를 중단한다. DB 작업이 이미 시작된
경우에는 별도 연결·Statement Timeout으로 제한한다.

## 4. 검색 안전성

실제 `VectorSearchService.search()` 진입점에 다음 Allowlist를 적용했다.

```text
model_code=WPUJAC104DWH
product_generation=D
```

미지원 모델·세대와 미검증 FAQ 단독 근거 요청은 Embedding과 DB Query 전에
빈 근거로 차단한다. 평가 보고서에 실행 경로를 다음처럼 분리했다.

## 5. 팀 DB 보호형 인덱싱·검증

Schema 초기화와 데이터 적재를 분리했다.

- `build_vector_index`: DDL 없이 승인 청크 UPSERT만 수행
- 적재 확인: DB 전체 행 수가 아니라 이번 배치 청크 ID 7건만 Count
- `initialize_disposable_vector_schema`: 격리 DB 전용 DDL 명령
- DDL 확인값: `AI_VECTOR_DISPOSABLE_CONFIRM=DISPOSABLE_ONLY`
- DB 이름 Guard: `verify`, `test`, `tmp`, `disposable` 중 하나 필수
- 확인값 또는 이름 Guard 실패 시 연결 후 DDL 전 중단

`verify_pgvector_runtime`의 금지 Fixture 4건과 잘못된 차원 Fixture는 하나의
Transaction에서 검증하고 Rollback한다. 실행 후 `VERIFY-%` 잔존 행은
SQL로 `0`건을 확인했다.

팀 공용 DB에서는 AI 스크립트가 `CREATE EXTENSION` 또는 `CREATE TABLE`을
실행하지 않는다. 정식 Schema는 T-005 Backend/DB Migration 후속 범위다.
