### 2.2 3.2 Multi-Agent Architecture 확정·실제 Runtime 전환 — 25%

- Consultation Summary Formatter·Schema와 단위 Test는 존재한다.

미완료 및 완료 방법:

- 현재 [Pipeline Router](../../../ai/app/orchestration/pipeline_router.py)와 `SingleRAGPipeline`을 Supervisor 기반 Runtime으로 확장하고 각 Agent가 구조화 입출력을 갖도록 구현해야 한다.
- Routing 조건, 최대 Hop, Handoff Trace, Safety 우선, No Evidence·Validation 실패 경로를 코드와 Test로 증명해야 한다.
- Single RAG와 Multi-Agent를 같은 평가셋으로 비교해야 한다.

별도 확인: 5주차에 실제 Agent를 몇 개까지 P0로 구현할지 PM 승인이 필요하다.

별도 확인: 사용할 Provider·모델·API Key·비용 한도 승인이 필요하다.

### 2.4 3.4 팀 DB pgvector·bge-m3 Retrieval 기준선 — 60%

완료된 내용과 근거:

- [전체 Corpus 결과](../../../ai/evaluation/reports/experiments/full_corpus_baseline_v1/retrieval_summary.json)에 bge-m3 기반 Hit@5·MRR·금지 Hit와 제품 Filter 비교가 있다.
- [Performance 결과](../../../ai/evaluation/reports/experiments/full_corpus_baseline_v1/performance_summary.json)에는 96개 문서·35개 Query 처리 시간이 기록됐다.
- 모델 Revision·1024차원·Dataset·Corpus Hash가 고정돼 있다.

미완료 및 완료 방법:

- 현재 결과는 Local Index 기반 Draft이며 공식 공개 불가다. 팀 PostgreSQL pgvector에 같은 Dataset을 적재해 실제 SQL 검색으로 재실행해야 한다.
- Gold 60건 2인 검수, P0 모델·세대·문서 정책, 금지 FAQ 차단을 김은진과 공동 승인해야 한다.
- DB 장애와 검색 0건을 별도 오류로 검증하고 Retrieval Agent에 실제 연결해야 한다.

별도 확인: 팀 DB Extension·Index·Embedding Revision과 Gold 승인 여부가 필요하다.

### 2.5 3.5 Django Backend↔Multi-Agent 실제 HTTP 수직 연동 — 50%

완료된 내용과 근거:

- Backend [AI Client](../../../backend/integrations/ai/client.py)는 실제 HTTP·Schema·30초 Timeout·자동 Retry 0 정책을 구현한다.
- [추가 답변 Service](../../../backend/apps/inquiries/services/followup_answer_service.py)는 Commit 이후 `InquiryAIService`를 호출하며 저장 Service·단위 Test가 있다.

미완료 및 완료 방법:

- 실제 Django와 FastAPI를 기동해 MockTransport가 아닌 정상·위험·근거 없음·Timeout·Schema 오류 Test를 작성해야 한다.
- 최초 `SUBMIT_SYMPTOM` 이후 AI 호출점과 중복 요청 0회 정책을 확정해야 한다.
- FastAPI가 실제 Multi-Agent와 팀 pgvector를 실행하고 DB 저장·State Event·`correlation_id`를 한 Trace로 검증해야 한다.

별도 확인: 공용 Backend·AI·PostgreSQL 실행환경과 로그 접근이 필요하다.

### 2.6 3.6 Timeout·Retry·Fallback·안전성 — 75%

완료된 내용과 근거:

- 전체 30초, AI 내부 Retry 최대 1회, Backend 자동 Retry 0회가 설정돼 있다.
- 위험·근거 없음·Vector 미설정·Schema Invalid·Timeout 단위 Test와 Rule/Template Fallback이 있다.
- 안전·제품 범위·근거 정책이 LLM 단독 판단에 의존하지 않는다.

미완료 및 완료 방법:

- Agent별 Timeout·Hop·Retry Matrix를 실제 Multi-Agent 코드에 적용해야 한다.
- 실제 LLM·Vector 장애와 위험 입력 조합을 Live Integration으로 실행해 Latency·실패 단계·Fallback을 기록해야 한다.
- 코드·Test·Architecture Diagram의 경로를 일치시켜야 한다.
