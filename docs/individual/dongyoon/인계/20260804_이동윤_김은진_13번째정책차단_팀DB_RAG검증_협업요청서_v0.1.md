## 1. 요청 요약

현재 AI는 개인 격리 pgvector에서 공식 평가 12건을 통과했지만 다음 두 항목은
팀 완료 증거가 아니다.

1. 제품은 `WPUJAC104DWH`·D세대로 일치하지만 문서 정책상 고객 안내 근거로
   사용할 수 없는 자료를 실제 검색 후 차단하는 13번째 공식 평가 Case
2. 팀 공용 DB의 승인 청크 적재·재실행·독립 QA

김은진에게 13번째 Case의 문서·Fixture와 기대값을 Data Owner 관점에서
확정하고, 팀 DB 검증 시 Dataset·Chunk·Revision·금지 Hit를 독립 확인해 달라고
요청한다.

이 요청은 최지용의 Backend Client·Mapper 구현을 막지 않는다. 다만 팀 DB
RAG 공식 완료, 최종 평가 JSON과 발표 기준선 동결 전에는 반드시 반영해야
한다.

## 3. 요청 1 — 13번째 문서 정책 차단 Case 확정

### 3.1 필수 조건

13번째 Case는 다음 조건을 만족해야 한다.

```text
요청 제품=WPUJAC104DWH
제품 세대=D
질의 정책=정상, 검색 전 차단 아님
검색 후보=동일 제품·세대로 연결된 QA Fixture
문서 정책=고객 안내 근거 사용 불가
실제 실행=PGVECTOR_QUERY
검색 후 검증=부적격 후보 제거
최종 근거=[]
expected_no_evidence=true
forbidden_hit_count=0
```

문서 정책 차단 조건은 다음 중 Data Owner가 승인한 값을 사용한다.

- `allowed_use=false`
- 공식 검증 상태 미충족
- `scope_role`이 MVP 아님
- `rag_policy=EXCLUDE_*`
- 문서 Revision·Hash·제품 적용 범위 불일치

정확 제품·세대가 확인되지 않은 기존 공통 FAQ를 임의로 “제품 일치” Fixture로
바꾸지 않는다. 실제 원천과 다른 판매 코드·세대를 만들어 영구 승인 데이터로
저장하지 않는다.

### 3.3 Fixture 안전 원칙

- 부적격 Fixture는 승인 청크 7건에 포함하지 않는다.
- 공유·운영 DB의 영구 지식 데이터로 승격하지 않는다.
- 통합 테스트 Transaction 또는 명시적 QA Batch에서만 삽입한다.
- 검증 후 Rollback하고 잔존 행 0을 확인한다.
- 실제 문서 ID와 혼동되는 ID를 임의 생성하지 않는다.
- Fixture 원문·메타데이터·Hash의 출처를 결과에 기록한다.

후보로 검토하고 새 Chunk Set Hash와 검색 회귀를 만든다.

## 5. 요청 3 — 팀 DB RAG 독립 QA

### 5.1 실행 전 확인

- Backend 정식 Migration으로 pgvector Schema가 준비돼 있다.
- AI 스크립트가 팀 DB에서 `CREATE EXTENSION`·`CREATE TABLE`을 실행하지 않는다.
- DSN은 문서·Git·로그가 아닌 Secret 경로로 전달한다.
- AI 적재 계정은 필요한 최소 권한만 가진다.
- 실행 Branch·40자리 Commit SHA·Dirty 여부를 기록한다.
- Python·PostgreSQL·pgvector Version을 기록한다.

1. 승인 청크 7건 UPSERT

3. Vector Dimension 1024 확인
4. Model Revision·Index Version·Chunk Set Hash 확인
5. 양성 7건 실제 pgvector Query
6. 기존 정책 차단 5건 확인
7. 승인된 13번째 후검증 차단 Case 실행
8. 잘못된 모델·세대·미검증·사용 금지 근거 혼입 0건 확인
