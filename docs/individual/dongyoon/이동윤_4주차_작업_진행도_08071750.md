## 3. 4주차 필수 업무별 평가

### 3.1 AI·RAG 기준선 재검증과 발표 Version 동결 — 85%

- 완료·근거: [AI 기준선](../../testing/ai/week4-ai-baseline.md), [RAG 기준선](../../testing/rag/week4-rag-baseline.md), [공식 MVP 후보](../../../ai/evaluation/reports/official_mvp_baseline_20260803.json), [평가 Runner](../../../ai/evaluation/evaluation_runner.py). 계약 1.1.0·Schema 16개·bge-m3 Revision·Dataset/Chunk Hash, 101 Test와 안전 4/4가 기록되고 현재 HEAD에 병합됐다.
- 미완료: 공식 JSON 내부의 `source_commit`, `working_tree_committed=false`, Pending Commit 표기가 병합 후 상태로 갱신되지 않았고 팀 DB RAG 재실행이 없다.
- 완료 방법: 현재 승인 Commit에서 전용 `.venv`를 복구해 Test와 평가를 재실행하고 공식 JSON의 Commit·Clean 상태를 갱신한다.
- 별도 확인: 팀 DB·모델 Cache 접근, 결과의 이동윤·김은진 공동 승인이 필요하다.

### 3.2 Django Backend↔FastAPI 실제 호출·저장 — 15%

- 완료·근거: [Backend↔AI 협업 요청 v0.3](20260807_이동윤_최지용_Backend_AI_수직연동_협업요청서_v0.3.md), [AI FastAPI](../../../ai/app/main.py), [계약 Schema](../../../contracts/ai). 요청·응답·Timeout·Fallback 계약과 연동 요청은 구체화됐다.
- 미완료: Django의 실제 HTTP Client·Mapper·Validator·AI 실행/Evidence 저장과 수직 통합 Test가 없다.
- 완료 방법: Backend Client에서 FastAPI를 호출하고 Schema 검증 후 AI 실행·위험도·근거·실패 단계를 Transaction으로 저장하는 Service와 통합 Test를 구현한다.
- 별도 확인: 최지용의 Endpoint·DB Migration·재시도 책임 경계 승인과 팀 DB 실행 환경이 필요하다.

### 3.3 `T-026` 증상 구조화·누락 정보·추가 질문 — 95%

- 완료·근거: [구조화 코드](../../../ai/app/structuring), [평가 Dataset](../../../ai/evaluation/datasets/structuring/symptom_eval_dataset.json), [구조화 결과](../../../ai/evaluation/reports/structuring_evaluation_20260807.json), [구조화 Runner](../../../ai/evaluation/runners/structuring_runner.py). 대표·복수·오타·부정·이전 답변·답변 거절 등 12/12 Case가 PASS했다.
- 미완료: 12건은 결정적 규칙 평가이며 자유 입력 일반 성능이나 Backend·Web·Mobile 실제 소비를 증명하지 않는다.
- 완료 방법: 실제 API 입력 Corpus와 오류 사례를 추가하고 Backend 저장·화면 표시까지 계약 Test로 연결한다.
- 별도 확인: 평가 Case 대표성, 추가 질문 문구의 상담 업무 적합성에 대한 사용자·상담 담당 검토가 필요하다.

### 3.4 `T-032` Timeout·재시도·상담 Fallback — 75%

- 완료·근거: [단일 RAG Pipeline](../../../ai/app/orchestration/pipelines/single_rag_pipeline.py), [공식 MVP 후보](../../../ai/evaluation/reports/official_mvp_baseline_20260803.json), [Demo 검증 절차](../../../scripts/demo/README.md). 전체 30초, AI 내부 일시 검색 오류 최대 1회, Backend 재시도 0회와 구조화 Fallback 정책이 기록됐다.
- 미완료: Backend가 Timeout·검색 장애·Schema 오류 후 입력을 보존하고 상담 상태로 전환하는 E2E는 없다.
- 완료 방법: 실패 주입 Test를 추가하고 Django에서 동일 `correlation_id`와 입력을 보존해 상담 전환·DB 기록까지 검증한다.
- 별도 확인: 운영 Timeout 수치와 상담 전환 정책의 팀 승인, 실제 네트워크 지연 환경 검증이 필요하다.

### 3.5 사전학습 모델·Vector DB 결과서 — 100%

- 미완료: 지침서상 산출물 작성 항목은 없다. 팀 DB 결과는 다음 통합 Gate로 남는다.
- 완료 방법: 추가 필수 조치는 없으며 팀 DB 재실행 결과를 후속 Version에 반영한다.
- 별도 확인: 최종 제출본 승인과 DOCX/PDF 변환본의 내용 일치를 확인한다.
