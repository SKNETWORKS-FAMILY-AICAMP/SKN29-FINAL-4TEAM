## 2. 3장 필수 업무별 평가

### 2.1 3.1 AI·RAG·Backend 연동 기준선 재검증과 Blocker 폐쇄 — 95%

완료 근거:

- [AI Entry Gate](../../testing/ai/week5-ai-entry-gate.md)와 [Walkthrough](walkthrough.md)에 환경·모델·Mock/Local 경계와 최신 AI Unit `167 passed, 3 warnings`가 기록돼 있다.
- [Backend–AI Gate](../../testing/week5/backend-ai-integration-gate.md)에 정상·Replay 실제 소켓 Mock 결과와 남은 Blocker가 있다.
- No-Evidence·금지 자료·제품 범위·Fallback 정책이 코드와 Test에 반영됐다.

미완료 및 완료 방법: 현재 최종 SHA에서 AI Unit·Contract·FastAPI Smoke를 다시 실행해 SHA·Python·의존성·PASS 수를 하나의 최신 Gate로 고정한다.

### 2.2 3.2 Multi-Agent Architecture 확정과 실제 Runtime 전환 — 30%

완료 근거:

- [Multi-Agent 계약 초안](../../testing/ai/week5-multi-agent-contract-draft.md), [Test Plan](../../testing/plans/week5-multi-agent-test-plan.md), Shared State·Routing 목표가 있다.
- Consultation Summary 등 일부 역할별 Formatter·Schema·Test가 존재한다.

미완료 및 완료 방법:

- [Pipeline Router](../../../ai/app/orchestration/pipeline_router.py)와 현행 Single RAG를 Supervisor 기반 Runtime으로 전환한다.
- Symptom·Safety·Retrieval·Guidance·Validation 최소 Agent를 독립 구조화 입출력으로 구현한다.
- Route 선택, Handoff, 최대 Hop, Safety 우선, No-Evidence, 재검증 실패 Trace를 Test한다.

별도 확인: 5주차 P0 최소 Agent 수와 구현 범위를 PM에게 승인받아야 한다.

### 2.3 3.3 실제 LLM Provider·Model Routing·Structured Output — 20%

완료 근거:

- Schema 기반 Rule/Template Output과 Fallback은 있으며 `external_llm_used=false`를 기록한다.

미완료 및 완료 방법:

- [LLM Client](../../../ai/app/integrations/llm/llm_client.py)와 [Model Router](../../../ai/app/integrations/llm/model_router.py)를 실제 Interface·Provider Adapter로 구현한다.
- 환경변수 on/off, Timeout·Rate Limit·Token·Latency·비용, JSON Schema 재검증을 추가한다.
- Rule-only와 실제 LLM을 같은 Case로 비교하고 Provider 미설정 시 fail-closed를 검증한다.

별도 확인: 모델·API Key·비용 한도·외부 전송 허용 범위 승인이 필요하다.

### 2.4 3.4 팀 DB pgvector·bge-m3 Retrieval 공식 기준선 — 75%

완료 근거:

- [전체 Corpus Retrieval](../../../ai/evaluation/reports/experiments/full_corpus_baseline_v1/retrieval_summary.json)과 Performance 결과가 있다.
- Chunking, Threshold·Scope, Query Intent, Dense/BM25, Alias Expansion 실험 코드·결과가 추가됐다.
- 모델 Revision·1024차원·Dataset·Corpus Hash와 No-Evidence Gate가 고정돼 있다.

미완료 및 완료 방법:

- 동일 Corpus를 팀 PostgreSQL pgvector에 적재하고 실제 SQL 검색으로 동일 평가셋을 재실행한다.
- Gold 2인 검수 후 Hit@5·MRR·금지 Hit·Latency를 공식 승인 결과서로 묶는다.
- DB 장애와 검색 0건을 Retrieval Agent의 실제 경로에서 검증한다.

### 2.5 3.5 Django Backend↔Multi-Agent 실제 HTTP 수직 연동 — 65%

완료 근거:

- [P0-2 공동 Mock 회신](인계/20260812_이동윤_to_최지용_P0-2_공동Mock_후속정보_회신_v0.1.md)은 AI Unit 167건과 Django→Uvicorn 실제 소켓 Mock 1건 PASS를 기록한다.
- 실제 HTTP에서 AI Schema·Correlation·AIRun·Assessment·Guidance 저장과 Replay 추가 저장 0이 검증됐다.

미완료 및 완료 방법:

- FastAPI `mode=local`이 Multi-Agent·팀 pgvector·실제 Evidence를 실행하도록 연결한다.
- 정상·위험·근거 없음·Timeout·Schema 오류를 Django 요청부터 DB State/Event까지 한 Trace로 검증한다.
- 실제 LLM과 Vector 장애를 포함한 팀 공통 E2E 결과를 남긴다.

### 2.6 3.6 Multi-Agent Timeout·Retry·Fallback·안전성 — 80%

완료 근거:

- 전체 30초, AI 내부 Retry 최대 1회, Backend 자동 Retry 0회, 위험·No-Evidence·Schema Invalid·Vector 장애 Fallback 정책과 단위 Test가 있다.
- Answerability·제품/세대/문서 허용 정책이 LLM 단독 판단에 의존하지 않는다.

미완료 및 완료 방법:

- Agent별 Timeout·Retry·Hop Matrix를 실제 Runtime에 적용한다.
- 실제 LLM 429/Timeout, pgvector 장애, Evidence 모순, 위험 입력 조합을 HTTP 통합 Test로 실행한다.
- 재생성도 실패하면 일반 안내를 생성하지 않고 상담 전환·안전 고정 문구로 끝나는지 검증한다.
