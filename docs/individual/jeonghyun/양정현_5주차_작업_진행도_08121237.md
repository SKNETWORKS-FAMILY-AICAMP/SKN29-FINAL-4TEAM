## 2. 3장 필수 업무별 평가

### 2.1 3.1 Mobile 기준선 재검증·연동 가능 범위 확정 — 100%

완료 근거:

- [Mobile 독립 Closeout](../../../mobile/docs/week5/week5-mobile-independent-closeout.md)에 Unit·Connected·Build·APK 설치와 Remote/Fake 경계가 기록돼 있다.
- [Mobile E2E 결과](../../../mobile/docs/week5/week5-mobile-e2e-result.md)는 고객·기사 실제 로그인과 제공/미제공 Route를 구분한다.
- `CUSTOMER_CARE_MODE=REMOTE`에서 실패를 Fake 성공으로 대체하지 않는다.

별도 확인: 이 판정은 Mobile 독립 Gate이며 전체 팀 Feature Complete 승인은 아니다.

### 2.2 3.2 고객 제품·구독 Remote 전환과 홈 Fake 제거 — 100%

완료 근거:

- 실제 고객 Demo Login, 활성 구독 목록·상세 조회가 실기기 Remote Smoke에서 PASS했다.
- [Customer App 코드](../../../mobile/customer-app/src/main/java/com/skn29/watercare/customer)는 Backend DTO→Domain→UiState 경계를 사용한다.
- Remote 실패·빈 결과·권한 오류를 Fake 구독으로 보충하지 않는다.

별도 확인: 운영 계정·실제 개인정보 데이터는 합성 계정 검증 범위 밖이다.

### 2.3 3.3 문의 생성·증상 제출·추가 질문 실제 흐름 — 95%

완료 근거:

- 문의 생성·증상 제출에 이어 [Customer Inquiry 3 API Adapter](../../../mobile/docs/week5/2026-08-12_customer_inquiry_3api_mobile_adapter.md)가 Snapshot·Questions·Answers를 Remote 기본 경로에 연결한다.
- 실기기에서 Snapshot, FREE_TEXT·SINGLE_CHOICE 답변, 상태 Version 상승, 답변 후 재조회가 PASS했다.
- 409는 입력을 보존하고 최신 Snapshot을 다시 읽으며, 동일 Key 자동 재시도와 Fake 자동 성공을 금지한다.

미완료 및 완료 방법:

- 현재 Backend·Mobile과 전체 계약을 같은 최종 Commit에 고정해 정상·409·422·404를 팀 공통 E2E 결과서에 재수록한다.
- 문의 후 AI Guidance까지 이어지는 다음 단계는 3.4 공개 Route가 생긴 뒤 연결한다.

별도 확인: 실제 Backend 로그의 Idempotency·Correlation과 기기 화면 결과를 공동 대조해야 한다.

### 2.4 3.4 AI 안내·공식 근거·Fallback 실제 Backend 소비 — 40%

완료 근거:

- Mobile은 Guidance 미제공 상태를 명시적으로 fail-closed 처리하고 AI FastAPI를 직접 호출하지 않는다.
- 내부 `chunk_id`, 점수, 경로, 원문 전체를 UI에 노출하지 않는 모델 경계와 Test가 있다.

미완료 및 완료 방법:

- Backend가 CUSTOMER Guidance·Public Evidence Route와 DTO를 공개하면 Retrofit·Mapper·UiState를 구현한다.
- 정상·위험·근거 없음·AI 실패·Timeout의 실제 응답을 실기기에서 검증한다.

별도 확인: Evidence 공개 허용 필드와 상담 전환 UX를 Backend·AI·QA와 승인해야 한다.

### 2.5 3.5 방문기사 앱 Fixture 제거·실제 방문 업무 연동 — 40%

완료 근거:

- 기사 Demo Login과 `/me`는 실기기 Remote에서 PASS했고 미제공 Visit 기능은 닫혀 있다.
- 고객·기사 역할 분리와 Remote 실패 시 Fake 방문 미표시 정책이 유지된다.

미완료 및 완료 방법:

- Backend의 TECHNICIAN 방문 목록·상세·시작·완료·결과 등록 Route가 공개되면 Repository·DTO·화면을 연결한다.
- 배정 기사만 접근, date-only, 409 입력 보존, 재로그인 복구를 실제 기기에서 검증한다.

별도 확인: 기사 배정 Seed와 실제 방문 Route 제공 시점이 필요하다.

## 3. 완료 우선순위

1. 현재 고객 3 API 결과를 팀 공통 Gate에 반영
2. CUSTOMER Guidance·Evidence 계약 수신 후 Remote 구현
3. TECHNICIAN Visit Route 수신 후 기사 앱 Remote 구현
4. 고객→AI→상담→방문 대표 E2E 참여

## 4. 코드만으로 확인할 수 없는 사항

- Backend 공개 Route 일정과 담당자 계약 승인
- 실제 기기·Backend 로그의 Correlation 대조
- Public Evidence의 사람 검수와 개인정보 비노출 승인
- 기사 배정 Seed 및 팀 E2E 실행 환경

## 5. 완료 기준 및 최종 체크리스트 판정

현재 완료로 체크해도 되는 항목:

- [x] Mobile Unit·Connected·Build·APK 설치·실기기 기본 Gate 결과가 있다.
- [x] 고객 제품·구독이 실제 Backend Remote를 사용하고 Fake 자동 대체가 없다.
- [x] 문의 생성·증상 제출이 실제 Backend와 연결돼 있다.
- [x] Snapshot·추가 질문 조회·답변 제출 3 API가 Remote 경로에 연결돼 있다.
- [x] 추가문진의 `state_version`, `allowed_actions`, Idempotency·409 입력 보존이 구현돼 있다.
- [x] AI FastAPI를 직접 호출하지 않고 Backend 미제공 기능을 fail-closed 처리한다.
- [x] 내부 Evidence 메타데이터를 UI 모델에 노출하지 않는다.

- [ ] 기사 Visit 목록·상세·시작·완료·결과가 실제 Backend와 연결됐다.
- [ ] 고객→AI→상담→방문 전체 대표 E2E가 동일 Commit에서 PASS했다.
