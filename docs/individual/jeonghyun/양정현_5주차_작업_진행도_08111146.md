완료된 내용과 근거:

- Remote 모드 초기화는 [WaterCareCore](../../../mobile/core/src/main/java/com/skn29/watercare/core/WaterCareCore.kt)에서 실제 Subscription Repository를 주입한다.

미완료 및 완료 방법:

- 빈 구독, 401·403·404·5xx에서 Fixture 화면으로 바뀌지 않고 Loading·Empty·Error가 올바르게 표시되는지 UI Test를 추가해야 한다.

별도 확인:

- 합성 계정의 구독 Seed와 화면에 표시된 제품 정보가 실제 DB Row와 일치하는지 확인해야 한다.

### 2.4 3.4 AI 안내·공식 근거·Fallback 실제 Backend 소비 — 35%

완료된 내용과 근거:

- Remote 모드에서 Guidance API가 없으면 [Remote 고객 Repository](../../../mobile/core/src/main/java/com/skn29/watercare/core/repository/RemoteIntakeCustomerCareRepository.kt)가 `GUIDANCE_ROUTE_UNAVAILABLE`로 Fail-closed하며 Fake 성공으로 바꾸지 않는다.
- 고객 화면에는 위험·근거 없음·AI 실패·Network 실패 상태와 내부 필드 비노출 구조가 있다.

미완료 및 완료 방법:

- Backend Public Guidance·EvidenceCardDTO가 확정되면 API DTO·Mapper·Repository를 추가하고 Fake Guidance를 Remote 기본 흐름에서 완전히 분리해야 한다.
- 정상·위험·근거 없음·Timeout·Fallback 실제 응답을 고객 화면과 연결하고 `allowed_actions` 기반 버튼을 검증해야 한다.

별도 확인:

- 공개 Evidence에 `chunk_id`, Vector 점수, 내부 경로, Prompt가 없는지 실제 응답으로 확인해야 한다.

### 2.5 3.5 방문기사 앱 Fixture 제거·실제 방문 업무 연동 — 35%

완료된 내용과 근거:

- 기사 로그인·`/me`는 실제 Backend를 사용하고 Offline Preview가 명시적으로 분리돼 있다.
- [Technician ViewModel](../../../mobile/technician-app/src/main/java/com/skn29/watercare/technician/TechnicianViewModel.kt)은 Remote 실패 시 Fixture를 자동 사용하지 않고 Runtime Blocked로 표시한다.
- 기사 Unit·Connected Test와 실단말 설치 증거가 있다.

미완료 및 완료 방법:

- Backend에 배정 기사 전용 Visit 목록·상세 API를 만들고 Mobile `RemoteTechnicianVisitRepository`를 구현해야 한다.
- 기사 시작·완료·조치 결과 Runtime이 승인되면 State Version·권한·멱등성 DTO를 연결해야 한다.
- 본인 배정만 조회, 타 기사 404/403, 최소 PII, 실제 사전 점검 표시를 Smoke·UI Test로 남겨야 한다.

별도 확인:

- 실제 기사 배정 Seed와 객체 권한, 표시 가능한 고객 주소 범위는 최지용·윤승혁 승인 확인이 필요하다.
