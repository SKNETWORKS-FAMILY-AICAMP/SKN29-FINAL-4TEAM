#### Data CI 트러블슈팅

로컬 PASS·GitHub Actions FAIL의 원인을 한 번에 덮지 않고 다음 순서로
분리했다.

1. 최초 실패 시점의 33개 테스트 중 4개 실패를 재현했다. QA Manifest
   SHA가 현재 생성 결과와 달랐고, 실제 `Visit 4`, 상태이력 123,
   감사 이벤트 123에 대해 Manifest가 `Visit 5`, 상태이력 115,
   감사 이벤트 115를 가리키고 있었다.
2. 최신이 아닌 QA·Manifest를 파이프라인으로 재생성하고 T-005
   Projection 반영 후 상태이력과 감사 이벤트를 각각 125건으로
   정합화했다.
3. Shallow Checkout 때문에 계약 원본 Commit을 찾지 못하는 문제를
   전체 Git 이력 Checkout으로 해결했다.
4. Windows CRLF와 Linux LF가 다른 SHA-256을 만드는 문제를
   UTF-8·LF 기준 Hash로 정규화했다.
5. 최종 Manifest의 텍스트 파일 크기·Hash도 LF 기준으로 계산했다.
6. Windows·Linux의 경로 정렬 차이를 POSIX 문자열 정렬로 고정했다.
7. 수동 Hash 편집 대신 `refresh_source_hashes.py`와 `--check`를
   추가했다.

수정 과정에서는 LF Hash 문제 해결 후 56/56까지 통과했지만 생성
산출물 Drift가 남았다. 텍스트 크기·Hash와 POSIX 경로 정렬까지
보완한 뒤 최종 57/57 PASS가 됐다. 당시 최종 기록은 State Machine
계약 PASS, 오류·경고 0/0, Source Hash Stale 0, Drift 0,
[GitHub Actions Data CI SUCCESS](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN29-FINAL-4TEAM/actions/runs/30441177288)다.
Node.js 20 사용 중단 예정 경고는 남았지만 실패 원인은 아니었다.
이 수치는 7월 29일 CI 해결 시점의 역사 기록이며 현재 검증 수치는
7절에 별도로 적는다.

## 11. 최종 요약

2. 전처리 데이터와 Schema·Manifest·QA를 정합화했다.
3. 공통 합성 Fixture와 Expected Data를 서비스 계약에 맞췄다.
4. Backend와 AI가 필요한 최소 전달면을 프로필로 분리했다.
5. PostgreSQL Handoff와 pgvector 검색 증거를 Data 계약에 연결했다.
6. Windows·Linux에서 동일한 결과를 만드는 CI 결정성을 확보했다.
7. Owner Review, 인계 문서, 제출 기준본을 최신화했다.
8. 데이터 수집 보고서와 데이터 전처리 보고서 제출을 완료했다.

현재 Data Source Hash와 61개 단위 테스트는 현재 HEAD에서 다시
통과했다. 다만 전체 완료 조건은 동일 Commit에서 Backend·AI·Web·Mobile
Runtime을 연결한 수직 E2E와 운영 범위 검증이다. 이 범위는 이번 주 Data
파트 완료 수치와 구분해 후속 작업으로 유지한다.
