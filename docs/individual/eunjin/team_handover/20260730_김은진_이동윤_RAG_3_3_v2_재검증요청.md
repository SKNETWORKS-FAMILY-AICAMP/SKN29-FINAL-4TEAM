- 작성일: 2026-07-30
- RAG 실행 증거 병합 기준: `4adc84d`
- v2 요청 작성 기준: `main=643b23f`
- 현재 계약: 양성 7건·부정 5건, pgvector 12/12 PASS
- 목적: 현재 12개 증거를 보존하면서 업무 지침서 3.3의 미충족 항목을
  v2 계약과 13개 재실행으로 닫는다.

## 1. 변경 원칙

현재 `data/config/rag/jac104_retrieval_cases.json` v1.1의 Case·Query·
기대값은 12/12 실행 증거의 기준이므로 변경하지 않는다. v1.1이 main에
병합된 뒤 별도 변경으로 v2를 작성한다. v2 작성 시 상태는
`DATA_EXPECTATION_READY_AI_REVERIFY_REQUIRED`이며 새 실행 결과를 받기
전에는 `PASS`로 표시하지 않는다.

공식 원문과 기존 7개 `chunk_text`는 검색 점수를 위해 수정하지 않는다.

## 3. 13번째 정책 차단 Case

Case ID는 `RAG-NEG-POLICY-DISALLOWED`, Type은 `NEGATIVE_POLICY`로
고정한다. 실제 RAG 원본이 아니라 AI SQL Filter 평가 전용 Fixture를
사용한다.

- exact sales code: `WPUJAC104DWH`
- generation: `D`
- verification status: `official_verified`
- allowed use: `false`
- fixture chunk ID: `VERIFY-DISALLOWED`
- fixture document ID: `VERIFY-DOC-POLICY-DISALLOWED`
- 기대 결과: 검색 결과 없음

현재 Filter Fixture가 같은 `VERIFY-DOC`를 공유하므로 이동윤은 Fixture별
문서 ID를 고유하게 바꾼다. 평가 Fixture는 검증 후 삭제하며 Canonical
7개 인덱스와 Dataset Manifest에 포함하지 않는다.

## 4. AI 결과 계약

각 Case 결과에는 다음을 기록한다.

```json
{
  "case_id": "RAG-POS-LOW-FLOW",
  "applied_filter": {
    "exact_sales_code": "WPUJAC104DWH",
    "manual_generation": "D",
    "verification_status": "official_verified",
    "allowed_use": true
  },
  "ranked_results": [
    {
      "rank": 1,
      "chunk_id": "RAG-WPUJAC104DWH-LOW-FLOW-001",
      "document_id": "MAN-SKMAGIC-WPU-JAC104D-JCC104D-REV00",
      "page": 38,
      "score": 0.0
    }
  ],
  "metrics": {
    "recall_at_k": 1.0,
    "hit_at_k": 1.0,
    "expected_page_hit": true,
    "mrr": 1.0,
    "forbidden_hit_count": 0
  },
  "outcome": "PASS",
  "failure_reason": null,
  "review_owner": "LEE_DONGYUN"

```

`outcome`은 `PASS`, `FAIL`, `MANUAL_REVIEW` 중 하나다. 실패나 수동
검토는 `DATA`, `FILTER`, `INDEX`, `QUERY`, `POLICY` 중 원인 분류와
담당자를 함께 기록한다.

Result Manifest 전역에는 평가 계약 SHA-256, Canonical Dataset SHA,
Embedding 모델·revision, Index version·Chunk Set SHA, PostgreSQL·
pgvector 버전, Top-k와 Score threshold를 기록한다.

## 5. 재검증과 반환

1. Data v2 Schema와 13개 Case 수신
2. 평가 전용 Filter Fixture 생성
3. Canonical 7개 적재 동일성 확인
4. 13개 검색 실행
5. Fixture 유출 0·잘못된 차원 거부 확인
6. Result·Index Manifest Commit
7. AI Commit SHA와 Data 담당자 회신

누수 Case는 순위 개선 여부와 무관하게 실제 순위·점수·MRR을 그대로
기록한다. 13개 결과와 모든 Hash를 받은 뒤 Data가 v2
`ai_execution=PASS`로 승격한다.
