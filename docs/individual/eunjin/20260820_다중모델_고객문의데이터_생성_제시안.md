# 다중 모델 고객 문의 데이터 생성 제시안

## 1. 작성 목적

현재 고객 문의 데이터는 대부분 JAC104를 사용하는 고객을 기준으로 만들어져 있다.
IAC425와 IAC606이 추가되면서 고객이 사용하는 제품, 구독 상태와 문의 상황도
모델에 맞게 다양해져야 한다.

이 문서는 기존 데이터를 최대한 유지하면서 고객을 18명으로 확장하고,
각 고객에게 어떤 제품과 문의 상황을 배정할지 설명하는 1차 제시안이다.

## 2. 기본 원칙

- 고객 한 명을 제품 모델마다 따로 만들지 않는다.
- 한 고객이 여러 제품을 사용할 수 있도록 제품과 구독을 각각 연결한다.
- 문의는 고객이 실제로 보유한 제품에만 연결한다.
- 문의한 제품과 같은 모델의 안내 자료만 사용한다.
- 이용 중인 구독만 정상 문의를 접수할 수 있다.
- 이번 1차 데이터는 모든 구독을 이용 중 상태로 구성한다.
- 기존 JAC104 고객 12명과 기존 문의는 변경하지 않는다.
- 실제 개인정보는 사용하지 않고 합성 이름과 가상 정보만 사용한다.

## 3. 전체 고객 구성

| 구분 | 고객 수 | 설명 |
|---|---:|---|
| 기존 JAC104 고객 | 12명 | 기존 고객과 문의 내역을 그대로 유지한다. |
| IAC425 신규 고객 | 3명 | 모두 이용 중인 고객으로 구성한다. |
| IAC606 신규 고객 | 3명 | 모두 이용 중인 고객으로 구성한다. |
| 여러 제품을 보유한 고객 | 기존 고객 중 2명 | 각각 IAC425와 IAC606을 한 대씩 추가한다. |

확장 후 전체 고객은 18명이고, 고객과 제품의 연결은 총 20건이 된다.

- JAC104: 12건
- IAC425: 4건
- IAC606: 4건
- 여러 제품을 보유한 고객: 2명

## 4. 고객별 제품·구독·문의 상황 배정표

| 번호 | 고객명 | 보유 제품 | 구독 상태 | 문의 상황 및 예상 처리 |
|---:|---|---|---|---|
| 1 | 고서온 | JAC104, IAC425 | 두 제품 모두 이용 중 | 기존 물 안 나옴·누수 문의는 유지한다. 새 온수 중단 문의에서는 어느 제품의 문제인지 먼저 확인하고 IAC425 상담으로 연결한다. |
| 2 | 구하린 | JAC104 | 이용 중 | 출수량이 줄어든 뒤 누수까지 발생하여 상담을 진행한다. |
| 3 | 노재온 | JAC104 | 이용 중 | 냉수 온도 이상과 물맛·냄새 문제를 문의한다. |
| 4 | 류다은 | JAC104 | 이용 중 | 누수 위험 안내를 받은 뒤 상담으로 연결한다. |
| 5 | 문하겸 | JAC104 | 이용 중 | 물맛·냄새와 순간온수 사용 안전을 문의한다. |
| 6 | 백서율 | JAC104 | 이용 중 | 순간온수 사용 중 안전 여부를 확인한다. |
| 7 | 설도윤 | JAC104, IAC606 | 두 제품 모두 이용 중 | 기존 물 안 나옴·소음 문의는 유지한다. 얼음 미출수 문의에서는 IAC606 제품임을 확인한 뒤 고객이 직접 점검하도록 안내한다. |
| 8 | 심나예 | JAC104 | 이용 중 | 물이 나오지 않고 소음이 반복되는 문제를 문의한다. |
| 9 | 우하람 | JAC104 | 이용 중 | 출수량 감소와 소음이 함께 발생한 상황을 문의한다. |
| 10 | 위서진 | JAC104 | 이용 중 | 출수량 감소와 제품에서 지원하지 않는 연결 기능을 문의한다. |
| 11 | 진가온 | JAC104 | 이용 중 | 냉수 온도 이상과 연결 기능 지원 여부를 문의한다. |
| 12 | 채도현 | JAC104 | 이용 중 | 제품에서 지원하지 않는 연결 기능을 문의한다. |
| 13 | 김은별 | IAC425 | 이용 중 | 온수가 나오지 않아 기본 확인을 진행한 뒤 상담사에게 연결한다. |
| 14 | 윤승아 | IAC425 | 이용 중 | 제품 아래에 물이 고이는 누수가 발생한다. 사용 중지 안내 후 상담과 방문 점검을 검토한다. |
| 15 | 이다윤 | IAC425 | 이용 중 | 냉수 버튼을 눌러도 소리만 나고 선택되지 않는다. 냉수 기능의 잠금 상태를 확인하고 잠금 해제 방법을 안내받아 직접 해결한다. |
| 16 | 최지안 | IAC606 | 이용 중 | 얼음이 나오지 않아 설정, 밸브와 얼음 생성 대기시간을 확인하고 직접 해결한다. |
| 17 | 양정원 | IAC606 | 이용 중 | 누수가 발생하여 즉시 사용을 멈추고 상담과 방문 점검으로 연결한다. |
| 18 | 한예림 | IAC606 | 이용 중 | 얼음이 자꾸 깨져 나오고 단단하지 않은 문제를 문의한다. 장시간 사용하지 않았는지 확인하고 얼음 저장 공간의 특성을 안내받는다. |

## 5. 새로 만들어야 할 데이터

기존 고객 12명과 기존 문의 22건은 그대로 유지한다. 새로 추가하는 내용은
다음과 같다.

| 항목 | 추가 수량 | 설명 |
|---|---:|---|
| 신규 고객 | 6명 | IAC425 고객 3명, IAC606 고객 3명 |
| 고객이 보유한 제품 | 8건 | 신규 고객용 6건과 기존 고객의 추가 제품 2건 |
| 제품별 구독 | 8건 | 모두 이용 중인 구독으로 구성 |
| 정상 문의 | 8건 | 신규 모델 제품 연결마다 문의 1건씩 구성 |
| 상담 연결 | 4건 | 온수 이상 또는 누수처럼 상담이 필요한 상황 |
| 방문 점검 검토 | 2건 | IAC425 누수와 IAC606 누수 상황 |

정상 문의는 기존 22건에 8건을 더해 총 30건이 된다.

## 6. 문의 작성 기준

문의 문장은 고객이 실제로 말할 법한 짧고 자연스러운 표현으로 작성한다.

예시:

- “온수가 나오다가 갑자기 멈췄어요.”
- “얼음 버튼을 눌러도 얼음이 나오지 않아요.”
- “냉수를 누르면 소리만 나고 선택이 안 돼요.”
- “얼음이 자꾸 깨져 나오고 단단하지 않아요.”
- “제품 아래쪽에 물이 고여 있어요.”
- “정수기가 두 대인데 어떤 제품을 선택해야 하나요?”

각 문의에는 다음 정보가 빠짐없이 연결되어야 한다.

- 문의한 고객
- 문제가 발생한 제품
- 해당 제품의 구독 상태
- 문의 내용과 위험 정도
- 고객이 먼저 확인할 내용
- 상담 또는 방문이 필요한 조건
- 문의 처리 결과

## 7. 데이터 생성 순서

1. 기존 고객 12명과 기존 문의 22건이 바뀌지 않았는지 확인한다.
2. 신규 고객 6명을 만든다.
3. 신규 고객 6명과 기존 고객 2명에게 새 제품을 연결한다.
4. 제품마다 구독을 한 건씩 연결하고 이용 상태를 지정한다.
5. 이용 중인 신규 구독 8건에 문의를 한 건씩 만든다.
6. 문의한 제품과 같은 모델의 안내 자료가 사용되는지 확인한다.
7. 다른 모델의 안내가 섞이지 않는지 확인한다.
8. 검증이 끝난 뒤에만 실제 서비스용 데이터로 전환한다.

## 8. 완료 확인 기준

- 전체 고객이 18명인지 확인한다.
- 고객과 제품의 연결이 20건인지 확인한다.
- IAC425와 IAC606 제품 연결이 각각 4건인지 확인한다.
- 여러 제품을 보유한 고객이 2명인지 확인한다.
- 신규 구독 8건이 모두 이용 중 상태인지 확인한다.
- 신규 구독마다 문의가 한 건씩 연결됐는지 확인한다.
- 전체 정상 문의가 30건인지 확인한다.
- 문의한 모델과 안내 자료의 모델이 일치하는지 확인한다.
- 기존 JAC104 고객과 문의 데이터가 변경되지 않았는지 확인한다.
- 실제 개인정보나 내부 비밀정보가 포함되지 않았는지 확인한다.

## 9. 이번 제시안에서 제외하는 내용

- 일시 중지·중도 해지·계약 만료와 제품 회수 처리
- 실제 서비스 데이터베이스 등록
- 기존 고객과 문의 내용 수정
- 제품별 상세 처리 단계 확정
- 실제 상담사와 방문기사 배정
- 실제 고객 개인정보 사용

이 문서는 데이터 생성 방향을 정하기 위한 제시안이다. 서비스 개발 담당자와
인공지능 검색 담당자가 제품별 처리 흐름과 검색 결과를 확인한 뒤 별도의
구현·검증 작업으로 진행한다.
