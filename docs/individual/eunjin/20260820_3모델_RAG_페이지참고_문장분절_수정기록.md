# 3모델 RAG 페이지 참고 문장 분절 수정 기록

## 1. 작업 배경

신규 2모델 격리 E2E 검증 중 IAC425와 IAC606의 일부 안전조치가 다음처럼
부자연스럽게 나뉜 것을 확인했다.

```text
"(청소하기 p."
"36 참고) 배수 호스가 꺾이거나 ..."
```

매뉴얼 원문과 RAG Child 본문에는 `(청소하기 p.36 참고)`가 정상적으로
들어 있었다. 오류는 원문 추출 단계가 아니라 Child의 `safe_actions`를 만드는
후처리 단계에서 발생했다.

## 2. 원인과 수정 내용

기존 빌더는 모든 마침표를 문장 끝으로 처리했다. 이 때문에 페이지 번호인
`p.36`, `p.41` 등의 마침표도 문장 끝으로 잘못 인식했다.

다음 기준으로 분절 규칙을 수정했다.

- `p.숫자`의 마침표는 문장 끝으로 처리하지 않는다.
- `(청소하기 p.36 참고)`처럼 독립된 줄에서 추출된 참고 문구는 바로 앞의
  청소 안내에 붙인다.
- `(해제 방법은 p.27 참고)`, `(필터 교체하기 p.31 참고)`에도 같은 규칙을
  적용한다.
- 참고 문구 뒤에 별도의 확인 조치가 있으면 각각 독립된 안전조치로 나눈다.

수정 후 IAC606 예시는 다음처럼 생성된다.

```text
"방열팬 덮개 막힘 (먼지에 의한 막힘) - 청소하기 페이지 확인 후 방열팬
덮개를 청소해 주세요 (청소하기 p.36 참고)."
"배수 호스가 꺾이거나 수돗물이 얼진 않았는지 확인해 주세요."
```

## 3. 영향받은 RAG Child

기존 페이지 참고 표기가 잘못 분절됐던 다음 7개 Child가 다시 생성됐다.

- `CHILD-WPUIAC425SNW-P043-COLD-LOCK-001`
- `CHILD-WPUIAC425SNW-P045-NO-ICE-001`
- `CHILD-WPUIAC425SNW-P045-TASTE-ODOR-001`
- `CHILD-WPUIAC606SNW-P040-COLD-LOCK-001`
- `CHILD-WPUIAC606SNW-P040-NOISE-VENTILATION-001`
- `CHILD-WPUIAC606SNW-P042-NO-ICE-001`
- `CHILD-WPUIAC606SNW-P042-TASTE-ODOR-001`

Child와 연결된 Evidence Group, 신규 모델 E2E 후보 Fixture, 인계 Manifest와
최종 Manifest도 파이프라인으로 다시 생성했다. 원문 PDF, 전체 페이지 본문,
제품 코드, Child 본문과 원문 Anchor는 변경하지 않았다.

## 5. 남은 검증과 인계

이번 작업은 Data 전처리와 산출물 재생성까지만 완료했다. 변경된 안전조치를
실제 pgvector와 Backend E2E에 다시 반영한 결과는 아직 확정하지 않았다.

최지용 담당자가 기존 팀 DB의 JAC104 매뉴얼 제목 공백 문제를 수정한 뒤 다음
순서로 재검증한다.

1. 최신 main 동기화
2. 53개 Child 재적재
3. Crosswalk 53건 확인
4. Readonly View 분포 `15 / 19 / 19` 확인
5. IAC425·IAC606 격리 E2E 재실행

이 재검증이 끝나기 전에는 이번 Data 수정만으로 신규 두 모델의 Runtime
활성화 또는 전체 E2E 완료를 선언하지 않는다.
