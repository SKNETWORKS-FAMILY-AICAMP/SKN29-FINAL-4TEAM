- [Web Entry Gate](../../testing/web/week5-web-entry-gate.md)와 [최신 Web Entry 인계](../../handoffs/week5/week5-web-entry-gate.md)에 Mock/Remote, Runtime·Blocker가 기록돼 있다.

미완료 및 완료 방법: 현재 HEAD에서 전체 Test를 충분한 제한 시간·단일 worker로 끝내고 결과 수와 SHA를 Entry Gate에 갱신한다.

### 2.2 3.2 Mock 전용 Repository의 비동기 Remote 전환 — 100%

완료 근거:

- [Data Repository](../../../web/src/features/consultation/repositories/consultantWorkspaceDataRepository.ts)는 비동기 Mock/Remote 구현과 DTO Mapper를 분리한다.
- Remote Mode 실패를 Mock 성공으로 바꾸지 않고 공통 HTTP·Token Refresh·Correlation·Idempotency 경계를 재사용한다.
- Repository Boundary Test가 있다.

### 2.3 3.3 상담사 문의 목록 실제 API·Server Filter·Pagination — 90%

완료 근거:

- 실제 `GET /inquiries` 코드 경로, 서버 검색·Filter·Sort·Pagination, `page_info`, Loading·Empty·Error·Forbidden·Retry UI가 연결돼 있다.
- Remote Repository는 전체 결과를 다시 로컬 Filter하지 않고 계약에 없는 Query를 보내지 않는다.

미완료 및 완료 방법: 실제 상담사 로그인으로 목록·검색·복수 Filter·Sort·Pagination을 브라우저에서 실행하고 Backend 행 수·Correlation을 대조한다.

### 2.4 3.4 상담사 문의 상세 Remote·DTO Mapper·PII — 90%

완료 근거:

- 실제 상세 DTO→Section Mapper→ViewModel이 `section_errors`, History, `state_version`, `allowed_actions`를 처리한다.
- 주소·내부 ID·원문 전체·Vector 메타데이터를 Remote ViewModel로 보충하거나 노출하지 않는다.

미완료 및 완료 방법: 실제 상세 정상·403·404·부분 Section 오류를 Smoke하고 Network payload와 화면에서 PII·내부 필드 비노출을 확인한다.
