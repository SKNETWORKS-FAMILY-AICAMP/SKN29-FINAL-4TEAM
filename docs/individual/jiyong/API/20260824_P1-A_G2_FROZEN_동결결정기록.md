## 1. 목적

P1-A 회원가입·계정연결 API 계약에 대한 양정현(Mobile)의 Android 호환성
확인과 윤승혁(PM)의 최종 G2 승인이 모두 완료됐음을 기록한다.

이 문서는 정책을 다시 제안하거나 Runtime 완료를 선언하는 문서가 아니다.
두 ACK를 근거로 계약 변경을 제한하고, 다음 커밋에서 OpenAPI 상태를
`CONFIRMED`로 승격하기 위한 동결 결정 기록이다.

## 2. 동결 승인 근거

### Mobile 호환성 확인

양정현은 다음 결과를 회신했다.

- G2 로그인 규칙을 실제 Android 앱 구조에서 사용할 수 있음을 확인했다.
- 최신 코드 기준 앱 빌드와 기존 기능 회귀 테스트가 통과했다.
- 기존 로그인 성공 응답 수신이 가능한지 확인했다.
- `422` 입력값 오류와 `429` 재시도 대기 오류를 공통 오류 처리에서
  수신할 수 있는지 확인했다.
- 로그인 응답·`422`·`429` 표적 테스트 3건이 모두 통과했다.
- G2 계약 관점에서 Backend에 추가로 요구할 수정사항이 없다고 판정했다.
- 이번 확인은 계약 호환성 검증이며 Mobile Production 회원가입·로그인
  화면 구현은 아직 시작하지 않았다.

### PM 최종 승인

최지용은 Mobile ACK 반영 후 윤승혁(PM)의 G2 최종 승인을 수신했다.
기존 조건부 승인에서 요구한 비노출 응답과 Mobile 검토 조건이 모두
충족됐으므로, 아래 계약을 G2 동결 대상으로 확정한다.

승인 원문에 Secret·OTP·개인정보는 없으며, 저장소에는 승인 결과와 확정
정책만 기록한다.

## 3. 동결하는 계약 범위

다음 9개 신규 Operation을 P1-A G2 계약 범위로 고정한다.

1. `POST /api/v1/auth/contract-verification/challenges`
2. `POST /api/v1/auth/contract-verification/challenges/{challenge_id}/verify`
3. `POST /api/v1/auth/signup`
4. `POST /api/v1/auth/login`
5. `POST /api/v1/auth/account-recovery/username/challenges`
6. `POST /api/v1/auth/account-recovery/username/challenges/{challenge_id}/verify`
7. `POST /api/v1/auth/password-reset/challenges`
8. `POST /api/v1/auth/password-reset/challenges/{challenge_id}/verify`
9. `POST /api/v1/auth/password-reset/confirm`

기존 `GET /api/v1/me`는 새 Operation이 아니라 기존 로그인 사용자 조회
계약을 재사용한다.

## 4. 동결 정책

| 항목 | 확정값 |
|---|---|
| OTP 유효시간 | 300초 |
| OTP 재전송 대기 | 60초 |
| OTP 최대 실패 | 5회, 초과 시 Challenge 폐기 |
| 비밀번호 | 12~64자, 영문·숫자 필수, 특수문자 선택 |
| 필수 동의 | 이용약관, 개인정보 수집·이용 |
| 선택 동의 | 마케팅 |
| Challenge 생성 | 계약·계정 존재 여부와 무관하게 동일 HTTP `202` |
| OTP Verify 주소 | 모두 `challenges/{challenge_id}/verify` |
| 로그인 성공 응답 | 기존 `LoginResponse` 재사용 |
| claim/reset ticket | JWT와 분리해 해당 요청 Body에만 전달 |
| `422` | `details.fields`에 안전한 필드 오류 제공 |
| `429` | `Retry-After`와 `details.retry_after_seconds` 제공 |
| 공개 범위 | 합성 고객 ID/PW·OTP·계정연결·로그인·복구 |

계약 후보 없음은 `404`로 공개하지 않는다. HTTP Status, 응답 Schema,
메시지 또는 이메일 힌트만으로 계약·계정 존재 여부를 구분할 수 없어야 한다.

## 5. 보안 불변조건

- OTP, Password, JWT, `claim_ticket`, `reset_ticket` 원문을 로그·감사 이벤트·
  문서·AI Prompt·RAG Context에 기록하지 않는다.
- Challenge와 ticket은 목적·후보·만료시각에 묶고 단회성으로 소비한다.
- OTP 성공 전 CUSTOMER JWT를 발급하지 않는다.
- 회원가입 Transaction이 실패하면 User·Link·동의·감사 이벤트를 모두
  Rollback한다.
- 실제 고객 원장·개인정보와 P1-B 카카오 로그인은 이 동결 범위가 아니다.

## 6. 이번 기록의 경계

이번 커밋은 동결 결정 문서만 추가한다.

- `contracts/api/paths/p1-auth.yaml`의 현재 `IN_REVIEW` 상태는 다음 계약 승격
  커밋에서 `CONFIRMED`로 변경한다.
- `x-runtime-status`는 계속 `NOT_IMPLEMENTED`로 유지한다.
- Model·Migration·Seed·OTP 발송·회원가입 Runtime은 구현하지 않는다.
- Mobile·Web Production 코드를 수정하지 않는다.
- 이 문서는 Backend Runtime, PostgreSQL, Mobile 실기기 수직 E2E의 PASS
  증거가 아니다.

계약 승격 커밋이 검증되고 `main`에 병합되기 전에는 G3 구현을 시작하지 않는다.

## 8. 최종 판정

Mobile 호환성 검토와 PM 승인은 완료됐다. G2 동결 결정은 기록됐지만,
기계 판독 계약의 `CONFIRMED` 승격은 후속 커밋 대상이다.

따라서 현재 판정은 다음과 같다.

```text
G2_POLICY_DECISION=FROZEN
G2_MOBILE_COMPATIBILITY=ACK
G2_PM_APPROVAL=ACK
OPENAPI_CONTRACT_PROMOTION=PENDING
BACKEND_RUNTIME=NOT_IMPLEMENTED
MOBILE_PRODUCTION=NOT_IMPLEMENTED
G3_START=WAIT_FOR_CONFIRMED_CONTRACT_MAIN
```
