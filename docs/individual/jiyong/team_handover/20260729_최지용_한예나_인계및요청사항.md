# 최지용 → 한예나 인계 및 요청사항

> 기준일: 2026-07-29
> 대상: 한예나(Web)
> 작성자: 최지용(Backend·DB·API 계약)
> 문서 역할: 팀 공용 인계 허브를 보완하는 한예나 담당 실행 상세
> 현재 판정: `WEB_RUNTIME_REVIEW_REQUIRED`
> 목적: 구현된 Backend API만 실제 소비하고, Mock·DTO·식별자·오류 처리
> 경계를 확정한다.

## 1. 한 줄 인계

최지용이 전달할 수 있는 API 기준선은 **OpenAPI 9개 중 Runtime 7개**와
정상·오류·Replay JSON 예시 22개다. 한예나에게는 Web 공통 API 계층과
DTO를 이 기준으로 검토하고, Runtime이 없는 문의 목록·상세·상담 Action은
Mock/Blocked로 명시한 상태에서 실제 Auth Smoke 결과를 반환해 달라고
요청한다.

## 2. 역할 경계

| 경로·기능 | 한예나 | 최지용 |
|---|---|---|
| `web/**` | 주관 | 직접 수정하지 않고 계약·예시 제공 |
| `web/src/common/api/**` | 주관 | API 계약 부관할 |
| `web/src/features/*/api/**` | 주관 | Runtime 지원 범위 설명 |
| `web/src/features/workflow-action/**` | 주관 | State 응답·409 계약 제공 |
| `backend/apps/operations/**` | 부관할·소비자 리뷰 | 주관 |
| `contracts/api/**`, `contracts/error-codes/**` | 소비자 리뷰 | 주관 |

Web에서 발견한 계약 차이는 Backend 파일을 직접 수정하지 말고, Method·
Path·필드·예시·기대값을 적은 리뷰 의견으로 최지용에게 전달한다.

## 3. 현재 전달하는 API 범위

| 상태 | Method·Path | Web에서 할 일 |
|---|---|---|
| Runtime | `GET /health` | Backend 준비 상태 확인 |
| Runtime | `POST /api/v1/auth/demo-login` | 로그인·Token 저장 |
| Runtime | `POST /api/v1/auth/refresh` | Access 갱신 |
| Runtime | `POST /api/v1/auth/logout` | Refresh 폐기·세션 정리 |
| Runtime | `GET /api/v1/me` | 역할·사용자 Guard |
| Runtime | `POST /api/v1/inquiries` | CUSTOMER 전용임을 유지 |

실제 연동 완료로 표시하지 않는다.

## 4. DTO·식별자 검토 요청

Web Mock·Fixture의 `inquiry_id`와 Data Fixture의 `public_id`가 혼동되지
않도록 다음 의미를 유지해 달라.

- URL의 `{id}`와 API 응답 `inquiry_id`는 문의의 외부 공개 UUID다.
- 내부 정수 PK와 `DEMO-*`·`SYN-*` 업무 코드를 URL ID로 사용하지 않는다.
- Data 원본의 `public_id`를 Web 도메인 모델로 변환할 때 Mapper에서
  외부 UUID 의미를 보존한다.
- API JSON은 `snake_case`, Web 내부 모델은 기존 `camelCase` 규칙을
  Mapper 경계에서 변환한다.
- Public API 시각은 ISO 8601 `+09:00` Offset을 보존한다.

확인 대상:

- `web/src/common/api/httpClient.ts`
- `web/src/common/api/apiResponse.ts`
- `web/src/common/api/apiError.ts`
- `web/src/features/auth/api/authApi.ts`
- `web/src/features/auth/model/authContract.ts`
- `web/src/features/workflow-action/model/*`
- `web/src/features/consultation/model/*`

## 5. Auth·오류·상태 처리 요청

### Auth

- Access Token 60분, Refresh Token 최대 7일 정책을 임의 변경하지 않는다.
- 401이면 승인된 Refresh 흐름만 1회 수행하고, 실패하면 세션을 정리한다.
- 인증 부족 401, 역할 부족 403, 타인 자원 비노출 404를 구분한다.
- CONSULTANT가 CUSTOMER 전용 문의 생성·취소를 호출했을 때 403을 정상
  결과로 처리한다.

### 쓰기 요청

- 새 업무 시도마다 `Idempotency-Key`를 생성한다.
- 네트워크 재전송은 같은 Key를 유지하고 새 `correlation_id`를 사용한다.
- Payload에 현재 `state_version`을 포함한다.
- 409 응답의 최신 상태·`current_state_version`·`allowed_actions`로
  화면을 갱신한다.

### 화면 행동

- 버튼 노출은 Backend의 `allowed_actions`만 사용한다.
- Web에서 다음 상태를 자체 계산하거나 강제하지 않는다.
- `DUPLICATE_EVENT`와 `STATE_VERSION_CONFLICT`를 같은 일반 오류로
  뭉개지 않는다.

기존 `requestContext.ts`, `idempotencyOperation.ts`,
`workflowActionMapper.ts`의 테스트 기반은 유지하고 실제 API 응답과
연결해 검증한다.

## 6. 실제 Web 검증 요청

현재 팀 인계 문서에는 Node `24.14.0`이 `jsdom@30.0.0`의 요구 범위에
들지 않고, 자동 검증에서 Vitest Config 로딩 중 `spawn EPERM`이 있었다고
기록돼 있다. 지원 Node 환경의 한예나 일반 터미널에서 원인을 분리해
재실행해 달라.

```powershell
Set-Location (git rev-parse --show-toplevel)
Set-Location .\web
node --version
npm ci
npm test
npm run lint
npm run build
```

정적 테스트 통과 후 실제 API 모드로 별도 Smoke를 수행한다.

```powershell
$env:VITE_API_BASE_URL = "http://127.0.0.1:8000/api/v1"
$env:VITE_USE_MOCK_API = "false"
npm run dev -- --host 127.0.0.1
```

실제 Smoke 최소 범위:

1. `DEMO-CONSULTANT-001` 로그인
2. `/me` 역할·Guard 확인
3. 잘못된 Token 401
4. CONSULTANT의 CUSTOMER 전용 문의 생성·취소 403
5. Refresh 성공·실패 후 세션 처리
6. 서버 오류의 `correlation_id` 노출

문의 목록·상세·상담 Action은 Runtime이 없으므로 Smoke 성공 범위에
포함하지 않는다.

## 7. 최지용에게 반환할 검토 결과

아래 표로 차이를 반환해 달라.

| Method·Path | 요청/응답 필드 | Web 현재 구현 | OpenAPI·예시 | 판정 | 요청사항 |
|---|---|---|---|---|---|
| 대상별 작성 | 필드명·타입 | 파일·행 | 계약 경로 | 일치/불일치/Blocked | Backend 또는 Web 후속 |

함께 제공할 증거:

- Web Branch와 40자리 Commit SHA
- Node·npm 버전
- `npm ci`, Test, Lint, Build의 명령·Exit code·결과
- 실제 API Smoke의 요청 역할·HTTP 상태·`correlation_id`
- Runtime 7 / OpenAPI-only 2 / Web Mock 목록
- 발견한 DTO·오류 코드·식별자 차이

## 8. 이번 주 완료 조건

- [ ] Runtime 7개와 OpenAPI-only 2개가 Web 지원표에서 분리됨
- [ ] Auth 4개와 `/me` 실제 API Smoke 통과
- [ ] `public_id`·`inquiry_id`·업무 코드 의미가 Mapper에서 분리됨
- [ ] 401/403/404·409·Replay 처리 테스트 유지
- [ ] `allowed_actions` 외 행동 버튼이 노출되지 않음
- [ ] 상담·방문 Mock에 Mock/Blocked 표시가 있음
- [ ] Test·Lint·Build의 지원 Node 재현 증거가 있음
- [ ] `.env.local`, Token, 실제 개인정보가 Commit에 없음

## 9. 금지·주의사항

- OpenAPI-only 2개 또는 상담사 Mock API를 Runtime으로 호출하지 않는다.
- Backend·Data 계약을 Web 사정에 맞춰 직접 수정하지 않는다.
- 내부 PK·업무 코드를 외부 문의 UUID로 대체하지 않는다.
- Web에서 State Machine이나 완료 상태를 자체 확정하지 않는다.
- PM이 공유한 `main` SHA 전에 로컬 Data 산출물을 하드코딩하지 않는다.
