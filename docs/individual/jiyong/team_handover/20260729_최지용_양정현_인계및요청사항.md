# 최지용 → 양정현 인계 및 요청사항

> 기준일: 2026-07-29
> 대상: 양정현(Mobile)
> 작성자: 최지용(Backend·DB·API 계약)
> 문서 역할: 팀 공용 인계 허브를 보완하는 양정현 담당 실행 상세
> 현재 판정: `MOBILE_API_FOLLOW_UP`
> 목적: 확정된 3모듈 구조에서 Backend DTO·Network·JWT·오류 처리를
> 연결하고, 미구현 API와 로컬 상태의 경계를 유지한다.

## 1. 한 줄 인계

Mobile 구조는 `customer-app`·`technician-app`·`core` 3모듈로 확정됐다.
양정현에게는 구조 재설계가 아니라 **Runtime 7개 기준의 고객 Auth·문의
START/CANCEL 연동**, **Backend 상태·409·멱등 처리**, **두 App Build와
Emulator Smoke 증거**를 요청한다.

## 2. 역할 경계

| 경로·기능 | 양정현 | 최지용·협업자 |
|---|---|---|
| `mobile/**` | 주관 | Backend 계약 제공 |
| `mobile/core/**` 모델 | 주관 | 최지용 API 모델 부관할 |
| `mobile/core/**/InquiryStateMachine` | 주관 | 윤승혁 State 계약 부관할 |
| 고객 CUST-03·04, 기사 방문 상세 | 주관 | 이동윤 Evidence·AI 부관할 |
| Mobile Test·Build | 주관 | 김은진 QA 부관할 |
| `contracts/api/**`, Backend Runtime | 소비자 리뷰 | 최지용 주관 |

Mobile에서 발견한 API 차이는 Backend 파일을 직접 수정하지 말고 요청·
응답·오류·재현 절차를 최지용에게 전달한다.

## 3. 현재 전달하는 Runtime 범위

| 사용 가능 | 용도 |
|---|---|
| `GET /health` | 서버 준비 상태 |
| `POST /api/v1/auth/demo-login` | 고객 Demo 로그인 |
| `POST /api/v1/auth/refresh` | Access 갱신 |
| `POST /api/v1/auth/logout` | Refresh 폐기 |
| `GET /api/v1/me` | 사용자·역할 확인 |
| `POST /api/v1/inquiries` | 고객 문의 START |
| `POST /api/v1/inquiries/{id}/cancel` | 고객 소유 문의 CANCEL |

다음 두 계약은 아직 Runtime이 없으므로 실제 호출하지 않는다.

- `PATCH /api/v1/inquiries/{id}/questionnaire`
- `POST /api/v1/inquiries/{id}/action-results`

기사 방문 목록·상세·결과·위치 추적 API도 현재 Runtime 7개에 포함되지
않는다. 기존 Tracking API·화면이 있더라도 실제 Backend 연동 완료로
표시하지 말고 Mock/Blocked 경계를 남긴다.

## 4. DTO·Network 요청

### 공통 DTO

- 외부 문의 식별자는 Public UUID인 `inquiry_id`다.
- 내부 정수 PK와 `DEMO-*`·`SYN-*` 업무 코드를 URL ID로 사용하지 않는다.
- JSON 필드는 `snake_case`, Kotlin 모델은 기존 규칙으로 Mapper에서
  변환한다.
- API 시각은 ISO 8601 `+09:00` Offset을 보존한다.
- 공통 성공·오류 Wrapper와 `metadata.correlation_id`를 손실하지 않는다.

### 인증

- Access Token 60분, Refresh Token 최대 7일 정책을 따른다.
- 401 Refresh는 승인된 흐름으로 1회만 수행하고 실패 시 세션을 정리한다.
- 고객·상담사·기사·운영자 역할을 문자열 추측으로 확장하지 않는다.
- 실제 Token·Refresh Token을 Logcat, Screenshot, Commit에 남기지 않는다.

### 쓰기·상태

- 신규 업무 요청마다 `Idempotency-Key`를 만든다.
- 네트워크 재전송은 같은 Key, 새 `correlation_id`를 사용한다.
- 요청의 `state_version`과 응답의 새 버전을 저장한다.
- 409에서 최신 상태·`current_state_version`·`allowed_actions`를 반영한다.
- 행동 버튼·화면 이동은 Backend `allowed_actions`를 우선한다.

## 5. `core` 상태 처리 경계

`mobile/core/.../InquiryStateMachine.kt`는 Offline·Demo 표현과 UI 보조
검증에만 사용하고, 서버 업무 상태의 최종 권한으로 사용하지 않는다.

- Backend 응답 상태와 `allowed_actions`가 최종 기준이다.
- Mobile이 AI 결과를 받아 업무 상태를 직접 변경하지 않는다.
- Offline에서 만든 임시 전이를 재연결할 때 현재 서버 버전을 먼저
  조회·비교한다.
- 충돌 시 로컬 상태를 강제 업로드하지 않고 409 계약에 따라 사용자에게
  재시도를 안내한다.
- 윤승혁의 `contracts/state-machine/**`와 다른 전이 코드를 추가하지
  않는다.

## 6. Emulator 연동 요청

로컬 설정은 다음 기준을 사용한다.

```properties
BACKEND_BASE_URL=http://10.0.2.2:8000/
```

`local.properties`는 개인 환경 파일이므로 Git에 올리지 않는다.

빌드·테스트:

```powershell
Set-Location (git rev-parse --show-toplevel)
Set-Location .\mobile
java -version
.\gradlew.bat projects
.\gradlew.bat test
.\gradlew.bat lintDebug
.\gradlew.bat :customer-app:assembleDebug
.\gradlew.bat :technician-app:assembleDebug
```

JDK 17과 Android Emulator에서 다음 실제 Smoke를 수행해 달라.

1. 고객 Demo Login
2. `/me` 사용자·역할 표시
3. 문의 START 성공과 Public UUID·상태·버전·허용 행동 저장
4. 같은 문의 CANCEL 성공
5. 동일 `Idempotency-Key` Replay
6. 오래된 `state_version` 409 화면 처리
7. 잘못된 Token 401과 타 역할 403
8. Network 오류 후 동일 업무 요청의 안전한 재시도

Questionnaire·Action Result·기사 Visit/Tracking은 Runtime이 생기기 전까지
실제 Smoke 성공 항목에 넣지 않는다.

## 7. 최지용에게 요청할 계약 검토 결과

아래 내용을 화면별로 반환해 달라.

| 화면/기능 | 필요한 API·필드 | 현재 DTO·Mock | Runtime 여부 | Backend 요청 |
|---|---|---|---|---|
| 고객 문의 입력 | START 요청·응답 | 파일 경로 | Runtime | 누락 필드 |
| 고객 추가 문진 | Questionnaire | 파일 경로 | OpenAPI-only | 구현 전 Mock |
| 고객 조치 결과 | Action Result | 파일 경로 | OpenAPI-only | 구현 전 Mock |
| 기사 방문 상세 | Visit/Evidence | 파일 경로 | 미지원 | 필요 DTO·우선순위 |
| 위치 추적 | Tracking | 파일 경로 | 미지원 | Method·Path 제안이 아닌 요구 필드 |

최지용은 이 결과를 받아 Backend Runtime 구현 순서를 검토한다. Mobile이
임의 Endpoint를 먼저 확정하지 않는다.

## 10. 금지·주의사항

- 구형 단일 App 구조를 다시 도입하지 않는다.
- Mobile `InquiryStateMachine`을 서버의 최종 상태 권한으로 사용하지
  않는다.
- Runtime이 없는 Endpoint를 하드코딩해 완료 처리하지 않는다.
- 기사 미배정·타인 자원 접근을 UI 숨김만으로 보호했다고 간주하지 않는다.
- Kakao Key·Token·실제 위치·개인정보를 저장소나 인계 문서에 넣지 않는다.
