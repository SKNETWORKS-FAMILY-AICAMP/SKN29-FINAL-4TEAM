# 최지용 → 김은진 인계 및 요청사항

> 기준일: 2026-07-29
> 대상: 김은진(Data·QA·DevOps)
> 작성자: 최지용(Backend·DB·API 계약)
> 문서 역할: 팀 공용 인계 허브를 보완하는 김은진 담당 실행 상세
> 현재 판정: `DATA_OWNER_REVIEW_REQUIRED`
> 기준 `main` SHA: `0bcb8b514f2b0d1476882d926b667dbdb5d8c06a`
> 기능·Data 검토 기준 `jiyong` SHA: `665bef9b4f43db3c1d8bd847b58b620b5d462736`
> 게시 상태: 원격 `jiyong` 게시·SHA 일치 확인 완료, 김은진 Data Owner Review 대기
> 목적: Crosswalk v2와 Data 생성물의 소유자 검토를 받고, 반환된 결과로
> 최지용이 Backend·PostgreSQL을 다시 검증한다.

## 1. 지금 요청하는 한 가지

과거 `58 passed, 6 failed`와 Runtime 문서 Hash 불일치는 해결됐다.
현재 후보는 Backend·PostgreSQL·Data 자동 검증을 모두 통과했지만,
`data/**`와 `scripts/data/**`는 김은진 주관 경로이므로 **의미·생성물·
결정성에 대한 Owner Review**가 남아 있다.

김은진에게 요청하는 일은 Backend를 다시 구현하거나 격리 DB를 삭제하는
것이 아니다. 아래 19개 Data 소유 변경을 검토하고 승인 또는 수정 결과를
`eunjin` Branch와 재현 증거로 반환하는 것이다.

## 2. 역할과 편집 경계

| 범위 | 주담당 | 이번 인계에서 할 일 |
|---|---|---|
| `backend/**`, `backend/tests/**` | 최지용 | Importer·Model·Migration·Backend 회귀 유지 |
| `contracts/codes/**` | 최지용 | Backend·Data 공통 코드 정합 유지 |
| `data/**` | 김은진 | Crosswalk·Schema·QA·생성물 Owner Review |
| `scripts/data/**` | 김은진 | Source Hash 갱신기의 동작·안전성 검토 |
| `docs/**` | 공동 편집 | 실제 검증값과 미완료 경계를 명확히 기록 |

최지용은 김은진 승인 없이 Data 변경을 팀 최종 완료로 표시하지 않는다.
김은진은 Backend Source Hash를 맞추기 위해 Backend 구현을 임의 변경하지
않고, 변경 요청을 경로·필드·기대값으로 반환한다.

## 4. 검토할 Data 소유 범위

현재 검토 후보의 Data 관련 변경은 다음 두 묶음이다.

1. `data/**` 18개
   - Crosswalk·Consumer Profile·Service Contract Mapping
   - 위 설정의 JSON Schema
   - Handoff·Service Contract 단위 테스트
   - Text Hash·Validation 로직
   - QA·Manifest 생성물
2. `scripts/data/refresh_source_hashes.py` 1개
   - 중첩된 Runtime 문서 Hash의 검사·갱신 지원

Fixture 원본인 `data/synthetic/fixtures/**`와 PM 소유
`contracts/state-machine/**`는 이번 후보에서 수정하지 않았다.

## 5. 김은진 검토 순서

### 5.1 Branch와 기준 확인

```powershell
Set-Location (git rev-parse --show-toplevel)

git fetch --prune origin
git status --short --branch
git rev-parse HEAD
git rev-parse origin/main
```

검토는 최지용이 전달한 `jiyong` 후보 SHA 또는 해당 Diff를 기준으로 한다.
자기 작업트리에 미커밋 변경이 있으면 삭제·초기화하지 말고 별도 Worktree
또는 안전한 Branch에서 확인한다.

### 5.2 Source Hash 검사

```powershell
.\backend\.venv\Scripts\python.exe `
  .\scripts\data\refresh_source_hashes.py `
  --check
```

완료 기준:

```text
status=PASS
changed=0
```

### 5.3 Data 전체 테스트

```powershell
.\backend\.venv\Scripts\python.exe -B `
  -m unittest discover `
  -s .\data\tools\tests `
  -v
```

완료 기준:

```text
Ran 61 tests
OK
exit_code=0
```

### 5.4 QA·Manifest 결정성 2회 확인

```powershell
.\backend\.venv\Scripts\python.exe -B `
  .\data\tools\pipeline.py `
  qa `
  --verify-rebuild

.\backend\.venv\Scripts\python.exe -B `
  .\data\tools\pipeline.py `
  qa `
  --verify-rebuild
```

두 실행 모두 다음을 만족해야 한다.

```text
status=PASS

```

### 5.5 Git 무결성

```powershell
git diff --check
git status --short
```

김은진이 생성물을 다시 만들었다면 실제로 변경된 파일만 Owner Commit에
포함하고, 실행할 때마다 내용이 달라지는 비결정적 필드가 없는지 확인한다.

## 6. 반환 방식

다음 중 하나로 반환한다.

1. 권장: `eunjin` Branch에서 검토·수정한 Data 소유 파일을 Commit하고
   40자리 SHA와 QA 결과를 전달
2. 변경이 필요 없으면: `jiyong` 후보의 19개 경로에 대한 명시적
   `APPROVED` Owner Review와 실행 증거를 전달

반환 형식:

```text
[김은진 Data Owner Review]
review_status=APPROVED | CHANGES_REQUESTED
review_base_jiyong_sha=665bef9b4f43db3c1d8bd847b58b620b5d462736
data_branch=eunjin
data_commit_sha=<변경이 있을 때 40자리 SHA>
reviewed_paths=<19개 경로>
source_hash_check=PASS
data_test_result=61 passed
qa_run_1=PASS/errors=0/warnings=0/e2e=17/17
qa_run_2=PASS/errors=0/warnings=0/e2e=17/17
manifest_hash_diff=0
changed_generated_outputs=<목록 또는 없음>
remaining_blocker=<없음 또는 상세>
```

## 7. 반환 후 최지용이 할 일

1. 김은진이 승인한 Data 변경만 최신 `main` 기준 후보에 반영한다.
2. Source Hash 검사를 다시 실행한다.
3. Data 61건과 QA를 다시 실행한다.
4. Backend 397건을 다시 실행한다.
5. PostgreSQL Migration 적용 상태와 합성 Import 증거를 재확인한다.
6. 위 결과를 윤승혁 PM에게 전달하고 `main` 병합을 요청한다.

김은진 반환 전에는 PM에게 현재 후보의 `main` 병합을 요청하지 않는다.

## 8. PostgreSQL 재검증 경계

김은진이 Data 의미·Hash·생성물만 검토하는 동안 기존 증적 DB를 삭제하거나
다시 만들 필요는 없다.

- `watercare_synthetic_smoke_verify_20260729_mainv2`
- `watercare_synthetic_full_verify_20260729_mainv2`

Fixture Mapping 의미나 Import 대상 필드가 변경되면 최지용이 새 격리 DB를
만들어 Smoke·Full·Replay를 다시 검증한다. 단순 문구·정렬·결정적 생성물
변경만으로는 DB를 재생성하지 않는다.

## 9. 금지사항

- 실패 테스트를 삭제하거나 검증 규칙을 완화해 PASS로 만들지 않는다.
- Fixture 원본·State Machine 계약을 Hash에 맞추기 위해 임의 변경하지 않는다.
- 실제 고객정보·DB Dump·`.env`·Token·Secret을 전달하지 않는다.
- 개인 PC 절대경로를 문서·Commit에 넣지 않는다.
- T-005 10/32를 전체 완료로 표시하지 않는다.
