# 최지용 → 이동윤 인계 및 요청사항

> 기준일: 2026-07-29
> 대상: 이동윤(AI·RAG)
> 작성자: 최지용(Backend·DB·API 계약)
> 문서 역할: 팀 공용 인계 허브를 보완하는 이동윤 담당 실행 상세
> 현재 판정: `AI_CONTRACT_INPUT_REQUIRED`
> 목적: AI 계약과 Runtime을 먼저 재현 가능하게 확정한 뒤 Backend
> Adapter·Evidence·DB Wave를 연결한다.

## 1. 한 줄 인계

최지용의 `backend/integrations/ai/**` 작업은 계획표대로 **입력 대기**다.
Backend 397 passed와 PostgreSQL Gate PASS는 AI 연동 완료 증거가 아니다.
이동윤에게는 실제 AI Schema·예시·오류·실행 명령·Commit SHA를 먼저
확정해 달라고 요청한다.

## 2. 역할 경계

| 경로·기능 | 이동윤 | 최지용·협업자 |
|---|---|---|
| `ai/**` | 주관 | Runtime 소비 |
| `contracts/ai/**` | 주관 | 최지용 부관할·Backend Adapter 소비 |
| `backend/integrations/ai/**` | 부관할·계약 검토 | 최지용 주관 |
| `backend/apps/evidence/**` | 부관할 | 최지용 주관 |
| API Evidence Schema | 이동윤 부관할 | 최지용 주관 |
| Data의 AI/RAG Schema·Catalog | 이동윤 부관할 | 김은진 주관 |
| Web·Mobile Evidence 화면 | 부관할 | 한예나·양정현 주관 |

AI는 증상 구조화·질문·안전·검색·생성·검증 결과를 반환하지만 업무 상태,
권한, 최종 DB 기록을 직접 변경하지 않는다. 상태 전환과 최종
EvidenceCard 조립·저장은 Backend 책임이다.

## 3. 현재 교차검증 결과

### Backend AI·Evidence

- `backend/integrations/ai/**`의 Client·Mapper·Validator·Retry 파일은
  현재 설명문 위주의 골격이며 실제 호출·Timeout·오류 매핑 증거가 없다.
- `backend/apps/evidence/**`도 Model·Service 골격은 있으나 최종 Runtime
  연결과 Migration·App 등록 검증이 남아 있다.
- T-005는 전체 `10/32`; 지식·RAG·AI 추적 테이블은 다음 Wave다.
- T-023은 START·CANCEL 수준의 `PARTIAL`이며 AI 결과의 상태 적용은
  Backend Guard를 거쳐야 한다.

### AI 계약과 Runtime 불일치

`SymptomAnalysisResponse.schema.json`과 현재 AI Runtime 모델을 대조하면
다음 세 경계가 맞지 않는다.

1. Runtime 최상위 `inquiry_id` 누락
2. Runtime 최상위 `correlation_id` 누락
3. Runtime의 `trace_context`·`model_metadata`·`processing_traces`가 계약의
   추가 속성 금지와 충돌

다음 계약은 속성 정의가 없거나 골격 수준이다.

- `contracts/ai/common/`의 `MissingField`, `FollowUpQuestion`,
  `ModelMetadata`, `ProcessingTrace`, `ValidationResult`
- `contracts/ai/requests/`의 `ConsultationSummaryRequest`,
  `TechnicianReportRequest`
- `contracts/ai/responses/`의 `ConsultationSummaryResponse`,
  `TechnicianReportResponse`
- `contracts/api/components/schemas/evidence/**`

또한 `contracts/ai/examples/**`에는 실제 JSON 대신 README만 있고,
`contracts/error-codes/categories/ai.yaml`은 오류 목록이 비어 있다.
현재 FastAPI 오류 이름과 Backend 공통 오류 계약을 연결할 수 없다.

### Timeout·추적·실행 주소

- `ai/configs/retry_policy.yaml`에는 전체 30초, AI 내부 최대 1회,
  Backend 재시도 0회 정책이 있으나 Runtime 강제 증거가 없다.
- AI 공통 retry·timeout·tracing·logging과 Fallback Validator는 골격
  수준이다.
- Runtime Stage의 소문자 값과 `contracts/codes/ai-stages.yaml`의 표준
  코드가 다르다.
- AI 오류 응답의 `correlation_id` 전달 기준이 확정되지 않았다.
- AI 기본 Port 8000과 Backend의 `AI_SERVICE_BASE_URL` 8001 설정이
  충돌하므로 서비스별 Port·Endpoint 확정이 필요하다.

### RAG 현재 범위

현재 검색은 샘플 텍스트 기반이고 실제 pgvector Exact Search 증거가
없다. 고정 샘플·예시 URL·비표준 문서 Hash가 남아 있으므로
`실제 RAG 완료`로 인계하지 않는다. 이번 문서 작성 과정에서는 AI 전체
테스트를 재실행하지 않았으므로 기존 보고서 수치를 현재 통과 증거로
사용하지 않는다.

## 4. P0 요청 — AI 계약 PR 선행

다음 항목을 `contracts/ai/**` 계약 PR로 먼저 확정해 달라.

- 요청·응답·공통 Schema의 실제 Properties·Required·Enum
- `inquiry_id`, `correlation_id`, `state_version` 전달 위치
- `trace_context`와 최상위 추적 필드 중 단일 구조
- Schema ID·Version·변경 기록
- 정상·위험·근거 없음·Schema 오류·Timeout 실제 JSON 예시
- `risk_level`, `usage_guidance_status`, AI Stage,
  `verification_status`의 `contracts/codes/**` 참조
- AI 오류 코드·HTTP 상태·`retryable`·`failure_stage`
- 응답의 추가 속성 허용 여부

계약 PR이 병합되기 전에 Backend Mapper를 추측 구현하지 않는다.

## 5. P0 요청 — State·멱등·추적 필드 확정

State 계약과 맞도록 아래 필드를 요청·응답에서 어떻게 전달할지 명시해
달라.

| 필드 | 요청사항 |
|---|---|
| `inquiry_id` | 외부 Public UUID 사용 |
| `correlation_id` | Backend → AI → 응답·오류·로그까지 동일 흐름 추적 |
| `state_version` | AI 호출 시작 시점 버전 전달·Echo 여부 확정 |
| AI 멱등 키 | `ai_request_id` 또는 별도 Key의 이름·재사용 기준 |
| `status` | 성공·실패·Fallback 상태 코드 |
| `failure_stage` | 표준 AI Stage 코드 |
| `retry_count` | AI 내부 재시도 횟수 |
| 제안 결과 | 상태를 바꾸지 않고 Backend Guard가 소비할 구조 |

AI 응답이 늦게 도착했을 때 Backend가 현재 `state_version`을 다시 확인할
수 있도록 응답 식별자와 버전을 보존한다.

## 6. P0 요청 — 재현 가능한 AI Runtime 인계

아래 내용을 실제 실행 확인 후 제공해 달라.

```text
ai_branch=dongyoon
ai_commit_sha=<40자리 SHA>
python_version=<정확한 버전>
dependency_manifest=<lock 또는 requirements 경로>
start_command=<실제 검증 명령>
test_command=<실제 검증 명령>
health_url=<실제 응답 URL>
analysis_endpoint=<Method·Path>
ai_service_base_url=<Port 포함>
request_schema_version=<버전>
response_schema_version=<버전>
```

추가로 확인할 것:

- 30초 전체 Timeout의 측정 시작·종료 지점
- AI 내부 최대 1회 재시도, Backend 재시도 0회
- Timeout·Schema 오류·근거 없음의 Fallback 응답
- `correlation_id`의 Header·Body·Log 전달 방식
- 정상·위험·근거 없음·Schema 오류·Timeout Mock Fixture

## 7. P1 요청 — RAG·Evidence·DB Wave 입력

T-005의 지식·RAG·AI 추적 Wave를 시작하기 전에 다음 값을 확정해 달라.

- Embedding 모델의 정확한 이름·버전과 Vector 차원
- Cosine Exact Search·Top-5·ANN 미사용 여부
- 문서·페이지·청크·제품 모델·검증 상태 필터
- 실제 문서 SHA-256과 청킹·Tokenizer·Embedding·검색 설정 버전
- AI 실행의 작업 유형·상태·오류·Token·지연·재시도·추적 필드
- EvidenceReference의 문서 코드·버전·페이지·청크·공식 URL·요약·점수·
  검증 상태
- 다른 제품 세대·미검증 FAQ·내부 경로·원문 전체의 비노출 기준

대상 범위는
[테이블 사전](../../../database/watercare_table_dictionary.md)의
지식·RAG·AI 추적 구간을 기준으로 최지용과 한 Wave씩 확정한다.

AI는 EvidenceReference만 반환하고 최종 EvidenceCard·업무 DB 저장은
Backend가 수행한다.

## 8. 연동 순서

```text
이동윤 contracts/ai 계약 PR
→ 이동윤 AI Runtime PR
→ 최지용 Backend Adapter·오류·Fallback·추적 구현
→ 김은진 계약·통합·Resilience QA
→ 윤승혁 PM 검토·main 병합
```

각 단계가 같은 계약 Version을 사용해야 다음 단계로 이동한다.

## 9. 반환할 완료 증거

- Branch, 40자리 Commit SHA, Dirty 여부
- Python·의존성 Manifest·실행·테스트 명령
- 실행 시각·Exit code·Health·분석 Endpoint
- JSON Schema ↔ Runtime 모델 왕복 검증
- 정상·위험·근거 없음·Schema 오류·Timeout HTTP 결과
- 실제 30초 제한과 Backend 호출 1회 증거
- 요청 → AI Stage → 응답·오류의 `correlation_id` 추적
- 실제 pgvector Query·Top-5와 부적합 근거 0건
- 계약·AI 단위·Backend-AI 통합·Resilience 테스트
- Prompt·내부 경로·API Key·Token·개인정보 미노출 검사

## 10. 이번 주 완료 조건

- [ ] AI 계약 Schema와 Runtime 모델 불일치 0
- [ ] 실제 JSON 예시 5종 이상 제공
- [ ] AI 오류 Registry와 Backend 오류 Mapping 확정
- [ ] 서비스 Port·Health·분석 Endpoint 확정
- [ ] 30초·AI 1회·Backend 0회 정책의 실행 증거 확보
- [ ] `correlation_id` End-to-End 추적
- [ ] AI가 상태·권한·최종 DB 기록을 변경하지 않음
- [ ] 재현 가능한 Branch·40자리 SHA·명령·의존성 제공

## 11. 금지·주의사항

- AI 계약 입력 없이 Backend Client·Mapper를 추측 구현하지 않는다.
- AI가 업무 상태를 직접 변경하거나 최종 EvidenceCard를 확정하지 않는다.
- 샘플 텍스트 검색을 실제 pgvector RAG 완료로 표시하지 않는다.
- 재시도 횟수를 늘려 30초 제한을 우회하지 않는다.
- 내부 Source Path·Prompt·Secret·개인정보를 응답·Log·예시에 넣지 않는다.
