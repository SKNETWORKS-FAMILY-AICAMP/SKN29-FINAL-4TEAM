> 작성자: 최지용(Backend·DB·API 계약)
> 문서 역할: 팀 공용 인계 허브를 보완하는 윤승혁(PM) 실행 상세
> 현재 판정: `PM_MERGE_GATE_WAITING_FOR_DATA_OWNER_REVIEW`
> 작업 기준 `main` SHA: `0bcb8b514f2b0d1476882d926b667dbdb5d8c06a`
> 기능·Data 검토 기준 `jiyong` SHA: `665bef9b4f43db3c1d8bd847b58b620b5d462736`
> 목적: 기술 검증 완료와 소유자 검토 완료를 구분하고, 안전한 병합
> 순서와 다음 Backend Wave의 PM 결정 항목을 확정한다.

## 1. PM에게 먼저 전달할 결론

최신 `main` 기준 후보에서 Crosswalk v2·Backend Importer·PostgreSQL
Smoke/Full·Data QA·Backend 회귀는 모두 통과했다. 그러나
`data/**` 18개와 `scripts/data/**` 1개에 김은진 Owner Review가 남아
있으므로 **현재는 바로 `main`에 병합할 상태가 아니다.**

최지용은 `jiyong`에 검토 후보를 게시하고 김은진에게 Data Owner Review를
요청한다. PM은 김은진의 승인 또는 `eunjin` 수정 Commit과 최지용의
재검증 결과를 받은 뒤에만 `main` 병합을 진행한다.

## 3. 병합 전 필수 왕복

```text
최지용
  └─ jiyong 검토 후보·17 Source·12 Mapping·PostgreSQL 증거 전달
      ↓
김은진
  └─ Data 19경로 Owner Review
     ├─ APPROVED
     └─ 또는 eunjin 수정 Commit·QA 증거 반환
      ↓
최지용
  └─ 반환본 기준 Source Hash·Data 61·Backend 397·PostgreSQL 재검증
      ↓
윤승혁 PM
  └─ 소유권·계약·테스트 증거 확인 후 main 병합
      ↓
PM이 팀에 40자리 main SHA 전달
```

한예나·양정현은 PM의 새 `main` SHA가 나오기 전 현재 후보를 공용 기준으로
사용하지 않는다. 이동윤의 AI Schema는 이후 AI·Knowledge Wave와
Backend AI Client 착수 시 받는다.

## 4. PM 병합 Gate

다음 항목이 모두 충족되어야 병합 가능하다.

- [x] `jiyong` 후보 40자리 SHA가 제공됨:
  `665bef9b4f43db3c1d8bd847b58b620b5d462736`
- [ ] 김은진이 Data 19경로를 `APPROVED`했거나 `eunjin` 수정 SHA를 제공함
- [ ] Source Hash 검사 PASS
- [ ] Data `61 passed`
- [ ] QA 2회 PASS·Manifest Hash 차이 0
- [ ] Backend `397 passed`
- [ ] PostgreSQL Migration drift·적용 상태 정상
- [ ] `git diff --check` PASS
- [ ] 미구현 T-005·T-022·T-023 범위가 문서에 표시됨
- [ ] `.env`, `.venv`, Token, DB Dump, 실제 개인정보가 Commit에 없음

핵심 테스트가 실패하거나 김은진 Owner Review가 없으면 PM은 병합을
보류한다.

## 5. PM 검토 명령

```powershell
Set-Location (git rev-parse --show-toplevel)

git fetch --prune origin
git status --short --branch
git rev-parse HEAD
git rev-parse origin/main

.\backend\.venv\Scripts\python.exe `
  .\scripts\data\refresh_source_hashes.py `
  --check

.\backend\.venv\Scripts\python.exe -B `
  -m unittest discover `
  -s .\data\tools\tests `
  -v

.\backend\.venv\Scripts\python.exe -m pytest `
  .\backend\tests `
  -q `
  -p no:cacheprovider

.\backend\.venv\Scripts\python.exe -B `
  .\data\tools\pipeline.py `
  qa `
  --verify-rebuild

git diff --check
```

PostgreSQL 재현은 대상 DB와 `.env`를 확인한 뒤 실행한다. PM 검토 과정에서
팀 공용 DB를 임의로 초기화하거나 다른 사람의 DB Volume을 삭제하지 않는다.

## 6. PM 결정이 필요한 다음 작업

### 6.1 T-005 계약 밖 5개 테이블

현재 Runtime에는 있으나 T-005 32개 계약 테이블에는 없는 다음 테이블을
공식 계약에 포함할지, 운영 보조 테이블로 분리할지 결정해 달라.

- `audit_event`
- `operations_synthetic_import_batch`
- `operations_synthetic_import_item`

- `workflow_transition_history`

## 8. 팀 전달 순서

1. PM이 실제 병합된 `main` 40자리 SHA를 전달한다.
2. 팀원은 자기 Branch에서 해당 SHA를 반영한다.
3. 최지용은 같은 SHA에서 Backend·PostgreSQL을 재확인한다.
4. 김은진은 Data·통합 QA를 독립 재현한다.
5. 한예나·양정현은 실제 API 소비 Smoke를 수행한다.
6. 결함은 담당 경로의 주담당자에게 재현 절차와 함께 반환한다.

`jiyong` Branch SHA 자체를 전 팀 공용 기준으로 안내하지 않는다.
