## 1. 판정 기준

- 최신 병합에서 Backend Runtime 자체의 추가 구현은 확인되지 않았다. 새 Action Crosswalk·계약 소비자 검토·5주차 인계는 문서화 진척으로 반영하되 Runtime 완료로 승격하지 않았다.
- 현재 Workspace Python에는 Django 의존성이 없어 Backend Test·Migration을 직접 재실행할 수 없었다. 따라서 기존 저장 증거와 코드 구조를 판정 근거로 사용했다.
- 발표 완료와 Backend 기능 완료는 분리했다. 발표는 끝났지만 실패한 Smoke와 미구현 수직 흐름은 완료 처리하지 않았다.

## 3. 4주차 필수 업무별 평가

### 3.1 Backend 기준선·Migration·Runtime 증빙 복구 — 65%

- 완료·근거: [Backend README](../../../backend/README.md), [Backend 계약·구현 검증 가이드](API/Django_REST_API_OpenAPI_계약_구현_보안검증_가이드.md), [4주차 Exit Gate](../../testing/week4-exit-gate.md), [계약 소비자 검토](../../testing/week4-contract-consumer-review.md). Runtime·OpenAPI·미구현 구분과 5주차 차단 조건이 정리됐다.
- 미완료: 현재 HEAD에서 빈 PostgreSQL Migration·Seed 반복 실행·Readiness·Backend Test를 재현한 증거가 없다.
- 완료 방법: 고정된 Python/PostgreSQL 환경에서 `migrate`, `makemigrations --check`, Seed 2회, Liveness/Readiness, Test를 실행하고 결과·Commit을 문서화한다.
- 별도 확인: 팀 DB 접근 권한과 실제 Migration/Seed 로그, 다른 팀원의 재현 결과가 필요하다.

### 3.2 제품·구독 최소 API (`T-018`) — 20%

- 완료·근거: [OpenAPI](../../../contracts/api), [Backend 앱](../../../backend/apps), [Action Crosswalk](../../../contracts/api/action-operation-crosswalk.yaml). 계약과 Example은 있으나 Runtime 구현 상태는 명시적으로 차단돼 있다.
- 미완료: 고객 본인 제품·구독 목록·상세 URL·View·Serializer·Service와 소유권 Test가 없다.
- 완료 방법: Model Query Service와 목록·상세 Endpoint를 구현하고 타 고객 404·미인증 401·역할 부족 403 Test를 추가한다.
- 별도 확인: Mobile/Web이 요구하는 공개 필드와 Data Seed ID의 Owner 합의가 필요하다.

### 3.3 문의 증상 제출·추가 답변·자가조치 누적 (`T-022`) — 60%

- 완료·근거: [Inquiry 앱](../../../backend/apps/inquiries), [Backend Test](../../../backend/tests), [State Machine 계약](../../../contracts/state-machine). 문의 생성·증상 제출, 상태 전이, `state_version`, 멱등 Replay/Conflict와 이력 저장 기반이 있다.
- 미완료: 같은 문의의 추가 답변·자가조치 누적, 고객 원문과 AI 구조화 결과 분리 저장, 전체 소유권 Test가 없다.
- 완료 방법: 추가 답변·자가조치 Model/Serializer/Service와 Transaction Test를 구현하고 원문·구조화 필드를 분리한다.
- 별도 확인: 데이터 보관·마스킹·삭제 정책과 상담 업무의 누적 방식 승인이 필요하다.

### 3.4 State Machine Event API Runtime (`T-023`) — 50%

- 완료·근거: [Action–Operation Crosswalk](../../../contracts/api/action-operation-crosswalk.yaml), [계약 소비자 검토](../../testing/week4-contract-consumer-review.md), [Backend Workflow](../../../backend/apps/workflow). 계약 State 13·Action 23을 참조하고 현재 Runtime Action 2개와 후속 범위를 분류했다.
- 미완료: 발표 필수 Event 전체와 AI 결과·상담·방문 Event가 Runtime에 연결되지 않았다.
- 완료 방법: P0 Event별 URL·Service·Guard·이력·`allowed_actions` 응답과 정상/409/403 Test를 구현한다.
- 별도 확인: PM 기준선 후보의 Backend Owner 승인과 Event 구현 우선순위가 필요하다.

### 3.5 Backend↔AI 최소 수직 연동 — 10%

- 완료·근거: [이동윤 협업 요청 v0.3](../dongyoon/20260807_이동윤_최지용_Backend_AI_수직연동_협업요청서_v0.3.md), [AI 계약](../../../contracts/ai), [5주차 진입 조건](../../planning/week5-entry-criteria.md). 요청·응답·Timeout·Fallback 책임 경계는 구체화됐다.
- 미완료: 실제 HTTP Client·Mapper·Validator·DB 저장·오류 처리와 통합 Test가 없다.
- 완료 방법: Django Service가 FastAPI를 실제 호출하고 Schema 검증 후 AI 실행·근거·상태를 저장하도록 구현한다. Timeout/Schema 오류/근거 없음 Test도 추가한다.
- 별도 확인: AI URL·인증·Timeout·재시도 책임과 팀 DB Transaction 경계를 합의해야 한다.

### 3.6 케어 이력 최소 API (`T-019`) — 5%

- 완료·근거: [Backend Care 앱](../../../backend/apps/care), [Data Fixture](../../../data/synthetic). Model·Seed 수준의 기반은 있으나 실행 API는 확인되지 않는다.
- 미완료: 목록·상세·등록 URL·Serializer·Service·권한 Test가 없다.
- 완료 방법: 고객 본인 조회와 상담사/기사 등록 정책을 반영한 최소 API 및 Test를 구현한다.
- 별도 확인: 케어 이력 공개 범위·보관 기간·역할별 쓰기 권한을 확인해야 한다.

## 4. 코드로 확인할 수 없는 항목

| 항목 | 필요한 증거 |
| --- | --- |
| Migration·Seed 재현 | 빈 PostgreSQL 실행 로그·Version·Commit |
| 실제 Backend Runtime | Health/Readiness·요청/응답·DB Row |

| Owner 계약 승인 | Backend·AI·Web·Mobile Review 기록 |
| 개인정보 로그 비노출 | 운영 설정의 Log Sample·보안 검토 |
