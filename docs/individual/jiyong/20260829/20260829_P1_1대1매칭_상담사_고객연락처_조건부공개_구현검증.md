## 2. 목적

상담사 화면의 기본 개인정보 보호 원칙은 유지하면서, P1 팀 합성 고객 6명과
상담사 6명의 사전 확정된 1:1 조합에서는 담당 상담사가 본인 고객의 전화번호를
문의 상세 화면에서 확인할 수 있게 한다.

단순히 문의에 배정됐다는 이유만으로 원문 번호를 공개하면 잘못된 교차 배정이나
일반 합성 데이터까지 노출될 수 있다. 따라서 로그인 상담사, 문의 배정 상담사,
P1 예약 계약번호가 모두 정확히 일치하는지를 Backend가 최종 판정한다.

## 4. 공개 계약

대상 Endpoint는 기존 상담사 상세 조회다.

```text
GET /api/v1/inquiries/{inquiry_id}
```

고객 응답은 다음 규칙을 따른다.

```json
{
  "phone": "010-****-0000",
  "phone_masked": "010-****-0000",
  "contact_phone": null
}
```

- `phone`과 `phone_masked`는 항상 마스킹 상태를 유지한다.
- `contact_phone`은 정확한 P1 1:1 매칭에서만 원문 합성 번호다.
- 그 외에는 필드를 생략하지 않고 `null`을 반환한다.

`contact_phone` 공개 조건은 다음 다섯 가지를 모두 만족해야 한다.

1. 로그인 사용자가 `CONSULTANT`다.
2. Inquiry가 로그인 상담사에게 배정돼 있다.
3. Inquiry 배정 역할이 `CONSULTANT`다.
4. Inquiry 구독 계약번호가 P1 예약 계약 6건 중 하나다.
5. 로그인 상담사의 P1 담당 계약과 Inquiry 계약이 정확히 일치한다.
