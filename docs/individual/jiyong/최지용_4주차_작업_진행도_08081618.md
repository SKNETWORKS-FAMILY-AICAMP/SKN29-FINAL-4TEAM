## 1. 판정 기준

- 이전 점검 이후 추가된 Backend·DB·AI 연동 코드와 작성자 검증 결과를 업무 지침서의 3장·5장 기준으로 다시 판정했다.
- 현재 `main`과 `origin/main`이 같은 Commit이고 작업 트리는 깨끗하다.
- 작성자 검증 문서에는 PostgreSQL 16.14에서 빈 DB Migration·Rollback·재적용, T-018 Runtime, 전체 Backend **817 passed, 13 skipped**가 기록됐다.
- 현재 Workspace에는 Backend `.venv`와 Django 의존성이 없어 동일 Test를 직접 재실행하지 못했다. 따라서 작성자 실행 증거는 인정하되 독립 QA는 별도 확인으로 남겼다.
- `InquiryAIService`는 실제 HTTP Client·Schema 검증·DB 저장을 구현했지만 아직 Runtime View/Endpoint에서 호출되지 않고 Test도 `httpx.MockTransport` 기반이므로, 실 FastAPI E2E 완료로 과장하지 않았다.

## 3. 4주차 필수 업무별 평가

### 3.1 Backend 기준선·Migration·Runtime 증빙 복구 — 90%

- 완료·근거: [Django·PostgreSQL 검증보고서](데이터베이스/Django_PostgreSQL_계정관리_구독조회_검증보고서_20260808.md), [Accounts Migration 0004](../../../backend/apps/accounts/migrations/0004_add_user_is_synthetic.py), [AI Run Migration 0005](../../../backend/apps/audit/migrations/0005_airun_analyze_symptom_task.py), [Backend Test](../../../backend/tests). 빈 DB 전체 Migration·Rollback·재적용, 기존 DB Backfill, `migrate --check`, `makemigrations --check`와 전체 Backend 817 Test가 작성자 환경에서 통과했다.
- 미완료: 독립 QA가 실행되지 않았고 Liveness와 DB Readiness를 별도 HTTP Endpoint로 검증한 증거는 없다.
- 완료 방법: QA 격리 DB에서 보고서의 재현 절차를 실행하고 `/health`와 별도 DB Readiness Endpoint·Test를 추가한다.
- 코드 외 확인: QA 실행 Machine·PostgreSQL Version·DB 이름·Commit·원시 Test 로그와 승인자를 확인해야 한다.

### 3.2 제품·구독 최소 API (`T-018`) — 90%

- 완료·근거: [구독 URL](../../../backend/apps/subscriptions/api/urls.py), [구독 View](../../../backend/apps/subscriptions/api/views.py), [Serializer](../../../backend/apps/subscriptions/api/serializers.py), [Service](../../../backend/apps/subscriptions/services/subscription_service.py), [Runtime Test](../../../backend/tests/api/test_t018_subscription_runtime.py). 고객 본인의 ACTIVE·지원 모델 목록/상세, 필터·정렬·페이지네이션·최근 케어 Projection과 타 고객·비활성·미지원·삭제 고객 404가 구현됐다.
- 미완료: T-018 등록·수정·기본 제품 지정은 미구현이며 독립 QA가 아직 없다.
- 완료 방법: 우선 R1 GET을 독립 QA로 승인하고, 등록·수정은 5주차 별도 Scope와 권한·멱등 기준으로 구현한다.
- 코드 외 확인: Mobile/Web의 공개 필드 소비 결과와 실제 사용자 Seed로 목록·상세가 재현되는지 확인해야 한다.

### 3.3 문의 증상 제출·추가 답변·자가조치 누적 (`T-022`) — 70%

- 완료·근거: [Inquiry AI Service](../../../backend/apps/inquiries/services/inquiry_ai_service.py), [AI Service Test](../../../backend/tests/unit/ai_integration/test_inquiry_ai_service.py), [문의 Model](../../../backend/apps/inquiries/models). 고객 원문과 구조화 결과, Guidance, 추가 질문, AI Run이 분리 저장되고 답변 거절 전달과 동일 질문 재생성 차단이 Test로 검증된다.
- 미완료: 고객이 후속 답변과 자가조치 결과를 제출·누적하는 공개 Runtime API는 여전히 완성되지 않았다.
- 완료 방법: 추가 답변·자가조치 입력 Serializer·Service·Endpoint를 구현하고 원문 보존·질문 연결·상태 Version·Transaction Test를 추가한다.
- 코드 외 확인: 추가 답변과 자가조치의 보관·마스킹·상담사 공개 범위에 대한 업무 승인이 필요하다.

### 3.4 State Machine Event API Runtime (`T-023`) — 70%

- 완료·근거: [AI 결과 상태 연동](../../../backend/apps/inquiries/services/inquiry_ai_service.py), [Transition History Service](../../../backend/apps/workflow/services/transition_history_service.py), [Workflow Repository](../../../backend/apps/workflow/repositories/workflow_repository.py), [상태 연동 Test](../../../backend/tests/unit/ai_integration/test_inquiry_ai_service.py). 검증 근거가 있는 안전 안내, 근거 없음 상담 전환, Stale 응답 차단과 System 전이 이력이 구현됐다.
- 미완료: 발표 필수 Event 전체와 상담·방문 Event API, 계약 Action 23개 전체의 Runtime `allowed_actions` 소비는 완료되지 않았다.
- 완료 방법: P0 Event별 Endpoint·Guard·권한·이력·`allowed_actions` 응답과 정상/403/409 Test를 확장한다.
- 코드 외 확인: PM Crosswalk 기준선과 Backend Owner의 Runtime 분류 승인, Web·Mobile 소비 결과가 필요하다.

### 3.5 Backend↔AI 최소 수직 연동 — 65%

- 완료·근거: [AI Client](../../../backend/integrations/ai/client.py), [Request Mapper](../../../backend/integrations/ai/request_mapper.py), [Response Mapper](../../../backend/integrations/ai/response_mapper.py), [Schema Validator](../../../backend/integrations/ai/schema_validator.py), [Adapter Test](../../../backend/tests/unit/ai_integration/test_ai_adapter.py), [Inquiry AI Service](../../../backend/apps/inquiries/services/inquiry_ai_service.py). JSON Schema 검증, 식별자 일치, HTTP 1회 호출, Backend 재시도 0회, Timeout·오류 감사, AI Run·구조화·Guidance·질문 저장, 멱등 Replay/Conflict와 Stale 응답 차단이 구현됐다.
- 미완료: Service를 호출하는 Django Runtime Endpoint/비동기 Job이 없고 실제 FastAPI Process를 대상으로 한 통합 Test도 없다. 검증 근거와 실제 Evidence Row 연결도 제한적이다.
- 완료 방법: 증상 제출 후 승인된 Event/Job에서 `InquiryAIService.analyze_inquiry()`를 호출하고 실 FastAPI·PostgreSQL 환경에서 성공·근거 없음·Timeout·Schema 오류 E2E를 실행한다.
- 코드 외 확인: Backend·AI Base URL, 인증, Timeout, 운영 Secret, 팀 DB Transaction과 장애 대응 책임을 최지용·이동윤이 공동 승인해야 한다.

### 3.6 케어 이력 최소 API (`T-019`) — 5%

- 완료·근거: [Care Model](../../../backend/apps/care/models/care_history.py), [Care Seed](../../../backend/apps/care/management/commands/seed_demo_care_records.py). Model·Migration·Seed 기반만 존재한다.
- 미완료: 케어 이력 목록·상세·등록 URL·View·Serializer·Service·역할별 권한 Test가 없다.
- 완료 방법: 고객 본인 조회와 상담사/기사 등록 정책을 반영한 최소 API를 구현하고 타 고객 404·권한 403·Transaction Test를 추가한다.
- 코드 외 확인: 케어 이력 공개 범위, 보관 기간, 수정·삭제 정책과 역할별 쓰기 권한을 확인해야 한다.
