# 3종 정수기 이미지 자산 배치 및 활용 확인 요청

- 작성일: 2026-08-26
- 작성자: 최지용(Backend·DB)
- 확인 담당: 양정현(Mobile), 한예나(Web)
- 대상 브랜치: `jiyong`
- 문서 목적: 승인받은 정수기 이미지 3종의 저장 위치와 화면 연결 기준을 알기 쉽게 공유한다.

## 1. 한 줄 요약

정수기 이미지 3종을 Web과 Mobile의 정적 이미지 폴더에 각각 추가했으며, 담당자는 Backend가 내려주는 `model_code`를 기준으로 해당 화면에 연결하면 됩니다.

## 2. 이번 반영 범위

이번 변경에서는 다음 작업만 수행했습니다.

1. 원본 이미지 3개를 Web용 파일명으로 변경하여 복사
2. 같은 이미지 3개를 Android 규칙에 맞는 Mobile용 파일명으로 변경하여 복사
3. 제품 코드와 이미지 파일의 정확한 연결표 작성
4. Web·Mobile에서 사진을 띄울 권장 위치와 검증 기준 작성

아직 Web·Mobile 화면 코드는 변경하지 않았습니다.

따라서 이번 반영만으로 화면에 사진이 자동으로 나타나지는 않으며, 각 담당자가 아래 연결 작업을 수행해야 합니다.

## 3. 제품별 이미지 연결표

| 제품 | Backend Runtime 모델 코드 | Web 이미지 | Mobile 이미지 |
|---|---|---|---|
| 초소형 직수 정수기 `WPU-JAC104` | `WPUJAC104DWH` | `wpujac104dwh.png` | `product_wpujac104dwh.png` |
| 원코크 플러스 얼음물 정수기 `WPU-IAC425` | `WPUIAC425SNW` | `wpuiac425snw.png` | `product_wpuiac425snw.png` |
| 메가 아이스 미니 정수기 `WPU-IAC606` | `WPUIAC606SNW` | `wpuiac606snw.png` | `product_wpuiac606snw.png` |

파일명에 적힌 마케팅 모델명과 Backend Runtime 모델 코드의 표기가 다르므로, 파일명을 추측해서 연결하지 말고 위 표를 기준으로 명시적으로 연결해 주세요.

## 4. Web 담당 확인사항

### 4.1 이미지 저장 위치

Web 이미지 3개는 다음 폴더에 있습니다.

```text
web/public/images/products/wpujac104dwh.png
web/public/images/products/wpuiac425snw.png
web/public/images/products/wpuiac606snw.png
```

Web에서는 `/images/products/<파일명>` 주소로 사용할 수 있습니다.

예시는 다음과 같습니다.

```text
WPUJAC104DWH  -> /images/products/wpujac104dwh.png
WPUIAC425SNW  -> /images/products/wpuiac425snw.png
WPUIAC606SNW  -> /images/products/wpuiac606snw.png
```

### 4.2 권장 표시 위치

실제 Backend를 사용하는 상담 문의 상세 화면에 우선 연결해 주세요.

```text
web/src/features/consultation/components/RemoteConsultantInquiryDetail.tsx
```

권장 위치는 다음과 같습니다.

1. 상담 문의 상세 상단의 고객·제품 요약 영역
2. `제품·관리 정보` 영역의 제품명·모델 코드 옆
3. 필요하면 미배정 상담 목록 카드에 작은 썸네일로 추가

우선순위는 상담 문의 상세 화면이며, 목록 썸네일은 필수가 아닙니다.

### 4.3 연결 방법

Backend가 이미 제공하는 다음 값을 기준으로 사진을 선택해 주세요.

```text
inquiry.productAndCare.productModel
```

간단한 연결 기준은 다음과 같습니다.

```text
WPUJAC104DWH  -> wpujac104dwh.png
WPUIAC425SNW  -> wpuiac425snw.png
WPUIAC606SNW  -> wpuiac606snw.png
```

Backend API나 DB에 이미지 경로를 추가할 필요는 없습니다.

### 4.4 Web 주의사항

1. 기존 `wpu-iac425snw.png`는 덮어쓰지 않았습니다.
2. 기존 `wpu-jac115dnw.png`는 `WPU-JAC104`와 다른 제품이므로 사용하지 마세요.
3. 등록되지 않은 모델 코드에는 임의의 다른 제품 사진을 표시하지 마세요.
4. 미등록 모델은 `제품 이미지 없음` 또는 공통 자리표시자로 처리해 주세요.
5. 이미지 `alt`에는 제품명을 넣어 접근성을 유지해 주세요.
6. 제품명·모델 코드는 이미지와 함께 계속 표시해 주세요.

### 4.5 Web 완료 확인

다음 결과를 확인해 주세요.

- 3개 모델 코드가 각각 올바른 이미지로 표시됨
- 알 수 없는 모델 코드에서 다른 제품 사진이 잘못 표시되지 않음
- 상담 문의 상세의 기존 기능과 레이아웃이 유지됨
- Test PASS
- Lint PASS
- TypeCheck PASS
- Build PASS

## 5. Mobile 담당 확인사항

### 5.1 이미지 저장 위치

Android 리소스 규칙에 맞춰 영문 소문자와 밑줄만 사용했습니다.

### 5.2 권장 표시 위치

현재 고객 앱에서 제품 모델을 구분하는 다음 두 화면에 우선 연결해 주세요.

1. 고객 홈의 `내 정수기 상태` 제품 이미지
2. `제품 변경` 화면의 제품별 선택 카드

관련 코드는 다음 경로에 있습니다.

```text
mobile/customer-app/src/main/java/com/skn29/watercare/customer/feature/customer/home/CustomerModelCatalog.kt
mobile/customer-app/src/main/java/com/skn29/watercare/customer/feature/customer/home/CustomerHomeVisuals.kt
mobile/customer-app/src/main/java/com/skn29/watercare/customer/feature/customer/home/SubscriptionSelector.kt
```

### 5.3 연결 방법

`CustomerModelVisualSpec`에 모델별 제품 이미지 리소스를 연결하는 방식을 권장합니다.

```text
WPUJAC104DWH  -> R.drawable.product_wpujac104dwh
WPUIAC425SNW  -> R.drawable.product_wpuiac425snw
WPUIAC606SNW  -> R.drawable.product_wpuiac606snw
```

고객 홈에서는 현재 선택된 구독의 `home.product.modelCode`를 기준으로 사진을 선택하면 됩니다.

제품 변경 화면에서도 같은 `CustomerModelCatalog` 매핑을 재사용해 주세요.

Backend API나 DB에 이미지 경로를 추가할 필요는 없습니다.

### 5.4 Mobile 주의사항

1. 현재 제품 캐릭터나 일반 정수기 이미지는 미등록 모델의 fallback으로 유지할 수 있습니다.
2. 등록되지 않은 모델을 JAC104 사진으로 자동 대체하지 마세요.
3. 이미지 설명에는 실제 제품명을 사용해 접근성을 유지해 주세요.
4. 제품명·모델 코드는 이미지와 함께 계속 표시해 주세요.
5. IAC425 원본은 244×244이므로 큰 화면에서 확대 시 흐려지는지 Galaxy Tab에서 확인해 주세요.

- 제품 변경 시 사진도 선택 모델에 맞게 변경됨
- 미등록 모델에서 다른 제품 사진이 잘못 표시되지 않음

## 6. Backend·DB 변경 여부

이번 이미지 표시 작업에는 Backend와 PostgreSQL 변경이 필요하지 않습니다.

이유는 다음과 같습니다.

1. Backend가 이미 `model_code`와 `model_name`을 Web과 Mobile에 제공합니다.
2. 제품 이미지는 고정된 3개의 화면 자산입니다.
3. PostgreSQL에 이미지를 저장하면 DB 백업과 조회가 불필요하게 무거워집니다.
4. Backend 로컬 파일 경로는 다른 PC와 Galaxy Tab에서 사용할 수 없습니다.
5. 현재 Web과 Mobile은 각각 정적 이미지를 빌드에 포함할 수 있습니다.

제품이 크게 늘어나거나 앱 업데이트 없이 이미지를 자주 교체해야 할 때만 S3·CDN과 이미지 URL 계약을 별도 검토합니다.
