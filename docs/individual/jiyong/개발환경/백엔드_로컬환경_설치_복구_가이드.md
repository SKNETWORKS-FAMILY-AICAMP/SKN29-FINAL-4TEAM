# 백엔드 로컬환경 설치·실행·복구 가이드

> 관련 업무: 공통 Backend 환경
> 책임: 최지용 — Backend·Database

## 1. 목적

Windows에서 Python·Django·PostgreSQL 개발환경을 재현하고, 환경 오류를
제품 코드 결함과 분리한다. 기존 `.venv`를 다른 PC에 복사하지 않고 각 PC에서
새로 만든다.

## 2. 기준 파일

- `backend/.python-version`
- `backend/requirements/base.txt`
- `backend/requirements/local.txt`
- `backend/requirements/constraints-py313.txt`
- `backend/.env.example`
- `docker-compose.yml`
- `scripts/development/bootstrap.py`
- `scripts/development/check_environment.py`

## 3. 최초 설치

```powershell
Set-Location .\backend
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r .\requirements\local.txt `
  -c .\requirements\constraints-py313.txt
python -m pip check
```

환경 파일은 `.env.example`의 키 이름만 참고해 로컬 보호 영역에 만든다.
Password·Token·DSN은 Git이나 문서에 기록하지 않는다.

## 4. PostgreSQL과 Django 실행

```powershell
Set-Location ..
docker compose --env-file .\backend\.env up -d postgres

Set-Location .\backend
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

`127.0.0.1`은 같은 PC 전용이다. 다른 PC에서 접근할 때는 공유 Backend 배포나
승인된 LAN 설정을 별도로 사용하고 PostgreSQL 포트를 직접 공개하지 않는다.

## 5. 매일 확인

```powershell
git status --short --branch
.\backend\.venv\Scripts\python.exe -m pip check
.\backend\.venv\Scripts\python.exe .\backend\manage.py check
.\backend\.venv\Scripts\python.exe .\backend\manage.py showmigrations
```

확인 순서는 Python 경로 → 패키지 → 환경변수 이름 → PostgreSQL 연결 →
Migration → Django Health다.

## 6. 오류별 복구

| 증상 | 확인 | 복구 |
| --- | --- | --- |
| `.venv` 실행 불가 | `pyvenv.cfg`의 다른 PC 절대경로 | `.venv` 삭제 전 목록을 확인하고 새로 생성 |
| 패키지 충돌 | `python -m pip check` | 제약 파일을 적용해 재설치 |
| DB 연결 거부 | 컨테이너·Host·Port | PostgreSQL 기동과 로컬 바인딩 확인 |
| 인증 실패 | Role 이름·비밀값 주입 | 승인된 Secret 경로에서 다시 주입 |
| Migration pending | `showmigrations` | 대상 DB 확인 후 `migrate --noinput` |
| Migration drift | `makemigrations --check --dry-run` | Model·Migration 변경을 별도 커밋으로 정리 |
| HTTP 400 | `ALLOWED_HOSTS` | 실제 Backend Host만 허용 목록에 추가 |
| CORS 실패 | Browser Origin | 정확한 Web Origin만 허용 |

## 7. 안전 경계

- `docker compose down -v`, 공유 DB 삭제, 기존 Migration 수정은 실행하지 않는다.
- 테스트 DB와 개발 DB, 팀 통합 DB를 같은 이름으로 사용하지 않는다.
- `.env`, `.runtime`, DB Dump, JWT를 커밋하지 않는다.
- 환경 복구와 기능 수정은 같은 커밋에 섞지 않는다.

## 8. 완료 판정

`pip check`, Django `check`, Migration drift 0, PostgreSQL 연결과 `/health`
응답이 확인되면 로컬 환경 준비 완료다. 기능 Runtime과 E2E 완료는 별도다.
