# 백엔드 공통환경 회귀검증 가이드

> 관련 업무: 공통 Backend 구조
> 판정 대상: 설정·Health·공통 오류·Correlation·로그 보안·전체 회귀

## 1. 구현 범위

- 필수 환경변수 누락 시 Fail-closed
- `/health`와 공통 JSON 오류 응답
- 요청·응답 Correlation ID
- 구조화 로그와 민감정보 Redaction
- Django·Migration·PostgreSQL Socket 검증
- 전체 Backend 회귀와 별도 통합 Gate 구분

## 2. 주요 경로

- `backend/config/settings/**`
- `backend/config/urls.py`
- `backend/common/exceptions/**`
- `backend/common/logging/**`
- `backend/common/middleware/**`
- `backend/tests/api/test_common_*`
- `backend/tests/integration/**`

## 3. 작성자 검증

```powershell
.\backend\.venv\Scripts\python.exe -m pip check
.\backend\.venv\Scripts\python.exe .\backend\manage.py check
.\backend\.venv\Scripts\python.exe .\backend\manage.py makemigrations `
  --check --dry-run

.\backend\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider `
  .\backend\tests\api `
  .\backend\tests\unit\common
```

PostgreSQL 전용 Case는 `config.settings.local`과 폐기 가능한 QA DB에서 실행한다.
공유 통합 DB를 pytest 대상으로 사용하지 않는다.

## 4. 검증 Matrix

| 구간 | 성공 조건 |
| --- | --- |
| 환경 | 필수 값 누락 시 명확한 시작 실패 |
| Health | 실제 Backend Process에서 200 |
| 404·403·409·422 | 공통 Envelope와 오류 코드 일치 |
| Correlation | 요청 Header·응답 Header·로그가 동일 UUID |
| 로그 | Password·Token·Cookie·원문 증상 비노출 |
| Migration | pending 0, drift 0 |
| PostgreSQL | 실제 vendor 확인, 필요한 Lock Case 0 skip |
| 전체 회귀 | failed 0, skip은 별도 Gate 사유와 Test ID 기록 |

## 5. 별도 Gate

다음 Skip은 공통 Backend 실패와 자동으로 같지 않지만 PASS로 바꾸지도 않는다.

- 실제 Django → Uvicorn AI Socket
- TEAM_INTEGRATION PostgreSQL Role Matrix
- Web·Mobile 실제 소비 E2E

각 항목은 필요한 Process·Credential·공유환경이 준비된 뒤 별도 검증한다.

## 6. 판정

공통 표적 테스트와 전체 회귀가 `failed 0`이면 Backend 공통환경 기술 Gate는
통과다. 독립 QA와 PM의 WBS 판정은 이 결과를 근거로 별도 기록한다.
