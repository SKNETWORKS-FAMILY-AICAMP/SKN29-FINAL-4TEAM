### 왜 바로 삭제하지 않았는가

현재 문의는 상담·방문·AI Run·상태 이력과 외래키로 연결돼 있다. 원본
`waterbridge`에서 고객만 먼저 삭제하면 기존 G4 증거와 다른 테스트 Fixture가
함께 깨질 수 있다. 따라서 아래 순서가 안전하다.

1. 새 폐기 가능 PostgreSQL DB를 만든다.
2. 승인된 Migration만 적용한다.
3. Git 제외 입력으로 P1 팀 고객 6명을 재생한다.
4. 합성 상담사 계정을 준비한다.
5. 회원가입→로그인→신규 문의를 검증한다.
6. 새 DB 검증 후에만 기존 로컬 Volume의 폐기 여부를 별도로 결정한다.

## 3. 고객정보 마스킹

Backend 공통 마스킹 함수를 추가해 상담사 목록·전화문의 고객 검색·Dashboard
목록이 같은 규칙을 사용하도록 정리했다.

| 입력 예 | 공개 표시 |
|---|---|
| `최지용` | `최*용` |
| `김가람 (합성)` | `김*람 (합성)` |
| `010-1234-5678` | `010-****-5678` |

Dashboard 목록의 상세 주소는 DTO 호환을 위해 필드는 유지하되 빈 문자열로
반환한다. 상담사가 권한을 갖고 여는 문의 상세 API의 업무 정보 계약은 이번
목록 마스킹 변경으로 수정하지 않았다.

Web Mock 목록도 같은 이름 마스킹을 적용해 Remote Mode와 디자인 화면의 노출
수준이 달라지지 않게 했다.

## 4. 합성 상담사 ID/PW 로그인

### Backend

기존 `POST /api/v1/auth/login`을 재사용한다. 다음 조건을 모두 만족한 상담사만
추가로 허용한다.

- `role_code=CONSULTANT`
- `is_synthetic=true`
- `is_active=true`
- 사번 `employee_no` 존재

고객 로그인 조건과 일반 401, 로그인 실패 횟수 제한은 그대로 유지했다.
운영자·방문기사·비합성 상담사는 이번 경로로 로그인할 수 없다.

### 비밀번호 준비

비밀번호를 Git, 문서 또는 명령 인자로 전달하지 않는다. 승인된 로컬
환경변수에 주입한 후 다음 명령을 사용한다.

```powershell
cd backend
.\.venv\Scripts\python.exe manage.py set_synthetic_consultant_password `
  --username DEMO-CONSULTANT-001 `
  --password-env WATERBRIDGE_CONSULTANT_PASSWORD `
  --dry-run `
  --json
```

Dry-run 결과 확인 후 `--dry-run`만 제거해 적용한다. 적용 시 기존 토큰의
`auth_version`을 올리며 비밀번호 원문은 출력하지 않는다.

사용자가 채팅이나 명령 기록에 비밀번호를 쓰지 않으려면 다음 로컬 스크립트를
실행한다. 비밀번호는 화면에 표시되지 않으며 현재 Process에서만 Backend로
전달된 뒤 즉시 제거된다.

```powershell
.\scripts\development\set_p1_consultant_password.ps1 -DryRun
.\scripts\development\set_p1_consultant_password.ps1
```

### Web

Remote Mode 로그인 화면에 아이디와 비밀번호 입력 폼을 추가했다. 성공하면
기존 JWT Session 저장과 `/me` 재조회 경로를 그대로 사용한다.

기존 Playwright 회귀를 위해 `API 데모 계정으로 로그인` 버튼은 삭제하지 않고
보조 테스트 경로로 유지했다. 운영 Runtime에서 Demo 로그인 허용 여부는 기존
Backend 설정이 계속 통제한다.
