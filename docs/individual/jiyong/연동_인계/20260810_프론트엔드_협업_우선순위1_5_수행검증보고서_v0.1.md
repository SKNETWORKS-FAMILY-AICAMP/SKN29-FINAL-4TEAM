## 2. 순서 1 — 상담사 GET QA Seed·Runtime

### 2.1 해결한 원인

기존 데이터에는 다음 두 값이 한 쌍으로 없었다.

- 로그인 가능 상담사: `DEMO-CONSULTANT-001`
- 그 상담사에게 배정된 합성 Inquiry

`db-full`의 상담사 문의는 `CNS-001`에 배정됐지만 해당 코드는 Demo Login
정책을 통과하지 않는다. 인증 정책을 완화하거나 기존 canonical Fixture를
수정하지 않고 로컬·QA 전용 Seed를 추가했다.

### 2.2 구현

- 관리 명령: `seed_demo_consultant_inquiry`
- prerequisite: `seed_demo_accounts`
- Scenario: `DEMO-CONSULTANT-READ-001`
- Consultant: `DEMO-CONSULTANT-001`
- Inquiry Public UUID: `4f829120-ecbb-5b30-9365-bf02f9044c3b`
- 개인정보: 실제값 없이 전부 합성
- 재실행: `created=1` 후 `updated=1`, Identity 유지
- 기존 Workflow 상태·버전은 재실행 때 무조건 초기화하지 않음

변경하지 않은 범위:

- `data/synthetic/fixtures/**`
- Demo Login Allowlist·Prefix 정책
- Model·Migration·Importer
- Web·Mobile Production 코드

## 4. 순서 3 — Visit 상태·DTO ACK

확정해 전달한 Backend 기준:

- Visit 상태는 7개 canonical 값만 사용
- `COORDINATING`, `WAITING_COMPLETION`은 canonical 아님
- `WAITING_COMPLETION → COMPLETED` 변환 금지
- Inquiry `COMPLETION_PENDING`과 Visit `COMPLETED` 분리
- `preferred_date`, `confirmed_date`는 `YYYY-MM-DD | null`
- 현 `VisitDetail`은 `schedule`, `technician` 중첩
- Handoff 6개를 기사 GET에 공개하는 범위는 PM 승인 전

Backend·Web 정적·자동 검증은 통과했지만 한예나·양정현의 실제 ACK 회신은 아직
수신하지 않았다. 사람 회신을 임의로 `ACK` 처리하지 않는다.

## 5. 순서 4 — Web 상담·방문 Write 준비

현재 대조 결과:

- Backend: 상담 4개 + 방문 5개 Write Runtime 존재
- Web: 상담 Remote 4개, 방문 4/5개 Repository 준비
- Web 누락: `markVisitNotNeeded`
- Web Production 화면: Write Repository 호출 연결 없음
- `useSaveConsultation`: Remote에서 차단 상태
- Response `resource`: 타입이 넓어 계약 Union 보강 필요
- Mock 실패를 Remote 성공으로 자동 전환하면 안 됨

권장 첫 연결은 상담사 GET 공동 UI Smoke 뒤 한 Action만 선택하는 수직 Slice다.

```text
상담 공통 저장
→ 완료 또는 방문 필요 중 한 분기
→ 방문 검토
→ Visit 생성
→ 일정 저장
→ 방문 확정
```

각 Action에서 `state_version`, Idempotency, Correlation, 두 종류 409, 성공 후
상세 재조회를 확인한 뒤 다음 Action으로 넘어간다.

## 6. 순서 5 — Technician Visit GET 결정안

현재 `/api/v1/technician/visits*`는 사람용 문서의 Design Backlog일 뿐
OpenAPI·Backend Runtime이 없다. 따라서 코드 구현은 시작하지 않았다.

PM 결정 ID `TVGET-D01..D10`으로 다음을 제안했다.

- Route·operationId
- 목록 Query·Paging·정렬
- 중첩 DTO
- Handoff 공개 6필드
- Null·canonical 상태
- PII 비노출
- 배정 기사 범위와 same-404
- Visit·Inquiry Version 분리
- 오류·Correlation
- Demo 기사·배정 Visit Fixture 정렬

PM 승인 전 상태는 `PROPOSED / NO_IMPLEMENTATION`이다.
