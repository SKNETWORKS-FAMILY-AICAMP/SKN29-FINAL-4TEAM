# 최지용 → 한예나: T-018 R1 main 계약 소비 확인 요청

## 시작 조건

```text
start_condition=PM_MERGED_TO_MAIN
consumer_integration_start_allowed=false
```

PM이 `jiyong → main` 병합 완료와 main SHA를 회신한 뒤 최신 main을 Pull해 확인해 주세요. 이번 요청은 정적 계약 소비 확인이며 Web 코드·Mock·Adapter·화면 연결 작업 요청이 아닙니다.

```powershell
git switch main
git pull --ff-only origin main
git rev-parse HEAD
```

## Endpoint 확인

| 용도 | Method·Path | 성공 | 오류 |
|---|---|---|---|
| 본인 구독 목록 | `GET /api/v1/me/subscriptions` | `200` | `401/403/422/500` |
| 본인 구독 상세 | `GET /api/v1/me/subscriptions/{subscription_id}` | `200` | `401/403/404/422/500` |

목록은 `items/page/size/total`을 반환하며 빈 목록도 `200`입니다. 알 수 없는 Query와 잘못된 Pagination은 `422`입니다.

## DTO 확인

목록 공통 필드:

- `subscription_id: uuid`
- `status_code: ACTIVE`
- `management_type_code: SELF_MANAGED | VISIT_CARE`
- `started_on: date`
- `last_care_on: date | null`
- `next_care_on: date | null`
- `product.product_model_id: uuid`
- `product.model_code: WPUJAC104DWH`
- `product.model_name`, `generation_code | null`, `manufacturer`

상세는 위 필드에 `ended_on: date | null`을 추가합니다. 응답에 없는 필드는 선택 표시가 아니라 Web에서 참조하지 않는 필드입니다.

## 소비 경계 확인

- 로그인 고객 본인의 활성 `WPUJAC104DWH`·ACTIVE 구독만 표시
- `last_care_on`은 `Asia/Seoul` 업무일 기준
- 내부 DB ID, 계약번호, Serial, 설치주소, 고객 개인정보, 제품 Features는 비노출
- 문의 가능 여부는 T-022 Guard에서 검증
- `allowed_actions`는 T-023 후속 범위이므로 T-018 DTO에 없음
- 두 Endpoint의 Runtime은 아직 `NOT_IMPLEMENTED`
- 따라서 현재 실제 API 연결과 Mock 제거는 금지
