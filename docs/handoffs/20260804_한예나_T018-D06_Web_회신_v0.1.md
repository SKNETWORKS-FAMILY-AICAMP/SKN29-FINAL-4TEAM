## Web 검토 근거

1. `ApiResponse<TData>`는 `success`, `data`, `error`, `metadata.correlation_id` Wrapper를 받을 수 있다.
2. `ApiClientError`는 `401`, `403`, `404`, `422`, `500`을 서로 다른 오류 종류로 구분하고 `correlation_id`를 보존한다.
3. 현재 Router에는 상담사와 운영자 Route만 있고 CUSTOMER 구독 Route는 없다.
4. Backend `ProductModel`에는 `is_supported_mvp`가 이미 있으므로 요청 문서의 “Scope 원본 필드가 없음”과 실제 코드의 관계를 재확인해야 한다.
5. `last_care_on`은 구독 Model의 직접 필드가 아니며 `CareRecord.performed_on` 등을 이용한 계산 규칙이 필요하다.

## 판정

두 GET의 응답 모양은 Web에서 소비할 수 있다. 그러나 Web이 제품 Scope와 선택 가능 상태를 임의로 판단하지 않도록 위 Blocking 항목이 계약에 확정되기 전까지 `IMPLEMENTATION_HOLD`를 유지한다.
