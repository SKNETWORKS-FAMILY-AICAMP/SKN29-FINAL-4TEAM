## 2. T-017A 검토 요청

현재 Auth Runtime은 `OWNER_IMPLEMENTATION_READY`, T-017A는
`OWNER_DESIGN_READY_REVIEW_PENDING`이다. T-017B Django Admin과 T-017C
수명주기·감사는 아직 구현하지 않았다.

### 2.1 윤승혁(PM) 결정 항목

- `accounts.User` 단일 계정 원장과 역할·접근 정책을 채택할지 결정
- `is_synthetic`, `auth_version` 추가와 마지막 관리자 보호 정책 결정
- 합성 계정 생성·비활성화·재활성화·삭제 금지 경계 결정
- 계정 관리 오류 코드·HTTP 상태·외부 노출 메시지 결정
- T-017B와 T-017C를 분리 구현한다는 순서 승인

### 2.2 김은진(Data·QA) 결정 항목

- `is_synthetic` 기존 행 backfill과 위반 행 차단 규칙 검토
- 빈 PostgreSQL과 기존 합성 DB에서의 Migration 재현 계획 검토
- Refresh 폐기·`auth_version`·rollback·동시성 테스트 범위 검토
- 계정 전용 append-only 감사 원장의 JSON Allowlist와 불변식 검토
- T-017B/C 비작성자 검증에서 반환할 최소 Evidence 확정

### 2.3 승인 결과

## 3. T-022 `SUBMIT_SYMPTOM` 검토 요청

현재 제안은 Slice A와 Slice B를 분리한다. Slice A는 DB 상태 전이만,
Slice B는 Commit 이후 AI 효과만 다룬다. 둘 다 아직 Runtime이 아니다.

### 3.1 Slice A 계약 제안

| 항목 | 제안 |
| --- | --- |
| Method·Path | `POST /api/v1/inquiries/{id}/submit` |
| `operationId` | `submitSymptom` |
| Header | `Authorization`, `Idempotency-Key` 필수 |
| Body | `{ "state_version": <positive integer> }` |
| 권한 | 인증된 CUSTOMER이며 본인 문의만 |
| 전이 | `DRAFT → QUESTIONNAIRE_IN_PROGRESS` |
| 원문 | 최초 `Inquiry.raw_text`를 불변으로 사용하고 제출 요청으로 덮어쓰지 않음 |
| 이력·멱등 | 상태·버전·이력·멱등 기록을 한 트랜잭션에서 저장 |
| ADHOC Projection | Inquiry 상태·이력으로만 파생, Target-only `QuestionnaireSession` 신규 행 없음 |

관련 기계 원본은 [OpenAPI](../../contracts/api/openapi.yaml),
[State Machine](../../contracts/state-machine/README.md)다. 위 표는 검토 제안이며
아직 두 기계 원본에 반영된 사실이 아니다.

### 3.2 담당자 결정 항목

| 담당 | 결정할 내용 | 완료 증거 |
| --- | --- | --- |
| 윤승혁 | Path·Body·응답, `MARK_QUESTIONNAIRE_SUBMITTED` 의미, 전이·409 정책 | State 계약과 OpenAPI 불일치 0 |
| 김은진 | Active 13 유지, 원문 보존, ADHOC Projection, rollback·Replay·동시 요청 | DB 수량·불변식·QA Matrix |
| 이동윤 | Slice B AI 요청 Schema, Timeout·재처리·stale 결과·durable dispatch 경계 | AI 계약 Parity와 E2E 계획 |

Slice A가 승인되어도 Slice B를 같이 구현하지 않는다. AI 호출은 DB
트랜잭션 안에서 실행하지 않으며, durable dispatch 위치가 결정될 때까지
AI Runtime 완료로 표시하지 않는다.

## 4. 반환 형식

아래 형식을 복사해 회신한다.

```text
reviewer=<이름>
branch=<검토 브랜치>
base_branch=main
main_pull_status=<UP_TO_DATE / NEEDS_PULL>
candidate_branch=jiyong
review_pr=<PR 번호 또는 URL>
environment=<OS·Python·PostgreSQL 등>
scope=<T-017A / T-022 Slice A / T-022 Slice B>
decision=<APPROVE / HOLD / CHANGE_REQUEST>
commands=<실행 명령 또는 문서 검토 경로>

contract_diff=<차이 또는 없음>
remaining_blockers=<남은 차단 요소>

```

## 5. 결과를 받은 뒤의 순서

1. 검토 결과와 계약 Diff를 기록한다.
2. T-017A 또는 T-022 중 한 작업만 선택한다.
3. 기계 계약을 먼저 변경하고 계약 검증을 실행한다.
4. 작은 Runtime Slice를 구현하고 집중 테스트를 실행한다.
5. 같은 PR 변경 묶음에서 빈 PostgreSQL·기본 PostgreSQL·전체 회귀를 검증한다.
6. 비작성자 Evidence와 PM 승인 뒤에만 `main` 병합 대상으로 전달한다.
