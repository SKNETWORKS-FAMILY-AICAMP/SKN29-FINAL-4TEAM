## 1. 최지용님께 회신

전달하신 RDS 구조·공식 Evidence·Crosswalk 결과를 후보 코드와 대조했습니다.
보고된 `53건·15/19/19·record_type=child 53건·JAC104 공식 Evidence 15건`은
`jac104_v2_recovery` 계약과 일치합니다. **추가 DB·View·Migration·Crosswalk
수정을 요청하지 않습니다.**

다만 이는 담당자의 RDS 선행검증 보고에 대한 AI 계약 검토입니다. 이번 작업에서
RDS에 재접속하거나 후보 이미지로 검색한 것은 아니므로, 실제 검색 Gate와 전체
복구까지 PASS로 회신할 수는 없습니다. 신규 합성 문의·Provider Canary는 계속
HOLD해 주세요.

지금 필요한 것은 DB 수정이 아니라 **고정된 후보 이미지와 대상 RDS를 연결하는
승인된 일회성 검증 실행 경로**입니다.

## 4. 실제 검색 Gate가 아직 실행되지 않은 이유

- 현재 Process에 대상 RDS의 보호된 `AI_VECTOR_DSN`이 연결되지 않았습니다.
- 확인한 AWS CLI·환경 인증·기본 AWS 설정·SSH Config 경로에는 실행 연결이 없습니다.
- 로컬 프로젝트 Docker 이미지 목록에 지정 후보가 없습니다.
- 첨부 문서에는 Digest만 있고, Pull에 필요한 전체 ECR 이미지 참조와 승인된
  CI/SSM 실행 경로·보호 환경 전달 위치는 없습니다.

이는 RDS 검색 실패가 아니라 **실행 전 환경 미연결**입니다. 빈 입력으로 CLI를
실행한 오류를 실제 RDS Gate 실패처럼 만들거나 로컬 DB 결과로 대체하지 않았습니다.

김은진님께 아래 환경 준비 또는 기존 승인 경로 안내를 요청드립니다.
AI 검색 Gate의 실행·판정 책임은 이동윤에게 유지합니다.

1. 대상 RDS에 접근 가능한 승인된 일회성 Runner 또는 CI/SSM 검증 Job.
2. 위 Digest로 고정된 전체 이미지 참조와 Pull 권한.
3. Readonly RDS 환경·CA·고정 Revision 모델 Cache의 보호된 전달 위치.
   DSN·키·비밀번호 값은 회신이나 채팅에 포함하지 않습니다.
4. 운영 프로세스에 영향을 주지 않을 별도 실행의 메모리·CPU·Cache 조건.

## 5. 승인된 실행 환경에서의 검증 계약

운영 env를 먼저 바꾸지 않습니다. 새 Profile은 별도 검증 컨테이너에만 지정합니다.

| 입력 | 값·조건 |

| 후보 Source | `c6036fe413ed94aa8ef2dd621941eea5e5d4f68d` |
| 후보 Image | 위 Digest의 동일 이미지 |
| Python | 3.13.13 |
| `AI_RAG_RUNTIME_PROFILE` | `jac104_v2_recovery` |
| `AI_RETRIEVAL_TRANSPORT` | `direct` |
| `AI_VECTOR_TABLE_NAME` | `backend_ai_rag_chunks_v1` |
| `AI_EMBEDDING_REVISION` | `5617a9f61b028005a4858fdac845db406aefb181` |
| `AI_VECTOR_DSN` | 대상 RDS Readonly 역할, 보호된 경로로만 전달 |
| Provider 자격증명 | 검증 컨테이너에 주입하지 않음 |

후보 Runtime 이미지의 `/workspace`에서 실행할 공식 명령은 다음입니다.
이는 **승인된 실행 환경이 준비된 뒤의 명령**이며 현재 실행 완료 결과가 아닙니다.

```bash
python -m ai.scripts.verify_jac104_v2_recovery
```

전후 역할 검사도 함께 기록합니다. 주의할 점은 Production Runtime Dockerfile이
`scripts/deployment/production/validate_ai_readonly_runtime.py`를 Copy하지 않는다는
점입니다. 배포 담당자가 **후보 SHA의 해당 파일을 Readonly Mount**하거나 승인된
검사 경로를 준비해야 합니다. 후보를 다른 QA 이미지로 바꾸어 같은 Digest라고
보고하지 않습니다.

기대 결과는 아래와 같습니다.

| Probe | 최소 1개 포함되어야 할 정확한 Child |
| --- | --- |
| 냉수 온도 | `CHILD-WPUJAC104DWH-P037-COLD-NORMAL-001` 또는 `CHILD-WPUJAC104DWH-P037-COLD-FAULT-001` |
| 출수량 | `CHILD-WPUJAC104DWH-P038-LOW-FLOW-001` |

세 Probe 모두 1~5건의 유효 JAC104 근거, 기대 Child 적중이 필요합니다.
IAC425·IAC606은 각각 `POLICY_BLOCK_UNSUPPORTED_MODEL`과 검색 결과 0건이어야 하며,
Provider 호출·DB Write·DDL은 없어야 합니다. 실제 종료 코드·Gate JSON·전후
Readonly 검사·Container/Image 식별자·실행 시각·파일 Hash를 같은 Run으로 묶습니다.
현재 이 실행 수치들은 미측정이며 PASS나 0으로 채우지 않습니다.

## 6. 이후 순서와 담당자

1. **이동윤**: 위 환경이 준비되면 Provider-free Direct Gate와 전후 정합성을 검증.
2. **김은진**: JAC104 v2 15건 Data 검수. Direct Gate와 병행 가능.
   `official_verified` 메타데이터나 일반 Data CI PASS를 운영 범위 승인 회신으로 대체하지 않음.
3. **윤승혁·김은진**: 두 결과 PASS 후 SSM 실패 조치, 배포할 Release·Image·Profile과
   롤백 또는 상담 대체 기준 승인. SSM 경로 자체가 Gate 실행도 막는다면 실행 기반 복구
   여부부터 담당자가 결정하되, 이를 서비스 배포 승인으로 확대하지 않음.
4. **배포 담당**: 승인된 새 이미지와 `jac104_v2_recovery`를 함께 적용.
   기존 Pipeline 선택과 `AI_HANDOFF_BACKEND_ENABLED=false` 유지.
5. **양정현·이동윤, 윤승혁 통합 검수**: 새 이미지의 운영 MCP 경로를 별도로 검증.
   현재 Direct CLI는 `mcp`를 거부하므로 env만 바꿔 재실행하는 방식은 사용하지 않음.
6. **이동윤·배포 담당**: Direct/MCP 결과와 최종 실제 Release SHA·Image Digest·
   Profile·Transport·Health·Restart Count·Data/PM 승인 근거를 결속해 최지용에게 전달.
7. **최지용**: 위 결과 확인 후 신규 합성 문의·Provider Canary 재개.

구버전 `mvp`와 v2 RDS 조합은 정상 복구 조합으로 승인되지 않았습니다.
env만 `mvp`로 되돌리거나 구버전 Health가 정상이라는 이유로 복구 완료 처리하지 않습니다.
DB 복원·Migration Rollback·재배포는 이번 작업에서 수행하지 않았습니다.
