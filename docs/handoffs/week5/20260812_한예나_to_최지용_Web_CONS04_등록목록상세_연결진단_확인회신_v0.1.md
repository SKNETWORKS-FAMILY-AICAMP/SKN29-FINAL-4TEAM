## 4. 상담 시작과 상태 지속성 확인

상세 응답에서 다음 값을 확인한 뒤 상담 시작 API를 호출했다.

```text
status=CONSULTATION_REQUIRED
state_version=1
allowed_actions=START_CONSULTATION
```

상담 시작 요청에는 다음 Header와 Body를 사용했다.

```text
Authorization=Bearer <공유하지 않음>
X-Correlation-ID=<UUID>
Idempotency-Key=<UUID>
```

```json
{
  "state_version": 1
}
```

검증 결과:

| 항목 | 결과 |
| --- | --- |
| 상담 시작 HTTP Status | `200` |
| 변경 상태 | `CONSULTATION_IN_PROGRESS` |
| 변경 State Version | `2` |
| 변경 Allowed Action | `UPDATE_CONSULTATION_SUMMARY` |
| 상세 재조회 | `200` |
| 재조회 상태 | `CONSULTATION_IN_PROGRESS` |
| 재조회 State Version | `2` |

`Idempotency-Key` 없이 상담 시작을 호출했을 때는 Backend가 `422
VALIDATION_ERROR`로 거부했고, 필수 Header를 포함한 요청은 `200`으로 처리됐다.
필수 멱등 Header 계약도 정상 적용된 것으로 확인했다.

## 5. Correlation 확인

각 요청에서 다음 세 값이 일치하는 것을 확인했다.

```text

Response Header X-Correlation-ID
Response Body metadata.correlation_id
```

| 요청 | Correlation ID | 결과 |
| --- | --- | --- |
| 목록 재조회 | `ebc0e05d-2668-4b67-b6b1-0722445642a0` | `MATCH` |
| 상세 조회 | `e813c2bc-f6e6-4e9f-9452-7923be263c80` | `MATCH` |
| 상담 시작 | `3a23f47b-98f2-4e75-9d50-c11bf9b96762` | `MATCH` |

Token, Authorization Header 전체 값과 전화번호 원문은 기록하지 않았다.

## 8. 추가 확인 또는 결정 요청

Runtime 연결을 차단하는 Backend 오류는 발견하지 못했다. 다음 항목은 제품·계약
결정이 필요하다.

1. 목록에서 `priority=HIGH`를 별도 처리 우선순위 배지로 보여 줄지 결정
2. 위험도 평가 전 전화 문의의 `risk_level=general` 표시를 유지할지,
   `미평가` 상태를 도입할지 결정
3. 전화 문의 구분을 위해 목록·상세 DTO에 `channel_code=PHONE`을 공개할지 결정
4. 등록 성공 후 상세 자동 이동 또는 현재 링크 선택 방식을 유지할지 결정

Web에서는 `HIGH → caution`, `URGENT → danger` 같은 임의 변환을 적용하지 않았다.
