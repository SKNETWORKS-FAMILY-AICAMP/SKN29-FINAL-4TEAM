# 한예나 → 최지용 Web 상담사 문의조회 API 실연동 재검증 회신 v0.2

## 1. 회신 목적

최신 `main`을 Web 개인 브랜치에 병합한 상태에서, 백엔드가 API 명세대로 동작하고 현재 상담사 문의조회 화면이 실제 Backend Runtime 응답을 정상적으로 사용하는지 재검증한 결과를 회신합니다.

이번 검증은 Mock 응답이 아니라 별도 API 모드 Web과 격리 PostgreSQL DB를 사용했습니다.

## 6. Web 실제 화면 확인

API 모드 Web에서 다음 흐름을 브라우저로 확인했습니다.

1. `/consultant/inquiries` 접근
2. API Demo Login 화면으로 이동
3. `CONSULTANT` 역할 로그인 성공
4. 상담사 문의 목록으로 복귀
5. Mock 30건이 아닌 실제 Seed 문의 1건 표시
6. 주의 문의 탭에 실제 문의 1건 표시
7. 문의 선택 후 UUID 상세 Route 이동
8. 실제 API 문의·고객·제품·증상·Workflow 정보 표시
9. Backend 응답 기준 `상담 시작` 허용 행동 표시

화면에서 확인한 주요 값은 다음과 같습니다.

```text
문의 번호=DEMO-INQ-CONSULTANT-READ-001
고객명=합성 상담조회 고객 001
연락처=010-****-0000
상태=CONSULTATION_REQUIRED
상태 버전=1
위험도=caution
허용 행동=상담 시작
```

따라서 현재 상담사 문의 목록·상세 화면은 Backend의 실제 목록 DTO와 상세 DTO를 정상적으로 렌더링합니다.

## 8. Git 반영 상태

화면 변경과 기존 PostgreSQL 공동 Smoke 회신은 `yena` 브랜치에 푸시했습니다. 최신 `origin/main` 병합 커밋도 원격 `yena`에 반영했습니다.

```text
origin/yena=1aad2b576782df8f7f7a2b3a98a61cd52cebc038
origin/main=b37678d097d9f9e5223f69b52a9f9c1338857ffc
```

## 9. 백엔드 담당자 확인 요청

현재 Web 문의조회 범위에서는 추가 Blocker가 없습니다. 아래 두 가지만 운영 방식 확정 시 공유 부탁드립니다.

1. 팀 공용 개발환경에서 사용할 공식 PostgreSQL DB명과 Migration 적용 책임자
2. 실제 배포·공동 Smoke 시 사용할 Backend Base URL 및 Demo Login 허용 정책

그 외 상담사 문의 목록·상세 계약과 오류 응답은 현재 Web 구현에서 사용 가능한 상태로 확인했습니다.
