## 1. 인계 목적

현재 상담사 화면의 Mock·입력 보호·오류 UI 기준을 유지하면서 Backend가
제공하는 목록·상세·상담·방문·Evidence API로 단계적으로 전환해 달라는
요청이다. Backend Route가 없는 상태에서 Web이 응답을 추측 구현하지 않고,
실제 Route 제공 뒤 소비 검증을 수행한다.

공통 실행 증거는
[Web–Backend 실제 연결 QA 보고서](../../testing/results/week4-web-backend-live-verification-20260810.md)를
참조한다.

## 4. 요청사항

### P0 — Adapter 전환 준비

- 현재 Repository를 Remote와 명시적 Mock 구현으로 분리한다.
- 실제 API 실패를 숨기기 위해 자동으로 전체 Mock으로 전환하지 않는다.
- DTO→Mapper→View Model 경계를 유지하고 Public ID를 opaque string으로
  취급한다.
- Backend가 제공한 `allowed_actions`만 버튼 노출 기준으로 사용한다.

### P0 — 실제 상담·방문 연결

- 최지용의 Runtime 전달 뒤 목록→상세→상담 저장→완료→방문 순서로
  단계별 연결한다.
- Mutation마다 최신 `state_version`, 논리 작업 단위 Idempotency-Key와
  요청별 `X-Correlation-ID`를 전송한다.
- 409에서 입력을 메모리에 유지하고 최신 상태·버전·허용 행동을 반영한다.
- 자동 덮어쓰기·자동 재전송·타이머 자동 저장을 추가하지 않는다.

### P1 — 오류·Evidence·추적

- 401, 403, 404, 409, 422, 네트워크 오류와 공통 Wrapper 불일치를 구분한다.
- Backend가 확정한 Public Evidence 필드만 표시하고 내부 AI 필드를 받더라도
  화면에 전달하지 않는다.
- 응답 `X-Correlation-ID`를 오류 문의·QA 확인에 사용할 수 있게 보존하되
  Token·고객 원문·개인정보와 함께 로그하지 않는다.
- 실제 API 요청의 correlation ID가 Backend Log·DB 결과와 이어지는 통합
  Smoke를 김은진에게 전달한다.
