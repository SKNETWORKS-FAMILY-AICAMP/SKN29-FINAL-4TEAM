- 검증 성격: 신규 구현 없이 현재 Web 코드와 5주차 계약의 일치 여부 확인

## 1. 결론

현재 Web 코드는 5주차 계약을 **조건부로 실제 사용 가능(READY_WITH_LIMITATIONS)** 한 상태입니다.

서버가 내려준 `status`, `state_version`, `allowed_actions`를 화면과 후속 요청에 사용하고 있으며, Remote API 실패를 Mock 성공으로 자동 대체하지 않습니다. Date 처리와 403·404·409 오류 처리도 계약 방향과 일치합니다.

다만 다음 두 항목은 제한 사항으로 남아 있습니다.

1. `allowed_actions`는 현행 계약에 등록된 액션 코드만 허용하는 fail-closed 화이트리스트 방식입니다. 서버에 신규 액션 코드가 추가되면 Web 코드가 갱신되기 전까지 해당 액션은 노출되지 않습니다.
2. Remote 422 응답의 오류 종류·메시지·Correlation ID는 처리하지만, 서버가 제공하는 필드별 오류 상세를 실제 Form 필드에 연결하는 매핑은 확인되지 않았습니다.

### 전체 Test 환경 주의 사항

현재 Remote 설정인 `VITE_USE_MOCK_API=false`로 전체 `npm test`를 실행하면 Mock 데이터를 전제로 작성된 기존 테스트가 실제 Remote 경로를 타면서 실패합니다.

- 결과: 6 files 실패 / 27 files 통과
- 테스트: 30 tests 실패 / 112 tests 통과
- 판단: Remote 계약 표적 테스트는 모두 통과하므로 계약 불일치보다는 Test 환경 분리 문제로 판단함

CI에서는 다음 Gate를 분리하는 것이 필요합니다.

1. Mock 기반 전체 회귀 Test: `VITE_USE_MOCK_API=true`
2. Remote 계약 및 Repository 표적 Test: `VITE_USE_MOCK_API=false`

## 5. PM 확인 및 협의 필요 사항

1. **422 완료 기준 결정**
   - 메시지 단위 오류 표시까지 허용할지, 서버의 필드별 오류를 각 Form 필드에 연결해야 완료로 볼지 결정이 필요합니다.
