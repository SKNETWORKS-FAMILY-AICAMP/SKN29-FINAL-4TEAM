## 3. 영역별 반영 내용

### Mobile

- 실제 고객 Guidance 조회 API 연결
  - `GET /api/v1/me/inquiries/{inquiry_id}/guidance`
- 실제 상담 요청 API 연결
  - `POST /api/v1/inquiries/{inquiry_id}/request-consultation`
- Backend의 `status`, `state_version`, `allowed_actions`를 화면 상태에 반영
- 상담 요청 재시도 시 같은 프로세스 내 `Idempotency-Key` 재사용
- 성공 후 재클릭과 즉시 연속 탭 차단
- 409 응답의 최신 Workflow Snapshot 반영
- Remote 실패 시 Fake Guidance나 로컬 성공으로 대체하지 않도록 유지
- 실제 Backend를 사용하는 Android 표적 테스트 추가

### Backend·AI

- 고객 소유 범위의 Guidance 조회 Runtime과 OpenAPI 계약 추가
- 검증된 최신 AI Guidance를 고객·상담사 DTO에 투영
- 내부 Chunk·Score·Trace는 외부에 노출하지 않음
- Public Evidence Runtime이 없으므로 `evidence: []` 반환
- Canonical Evidence ID·해시·계보 검증 추가
- 위험 판정과 구성된 안전 규칙이 일치할 때만 `CONSULTATION_REQUIRED`로 전이
- 안전 규칙 ID가 없거나 불일치하면 fail-closed 유지
- Mobile이 생성한 미배정 합성 문의를 상담사 Queue에 노출
- 상담 시작 시 상담사를 원자적으로 선점하고 다른 상담사의 접근 차단
- stale 상담 시작 실패 시 선점도 Rollback

### Web

- 상담사 상세에 실제 AI 안내 원문·상태·제한 기능 표시
- AI 안내가 없으면 `AI 안내 미제공 / 상담 검토 필요` 표시
- Public Evidence가 없으면 `공개 근거 미제공 / 상담 검토 필요` 표시
- 상담 시작 → 기록 저장 → 요약 확정 → 완료를 실제 Backend와 연결
- 새로고침·재진입 시 서버 상담 기록 복구
- 성공·409 재조회 중 작성 중인 상세와 Draft 보존
- 상담 요약 확정 Checkbox와 중복 클릭 방지 추가
- Backend에 저장되지 않던 Remote 전용 자유 텍스트 입력은 제거하고 실제 `result_code`만 사용

## 5. PM 승인 범위 준수

- 실제 AI Guidance 연결은 P0로 유지했다.
- Public Evidence Web 화면은 새로 만들지 않았다.
- 공개 근거가 없을 때 가짜 근거를 만들지 않고 안전 문구만 표시한다.
- Evidence 관련 변경은 Backend State 전이에 필요한 검증 범위만 반영했다.
- 진행 중이던 Dashboard·AI 검수 UI와 신규 화면 고도화는 건드리지 않았다.
- GPT 모델·임베딩·청킹·Retriever 비교 실험은 진행하지 않았다.

## 6. 팀별 확인 요청

### Backend·DB 담당

- 팀 PostgreSQL 환경에서 상담사 원자 선점과 row-lock 테스트를 재확인한다.
- `COMPLETION_PENDING` 이후 `RESOLVED` Runtime은 별도 우선순위 결정 전까지 P0 완료 조건에 포함하지 않는다.

### AI 담당

- 이번 P0 기준선과 안전 규칙 경로를 유지한다.
- 모델·임베딩·Retriever 비교 실험은 E2E 이후 별도 작업으로 진행한다.
- Public Evidence Runtime 합의 전 내부 Chunk를 고객 DTO에 직접 노출하지 않는다.

### Mobile 담당

- 물리 Android 기기에서 실제 네트워크와 UI 조작을 한 번 더 확인한다.
- 홈 복귀나 앱 재시작 후 동일 진행 문의에 재진입하는 경로는 P1로 분리한다.
- 앱 프로세스 재시작까지 포괄하는 Idempotency Key 영속화는 P2로 분리한다.

### Web 담당

- 상담 완료 후 정상 상태가 `COMPLETION_PENDING`임을 기준으로 화면을 유지한다.
- Public Evidence Runtime이 생기기 전까지 현재 안전 Fallback을 유지한다.
- Dashboard·AI 검수 UI 고도화는 E2E 완료 이후 별도 변경으로 분리한다.

## 7. 남은 후속 과제

1. **P1 — Mobile 재진입 경로**

   구독 API의 진행 문의 요약 또는 별도 진행 문의 조회를 이용해 홈 복귀·앱 재시작 후에도 같은 문의를 다시 열 수 있도록 한다.

2. **P2 — Mobile Idempotency Key 영속화**

   서버 처리 후 응답 유실과 앱 프로세스 종료가 동시에 발생해도 같은 상담 요청을 복구할 수 있도록 영속 Store를 검토한다.

3. **운영환경 Gate**

   팀 PostgreSQL과 물리 Android 기기에서 최종 smoke를 재수행한다.

4. **E2E 이후 고도화**

   Public Evidence 화면, Dashboard·AI 검수 UI, 모델·임베딩·Retriever 비교 실험은 별도 우선순위로 다시 결정한다.
