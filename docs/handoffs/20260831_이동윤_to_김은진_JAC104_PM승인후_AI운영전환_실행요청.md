- 상태: **Data PASS / PM 승인 전달받음 / 운영 반영 증거 대기**

## 1. 김은진님께 전달할 요청문

은진님, JAC104 Data PASS와 AI·RAG Direct Gate PASS에 이어 PM의 운영 전환 승인을
전달받았습니다. 배포 담당자는 은진님으로 지정됐습니다. 아래 고정 대상의
**JAC104-only AI 운영 Profile 반영**을 부탁드립니다.

- 대상 SHA: `ce22601bf4f21b0c11d7626fb3bd1b905464d1da`
- 대상 AI Image Digest / 기존 증거의 Docker Image ID:
  `sha256:6df3057e8f698dd613a3ed920bf9edb8ddf0d06593eacc356147dcf9053303c2`
- 반영 Profile: `AI_RAG_RUNTIME_PROFILE=jac104_v2_recovery`
- 허용 제품: `WPUJAC104DWH` 1종, 공식 Child 근거 15건.
- 유지: `AI_PIPELINE_RUNTIME=multi_agent`, `AI_RETRIEVAL_TRANSPORT=mcp`,
  `AI_HANDOFF_BACKEND_ENABLED=false`, 기존 최소 Readonly DB 권한.
- 제외: IAC425/IAC606 활성화, DB·View·Migration·재적재, Pipeline 기본값 변경,
  신규 합성 문의·Provider Canary, 다른 서비스의 임의 변경.

실행 순서는 다음과 같이 요청드립니다.

1. **실행 직전 확인**: 실제 운영 Release·AI Image·Profile과 디스크 여유,
   적용할 Compose/env 참조, 복구·롤백 절차를 확인해 주세요. 앞선 관찰값을 현재값으로
   가정하지 않습니다. 대상이 다른 SHA·이미지로 바뀌었다면 임의 대체하지 말고 회신해 주세요.
2. **Readonly 사전 검사**: 공식 Preflight PASS / exit 0을 확보해 주세요.
   권한·53건·15/19/19·Lineage·1024차원 등 기존 조건이 다르면 반영을 보류합니다.
3. **승인 범위 반영**: 기존 운영 런북에 따라 AI 서비스에 위 이미지·Profile을 반영해 주세요.
   이미 동일 이미지라면 불필요한 재빌드·다른 이미지 교체를 요청하는 것이 아닙니다.
   설정 파일 수정 여부만이 아니라 **실행 중인 AI 컨테이너의 실제 환경값**으로 확인해 주세요.
4. **반영 후 검사 및 인계**: Readonly Preflight를 다시 실행하고, 아래 식별자·환경·Health와
   실행 결과를 보내 주세요. 실패하면 실패 단계·원인·조치·복구 상태를 먼저 알려 주세요.

## 2. 완료 회신에 필요한 내용

아래 항목을 실제 실행값으로 회신해 주세요. Secret 값, 전체 env 출력, 전체 Docker
inspect 출력은 보내지 않습니다.

| 항목 | 필요한 증거 |
| --- | --- |
| 실행 시각·방법 | 시각과 타임존, 운영 반영 방법·종료 코드. CI 경로를 사용했다면 해당 Run·결과 |
| Release | 실제 40자리 SHA와 승인 대상 일치 여부 |
| AI Image | 실제 Digest와 Docker Image ID, 승인 대상 일치 여부 |
| AI Container | 실제 Container ID와 시작 시각 |
| Runtime | 실행 컨테이너의 `jac104_v2_recovery + multi_agent + mcp` 확인 |
| Handoff | `AI_HANDOFF_BACKEND_ENABLED=false` 유지 확인 |
| Readonly Preflight | 전·후 각각 PASS 여부, 종료 코드, 비밀값 없는 출력 |
| Health | Docker 상태·Health·Restart 횟수, AI Health HTTP 상태 코드 |
| 배포 장애 종결 | 최종 디스크 여유 및 실제 반영 성공/실패 결과 |
| 롤백 | 복구 대상 식별자와 절차 확인 여부. 이전 `mvp` 설정으로 돌아가는 것만으로 검색 정상 복구를 보장하지 않음 |

반영 완료 보고는 **운영 설정 반영 완료**로 구분해 주세요. 아직 실행하지 않은
운영 MCP 검증이나 전체 복구까지 PASS로 표시하지 않습니다.

## 3. 배포 회신 이후 AI·MCP 후속 검증

회신을 받은 뒤 이동윤·양정현이 승인된 실제 운영 **MCP 경로**에서 다음을 확인합니다.

- JAC104 냉수 미지근함·출수량 감소·맛/냄새의 기대 근거 검색 3/3.
- IAC425/IAC606 정책 차단 2/2, 교차 제품·Direct Parent·미검증 근거 배제.
- Provider 호출·Backend Write 없이 Readonly 조건 유지.
- 최종 Release·Image·Profile·Health 식별자와 검증 실행의 연결.

현재 1~3번은 기존 실제 검증 PASS이며, 4번의 **Data·PM 승인 조건은 충족**됐습니다.
다만 4번 배포 반영·장애 종결 증거, 5번 실제 운영 MCP, 6번 최종 복구 증거는 아직 대기입니다.
이 조건을 모두 확인하기 전까지 **FULL_RECOVERY 및 신규 합성 문의·Provider Canary는 HOLD**입니다.
전체 PASS 증거를 받은 뒤 최지용님이 후속 Backend 검증을 진행합니다.
