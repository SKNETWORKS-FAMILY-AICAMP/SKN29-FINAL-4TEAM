## 5. 사전 검증 실행 계약

승인된 CI/SSM의 별도 검증 Process에서 후보 이미지와 대상 RDS의 보호된
Readonly 환경을 사용한다. EC2 Host의 임의 Python이나 운영 AI 컨테이너 안에서
두 번째 Embedding 모델을 띄우는 방식은 피한다. 별도 실행의 메모리·모델 Cache와
Release 고정은 배포 담당자가 확인한다.

필수 입력은 Secret 값이 아니라 아래 변수와 전달 절차로 공유한다.

| 변수·환경 | 검증 값·조건 |
| --- | --- |
| Python | `3.13.13` |
| `AI_RAG_RUNTIME_PROFILE` | `jac104_v2_recovery`를 별도 Process에만 명시 |
| `AI_VECTOR_TABLE_NAME` | `backend_ai_rag_chunks_v1` |
| `AI_VECTOR_DSN` | 승인된 대상 RDS의 Readonly 역할. 보호 env/Secret 경로로만 전달 |
| `AI_EMBEDDING_REVISION` | 위 고정 Revision |
| `AI_RETRIEVAL_TRANSPORT` | `direct` 또는 미지정 기본값 `direct` |
| `OPENAI_API_KEY` | 이 검색 검증에는 불필요. 안내 생성 Provider를 호출하지 않음 |

현재 도구는 Direct 검색만 판정한다. 운영 Transport가 MCP라면 조용히 Direct로
바꾸지 말고 양정현·윤승혁과 해당 경로 검증을 별도로 확정한다.

저장소 Root가 작업 디렉터리인 후보 이미지 안에서 실행할 명령:

```bash
python -m ai.scripts.verify_jac104_v2_recovery
```

`ai/configs`의 Manifest·Canonical Identity만 사용하고 `data/.../expansion`
원본을 읽지 않으므로 현재 Runtime 이미지의 데이터 Copy 범위로 실행할 수 있다.
단, 이번 파일들이 포함된 **새 이미지**여야 한다.

수행 범위:

1. 명시 Profile·Table·Revision·Python·Transport 확인.
2. Readonly Transaction과 5초 SQL Timeout으로 승인 View 최대 54행 조회.
   54번째 행은 기대 53건 초과를 탐지하는 용도다. Source 본문은 가져오지 않고
   DB가 계산한 본문 SHA-256만 조회한다.
3. Canonical Child 53개, 중복·누락·초과 없음, 분포 `15/19/19`, 1024차원,
   모델·Revision·Index Version·Chunk Set Hash·Source/본문 Hash·공식 검증·
   Lineage·페이지 정합성 확인.
4. 다른 두 제품의 검색 전 정책 차단 확인.
5. JAC104 냉수 온도·출수량·물맛/냄새 검색에서 해당 주제의 정확한 Child가
   적어도 1개 포함되는지 확인. 단순히 관련 없는 Hit가 있는 것으로 통과하지 않음.

이 도구는 Backend 역할 권한 전체 감사, 실제 안내 생성, 물맛·냄새 문진의 HTTP
E2E, 3모델 공식 50 Case를 대신하지 않는다. 기존
`scripts/deployment/production/validate_ai_readonly_runtime.py`의 역할·권한
검사도 함께 유지한다. 이 파일이 포함된 QA 이미지와 실행 경로는 김은진이 정한다.

통과 결과에서 확인할 필드:

3. **김은진**: JAC104 v2 15건 자료 검수 및 동일 후보 이미지의 역할 검사·새 검색

   `three_model_integration` 전용이므로 그것을 실행한 것만으로 이 복구 후보의
   검증을 대신하지 않음. 필요 Job/Startup 연결은 해당 주관할에서 적용.
4. **윤승혁·배포 담당**: 위 결과와 롤백 방안을 검토하여 제한된 운영 반영 승인.
   새 이미지와 새 Profile을 함께 적용한 뒤 실제 실행 Profile·실제 검색 재확인.
   `AI_PIPELINE_RUNTIME`은 기존 선택을 유지하고 `AI_HANDOFF_BACKEND_ENABLED=false`도
   유지. 다른 두 제품의 Backend Public 허용 플래그는 변경하지 않음.
5. **최지용**: 검색 Gate 결과를 받은 뒤 신규 합성 Inquiry로 재개.
   첫 제출 안내 Provider 0회 → 공식 후속답변 1회 → 안내 Provider 정확히 1회 →
   공식 근거 의미 적합성 → 두 번째 HumanReview 거절 → 보호 입력 Export →
   Runner `inspect` → Hash·식별자 회신. 기존 실패 Inquiry 두 건은 재사용하지 않음.

이후의 맥락정리 Provider·Handoff·Replay는 기존 별도 승인 절차를 따른다.
3모델 공개 확대·공식 50 Case·Multi-Agent 기본값 승격은 이번 복구로 승인되지 않는다.
