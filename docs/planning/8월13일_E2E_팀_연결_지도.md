# 3. 실제 연결 순서

## ① 김은진 → 전원: 공용 환경

```text
PostgreSQL / pgvector
        +
     Backend
        +
        AI
        ↓
팀 공용 통합 환경
```

### 김은진이 전달해야 하는 것

- Backend Base URL
- AI 실행 여부
- DB·Seed 준비 상태
- 필요한 환경 변수 안내
- E2E 기준 Commit SHA

### 완료 신호

> “Mobile·Web에서 같은 Backend를 호출할 수 있고 Backend가 AI를 호출할 수 있음.”

---

## ② 양정현 → 최지용: 고객 문의 입력

```text
고객 Mobile
→ 로그인
→ 구독 제품 선택
→ 문의 생성
→ 증상 제출
→ 추가 질문·답변
→ Backend
```

### 양정현이 Backend에 넘기는 것

- 고객 인증 정보
- 구독·제품 식별자
- Inquiry
- 증상 원문
- 추가 질문 답변
- `state_version`
- Idempotency Key
- Correlation ID

### 최지용이 보장해야 하는 것

- 실제 DB 저장
- 최신 Inquiry Snapshot
- 올바른 `state_version`
- 올바른 `allowed_actions`
- 필요한 시점에 AI 호출

---

# 4. 최지용 → 이동윤: 실제 AI 호출

```text
Backend
→ 문의·제품·증상 Context
→ AI FastAPI
```

### 최지용이 AI에 넘기는 것

- Inquiry 식별 정보
- 제품 모델
- 고객 증상
- 추가 답변
- 필요한 Context
- Correlation ID

### 이동윤이 해야 하는 것

이번 이틀에는 실험하지 않고 아래 Baseline으로 실행한다.

```text
SingleRAGPipeline
+ BAAI/bge-m3 1024d
+ 승인 7청크
+ PostgreSQL/pgvector
+ Cosine Exact Search
+ Top-K 5
+ Threshold 0.4
+ gpt-4.1-mini
```

---

# 5. 이동윤 → 최지용: AI 결과 반환

```text
RAG
→ Evidence 검색
→ LLM Guidance 생성
→ Schema 검증
→ Backend
```

### 이동윤이 Backend에 넘겨야 하는 것

- 구조화된 AI 처리 결과
- 고객 Guidance
- Public Evidence로 변환 가능한 근거
- 위험·No-Evidence·Fallback 상태
- Correlation ID

### 넘기면 안 되는 것

- AI가 계산한 Backend State
- 내부 `chunk_id`를 Client용 ID처럼 사용
- Vector score를 고객 데이터로 노출
- 내부 파일 경로
- Prompt

AI는 **판단 결과를 반환하고 State 최종 결정은 Backend가 한다.**

---

# 6. 최지용 → 양정현: 고객 AI 안내 반환

```text
AI Response
→ Backend 검증·저장
→ Guidance / Evidence DTO
→ 고객 Mobile
```

### 최지용이 해야 하는 것

- AI Run 저장
- Guidance 저장
- Evidence 연결
- State Machine 적용
- 최신 `state_version`
- 최신 `allowed_actions`
- 고객에게 허용된 DTO만 반환

### 양정현이 해야 하는 것

Mobile에서 다음만 제대로 표시한다.

- AI 안내
- 공식 근거
- 현재 상태
- 다음 행동
- `상담 요청`

AI 결과가 완벽한지는 지금 평가하지 않는다.

---

# 7. 양정현 → 최지용 → 한예나: 상담사 연결

고객이 AI 안내 후 해결되지 않으면:

```text
고객 Mobile
→ 상담 요청
→ Backend
→ CONSULTATION_REQUIRED
→ 상담사 문의 목록
→ 상담사 Web
```

### 양정현

`allowed_actions`에 상담 요청이 있을 때 실제 API를 호출한다.

### 최지용

- 상담 요청 저장
- Inquiry State 갱신
- 상담사 목록·상세에 해당 Inquiry 노출
- 동일 Inquiry를 계속 사용

### 한예나

Web에서 해당 Inquiry가 실제로 보이는지 확인한다.

---

# 8. 한예나 → 최지용: 상담 처리

```text
상담사 Web
→ 문의 상세
→ AI 결과 확인
→ 상담 시작
→ 상담 기록
→ 상담 완료
→ Backend
```

### 한예나가 보내는 것

- 상담 시작 Action
- 상담 내용·요약
- 상담 완료 Action
- 현재 `state_version`
- Idempotency Key

### 최지용이 반환하는 것

- 최신 State
- 최신 `state_version`
- 최신 `allowed_actions`
- 저장된 상담 결과

이번 E2E에서는 **방문 전환 대신 상담 완료 경로를 우선한다.**

---

# 9. 최지용 → 양정현: 마지막 확인

```text
상담 완료
→ Backend State 갱신
→ 고객 Mobile Snapshot 재조회
→ 최종 상태 표시
```

양정현은 고객 앱을 새로고침하거나 재진입하여 상담 처리 결과가 실제로 반영되었는지 확인한다.

여기까지 되면 이번 대표 E2E가 끝난다.

---

# 10. 김은진은 전체 흐름 옆에서 무엇을 하는가

김은진은 특정 한 구간의 기능을 대신 개발하지 않는다.

```text
Mobile ─┐
Backend ├─→ 같은 Commit / 같은 DB / 같은 환경인지 검증
AI      ┤
Web     ┘
```

### 김은진 책임

- 공용 실행 환경 유지
- 같은 Inquiry를 기준으로 로그 확인
- `correlation_id` 추적
- 실제 DB 저장 확인
- 실패 구간 재현
- 수정 후 즉시 재검증
- E2E Blocker 목록 관리

---

# 11. 윤승혁은 전체 흐름에서 무엇을 하는가

윤승혁은 기능 개발자가 아니라 **흐름이 옆길로 새지 않게 막는 역할**을 한다.

### 판단 기준은 하나다.

> **“이 문제가 해결되지 않으면 위 E2E 흐름이 멈추는가?”**

### YES

즉시 P0.

예:

- Mobile과 Backend DTO 불일치
- Backend가 AI를 호출하지 못함
- AI Response Schema 불일치
- 상담 요청 후 Web에 Inquiry가 안 보임
- State 때문에 다음 Action을 실행할 수 없음

### NO

Backlog.

예:

- 챗봇으로 바꾸면 더 편할 것 같음
- 다른 LLM이 더 좋을 것 같음
- 청킹을 바꾸면 성능이 좋아질 것 같음
- UI를 더 예쁘게 만들고 싶음
- 방문기사 기능을 보완해야 함
- Dashboard에 새로운 통계를 추가하고 싶음

# 12. 오늘 병렬 작업 순서

모든 사람이 한 사람의 완료를 기다렸다가 시작하면 늦어진다.

따라서 아래처럼 병렬 진행한다.

```text
김은진
└─ 공용 Backend·DB·AI 환경 준비
         │
         ├────────────────────────────┐
         │                            │
최지용 + 이동윤                   양정현
Backend↔실제 AI 연결              Guidance 소비 준비
         │                            │
         └─────────────┬──────────────┘
                       ↓
                Mobile 실제 AI 확인
                       ↓
                 상담 요청 생성
                       ↓
              최지용 + 한예나
              상담사 Web 실제 연결
                       ↓
                  상담 완료
                       ↓
                Mobile 최종 확인
```

한예나는 앞 구간이 끝날 때까지 기다리지 않고 **상담 목록·상세·Action의 실제 Backend Smoke를 병렬로 수행**한다.

# 14. 이번 E2E 완료 선언 조건

```text
고객 Mobile에서 문의 생성 가능
        ↓
실제 Backend 저장
        ↓
실제 AI 호출
        ↓
실제 RAG + LLM 실행
        ↓
Guidance / Evidence 저장
        ↓
Mobile에 AI 안내 표시
        ↓
고객 상담 요청
        ↓
```
