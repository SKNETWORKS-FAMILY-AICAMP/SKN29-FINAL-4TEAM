# 2. 대상 정수기 제품 범위 확대

기존에는 `WPU-JAC104 / WPU-JCC104` 매뉴얼을 중심으로 AI/RAG 기능을 검증해 왔다.

이번 주부터 다음과 같이 **3개 제품군, 4개 모델 코드**를 대상으로 확장한다.

| 구분 | 모델 | 유형 | 비고 |
|---|---|---|---|
| 기존 제품군 | WPU-JAC104 | 냉온정수기 | 기존 기준 모델 |
| 기존 제품군 | WPU-JCC104 | 냉정수기 | WPU-JAC104와 동일 매뉴얼 계열 |
| 신규 제품군 1 | WPU-IAC425 | 얼음 냉온정수기 | 얼음/얼음물/제빙 기능 포함 |
| 신규 제품군 2 | WPU-IAC606 | 얼음 냉온정수기 | 얼음/얼음물/제빙 기능 포함 |

제품 범위 확대에 따라 단순히 매뉴얼 두 개를 추가 적재하는 것이 아니라 다음을 함께 검증한다.

- 제품별 매뉴얼 Chunk 분리
- 제품별 Metadata 및 `model_code` 관리
- 제품군 공통 정보와 모델별 정보 구분
- 유사 매뉴얼 간 잘못된 Evidence 혼입 방지
- 제품별 Safety / Guidance 차이 검증
- 얼음/얼음물/제빙 관련 신규 증상 Case 추가
- 제품별 RAG Evaluation
- 제품별 E2E 검증

권장 Product Context 구조:

```text
product_family
├─ DIRECT_WATER_PURIFIER
└─ ICE_WATER_PURIFIER

model_code
├─ WPU-JAC104
├─ WPU-JCC104
├─ WPU-IAC425
└─ WPU-IAC606
```

AI는 제품군만 보고 근거를 허용하지 않고, 가능한 경우 실제 `model_code`까지 일치하는 Evidence를 우선 사용한다.

# 3. 확장 Multi-Agent 구성

기존 Multi-Agent를 여러 Agent가 독립 실행되는 형태가 아니라, **공유 Context와 명시적인 Handoff를 통해 하나의 고객 문제를 함께 해결하는 협업형 구조**로 확장한다.

```text
사용자 문의
    ↓
Orchestrator
    ↓
Product Context 확인
    ↓
Safety Agent
    ↓
Evidence Agent
    ↓
Guidance Agent
    ↓
Harness Verifier
 ┌──────┼───────────────┐
PASS   RETRY          ESCALATE
 │       │               │
고객   재검색/재생성      ↓
 │                 Consultation
 │                 Handoff Agent
 │                       ↓
 │                 상담사용 인계정보
 │                       ↓
 │                  Backend 저장
 │                       ↓
 │                   상담사 Web
 │                       ↓
 └────────────────── Human Care
```

## Agent 역할

### Orchestrator

- 문의의 현재 Context와 제품 모델을 확인하고 필요한 Agent 실행 순서를 결정한다.
- 모든 요청에서 모든 Agent를 강제로 실행하지 않고 필요한 경로만 선택한다.

### Safety Agent

- 위험도와 금지 안내 여부를 판단한다.
- A2A PoC 대상 Agent로 사용한다.
- 제품별 기능 차이가 Safety 판단에 영향을 주는 경우 Product Context를 함께 사용한다.

### Evidence Agent

- 제품·증상·문진 Context를 바탕으로 공식 근거를 검색한다.
- MCP Tool과 Hybrid Search를 사용한다.
- 현재 고객 제품과 다른 모델의 Evidence가 최종 Guidance로 전달되지 않도록 필터링한다.

### Guidance Agent

- Safety 결과와 공식 Evidence를 기반으로 고객용 안내를 생성한다.
- Evidence에 없는 사실을 새로 생성하지 않도록 제한한다.
- 다른 모델의 조작법이나 기능을 현재 모델 안내에 섞지 않는다.

### Consultation Handoff Agent

- 자가해결 실패 또는 Harness `ESCALATE` 시 실행한다.
- 앞선 Agent들이 수집한 정보를 상담사가 바로 이해할 수 있는 인계 정보로 변환한다.
- 새로운 진단을 추가하지 않고 기존 AI 처리 이력을 상담에 적합한 형태로 구조화한다.

Handoff 기본 출력 항목:

```text
고객 증상 요약
제품 모델 / 제품군
구독 및 기본 Context
고객이 응답한 문진
수행 또는 제안된 자가조치
사용된 공식 Evidence
Safety 결과 / 주의사항
상담 전환 사유
상담사가 우선 확인할 항목
```

# 4. 이번 주 역할 조정

기존 역할을 유지하되, AI 영역은 이동윤 1인 중심에서 **윤승혁·양정현·이동윤 3인 분담 체제**로 확장한다.

| 담당자 | 이번 주 핵심 역할 |
|---|---|
| 윤승혁 | PM + Agent Reliability / Harness / HITL / Consultation Handoff Agent |
| 양정현 | Mobile + MCP / A2A / Product Context 소비 |
| 한예나 | Web + HITL UI + Consultation Handoff UI + Playwright |
| 최지용 | Backend / State Machine / Product Context API / Handoff 저장 / Backend Container |
| 이동윤 | Multi-Agent Core / 3제품 RAG / Hybrid Search / Automated Evals |
| 김은진 | QA / 3제품 Data 검증 / Observability / CI/CD / AWS |

AI 영역은 가능하면 다음과 같이 파일 소유권을 분리한다.

```text
ai/app/orchestration/agents/**       이동윤
ai/app/retrieval/**                  이동윤
ai/app/generation/**                 이동윤
ai/evaluation/**                     이동윤

ai/app/orchestration/harness/**      윤승혁
ai/app/orchestration/hitl/**         윤승혁
ai/app/orchestration/handoff/**      윤승혁

ai/app/integrations/mcp/**           양정현
ai/app/integrations/a2a/**           양정현
```

공통 Pipeline, Shared State, Product Schema를 수정해야 할 경우 사전 공유 후 작업한다.

```text
고객 제품 식별

→ Agent 협업
```
