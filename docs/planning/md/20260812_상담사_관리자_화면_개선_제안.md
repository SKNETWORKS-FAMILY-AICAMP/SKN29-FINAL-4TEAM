## 1. 핵심 결론

현재 필요한 것은 화면 수를 늘리는 것이 아니라, 한 문의가 아래 흐름으로 끊기지 않게 만드는 것이다.

> 문의 접수 → 안전 판단 → 상담 → 방문 기사 인계 → 처리 결과 확인

- 상담사 화면은 **문의 분류 목록**에서 **한 문의를 빠르게 끝내는 업무 처리 화면**으로 바꾼다.
- 관리자 화면은 **통계 조회 화면**에서 **문제가 있는 문의에 즉시 개입하는 예외 관리 화면**으로 바꾼다.
- 고객에게는 항상 **지금 해야 할 행동, 현재 담당자, 다음 연락 시점**이 명확하게 전달되어야 한다.

## 2. 현재 화면에서 유지할 부분

다음 기능은 현재 방향이 적절하므로 유지하고 개선한다.

- 고객·구독 정보 자동 연결
- 개인정보 마스킹
- 등록 실패 시 입력값 보존
- 문의 상태별 실행 가능 행동 관리
- 중복 등록 방지와 Correlation ID 추적
- 신규·처리 중·완료 문의의 업무 구분
- 전화 문의 등록 후 상담 기록으로 이어지는 흐름

## 3. 상담사 화면 개선안

### 3.1 현재 문제

#### 목록만 보고 처리 순서를 판단하기 어렵다

현재 문의 목록은 증상 요약과 고객명 중심이다. 상담사가 실제로 처리 순서를 정하는 데 필요한 아래 정보가 부족하다.

- 안전 위험도
- 처리 우선순위
- 현재 상태
- 대기시간과 SLA
- 담당자 또는 미배정 여부
- 제품 모델과 최근 관리 이력
- 누락된 문진·인계 정보
- 지금 수행해야 할 다음 행동

이 때문에 상담사가 문의마다 상세 화면을 열어 확인해야 하며, 장기 대기·재문의·고위험 문의를 놓칠 가능성이 있다.

#### 안전 위험도와 처리 우선순위가 혼동된다

현재 전화 문의 등록의 `긴급도`는 실제로 처리 우선순위인 `priority`를 의미한다. 안전 위험도 `risk_level`과 별개의 값이므로 높은 우선순위로 등록해도 일반 위험 탭에 표시될 수 있다.

다음 세 개념을 화면과 데이터에서 분리해야 한다.

| 구분 | 의미 | 예시 |
|---|---|---|
| 안전 위험도 | 고객이 제품을 계속 사용해도 되는지 | 위험 / 주의 / 일반 / 미평가 |
| 처리 우선순위 | 업무상 얼마나 빨리 처리해야 하는지 | 긴급 / 높음 / 보통 / 낮음 |
| 처리 상태 | 현재 문의가 어느 단계인지 | 신규 / 상담 중 / 방문 예정 / 완료 |

`긴급도` 필드명은 `처리 우선순위`로 변경하고, 안전 위험도는 별도 문진으로 평가한다. 위험 평가가 끝나지 않은 문의를 자동으로 `일반` 처리하지 않고 `미평가`로 표시한다.

#### Mock 화면과 실제 API 화면이 다르다

Mock 환경과 실제 API 환경이 서로 다른 상세 컴포넌트와 업무 흐름을 사용한다. Mock에서 확인한 디자인과 사용성이 실제 API 연결 화면에 그대로 이어지지 않는다.

화면 컴포넌트와 ViewModel은 하나로 통합하고, 데이터 출처만 Mock 또는 API로 교체해야 한다.

#### 상세 화면에서 지금 해야 할 행동이 명확하지 않다

현재 실API 상세 화면은 기술 코드와 여러 섹션이 길게 표시되며, 상담 입력란 여러 개가 한꺼번에 노출된다. 기존 기록이 있어도 빈 입력란부터 보일 수 있어 재작성 부담이 생긴다.

상담사가 다음 행동을 찾는 구조가 아니라, 시스템이 현재 단계에 맞는 다음 행동을 한 개씩 제시해야 한다.

### 3.2 목록 화면 권장 구조

문의 행에서 아래 정도의 정보를 한 번에 확인할 수 있어야 한다.

```text
[사용 중지] [안전 미평가] [우선 HIGH] [전화]
정수기 하단에 물이 고여 있습니다
최민준 · WPU-A100 · 최근 케어 05/27
대기 18분 · 미배정 · 다음: 안전 문진 · 사진 누락
```

기본 정렬 우선순위는 다음과 같이 권장한다.

1. 사용 중지 또는 안전 위험 문의
2. SLA 초과·임박 및 장기 대기 문의
3. 재문의·재오픈 문의
4. 문진 또는 기사 인계 정보가 누락된 문의
5. 일반 문의

빠른 필터도 함께 제공한다.

- 내 문의
- 미배정
- 긴급 처리
- 오래 기다린 순
- 재문의
- 인계 정보 누락

기존 긴급·주의·일반 탭은 안전 위험도를 확인하는 보조 필터로 유지할 수 있다. 단, 이것만으로 전체 업무 우선순위를 표현하면 안 된다.

### 3.3 상세 화면 권장 구조

#### 상단 고정 요약

- 현재 사용 가능 여부
- 안전 위험도와 처리 우선순위
- 현재 담당자
- 다음 행동
- 처리 기한 또는 SLA

#### 왼쪽: 판단에 필요한 정보

- 고객의 문의 원문과 첨부 사진
- 제품·구독 정보와 최근 관리 이력
- 고객이 이미 시도한 조치
- 단계별 안전 문진 결과
- 공식 매뉴얼과 답변 근거
- 접수부터 현재까지의 처리 타임라인

#### 오른쪽: 실제 작업 영역

- 수정 가능한 AI 상담 요약 초안
- 누락 정보 체크리스트
- 고객에게 안내할 문구
- 현재 단계에서 가능한 주요 실행 버튼 한 개
- 방문 기사 인계 내용 미리보기

주요 버튼은 상태에 따라 단순하게 제공한다.

| 상태 | 주요 버튼 |
|---|---|
| 신규 | 상담 시작 |
| 상담 중 | 안내 저장 |
| 방문 필요 | 기사 인계 요청 |
| 처리 완료 | 해결 결과 확정 |

### 3.4 상담 기록 입력 부담 개선

다섯 개 이상의 빈 입력란을 한 번에 작성하게 하지 않는다.

- 고객 원문과 문진 결과로 상담 기록 초안을 생성한다.
- 기존 저장값이 있으면 다시 불러와 입력란에 채운다.
- 입력을 단계별로 노출하고 통화 중 임시 저장을 지원한다.
- AI 요약은 상담사가 수정·확정할 수 있게 한다.
- 고객 원문은 수정할 수 없는 기록으로 유지한다.
- AI 초안 수정 이력과 최종 확정자는 감사 로그에 남긴다.

### 3.5 전화 문의 등록 개선

- `긴급도`를 `처리 우선순위`로 변경
- 안전 위험도 평가를 위한 짧은 문진 추가
- 동일 고객의 열린 문의와 최근 고장·방문 이력 경고
- 제품 모델과 최근 관리 이력 자동 표시
- 위험 증상일 때 사용 중지 안내 문구 제안
- 통화 중 임시 저장
- 기본 완료 버튼을 `등록하고 상담 시작`으로 제공
- `등록만`은 보조 버튼으로 제공

### 3.6 기사 인계와 처리 완료

기사 인계 전 다음 항목의 누락 여부를 검사한다.

- 제품 모델
- 증상과 발생 조건
- 안전 위험도
- 고객이 시도한 조치
- 사진 또는 첨부 자료
- 상담사가 제공한 안내
- 방문 시 우선 확인 항목

방문 이후에는 기사 처리 결과를 상담 문의로 회수해 해결 여부와 재방문 필요 여부를 확인한다. 상담에서 방문으로 넘기는 것만으로 문의를 완료 처리하지 않는다.

## 4. 관리자 화면 개선안

### 4.1 현재 문제

#### 실제 운영 데이터와 연결되지 않았다

현재 관리자 화면은 Mock 데이터를 기준으로 동작한다. 실제 API 환경에서는 운영자가 전체 문의 현황을 관리할 수 있는 데이터 연결이 준비되어야 한다.

관리자 화면 개선의 첫 단계는 시각 디자인이 아니라 실제 문의·상태·담당자·SLA·이력 API 연결이다.

#### 통계는 볼 수 있지만 조치할 수 없다

현재 예외 문의를 발견해도 다음 행동으로 이어지기 어렵다.

- 문의 상세 확인
- 담당자 배정·재배정
- 긴급 에스컬레이션
- 기록 보완 요청
- 위험도 수동 정정
- 기사 인계 반려
- 전체 처리 타임라인 확인

관리자 화면은 조회용 보고서가 아니라 위 조치를 실행할 수 있는 운영 콘솔이 되어야 한다.

#### KPI가 단순 건수 중심이다

총 문의, 위험 문의, 상담 전환, 방문 전환 등의 개수만으로는 실제 업무 개선 여부를 판단하기 어렵다. 기준값, 목표, 시간 추이, 분모가 포함된 지표가 필요하다.

### 4.2 관리자 첫 화면 권장 구조

관리자 첫 화면은 통계 카드보다 아래 예외 큐를 우선 표시한다.

- 고위험인데 상담이 시작되지 않은 문의
- SLA가 초과되었거나 임박한 문의
- 장시간 미배정 문의
- 재문의·재오픈 문의
- 기사 인계 정보가 부족한 문의
- 공식 근거가 없는 AI 안내
- 제품 모델과 매뉴얼 버전이 맞지 않는 문의
- 고객에게 다음 일정이 전달되지 않은 문의

각 예외 행에는 다음 정보를 표시한다.

- 예외 발생 사유
- 발생 시각과 처리 기한
- 현재 담당자
- 고객·제품·문의 요약
- 현재 상태와 다음 행동
- 재발 여부
- 조치 상태

행을 클릭하면 상세 화면으로 이동하고 담당자 배정, 에스컬레이션, 보완 요청 등을 바로 실행할 수 있어야 한다.

### 4.3 권장 KPI

#### 안전 KPI

- 고위험 미처리 건수
- 안전 문진 완료율
- 위험 문의 상담 연결 시간
- 근거 없는 안내 발생률
- 위험도 오분류·수동 정정률

#### 상담 품질 KPI

- 고객 재설명률
- 재문의·재오픈률
- AI 초안 수정률
- 다음 행동 안내 완료율
- 고객 해결 확인률

#### 운영 효율 KPI

- 상담 준비·정보 검색 시간
- 위험도별 평균 처리시간
- 미배정률과 SLA 초과율
- 상담사별 처리량과 현재 업무량
- 기사 인계 완성도

#### 현장 결과 KPI

- 최초 방문 해결률
- 정보 부족으로 인한 재방문률
- 제품 모델·증상별 반복 고장률
- 상담 안내와 기사 진단의 불일치율

일부 페인포인트는 아직 가설 단계이므로 개선 효과를 단정하지 않는다. 먼저 로그와 사용자 인터뷰를 통해 기준값을 확보한 뒤 개선 전후를 비교한다.

### 4.4 관리자 운영 기능

- 담당자 배정·재배정
- 상담사별 업무량 확인
- SLA 규칙과 알림 관리
- 안전 문진 및 금지 안내 규칙 관리
- 제품별 공식 문서와 버전 관리
- AI 답변 근거와 상담사 수정 이력 확인
- 상태 변경·확정·에스컬레이션 감사 로그
- 역할 기반 접근 권한 관리

## 5. 제거하거나 축소할 항목

- 대시보드와 내용이 중복되는 별도 인포그래픽 화면은 통합하거나 추세 분석 화면으로 전환
- 큰 장식 이미지·버블·오브젝트는 업무 정보보다 앞서지 않도록 축소
- `P1 MOCK`, `REMOTE`, `stateVersion` 같은 개발·백엔드 표시는 운영 화면에서 제거
- API 연결 상태와 개발용 점검 정보는 별도 개발자 패널 또는 설정으로 이동
- 여러 개의 빈 상담 입력창을 한 번에 보여주는 구조 제거
- 같은 정보를 카드와 탭에서 반복 표시하는 구성 축소
- 근거가 확인되지 않은 AI 자동 확정 기능 제외
- 일반적인 챗봇·FAQ·채널 추가는 핵심 상담 흐름 완성 이후로 연기
- 계약·결제·해지 기능은 현재 MVP 범위에 무리하게 포함하지 않음

## 6. 개발 우선순위

### P0: 실제 업무 흐름 완성

1. Mock과 실제 API 화면을 동일 컴포넌트·ViewModel로 통합
2. 안전 위험도, 처리 우선순위, 처리 상태 분리
3. 목록에 대기시간·담당자·상태·제품·다음 행동·누락 정보 표시
4. 상세 화면을 하나의 상담 작업대로 재구성
5. 기존 상담값 불러오기와 단계별 입력 적용
6. 관리자 실제 문의 API 연결
7. 관리자 예외 목록의 상세·배정·에스컬레이션 구현
8. 기사 인계 필수정보 검사와 방문 결과 회수

### P1: 업무 시간 단축과 품질 관리

1. 상담 기록 자동 초안과 임시 저장
2. 열린 문의·최근 방문 이력 경고
3. 안전 문진과 공식 안내 문구 추천
4. 관리자 안전·품질·SLA KPI와 시간 추이
5. 매뉴얼·안전 규칙 버전 관리
6. 수정·확정·에스컬레이션 감사 로그
7. 상담사 업무량 확인과 재배정

### P2: 분석과 편의성 고도화

1. 개인별 저장 필터와 업무 뷰
2. 업무량 기반 배정 지원
3. 반복 VOC와 제품 모델별 원인 분석
4. 만족도와 최초 해결률 분석
5. 시각 디자인과 애니메이션 정리

## 7. 개선 효과 검증 방법

기능 수나 화면 수가 아니라 아래 지표로 개선 효과를 확인한다.

| 대상 | 확인 지표 |
|---|---|
| 상담사 | 문의 준비·검색 시간, 고객 재설명률, 위험도별 처리시간, 인계 완성도 |
| 관리자 | 고위험 미처리 시간, 미배정률, SLA 초과율, 예외 조치 완료시간 |
| 방문 기사 | 정보 재확인 시간, 정보 부족 재방문률, 최초 방문 해결률 |
| 고객 | 다음 행동 이해도, 상태 확인 재문의율, 해결 확인률, 만족도 |

검증 시에는 위험 문의를 무조건 빠르게 종료하는 방식으로 평균 처리시간을 줄이지 않는다. 안전성과 상담 품질을 먼저 확인하고, 동일 위험군 안에서 처리시간 변화를 비교한다.

## 8. 최종 방향

상담사는 여러 화면을 오가지 않고 한 화면에서 다음 네 가지를 처리할 수 있어야 한다.

1. 지금 확인할 것
2. 고객에게 말할 것
3. 기록할 것
4. 다음 담당자에게 넘길 것

관리자는 통계를 보는 데서 끝나지 않고 문제가 있는 문의를 발견해 담당자 배정, 보완 요청, 에스컬레이션까지 즉시 수행할 수 있어야 한다.

이 구조가 완성되면 고객은 반복 설명을 줄이고, 안전한 다음 행동과 처리 진행 상황을 더 명확하게 안내받을 수 있다.
