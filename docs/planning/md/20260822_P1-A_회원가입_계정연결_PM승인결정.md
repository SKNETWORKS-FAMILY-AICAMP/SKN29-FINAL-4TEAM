# WaterBridge P1-A 회원가입·계정연결 PM 승인결정

> 결정 일자: 2026-08-22 KST
> 결정 책임: 윤승혁 (PM·기술 통합)
> 결정 상태: `APPROVED`
> 적용 범위: 합성 계약고객 기반 P1-A 최소 수직 기능

## 1. 결정 요약

```text
P1-A = APPROVED
P1-B = HOLD
REAL_CUSTOMER_RUNTIME = NO-GO
P0_E2E_PRIORITY = HIGHER_THAN_P1-A
```

이 결정은 P1-A의 설계·Fixture·계약 작업 착수를 승인한다. 현재 P0 완료 판정을 P1-A로 대체하거나, 아직 구현하지 않은 기능을 완료로 판정하는 승인이 아니다.

## 2. 승인 범위

P1-A는 다음 하나의 합성 계약고객 수직 흐름으로 고정한다.

```text
합성 계약고객
→ 계약정보 확인
→ 계약 이메일 OTP
→ WaterBridge ID/PW 생성
→ CustomerAccountLink
→ JWT
→ 일반 로그인
→ 아이디 찾기
→ 비밀번호 재설정
→ 마이페이지
→ 기존 문의/AI 기능 진입
```

최소 산출 범위는 다음과 같다.

- 합성 계약고객·활성 계약·활성 구독 Fixture
- 계약 이메일 확인과 OTP Challenge
- 단회성 `claim_ticket`을 이용한 회원가입
- `User`와 계약고객을 연결하는 `CustomerAccountLink`
- 일반 ID/PW 로그인과 JWT 발급
- 계약 이메일 OTP 기반 아이디 찾기와 비밀번호 재설정
- 로그인 고객의 안전한 마이페이지 Projection
- 기존 구독·문의·AI 기능에 대한 Owner 연결 유지
- 실패·Replay·동시성·Rate Limit·비밀값 비노출 검증

## 3. 제외 및 보류 범위

| 항목 | 결정 | 해제 조건 |
|---|---|---|
| 카카오 로그인 | `P1-B HOLD` | P1-A와 P0 Gate 완료 후 별도 PM 승인 |
| 실제 고객 계약 원장 | `NO-GO` | 데이터 제공·법무·보안·운영 승인과 별도 설계 |
| 실제 고객 개인정보 | `NO-GO` | 개인정보 처리 근거와 별도 보안 Gate 승인 |
| 이메일 변경 자동화 | 제외 | 별도 요구사항 및 재인증 정책 승인 |
| 공용·중복 이메일 자동 연결 | 제외 | 명의·소유권 충돌 정책 승인 |
| 명의·계약 변경 | 제외 | 실제 계약 원장 연동 범위 승인 |
| 소셜 로그인·실명/본인 인증 | 제외 | P1-B 또는 별도 후속 범위 승인 |

P1-A에서 사용하는 계약고객·계약·구독·이메일은 모두 합성 데이터여야 한다. 계약 이메일은 `.invalid` 도메인을 사용하고, 실제 발송 검증이 필요할 때만 승인된 시험 Inbox로 Runtime Redirect한다.

## 4. P0 우선 원칙

다음 상황에서는 P1-A보다 P0를 우선한다.

- 동일 Inquiry 기반 고객 Mobile→Backend→AI→상담사 Web→고객 재조회 E2E가 차단된 경우
- P0 회귀 실패, 배포 차단 결함 또는 데이터 무결성 결함이 발생한 경우
- 동일 담당자·환경·DB를 P0와 P1-A가 동시에 필요로 하는 경우
- P1-A 변경이 기존 인증·Owner·문의·AI 흐름을 깨뜨린 경우

충돌 시 P1-A를 일시 중단하고 P0를 복구한다. P1-A 일정 유지를 이유로 P0 Gate를 완화하거나 Skip을 PASS로 판정하지 않는다.

## 5. 역할과 단계별 Gate

| Gate | 작업 | 책임 | 상태 | 완료 조건 |
|---|---|---|---|---|
| G0 | P1-A 범위 승인 | 윤승혁 | `PASS` | 본 문서와 요구사항·WBS 범위 정합성 확보 |
| G1 | 합성 Fixture | 김은진, 최지용 | `READY` | 실개인정보 0건, `.invalid` 이메일, 활성 계약·구독, 기존 Link 없음 |
| G2 | API 계약 동결 | 최지용, 양정현 검토, 윤승혁 승인 | `NOT_STARTED` | Endpoint·Schema·오류·OTP/claim 규칙 동결 |
| G3 | Additive DB·Migration | 최지용 | `NOT_STARTED` | 신규 모델, Backfill 누락·중복 0건 |
| G4 | Signup·OTP·Login·Recovery | 최지용 | `NOT_STARTED` | Backend 정상·실패·보안 흐름 검증 |
| G5 | Owner Resolver 전환 | 최지용 | `NOT_STARTED` | Account Link 기반 소유권과 타 고객 차단 |
| G6 | Email Runtime | 최지용, 김은진 | `NOT_STARTED` | 시험 Inbox Redirect와 Secret 비노출 |
| G7 | Android | 양정현 | `NOT_STARTED` | 가입·로그인·복구·마이페이지 실기기 Flow |
| G8 | AI·Web 회귀 | 이동윤, 한예나 | `NOT_STARTED` | 인증 데이터 AI 비유입, 상담사 Web 무회귀 |
| G9 | 독립 QA | 김은진 | `NOT_STARTED` | OTP·Replay·동시성·로그 비노출 Gate |
| G10 | 최종 수직 E2E | 윤승혁, 전원; 김은진 독립 판정 | `NOT_STARTED` | 합성 가입부터 기존 문의·AI까지 동일 계정 완주 |

각 Gate는 선행 Gate의 실제 증거 없이 PASS로 승격하지 않는다.

## 6. 보안·데이터 불변조건

- OTP 평문, 비밀번호, JWT, 전체 이메일, Google/AWS Secret을 DB 감사 로그·앱 로그·문서·Git에 기록하지 않는다.
- OTP 성공 전 CUSTOMER JWT를 발급하지 않는다.
- `claim_ticket`은 단회성·단기 만료·목적 고정·계약 후보 고정이어야 한다.
- 회원가입은 `User`, `CustomerAccountLink`, 동의, 감사 이벤트를 하나의 Transaction 경계에서 처리하고 마지막에 JWT를 발급한다.
- 이미 연결된 계약, 중복 이메일 또는 경합 중인 Link를 자동 병합하지 않는다.
- 비밀번호 재설정 성공 시 `auth_version`을 증가시키고 기존 인증 세션을 폐기한다.
- OTP·이메일·Password·JWT 데이터는 AI Prompt, RAG Context, Inquiry Context에 포함하지 않는다.

## 7. G0 완료 판정

| 확인 항목 | 판정 |
|---|---|
| P1-A 최소 수직 범위 고정 | `PASS` |
| P1-B 분리 | `PASS` |
| 실고객 Runtime 차단 | `PASS` |
| P0 우선 원칙 명시 | `PASS` |
| 담당자·Gate 지정 | `PASS` |
| 요구사항·WBS 연결 | `PASS` |

따라서 `G0 P1-A 범위 승인 = PASS`로 판정하고 다음 착수자를 김은진·최지용으로 지정한다.

## 8. 전 팀원 인계

### 확정 범위

합성 계약고객의 계약 이메일 OTP부터 계정 생성·로그인·복구·마이페이지·기존 문의/AI 진입까지의 P1-A 최소 수직 기능이다.

### 제외 범위

P1-B 카카오 로그인, 실고객 계약 원장·개인정보, 이메일·명의·계약 변경과 중복 이메일 자동 연결은 포함하지 않는다.

### 다음 작업

김은진·최지용은 G1 합성 Fixture를 준비한다. Fixture가 승인되기 전에는 API·DB·Android 구현을 완료로 표시하지 않는다.

### 공통 인계 형식

모든 인계에는 Commit SHA, 변경 파일, 구현 내용, 실행·테스트 명령, 실제 결과와 제한사항을 포함한다. Secret, OTP 원문, 실제 이메일과 JWT 값은 포함하지 않는다.
