# 추가 의견 기반 상담 업무 개선 제안

- 작성일: 2026-08-12
- 대상: 고객용 앱, 상담사 메인화면, AI 요약 검수 기능
- 목적: 단순 문의는 고객이 스스로 해결하고, 상담사는 지금 개입해야 할 고객과 업무에 집중할 수 있도록 전체 흐름을 개선한다.
- 연계 문서: [상담사·관리자 화면 개선 제안](./20260812_상담사_관리자_화면_개선_제안.md)

## 1. 추가 의견

1. 상담사의 업무를 줄이기 위해 고객용 앱에 챗봇이 필요하다.
2. 상담사 한 명의 관점에서 지금 처리할 업무와 전화 연결이 필요한 고객을 한눈에 확인할 수 있는 메인화면이 필요하다.
3. AI가 상담 내용을 제대로 요약했는지 확인할 수 있는 기능을 메인화면에 제공한다.

## 2. 핵심 제안

세 의견은 각각 독립된 기능이 아니라 다음 하나의 업무 흐름으로 연결해야 한다.

> 고객 챗봇 접수·자가 해결 시도 → 해결 실패 또는 위험 감지 → 상담사 개인 업무 큐 배정 → 전화 상담 → AI 요약 검수 → 상담·방문 인계

핵심 방향은 다음과 같다.

- 챗봇은 상담사를 대신하는 범용 상담원이 아니라 **단순 문의 해결, 안전 분류, 상담 전 정보 수집** 역할을 맡는다.
- 상담사 메인화면은 전체 문의 통계보다 **내가 지금 해야 할 업무**를 우선 표시한다.
- AI 요약은 자동 확정하지 않고, **원문과 비교하여 승인·수정할 수 있는 검수 대상**으로 다룬다.
- 고위험 문의, 장기 대기, 전화 요청 고객은 챗봇 자가 해결률보다 우선한다.

## 3. 제안 1: 고객용 앱 챗봇

### 3.1 도입 목적

챗봇의 목적은 단순히 문의 채널을 하나 더 만드는 것이 아니다.

- 반복되는 단순 문의를 공식 안내로 해결
- 문의 접수 전에 고객·제품·증상 정보 수집
- 안전 위험 증상을 조기에 감지
- 상담이 필요할 때 고객이 같은 내용을 다시 설명하지 않도록 상담사에게 대화 맥락 전달
- 고객에게 현재 처리 상태와 다음 행동 안내

### 3.2 챗봇 권장 흐름

1. 로그인 고객과 구독 제품 자동 확인
2. 문의 유형 또는 증상 선택
3. 짧은 단계형 안전 문진 진행
4. 필요한 경우 사진·영상 첨부 요청
5. 공식 매뉴얼에 근거한 간단한 조치 안내
6. 고객에게 해결 여부 확인
7. 미해결·고위험·전화 요청이면 상담사에게 연결
8. 상담 연결 시 챗봇 대화, 문진 결과, 첨부파일, 시도한 조치를 함께 전달

### 3.3 즉시 상담사 연결 조건

다음 조건에서는 챗봇 대화를 길게 이어가지 않고 상담사 연결 또는 콜백 접수로 전환한다.

- 누전, 화재, 연기, 타는 냄새 등 안전 위험 신호
- 심한 누수 또는 제품 사용 중지 필요
- 고객이 명시적으로 상담사 연결을 요청
- 같은 증상으로 반복 문의
- 챗봇 안내 후에도 해결되지 않음
- 챗봇이 제품·증상·공식 근거를 확실하게 판단하지 못함
- 고객이 안내를 이해하지 못했거나 불만·불안이 높은 상태

고위험 문의에는 우선 안전 행동을 안내한 뒤 예상 연락 시간과 담당 상태를 표시한다.

### 3.4 상담사에게 전달할 챗봇 인계 정보

- 고객과 구독 제품
- 고객 문의 원문
- 챗봇이 파악한 증상 요약
- 안전 문진 질문과 고객 답변
- 위험 신호와 상담 연결 사유
- 고객이 이미 시도한 조치
- 제공한 공식 안내와 근거 문서
- 첨부 사진·영상
- 고객이 요청한 연락 방식과 가능 시간
- 해결 여부와 미해결 사유

상담사는 이 정보를 확인한 뒤 통화를 시작하며, 고객에게 동일 질문을 처음부터 반복하지 않는다.

### 3.5 챗봇에서 피해야 할 방식

- 모든 문의를 긴 자유 대화로 처리
- 근거가 불충분한 고장 원인이나 수리 방법 단정
- 고위험 문의의 상담 연결 지연
- 고객 확인 없이 `자가 해결 완료` 처리
- 챗봇 대화를 상담사 화면에 전달하지 않고 새 문의만 생성
- 자가 해결률을 높이기 위해 상담 연결 버튼을 숨김

### 3.6 자가 해결 완료 기준

챗봇이 답변을 제공했다는 이유만으로 해결로 집계하지 않는다. 다음 조건을 모두 만족해야 한다.

- 고객이 `해결됨`을 직접 선택
- 안전상 추가 조치가 필요하지 않음
- 같은 고객·제품·증상으로 일정 기간 내 재문의가 없음

초기 검증 기간은 7일을 권장하며, 제품과 증상 유형에 따라 조정한다.

## 4. 제안 2: 상담사 개인 업무 메인화면

### 4.1 화면의 목적

메인화면을 열었을 때 상담사는 다음 질문에 바로 답을 얻어야 한다.

1. 지금 가장 먼저 처리할 문의는 무엇인가?
2. 지금 전화해야 하는 고객은 누구인가?
3. 왜 전화 연결이 필요한가?
4. 언제까지 처리해야 하는가?
5. 통화 전에 무엇을 확인해야 하는가?

전체 운영 통계나 장식 요소보다 개인의 다음 행동을 먼저 보여준다.

### 4.2 권장 화면 구성

```text
┌ 오늘의 업무 요약 ──────────────────────────────────────────┐
│ 즉시 전화 2 │ 10분 내 처리 3 │ SLA 임박 1 │ AI 검수 4       │
└────────────────────────────────────────────────────────────┘

┌ 지금 처리할 업무 ─────────────────────┐ ┌ AI 요약 검수 필요 ─────┐
│ 1. [사용 중지][즉시 전화] 심한 누수    │ │ [중요 누락] 고객 원문 ↔ 요약 │
│    김00 · 대기 8분 · 챗봇 미해결        │ │ 승인 / 수정 / 반려           │
│    다음 행동: 고객에게 전화             │ │                            │
│                                         │ │ [낮은 신뢰도] ...            │
│ 2. [SLA 임박][콜백 예약] 냉수 미출수    │ │ 승인 / 수정 / 반려           │
│    이00 · 14:30까지                     │ └────────────────────────────┘
└─────────────────────────────────────────┘
```

### 4.3 상단 업무 요약

상단에는 개인이 실제 행동해야 하는 항목만 표시한다.

- 즉시 전화가 필요한 고객
- 예약된 콜백
- SLA 초과·임박 문의
- 새로 배정된 문의
- 고객 답변을 기다리는 문의
- AI 요약 검수 필요 건
- 기사 인계 보완 또는 결과 확인 건

각 숫자는 클릭 시 해당 조건으로 필터된 업무 목록을 보여준다.

### 4.4 개인 업무 큐 표시 정보

각 업무 행에는 다음 정보를 표시한다.

- 안전 위험도
- 처리 우선순위
- 전화 필요 여부와 사유
- 고객·제품·증상 요약
- 현재 상태
- 대기시간 또는 처리 기한
- 챗봇 해결 실패 사유
- 누락 정보
- 지금 수행할 다음 행동

예시는 다음과 같다.

```text
[사용 중지] [즉시 전화] [챗봇 미해결]
정수기 하단에 물이 계속 고입니다
김00 · WPU-A100 · 대기 8분
전화 사유: 심한 누수 + 고객 연결 요청
다음 행동: 고객에게 전화
```

### 4.5 전화 연결 필요 기준

`전화 필요` 여부는 단순 우선순위와 별도로 관리한다.

- 안전 위험으로 즉시 안내가 필요함
- 고객이 전화 상담을 요청함
- 챗봇으로 해결되지 않음
- 동일 증상 반복 문의
- 안내 이해 여부 또는 고객 상태 확인이 필요함
- 방문 접수 전 추가 확인이 필요함
- 약속한 콜백 시간이 도래함

화면에는 `전화 필요`만 표시하지 않고 반드시 이유와 기한을 함께 보여준다.

### 4.6 개인 업무 큐 기본 정렬

1. 안전 위험 및 즉시 전화
2. 약속한 콜백 시간 초과·임박
3. SLA 초과·임박
4. 반복 문의와 재오픈
5. 챗봇 미해결 및 낮은 확신도
6. 기사 인계 정보 누락
7. 일반 신규 문의

상담사는 자동 정렬을 기본으로 사용하되, `내 문의`, `미배정 가져오기`, `전화 필요`, `AI 검수` 빠른 필터를 사용할 수 있어야 한다.

## 5. 제안 3: 메인화면 AI 요약 검수

### 5.1 검수 목적

AI 요약 기능은 상담 기록 시간을 줄일 수 있지만, 증상·위험 신호·고객 요청이 빠지거나 사실과 다르게 정리되면 다음 상담과 기사 방문에 오류가 전달될 수 있다.

따라서 메인화면에서 다음을 빠르게 비교할 수 있어야 한다.

- 고객 원문 또는 통화 기록
- AI 요약 결과
- AI가 참고한 문장
- 누락 또는 충돌 가능성이 있는 정보
- 요약 신뢰도와 검수 필요 사유

### 5.2 모든 요약을 동일하게 검수하지 않는다

메인화면에는 전체 AI 요약이 아니라 우선 검수가 필요한 건을 표시한다.

- 고위험 문의 요약
- 신뢰도가 낮은 요약
- 제품·증상 정보가 서로 맞지 않는 요약
- 고객 원문의 위험 표현이 요약에서 누락된 경우
- 고객 요청과 다음 행동이 일치하지 않는 경우
- 상담과 방문 기사 인계 직전 요약
- 무작위 품질 표본

이렇게 해야 AI 검수가 새로운 반복 업무가 되는 것을 막을 수 있다.

### 5.3 권장 검수 UI

검수 카드는 원문과 AI 요약을 나란히 비교하는 구조로 제공한다.

| 고객 원문·기록 | AI 요약 |
|---|---|
| 위험 표현과 주요 문장을 강조 | 증상, 위험도, 고객 요청, 시도한 조치, 다음 행동을 구분 |
| 누락 후보 표시 | 근거 문장과 연결 |

검수 버튼은 다음과 같이 단순화한다.

- `승인`: 내용이 정확함
- `수정 후 승인`: 일부 내용을 고쳐 확정
- `반려`: 재요약 또는 직접 작성 필요

수정된 부분은 AI 품질 개선과 감사 목적으로 기록한다.

### 5.4 요약 상태 관리

| 상태 | 의미 |
|---|---|
| 검수 대기 | AI가 생성했지만 상담사가 확인하지 않음 |
| 승인 | 상담사가 원문과 비교해 정확성을 확인 |
| 수정 승인 | 상담사가 내용을 수정한 뒤 확정 |
| 반려 | 요약을 사용할 수 없어 재작성 필요 |

검수되지 않은 요약에는 `AI 초안` 표시를 유지하며, 고객 안내나 기사 인계의 최종 기록으로 자동 사용하지 않는다.

### 5.5 반드시 확인할 요약 항목

- 고객이 실제로 말한 핵심 증상
- 증상 발생 시점과 조건
- 안전 위험 신호
- 제품 사용 가능 여부
- 고객이 이미 시도한 조치
- 고객의 요청 사항
- 상담사가 안내한 내용
- 다음 담당자와 다음 행동
- 방문 필요 여부와 기사 확인 항목

## 6. 세 기능의 연결 데이터

챗봇, 상담사 업무 큐, AI 요약 검수가 연결되려면 최소한 다음 정보가 공통으로 관리되어야 한다.

- 챗봇 처리 상태: 진행 중 / 자가 해결 / 상담 연결 / 고객 이탈
- 상담 연결 사유
- 전화 필요 여부와 사유
- 콜백 예정 시각
- 현재 담당자
- 다음 행동과 처리 기한
- 고객이 시도한 조치
- 원문·문진·첨부자료 참조
- AI 요약 신뢰도와 위험 플래그
- AI 요약 검수 상태와 검수자
- 상담·방문 인계 상태
- 고객 해결 확인 결과

## 7. 추가·수정·제외 항목

### 추가

- 고객용 단계형 챗봇
- 안전 문진과 즉시 상담 연결 규칙
- 챗봇 대화 전체 인계
- 상담사 개인 업무 메인화면
- 전화 필요 고객 큐와 콜백 기한
- AI 요약 원문 비교 및 승인·수정·반려
- 상담사 수정 이력과 감사 로그

### 수정

- 상담사 메인화면을 전체 문의 목록 중심에서 `나의 다음 행동` 중심으로 변경
- 위험도, 처리 우선순위, 전화 필요 여부를 각각 분리
- AI 요약을 확정 기록이 아닌 검수 전 초안으로 표시
- 챗봇 해결 여부를 답변 제공이 아닌 고객 확인과 재문의 여부로 판단

### 제외 또는 후순위

- 근거 없는 자유대화형 고장 진단
- 고위험 문의의 완전 자동 처리
- 모든 AI 요약의 의무 수동 검수
- 상담 연결을 어렵게 만드는 복잡한 챗봇 단계
- 전체 통계와 장식 요소가 개인 업무보다 먼저 보이는 구성

## 8. 개발 우선순위

### P0: 업무 연결 기반

1. 전화 필요 여부·사유·기한 데이터 정의

3. 챗봇의 안전 문진과 상담사 연결 조건 정의
4. 챗봇 대화·문진·첨부자료의 상담사 인계
5. AI 요약 원문 비교와 승인·수정·반려
6. 검수되지 않은 AI 요약의 최종 인계 차단

### P1: 업무 시간 단축

1. 단순 문의용 공식 답변 챗봇

4. AI 누락·충돌 후보 자동 표시

6. 자가 해결 후 재문의 추적

### P2: 품질 개선

1. 상담사 수정 데이터를 이용한 AI 요약 품질 분석
2. 문의 유형별 챗봇 해결 가능 범위 조정

4. 고객 만족도와 최초 해결률 기반 최적화

## 9. 검증 지표

### 고객용 챗봇

- 고객 확인 및 재문의 조건을 반영한 실질 자가 해결률
- 챗봇 이용 후 동일 증상 재문의율
- 상담 연결 전 필수정보 수집 완료율
- 고위험 문의의 상담 연결 소요시간
- 챗봇 중도 이탈률

### 상담사 메인화면

- 로그인 후 첫 업무 시작까지 걸린 시간
- 콜백 약속 준수율
- 고위험·SLA 문의 누락 건수
- 문의 상세 탐색과 정보 검색 시간
- 상담사 1인당 완료 문의 수

### AI 요약 검수

- AI 요약 승인·수정 승인·반려 비율
- 요약 한 건당 평균 검수 시간
- 안전 정보 누락률
- 상담사 수정이 반복되는 항목
- 검수 완료 전 잘못 인계된 건수

처리량 증가만으로 성공을 판단하지 않는다. 안전 문의 누락, 재문의, 잘못된 인계가 함께 감소해야 실제 업무 감소와 고객 만족 개선으로 본다.

## 10. 최종 제안

추가 의견 세 가지는 다음 역할 분담으로 구현하는 것이 적절하다.

- **고객 챗봇:** 단순 해결, 안전 분류, 정보 수집
- **상담사 메인화면:** 지금 처리할 업무와 전화할 고객 결정
- **AI 요약 검수:** 원문과 비교해 정확성을 확인하고 다음 담당자에게 안전하게 전달

이 흐름이 연결되면 상담사는 반복 질문과 정보 검색을 줄이고, 전화가 반드시 필요한 고객에게 우선 집중할 수 있다. 고객은 단순 문의를 빠르게 해결하면서도 위험하거나 해결되지 않은 상황에서는 맥락을 유지한 채 상담사에게 연결될 수 있다.
