# 양정현 6주차 업무 지침서

> 담당자: 양정현  
> 역할: Mobile  
> 적용 기간: 2026-08-18 ~ 2026-08-21  
> 핵심 원칙: **6주차에는 고객 Mobile의 신규 기능을 늘리기보다 실제 Backend·AI와 연결된 고객 흐름을 끝까지 완주하고, 재진입·오류·실기기·Release 안정성까지 마감한다.**

---

# 1. 6주차 완료 목표

6주차가 끝났을 때 아래 기능이 **실제 Android 앱에서 동작해야 한다.**

- [ ] 고객이 실제 앱에서 로그인하고 본인의 정수기를 조회할 수 있다.
- [ ] 고객이 증상을 입력하면 실제 Backend에 신규 Inquiry가 생성된다.
- [ ] AI가 추가 질문을 만들면 실제 질문이 Mobile에 표시된다.
- [ ] 고객이 추가 질문에 답하고 제출하면 실제 Backend에 저장된다.
- [ ] 이미 답한 질문은 반복 표시되지 않는다.
- [ ] 추가 질문이 끝나면 실제 AI Guidance 화면으로 이동한다.
- [ ] 실제 pgvector·생성형 LLM 결과가 Backend를 통해 Mobile에 표시된다.
- [ ] Evidence가 있으면 고객이 근거 문서·페이지를 확인할 수 있다.
- [ ] 위험 상황에서는 일반 안내보다 사용 제한·안전 안내가 먼저 보인다.
- [ ] 근거가 없으면 임의 자가조치를 보여주지 않고 재질문 또는 상담 요청으로 이어진다.
- [ ] 고객이 실제 상담 요청을 생성할 수 있다.
- [ ] 상담 처리 후 같은 Inquiry의 최신 상태를 고객 Mobile에서 다시 확인할 수 있다.
- [ ] 앱을 종료했다 다시 실행해도 진행 중 Inquiry가 복구된다.
- [ ] 409가 발생해도 작성 중 입력이 유실되지 않는다.
- [ ] 접수·답변·상담 요청 버튼을 연타해도 중복 요청이 발생하지 않는다.
- [ ] 401·500·Network Error에서도 Crash·빈 화면 대신 고객용 안내와 재시도 흐름이 나온다.
- [ ] 고객 화면에 `stateVersion`, `allowed_actions`, `modelCode`, HTTP 코드 등 내부 기술정보가 노출되지 않는다.
- [ ] 위 핵심 흐름이 실제 Android 기기에서 처음부터 끝까지 PASS한다.

> **실제 Remote 연동, 추가 질문 제출, Guidance, 상담 요청, 앱 재진입 복구가 완료되지 않으면 6주차 Mobile 과업 완료로 판정하지 않는다.**

# 2. 이번 주 핵심 업무

## A. 고객 Remote E2E 완주

가장 먼저 아래 고객 흐름을 실제 Remote 환경에서 끝까지 연결한다.

```text
로그인
→ 내 정수기 조회
→ 증상 접수
→ Inquiry 생성
→ 최신 Snapshot
→ 추가 질문 조회
→ 추가 답변 제출
→ 최신 Snapshot 재조회
→ AI Guidance / Evidence
→ 상담 요청
→ 최신 상태 재조회
```

필수 원칙:

- Fixture / Mock 성공을 Remote 성공으로 계산하지 않는다.
- 실제 Backend 응답을 사용한다.
- `allowed_actions`에 없는 Action을 Mobile에서 강제로 활성화하지 않는다.
- Mobile이 AI FastAPI를 직접 호출하지 않는다.
- 항상 Backend를 통해 AI 결과를 소비한다.

### 추가 질문 Submit

반드시 다음 상태를 확인한다.

```text
질문 0개
→ Follow-up 미표시
→ Guidance 이동

질문 1개
→ 입력
→ Submit

질문 여러 개
→ 필수 답변 완료 전 비활성화
→ 완료 후 활성화

Submit 중
→ 중복 클릭 불가

409
→ 입력 유지
→ 최신 Snapshot 재조회

제출 후 질문 남음
→ Follow-up 유지

제출 후 질문 없음
→ Guidance 이동
```

실제 `SUBMIT_ANSWERS`가 허용된 Inquiry에서 POST가 성공해야 한다.

Backend Runtime Data 때문에 막히면 Mobile에서 임의 PASS 처리하지 않고 Blocker로 기록한다.

## B. Guidance·Evidence·상담 요청 실제 연동

고객이 AI 결과를 실제로 확인하고 다음 행동까지 할 수 있어야 한다.

확인할 것:

- Guidance 메시지
- 사용 가능 여부
- 제한 기능
- 다음 행동
- Evidence
- Evidence 없음
- Safety Critical
- AI Failure
- 상담 필요 여부

실제 흐름:

```text
실제 AI 결과
→ Backend 저장
→ Mobile 조회
→ 고객용 Guidance / Evidence 표시
→ 상담 요청
→ Backend 저장
→ 최신 Inquiry 상태 표시
```

완료 기준:

- 상담 요청이 실제 Backend에 저장된다.
- 연속 클릭으로 상담 요청이 두 번 생성되지 않는다.
- 상담 요청 후 Home 또는 Inquiry 재진입 시 최신 상태가 유지된다.
- 상담 처리 후 같은 Inquiry의 최신 상태를 고객이 다시 확인할 수 있다.

## C. 재진입·상태 복구·Navigation 안정화

실제 시연과 사용 중 자주 발생할 수 있는 재진입 상황을 닫는다.

필수 시나리오:

```text
문의 생성 후 앱 종료
→ 재실행
→ 최신 Inquiry 복구

Follow-up 중 앱 종료
→ 재실행
→ 최신 질문 상태 복구

Guidance 확인 후 앱 종료
→ 재실행
→ 최신 Guidance / Inquiry 복구

상담 요청 후 앱 종료
→ 재실행
→ 상담 진행 상태 복구
```

Navigation 핵심 경로:

```text
Home
→ Intake
→ Follow-up
→ Guidance
```

확인할 것:

- 이미 제출한 화면으로 잘못 돌아가지 않음
- 완료된 입력을 Back으로 다시 수정하지 않음
- 재진입 시 최신 Backend 상태 기준으로 화면 결정
- Home 복귀 후 진행 중 문의 정상 표시
- 화면 회전 후 Draft 유지

## D. 오류·중복 요청 대응

### 409 State Conflict

```text
409
→ 현재 사용자 입력 유지
→ 최신 Snapshot 재조회
→ 고객용 안내
→ 재시도
```

고객에게 아래와 같은 내부 표현을 보여주지 않는다.

```text
STATE-CONFLICT-01
state_version mismatch
HTTP 409
```

### 401 인증 만료

```text
401
→ 세션 만료 인식
→ 가능한 입력 보존
→ 고객용 안내
→ 로그인 화면
```

### 500 / Network Error

```text
500
→ 처리 오류 안내
→ Retry

네트워크 차단
→ 인터넷 연결 안내
→ Retry
```

완료 기준:

- Crash 없음
- 흰 화면 없음
- 무한 Loading 없음
- 가능한 범위에서 입력 유지
- 내부 오류 코드 미노출

### 중복 클릭

대상:

- 로그인
- Inquiry 생성
- 답변 Submit
- 상담 요청

Loading 중 재클릭을 막고 중복 API 요청이 발생하지 않게 한다.

```text
1. 고객 로그인

3. 신규 Inquiry 생성
4. 증상 입력
5. 추가 질문 확인
```

