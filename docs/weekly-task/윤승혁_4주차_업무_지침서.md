다만 3주차 코드 검사에서 다음 통합 문제가 확인되었다.

- `contracts/state-machine/diagrams/inquiry-state-machine.mmd`가 계약 `1.0.0`이 아니라 과거 `0.1.0` 기준으로 남아 있다.
- `render_state_machine.py --check`가 실패하지만 CI에서 해당 검사를 수행하지 않는다.
- `contracts/codes/inquiry-statuses.yaml`과 `workflow-actions.yaml`이 비어 있다.
- State Machine 외부 행동 23개 중 대부분이 OpenAPI Operation과 연결되지 않았다.
- 최종 WBS의 `미착수`, `진행 중` 상태가 실제 코드·테스트 수준과 맞지 않는다.
- 계약 불일치를 발견하고 담당자에게 요청했지만 최종 재검수 결과표가 없다.
- 최종 `main`에서 Data 단위 테스트 67개 중 6개가 실패하고 QA Gate가 차단된다.
- Backend Runtime 검증 문서 참조가 깨졌지만 최종 병합 전 전체 Gate에서 차단되지 않았다.
- 저장소 전체 계약을 한 번에 검증하는 Contract CI가 완성되지 않았다.
- Web·Mobile은 상당수 업무 흐름이 Mock이고, Backend↔AI 실제 수직 연결도 완료되지 않았다.

따라서 4주차 PM 업무는 새 계약을 계속 확대하는 것이 아니라 다음 순서로 진행한다.

1. 3주차 회귀 결함과 차단 요소를 8월 3일에 사실 기준으로 정리한다.
2. State Machine·공통 코드·OpenAPI·예시·다이어그램의 기준선을 닫는다.
3. 4주차 P0 작업과 중간 발표에 포함할 범위를 다시 확정한다.
4. 대표 시연을 실제 구현·Mock·미구현으로 구분하여 패키지화한다.
5. 김은진 발표자료와 전 팀원 시연 결과를 검수하고 최종 승인한다.
6. 발표 피드백과 미해결 통합 항목을 5주차 진입 조건으로 전환한다.

# 2. 4주차 역할 목표

1. **8월 3일까지 3주차 통합 회귀와 현재 기준선을 사실대로 확정한다.**

   현재 `main`에서 실패하는 QA, 오래된 State Machine 다이어그램, 비어 있는 공통 코드, WBS 상태 불일치와 영역별 Mock·실제 API 경계를 정리한다. 문서상 완료 여부가 아니라 재현 가능한 증거를 기준으로 상태를 갱신한다.

2. **8월 4일까지 State Machine과 공통 계약의 발표 기준선을 폐쇄한다.**

   상태·이벤트·전이·Guard·`allowed_actions`, 공통 코드 Registry, OpenAPI Operation, 역할 권한, 예시, 다이어그램과 Backend Runtime의 연결을 Crosswalk로 확정한다. 모든 23개 행동을 이번 주에 구현하는 것이 아니라, 구현·계약 전용·후속 범위를 명시한다.

3. **8월 5일까지 중간 발표용 대표 시연 범위와 기능 상태를 동결한다.**

   `T-052` 대표 시연은 `WPUJAC104DWH / SYN-JAC104-002 / DEMO-INQ-002 / 출수량 저하 / 매뉴얼 38쪽`으로 고정한다. 실제 동작, Mock 검증, 문서·계약만 존재, 미구현을 구분한다.

4. **8월 6일 발표 내용의 기술적 정확성과 범위 정직성을 책임진다.**

   김은진이 발표자료와 발표를 주도하고, 윤승혁은 프로젝트 문제 정의, 구조, 핵심 차별점, 구현 현황, 시연 흐름, 남은 위험과 다음 계획을 최종 검수한다. 사전학습 임베딩 모델 사용을 직접 ML/DL 학습으로 표현하거나 Mock을 실제 연동으로 표현하지 않는다.

5. **8월 7일까지 발표 피드백과 잔여 결함을 5주차 진입 조건으로 전환한다.**

   발표 후 발견된 문제를 즉시 기능 확장으로 대응하지 않고, 계약·연동·안전·시연·설명·일정 항목으로 분류하여 담당자와 완료 증거를 확정한다.

4주차 필수 범위는 **통합 기준선, 대표 흐름, 중간 발표와 5주차 진입 준비**이다. 운영 대시보드 P1, 전체 고객→상담사→기사 E2E, Kubernetes 배포, 전체 다중 Agent 완성, Graph DB 도입, 직접 모델 학습은 이번 주 PM 필수 범위가 아니다.

# 3. 4주차 필수 업무

## 3.1 3주차 통합 회귀 복구와 현재 상태 현행화

### 작업 목적

3주차 산출물이 존재한다는 이유로 완료 처리하지 않고, 현재 `main`에서 실행되는 코드·계약·테스트·문서를 기준으로 차단 결함과 진행 상태를 다시 확정한다. 4주차 팀원이 오래된 WBS와 성공 보고서를 기준으로 잘못된 작업을 시작하지 않게 한다.

### 작업 위치

```text
docs/planning/
├─ md/WBS.md
├─ week4-scope-and-dod.md
├─ week4-current-baseline.md
└─ week4-blocker-register.md

docs/testing/
├─ week4-entry-gate.md
├─ week4-main-regression-result.md
└─ week4-known-failures.md

docs/handoffs/
└─ week4-integration-handoff.md

.github/ISSUE_TEMPLATE/**
```

### 세부 작업 지침

1. 3주차 코드 검사 결과를 담당자별로 요약한다.
   - 김은진: Data·Schema·Fixture·QA 기반은 강하나 최종 QA Gate 실패
   - 최지용: DB·Backend 기반은 강하나 증상 제출·추가 입력과 수직 흐름 미완료
   - 이동윤: 계약·안전·pgvector·최소 RAG는 존재하나 Backend 연동·실제 LLM·추가 질문 미완료
   - 양정현: 모바일 UI·Mock 기준선은 존재하나 고객 핵심 흐름이 Fake
   - 한예나: Web Mock 기준선은 강하나 상담·방문 업무 API 미연결과 최종 Build 재검증 필요
   - 윤승혁: State Machine 계약은 강하나 공통 코드·OpenAPI·CI·최종 Gate 미완료
2. 현재 `main`에서 다음 검증 결과를 취합한다.
   - Data 단위 테스트
   - Data QA·Finalize
   - State Machine Validator
   - State Machine Diagram Check
   - Backend Test·Migration
   - AI Test·pgvector 검증
   - Web Test·Lint·Build
   - Mobile Test·Build
3. 실행 환경 부족과 코드 실패를 구분한다.
4. 3주차 결과를 다음 상태로 재분류한다.
   - `VERIFIED_DONE`
   - `DONE_WITH_LIMITATION`
   - `INTEGRATION_BLOCKED`
   - `MOCK_ONLY`
   - `CONTRACT_ONLY`
   - `NOT_STARTED`
5. WBS에서 실제 구현이 존재하는데 `미착수`로 남은 항목을 수정한다.
6. 반대로 파일만 존재하거나 Mock만 있는 업무를 `완료`로 올리지 않는다.
7. Data QA 실패의 직접 원인, 담당자, 수정 방법과 재검증 명령을 기록한다.
8. 삭제·이동된 Backend Runtime 문서와 Crosswalk를 최지용·김은진과 정리한다.
9. 최종 `main` QA 실패가 해결되기 전에는 3주차 완전 종료로 표시하지 않는다.
10. 각 차단 항목에 다음 정보를 포함한다.
    - 증상
    - 재현 명령
    - 직접 원인
    - 책임 영역
    - 협업 담당자
    - 해제 조건
    - 목표일
    - 증거 경로
11. GitHub Issue 상태와 WBS 상태를 같은 의미로 맞춘다.
12. 8월 3일 종료 시점에 4주차 기준 Commit과 차단 목록을 공지한다.

## 3.2 State Machine·공통 코드·OpenAPI 계약 기준선 폐쇄

### 작업 목적

3주차에 완성한 State Machine 계약을 Web·Mobile·Backend·AI·테스트가 실제로 소비할 수 있는 공통 기준으로 정리한다. YAML 내부 정합성 통과에 그치지 않고 다이어그램, 공통 코드 Registry, OpenAPI와 예시의 연결을 확정한다.

### 작업 위치

```text
contracts/state-machine/**
contracts/codes/
├─ inquiry-statuses.yaml
├─ workflow-actions.yaml
├─ user-roles.yaml
└─ visit-statuses.yaml

contracts/api/**
contracts/examples/**
contracts/VERSION
contracts/CHANGELOG.md
contracts/README.md

scripts/contracts/
├─ validate_state_machine.py
├─ render_state_machine.py
├─ validate_codes.py
├─ validate_openapi.py
├─ validate_examples.py
└─ validate_contract_crosswalk.py

tests/contract/
├─ state-machine/**
├─ codes/**
├─ api/**
└─ examples/**
```

### 세부 작업 지침

1. `inquiry-state-machine.mmd`를 최신 `1.0.0 / TEAM_APPROVED` YAML 기준으로 다시 생성한다.
2. `render_state_machine.py --check`가 통과하도록 한다.
3. 생성 파일 상단에 계약 Version·입력 Hash·생성 명령을 기록한다.
4. `contracts/codes/inquiry-statuses.yaml`에 State Machine 상태 13개를 등록한다.
5. `contracts/codes/workflow-actions.yaml`에 외부 행동 23개를 등록한다.
6. State Machine 내부 코드와 공통 Registry 코드가 정확히 일치하는지 검증한다.
7. 사용자 역할과 Visit 상태도 중복·누락 없이 연결되는지 확인한다.
8. State Machine의 각 외부 행동에 다음 상태를 부여한다.
   - `RUNTIME_IMPLEMENTED`
   - `OPENAPI_CONFIRMED`
   - `CONTRACT_ONLY`
   - `DEFERRED`
9. 외부 행동 23개와 OpenAPI Operation ID의 Crosswalk를 작성한다.
10. 이번 주 실제 Runtime에 필요한 행동을 우선한다.
    - 문의 생성
    - 증상 제출
    - 추가 답변
    - 상담 요청
    - 상담 시작·완료
    - 방문 요청·일정 변경
    - 문의 취소
11. 4주차에 구현하지 않는 Action도 누락하지 않고 `CONTRACT_ONLY` 또는 `DEFERRED`로 명시한다.
12. OpenAPI에 없는 Operation을 임의로 Runtime 완료 처리하지 않는다.
13. Backend Engine이 사용하는 Event·Guard·Action Code와 계약을 비교한다.
14. Web·Mobile의 `allowed_actions` Type과 Action Code를 비교한다.
15. Mobile·Web Mock에만 존재하는 임의 Action Code를 제거 요청한다.
16. AI 자동 결과 Event와 State Machine Event를 비교한다.
17. 대표 흐름 예시를 실제 계약 Version에 맞춰 다시 검증한다.
18. 계약 변경은 `contracts/CHANGELOG.md`에 기록한다.
19. Breaking Change 여부와 소비자 영향을 기록한다.
20. 김은진과 다음 Contract Test를 추가한다.
    - State와 Code Registry 일치
    - Action과 Code Registry 일치
    - Action–OpenAPI Operation 연결
    - Mermaid 최신성
    - Example Event 순서와 최종 상태
21. 최지용, 이동윤, 한예나, 양정현에게 각 소비자 영역 검토를 요청한다.
22. 최종 승인 전 “검토함”이 아니라 파일·Test·PR 증거를 확인한다.

### 완료 기준

4. 다음 5주차 핵심 작업과 연결한다.

   - 위험·사용 안내 분류
   - EvidenceCardDTO Backend 조립

   - Data QA Gate
   - Contract CI
   - Backend 증상 제출
   - Backend↔AI 실제 연결
   - Web·Mobile 실제 API 전환
   - State Machine Action–OpenAPI 연결

   - 계약 기준선 통과
   - 대표 Vector 검색 재현

10. 발표 피드백 대응 항목과 기존 기술 부채를 분리한다.

    - 완료 증거
    - 다음 담당자에게 전달할 결과

본 지침서의 필수 업무는 8월 3일에 3주차 회귀와 현재 기준선을 확정하고, 8월 4일에 계약·공통 코드·OpenAPI Crosswalk와 대표 시연 범위를 닫으며, 8월 5일에 중간 발표 기준 계약·기능·자료를 동결하는 것이다. 8월 6일에는 김은진이 발표를 주도하고 윤승혁은 기술 내용·범위·시연의 정확성을 책임진다. 8월 7일에는 발표 피드백과 미완료 통합 항목을 5주차 진입 조건으로 전환한다.
