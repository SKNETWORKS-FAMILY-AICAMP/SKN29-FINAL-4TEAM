# 1. 이번 이틀의 목표

이번 이틀 동안 윤승혁의 가장 중요한 역할은 **새로운 요구사항을 더 정리하는 것이 아니라, 팀 전체가 현재 구현 중인 흐름을 실제 E2E까지 밀어붙이도록 방향을 고정하는 것**이다.

현재 계약·State Machine·Backend·Mobile·Web의 기반은 상당 부분 갖춰져 있고, 남은 가장 큰 공백은 실제 AI Runtime과 각 Client를 하나의 흐름으로 연결하는 일이다.

따라서 8월 13~14일에는 다음 하나를 최우선 목표로 한다.

> **고객 Mobile → Backend → AI → Backend → 상담사 Web이 같은 Inquiry를 기준으로 처음부터 끝까지 실제 동작하도록 만든다.**

PM 업무 역시 이 목표를 직접 지원하지 않는다면 뒤로 미룬다.

## 4.3 Blocker 중앙 조정

이번 이틀에는 PM이 팀원별 진행률보다 **E2E가 어디에서 끊기는지**를 기준으로 업무를 관리한다.

```text
Mobile → Backend
Backend → AI
AI → pgvector / LLM
AI → Backend 저장
Backend → Mobile
Backend → Web
Web → Backend 상담 처리
```

문제가 생기면 담당자를 바로 연결한다.

- Mobile 소비 문제 → 양정현 + 최지용
- Backend↔AI → 최지용 + 이동윤
- pgvector·공용 환경 → 이동윤 + 김은진
- Web 소비 → 한예나 + 최지용
- Contract·State 해석 → 윤승혁 즉시 결정

### PM 판단 기준

다음 질문 하나로 즉시 판단한다.

> **이 문제가 해결되지 않으면 대표 E2E가 멈추는가?**

- YES → 즉시 P0 Blocker
- NO → Backlog로 이동

새로운 개선 아이디어에 대해서는 별도 회의를 열지 않는다.

# 5. PM의 직접 기술 작업 범위

윤승혁은 다른 담당자의 구현을 대신하지 않는다. 다만 E2E를 막는 **계약·State·공통 연결 문제**는 즉시 직접 처리한다.

### 직접 처리 가능

- `allowed_actions` 또는 State 계약 모순 수정
- 이미 승인된 Action과 OpenAPI의 불일치 수정
- 대표 E2E Example의 최소 정합성 수정
- Contract Validator·Crosswalk 오류 수정
- Client와 Backend가 서로 다르게 해석하는 공통 Code 문제 해결

### 이번에 하지 않는 것

- State Machine 대규모 재설계
- 신규 Event·State 대량 추가
- 챗봇 전용 계약 설계
- 방문기사 P1 계약 확대
- AI 내부 구조 대신 구현
- Backend·Web·Mobile 기능을 대신 개발

**기존 계약으로 E2E가 가능하다면 계약을 건드리지 않는다.**

# 7. 8월 14일 — E2E 완주 및 판정

## 7.1 정상 E2E 한 건 완주

팀 전체가 같은 환경에서 대표 Scenario를 실제로 실행한다.

윤승혁은 각 화면이나 내부 구현을 하나씩 검수하기보다 **전체 흐름이 실제로 이어지는지**를 확인한다.

### PASS 조건

- Mobile이 실제 Backend를 사용한다.
- Backend가 실제 AI Baseline을 호출한다.
- AI 결과가 DB에 저장된다.
- Mobile에서 Guidance를 확인할 수 있다.
- 고객 상담 요청이 실제 State로 반영된다.
- Web에서 같은 Inquiry를 조회할 수 있다.
- 상담사가 실제 Remote Action으로 상담을 완료한다.
- 고객이 최종 상태를 다시 확인할 수 있다.

---

## 7.2 정상 흐름 이후 최소 오류만 확인

Happy Path가 PASS한 뒤 다음만 확인한다.

- stale `state_version` 409
- 중복 요청·Idempotency
- AI Timeout 또는 503
- No-Evidence 또는 위험 입력 Fallback

이 단계에서도 새로운 실험이나 UX 고도화로 넘어가지 않는다.

# 10. 8월 14일 최종 PM 판정

최종 판정은 다음 세 단계만 사용한다.

### `PASS`

고객 Mobile → AI → 상담사 Web → 상담 완료 → 고객 상태 확인까지 실제 Runtime으로 동작한다.

### `CONDITIONAL_PASS`

대표 흐름 대부분이 동작하며 남은 문제가 명확하고 짧은 수정으로 닫을 수 있다.

### `HOLD`

핵심 연결 구간이 실제 Runtime으로 이어지지 않아 시연할 수 없다.

최종 보고에는 다음만 남긴다.

1. E2E 판정
2. 기준 Commit SHA
3. 성공한 실제 흐름
4. 남은 Blocker
5. 다음 주 우선순위
