## 1. 오늘 완료한 작업

### 상담 저장 구조

- Remote 모드에서 Mock 상담 저장을 호출하지 않도록 막았다.
- 상담 저장 API가 없을 때 저장 버튼을 비활성화하고 조회만 가능하다고 안내한다.
- 화면에서 `nextStatus`를 계산하지 않도록 제거했다.
- Mock에서도 서버 역할의 응답이 준 `status`, `state_version`, `allowed_actions`를 그대로 사용한다.
- 실제 API 연결용 Repository와 요청 DTO를 준비했다.
  - 상담 시작
  - 상담 요약 저장
  - 상담 요약 확정
  - 상담 완료

### AI 근거 정보 보호

- 화면에는 문서명, 버전, 페이지, 공개 링크, 요약, 검증 문구만 전달한다.
- `chunk_id`, 검색 점수, 내부 파일 경로, Prompt가 화면 데이터에 포함되지 않는 테스트를 추가했다.
- 공개 Evidence API가 준비되기 전에는 Mock 근거를 실제 응답처럼 사용하지 않는다.

### 방문 연결 준비

- 방문 희망일과 확정일 입력을 시간 없는 날짜 형식으로 변경했다.
- Web 이름을 `preferredDate`, `confirmedDate`로 정리했다.
- API 요청 이름은 `preferred_date`, `confirmed_date`로 고정했다.
- 방문 흐름을 아래 순서로 나눴다.
  1. 방문 요청 생성: 기사 없이 생성
  2. 기사와 날짜 저장
  3. 방문 확정
- 가상 기사 ID를 API 계약에 맞는 UUID 형식으로 변경했다.
- 방문 검토·생성·일정 저장·확정용 Repository와 요청 DTO를 준비했다.
- 방문 생성 요청에 기사 ID가 들어가지 않는 테스트를 추가했다.
- 시간까지 포함한 날짜가 API 요청으로 들어오면 거부하도록 검사한다.

## 3. 협업이 필요해 대기 중인 작업

### Backend 담당

- 목록·상세 GET을 공용 브랜치와 공용 실행 환경에 반영한다.
- 상담 Start·Save·Confirm·Complete API를 구현하고 아래 값을 반환한다.
  - `status`
  - `state_version`
  - `allowed_actions`
- 방문 Review·Create·Schedule·Confirm API를 구현한다.
- 방문 Create에서는 기사를 받지 않고, Schedule에서 기사와 날짜를 받는다.

### AI·Backend 담당

- 공개 Evidence DTO와 Route를 확정한다.
- 공개 응답에서 아래 내부정보를 제외한다.
  - `chunk_id`
  - 검색 점수
  - 내부 파일 경로
  - Prompt

### Backend·QA 담당

- 공용 Runtime URL과 상담사 테스트 계정을 공유한다.
- 테스트용 문의 UUID와 방문 UUID를 공유한다.
- Correlation ID로 Web 요청, Backend 로그, DB 저장 결과를 함께 확인한다.
