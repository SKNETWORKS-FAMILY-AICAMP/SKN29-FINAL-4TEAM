> 유일한 판정 기준: `docs/weekly-task/윤승혁_3주차_업무_지침서.md`의 3.1~3.6  
> 확인 범위: 현재 저장소에서 확인 가능한 코드·계약·문서·테스트 결과  
> 문서 상태: 1차 진행도 판정

## 1. 판정 원칙

- `완료`: 해당 절의 완료 기준과 필수 산출물을 모두 확인했다.
- `부분 완료`: 핵심 산출물은 있으나 완료 기준, 검토 승인 또는 실행 증거가 일부 남아 있다.
- `미완료`: 필수 산출물이 없거나 핵심 작업을 수행했다는 증거가 부족하다.
- `확인 불가`: GitHub Issue·PR처럼 현재 로컬 저장소만으로 사실을 확인할 수 없다. 확인 불가 항목은 완료로 계산하지 않는다.

이 문서는 지침서 4장 이후의 추가 업무나 5장의 최종 체크리스트를 별도 판정 기준으로 사용하지 않는다. 다만 3.1~3.6의 완료 여부를 판단하기 위한 현재 저장소 증거는 확인한다.

## 3. 절별 상세 판정

### 3.1 3주차 P0 범위와 완료 기준 확정 — 완료

- `.github/ISSUE_TEMPLATE/task.yml`에 요구사항·WBS ID, 담당자, 의존성, 완료 기준, 결과물 경로, 제외 범위와 상태 필드가 정의되어 있다.

#### 운영 시 유지할 사항

- 실제 GitHub Issue를 생성·사용하는 경우 로컬 작업 목록의 범위와 완료 기준을 그대로 연결한다.
- 담당자 결과가 바뀌면 WBS 계획 상태를 사실로 간주하지 않고 실제 진행 현황표를 먼저 갱신한다.
- 목표 시점이 지나면 `진행 중`으로 방치하지 않고 다섯 가지 분류 중 하나로 다시 판정한다.

위 유지 사항은 진행 중인 운영 문서의 갱신 규칙이며, 현재 3.1 완료 판정을 되돌리는 미완료 항목은 아니다.

#### 확인된 항목

- 계약 기준선이 `v1.0.0 / TEAM_APPROVED`로 확정되어 있다.

- Mermaid 원본과 계약 검증·렌더링 스크립트가 존재한다.
- `TEAM_APPROVED` 상태를 관련 영역의 검토를 거쳐 기준 계약이 채택됐다는 완료 증거로 인정한다.
- 화면설계서와 대표 흐름에서 사용하는 핵심 상태·행동이 계약의 상태·이벤트·예시와 연결되어 있다.

- Backend 상담·방문 Runtime 연결은 최지용 구현 및 3.6 진입 판정에서 추적한다.
- Mobile 상태·이벤트 정합성은 3.3 수정 대상으로 추적한다.
- 검증 스크립트 실행 결과는 3.6의 계약 검증 증거로 관리한다.

위 항목은 확정 계약의 후속 소비·구현 문제이며, 3.2 계약 최종 정리의 완료 판정을 되돌리는 사유로 사용하지 않는다.

#### 선택 보완 사항

### 3.3 API·AI·공통 코드의 영역 간 정합성 검토 — 부분 완료

#### 확인된 항목

- `docs/testing/week3-contract-alignment-review.md`에 Backend·AI·Web·Mobile·Data·QA의 1차 검토 결과가 기록되어 있다.
- 역할, 위험도, 사용 안내 상태, `state_version`, `allowed_actions`, 409, Evidence 공개 범위를 비교했다.
- State Machine 계약 버전과 변경 이력이 갱신되어 있다.
- 불일치 항목별 담당자와 후속 조치가 지정되어 있다.

#### 완료되지 않은 항목

- AI Runtime 응답과 `SymptomAnalysisResponse.schema.json`의 필드 구조가 일치하지 않는다.
- Web 상담 모델이 `PENDING_CONSULTATION`을 포함하지 않는다. Mock 사용 자체는 3.3 완료를 막지 않지만 Mock의 코드·필드는 확정 계약과 일치해야 한다.
- Mobile이 계약에 없는 `ERROR_CONFIRMED`와 자체 이벤트를 사용하며 `state_version`, `allowed_actions`, 409 처리가 없다.
- Data 계약 해시와 Manifest가 현재 State Machine 계약과 일치하지 않는다.
- API·AI·DB·화면 Mock의 날짜·식별자·Enum·인증·오류 정책을 모두 통과시킨 최종 검증 결과가 없다.
- API·AI·공통 코드 변경에 대한 각 주관 담당자의 최종 승인을 확인하지 못했다.

#### 완료 판정에 필요한 증거

- 담당자별 불일치 수정 결과
- 수정된 계약 DTO·Mock·예시 JSON의 Schema 통과 결과

- 주관 담당자 승인과 오류 코드 충돌 해소 기록
