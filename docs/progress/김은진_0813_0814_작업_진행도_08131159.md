## 2. 절별 평가와 완료 방법

### 2.1 3.1 공용 통합 실행 환경 확정 — 45%

- [E2E 팀 연결 지도](../../planning/8월13일_E2E_팀_연결_지도.md)에 대표 제품·흐름·담당 연결 관계가 고정됐다.
- PM 확인으로 전원이 최신 `main@945cb050ae1d9b9398a011fbfa970e22e09c769c`을 Pull해 소스 기준 SHA는 일치한다.
- Backend·AI·DB의 개별 실행·테스트 증거는 있으나 [Blocker Register](../../planning/week5-blocker-register.md)의 공용 Runtime 주소·DB·Seed는 아직 `NOT_CONFIRMED`다.

완료하려면 `docs/testing/e2e/`에 확정 SHA, Backend/AI Base URL, DB·Seed 상태, 필요한 환경변수명, Health 결과를 기록한 짧은 실행 결과서를 작성해야 한다. Secret 값은 기록하지 않는다.

별도 확인: 팀원 PC 또는 공용 서버에서 Mobile과 Web이 같은 Backend 주소를 실제로 호출하는지 확인해야 한다.

### 2.2 3.2 Backend↔AI 실제 Baseline 연결 검증 — 60%

- Backend Evidence Verifier·Safety Rule·Crosswalk·읽기 전용 View 사전점검이 추가됐고 현재 HEAD에서 합성 배정·G1-B 표적 Backend Test **26건 PASS**를 재확인했다.
- AI에는 OpenAI Responses API Adapter, Prompt v2, 안전·개인정보 Guard와 Local Runtime Verifier가 구현됐고 작성자 검증은 AI Unit **219건 PASS**다.
- 다만 [G1-B 사전점검 가이드](../jiyong/연동_인계/Backend_AI_Crosswalk_Readonly_View_Verifier_Danger_Guard_구현_검증_가이드.md)의 로컬 실측은 Crosswalk·View 행 `0/7`로 `BLOCKED`이며, [AI Walkthrough](../dongyoon/walkthrough.md)는 실제 Provider·팀 pgvector 실행을 `NOT_RUN`으로 명시한다.

완료하려면 실제 Local Mode에서 Backend→FastAPI→pgvector→LLM→Backend를 한 번 실행하고 AIRun·Guidance·EvidenceLink·State·`correlation_id`를 `tests/integration/backend-ai/**` 또는 실행 결과서에 연결해야 한다.

별도 확인: `OPENAI_API_KEY`, 팀 DB 최소 권한 DSN, 공식 Evidence 7건 적재·Crosswalk Apply 여부가 필요하다.

### 2.3 3.3 8월 13일 종료 Gate — 65%

- 기준 Scenario와 Blocker 담당·해제 조건은 [Blocker Register](../../planning/week5-blocker-register.md)에 기록됐다.
- 소스 SHA는 일치했고 `SYNTHETIC_E2E_ASSIGNMENT`가 구현·PostgreSQL 반복검증됐다.
- 실제 AI Runtime 1건, DB Delta, 공용 실행 명령은 아직 하나의 공동 환경 결과로 묶이지 않았다.

완료하려면 `baseline_commit`, 실행 명령, Health, Inquiry ID, Correlation ID, DB 저장 건수, PASS/HOLD, 남은 Blocker를 한 페이지 결과서로 남긴다.

### 2.4 4.1 대표 P0 E2E — 5%

- [E2E Acceptance](../../testing/e2e/week5-e2e-acceptance.md)에 Scenario와 단계별 기대값은 정의됐다.
- 실제 고객 Mobile→AI Guidance→상담 요청→Web 처리→고객 최종 조회는 실행되지 않았다.

완료하려면 방문기사 단계를 제외하고 동일 Inquiry를 사용한 정상 흐름을 실기기·브라우저·PostgreSQL에서 완주하고 화면·DB·로그 증거를 연결한다.

별도 확인: 실제 기기·브라우저 접근과 합성 CUSTOMER/CONSULTANT 계정이 필요하다.

### 2.5 4.2 Happy Path 후 최소 오류 — 25%

- 409·멱등성·No-Evidence·Timeout의 단위·API Test는 존재한다.
- 실제 공용 Runtime에서의 409, 중복 클릭, AI 503/Timeout은 아직 실행하지 않았다.

완료하려면 Happy Path 성공 후 실패 구간만 재현하여 추가 Business Record·Version·History가 생기지 않는지 기록한다.
