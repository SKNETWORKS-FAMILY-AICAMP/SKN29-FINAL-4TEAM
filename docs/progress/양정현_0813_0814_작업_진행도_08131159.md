## 2. 절별 평가와 완료 방법

### 2.1 4.1 Mobile 작업 범위 동결 — 75%

- 기존 고객 로그인·구독·문의·증상·추가 답변 Remote 흐름은 [Mobile E2E 결과](../../../mobile/docs/week5/week5-mobile-e2e-result.md)에 실기기 PASS로 기록돼 있다.
- 오늘 고객 앱 UX·디자인 변경과 상담 요청 코드가 병합됐고, PM 확인으로 전원이 최신 `main@945cb050ae1d9b9398a011fbfa970e22e09c769c`을 Pull했다.
- 현재 환경의 Gradle 검증은 Gradle 9.5 배포본 다운로드가 네트워크에서 차단돼 실행되지 못했다. 이는 제품 코드 FAIL이 아니라 `ENVIRONMENT_BLOCKED`다.

완료하려면 네트워크 또는 사전 캐시된 Gradle 환경에서 `verify-build.bat`, 고객 Unit Test, `assembleDebug`를 현재 SHA로 실행하고 APK 경로·Hash를 기록한다.

별도 확인: `CUSTOMER_CARE_API_BASE_URL`이 팀 공용 Backend를 가리키는지 실제 기기 설정에서 확인해야 한다.

### 2.2 4.2 AI Guidance·Evidence Remote 연결 — 20%

- 기존 Guidance UI·Mapper·No-Evidence fail-closed 화면은 있다.
- Backend 보고서는 고객 Snapshot에 Guidance/Evidence가 없고 공개 API도 아직 구현하지 않았다고 명시한다.
- 따라서 `getGuidance()`의 Remote 성공 경로는 여전히 연결할 수 없다.

완료하려면 최지용이 고객 공개 Guidance/Evidence 계약과 Route를 구현한 뒤 `WaterCareApi`, DTO, Mapper, Repository, ViewModel을 실제 응답에 연결하고 내부 `chunk_id`·점수·경로 비노출 Test를 추가한다.

별도 확인: Public Evidence 허용 필드와 빈 근거 Fallback을 PM·Backend·AI·QA가 승인해야 한다.

### 2.3 4.3 상담 요청까지 고객 E2E — 75%

- [Remote Customer Inquiry Repository](../../../mobile/core/src/main/java/com/skn29/watercare/core/repository/CustomerInquiryRepository.kt)와 [Guidance ViewModel](../../../mobile/customer-app/src/main/java/com/skn29/watercare/customer/feature/customer/guidance/GuidanceViewModel.kt)에 `REQUEST_CONSULTATION` 호출·멱등키·409 복구 코드가 추가됐다.
- Backend 상담 요청 Runtime은 PostgreSQL 실제 Socket에서 200·Replay·409·404·Correlation PASS 증거가 있다.
- Backend의 합성 E2E 배정은 Demo 상담사 목록·상세·Start, 타 상담사 404, Replay·Rollback을 구현했고 현재 HEAD 관련 Test **26건 PASS**를 확인했다.
- Mobile 신규 상담 요청 전용 Test와 실기기 결과는 아직 없다.

완료하려면 Unit Test에 성공·Replay·409·422·Network 실패·중복 클릭을 추가하고, 실기기에서 요청 후 `CONSULTATION_REQUIRED`, 증가한 `state_version`, 최신 `allowed_actions`를 재조회한다.

별도 확인: 합성 배정의 Backend 작성자 검증은 완료됐지만 Mobile이 만든 실제 Inquiry의 준비 명령과 Web UI 동일 Inquiry 노출은 공동 확인이 필요하다.

### 2.4 5 대표 Mobile E2E — 35%

- 로그인→구독→문의→증상→추가 질문·답변까지는 이전 실기기에서 완료됐다.
- 실제 AI Guidance·근거·상담 요청 실기기 실행·Web UI 인계가 빠져 전체 흐름은 미완료다. 다만 상담 요청 후 합성 상담사에게 배정하는 Backend 경로는 준비됐다.

완료하려면 `WPUJAC104DWH` 출수량 저하 한 건을 현재 APK에서 실행하고 Inquiry ID·각 상태 Version·화면·Backend 로그를 결과서에 남긴다.

### 2.5 6 최소 오류 대응 — 55%

- 기존 409 입력 보존·Snapshot 재조회와 Remote 실패 시 Fake 비대체 경계가 있다.
- 신규 상담 요청 코드도 Conflict 시 최신 Snapshot을 반영하도록 작성됐다.
- 실제 AI 503/Timeout과 신규 상담 요청 중복 전송은 실기기에서 미검증이다.

완료하려면 Happy Path 후 409, AI 실패, 근거 없음, 버튼 연타를 각각 한 번씩 실행하고 무한 Loading·중복 Business Record가 없음을 기록한다.

### 2.6 7 Blocker 처리 — 80%

- Guidance Route·공용 Runtime·Web 인계 Blocker가 [Blocker Register](../../planning/week5-blocker-register.md)에 담당자와 함께 기록됐다.
- 상담사 합성 배정 코드 Blocker는 해제됐지만 Register 최신화, Mobile Endpoint·실제 응답·화면 영향과 공동 재검증 로그는 아직 없다.

### 2.7 8 조기 완료 시 지원 — 15%

- 독립 작업이 아직 종료되지 않아 Cross-client 공동 Smoke 단계에 진입하지 않았다.
- 완료 후 같은 Inquiry의 Mobile 화면과 Web·Backend 로그를 공동 대조해야 한다.

### 2.8 10 8월 14일 발표 준비 — 0%

- 아직 8월 13일이며 최종 APK와 정상 E2E가 준비되지 않았다.
- 8월 14일에는 신규 기능 대신 전날 APK 재실행, 시연 계정·순서 고정, Screenshot·백업 영상을 준비한다.

### 2.9 11 보류 업무 준수 — 60%

- 기사 Visit 신규 Runtime은 건드리지 않았다.
- 다만 오늘 고객·기사 앱 UX와 Dashboard 관련 대규모 변경이 병합됐다. 이제부터는 디자인 변경을 동결하고 E2E 차단 해소만 진행해야 한다.

### 2.10 12 최종 완료 상태 — 35%

- 실제 Android 앱의 제품 선택→문의→추가 답변까지는 과거 실기기에서 확인됐다.
- Backend·AI를 거친 실제 안내 확인과 상담 요청 실기기 실행이 빠져 최종 완료 상태는 아니다.
