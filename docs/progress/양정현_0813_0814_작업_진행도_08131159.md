## 2. 절별 평가와 완료 방법

### 2.1 4.1 Mobile 작업 범위 동결 — 88%

- 기존 Remote 흐름에 더해 `1cd1905`에서 Mobile Unit **21 suites / 81 passed**, Kotlin Compile·Debug Assemble, Android Remote Smoke가 PASS했다.
- Android Emulator에서 실제 AI 위험 안내→상담 요청→최종 `COMPLETION_PENDING` v8 재조회까지 수행했다.
- 최신 `a29ec0f`에 E2E 고객 코드 `BuildConfig.E2E_CUSTOMER_CODE`, CUSTOMER 이외 역할 로그인 거부·세션 Token UI 비노출 Test 4건이 유지된다. 다만 독립 실행은 Android Plugin 의존성 다운로드 차단으로 `NOT_RUN`이며 작성자 실행 결과 문서도 아직 없다.
- Guidance Route와 관련 Mobile 계약은 원복 상태라 같은 APK 흐름을 다시 보장하지 못한다.

완료하려면 네트워크 또는 사전 캐시된 Gradle 환경에서 `verify-build.bat`, 고객 Unit Test, `assembleDebug`를 현재 SHA로 실행하고 APK 경로·Hash를 기록한다.

별도 확인: `CUSTOMER_CARE_API_BASE_URL`이 팀 공용 Backend를 가리키는지 실제 기기 설정에서 확인해야 한다.

### 2.2 4.2 AI Guidance·Evidence Remote 연결 — 60%

- `1cd1905`에서는 고객 Guidance Route와 Mobile Repository를 실제 연결해 `danger`·`TOTAL_STOP`을 표시했다.
- 최신 Backend에는 고객 Guidance Route가 없으므로 현재 `getGuidance()` Remote 성공 경로는 다시 차단됐다.

완료하려면 최지용이 고객 공개 Guidance/Evidence 계약과 Route를 구현한 뒤 `WaterCareApi`, DTO, Mapper, Repository, ViewModel을 실제 응답에 연결하고 내부 `chunk_id`·점수·경로 비노출 Test를 추가한다.

별도 확인: Public Evidence 허용 필드와 빈 근거 Fallback을 PM·Backend·AI·QA가 승인해야 한다.

### 2.3 4.3 상담 요청까지 고객 E2E — 90%

- [Remote Customer Inquiry Repository](../../mobile/core/src/main/java/com/skn29/watercare/core/repository/CustomerInquiryRepository.kt)와 [Guidance ViewModel](../../mobile/customer-app/src/main/java/com/skn29/watercare/customer/feature/customer/guidance/GuidanceViewModel.kt)에 `REQUEST_CONSULTATION` 호출·멱등키·409 복구 코드가 있다.
- Backend 상담 요청 Runtime은 PostgreSQL 실제 Socket에서 200·Replay·409·404·Correlation PASS 증거가 있다.
- Backend의 합성 E2E 배정은 Demo 상담사 목록·상세·Start, 타 상담사 404, Replay·Rollback을 구현했고 현재 HEAD 관련 Test **26건 PASS**를 확인했다.
- `1cd1905`에서 실제 Android 상담 요청 v4와 같은 Inquiry 최종 v8 재조회가 PASS했다.

완료하려면 Unit Test에 성공·Replay·409·422·Network 실패·중복 클릭을 추가하고, 실기기에서 요청 후 `CONSULTATION_REQUIRED`, 증가한 `state_version`, 최신 `allowed_actions`를 재조회한다.

별도 확인: 합성 배정의 Backend 작성자 검증은 완료됐지만 Mobile이 만든 실제 Inquiry의 준비 명령과 Web UI 동일 Inquiry 노출은 공동 확인이 필요하다.
