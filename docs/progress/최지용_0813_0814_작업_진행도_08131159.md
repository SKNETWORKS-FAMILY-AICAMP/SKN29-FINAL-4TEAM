## 2. 절별 평가와 완료 방법

### 2.1 4.1 Backend Runtime 기준선 확인 — 95%

- Migration·Seed·문의·추가문진·상담·전화문의 Runtime과 PostgreSQL 검증 문서가 있다.
- 현재 HEAD에서 신규 합성 배정·G1-B 사전점검 표적 Backend Test **26건 PASS**를 재확인했다.
- 합성 배정 작성자 검증은 SQLite 회귀 **43 passed / 1 skipped**, 격리 PostgreSQL **14건씩 2회 PASS**다.
- 전체 회귀는 착수 기준 **1114 passed / 19 skipped**이고 게시 기준 최신 전체 실행은 시간 제한으로 미완료이므로 최종 전체 PASS로 확대하지 않는다.

완료하려면 현재 후보 SHA에서 `migrate --check`, Seed Replay, Backend 표적 또는 전체 회귀와 PostgreSQL Role/Crosswalk Apply를 실행해 결과를 고정한다.

### 2.2 4.2 Backend↔실제 AI Runtime 연결 — 65%

- [Evidence·Safety 구현 가이드](연동_인계/Backend_AI_Crosswalk_Readonly_View_Verifier_Danger_Guard_구현_검증_가이드.md)의 Crosswalk, Read-only View, Evidence Verifier, EvidenceLink, Safety Rule과 강제 G1-B Audit 코드가 main에 병합됐다.
- Mock 실제 소켓과 저장 경계는 과거 검증됐다.
- 로컬 Audit은 Migration·View 열을 확인했지만 Crosswalk·View 행 `0/7`, AI Role 권한 미적용으로 `BLOCKED`다. 공식 Evidence 7건 적재·Crosswalk Apply와 실제 BGE-M3·pgvector·OpenAI 공동 HTTP는 미실행이다.

완료하려면 팀 PostgreSQL에서 Migration·Crosswalk Apply 후 실제 AI Local Mode를 호출하고 AIRun·Assessment·Guidance·EvidenceLink·State·Correlation을 조회하는 Integration Test와 결과서를 작성한다.

별도 확인: 팀 DB 운영자, 공식 Evidence 적재자, AI Secret 제공이 필요하다.

### 2.3 4.3 고객 Guidance·상담 전환 API — 80%

- [REQUEST_CONSULTATION 보고서](API/Django_REST_API_Mobile_REQUEST_CONSULTATION_Runtime_구현_검증_보고서_20260812.md)는 PostgreSQL 실제 Socket에서 상담 요청 200·Replay·409·404와 `CONSULTATION_REQUIRED` 전환을 검증했다.
- 고객 Guidance/Public Evidence 계약과 Route는 아직 구현되지 않았다.
- [합성 E2E 배정 보고서](연동_인계/Django_SYNTHETIC_E2E_ASSIGNMENT_Runtime_구현_검증_보고서_20260813.md)에 Marker 기반 Demo 상담사 배정, 타 상담사 404, Replay·Rollback, 목록·상세·Start 검증이 기록됐다.

완료하려면 고객용 Snapshot 확장 또는 별도 Guidance Route를 OpenAPI·Serializer·Service·Test와 함께 작성하고, Mobile이 만든 Inquiry UUID로 준비 명령→상담 요청→Web 동일 Inquiry 노출을 공동 실행한다.

별도 확인: Public Evidence 공개 필드와 PENDING 상태 공개 정책을 PM·AI·Mobile과 결정해야 한다.

### 2.4 4.4 상담사 Web Remote 공동 Smoke — 65%

- 8월 12일 실제 PostgreSQL·브라우저에서 전화 문의 등록→목록→상세→상담 시작→재조회 지속성은 PASS했다.
- Backend 합성 배정 Test에서 Demo 상담사의 목록·상세·Start와 타 상담사 404는 PASS했다.
- 상담 기록 저장·요약 확정·완료와 Mobile 최종 재조회까지의 공동 Smoke는 없다.

완료하려면 한예나와 Mock Off 환경에서 동일 Inquiry의 Start→Save→Confirm→Complete를 실행하고 DB Consultation·History·Version·Allowed Actions를 기록한다.

### 2.5 5.1 Happy Path 대표 E2E — 5%

- 합성 상담사 배정의 Backend 준비는 끝났지만 공용 AI·Mobile Guidance가 막혀 공동 실행은 시작하지 못했다.
- 8월 14일 방문 없이 고객→AI→상담 요청→Web 상담 완료→고객 재조회를 동일 Inquiry로 완주해야 한다.

### 2.6 5.2 최소 오류 — 60%

- 409 stale Version, 멱등 Replay, No-Evidence·Schema 실패의 단위·API Test는 있다.
- AI Timeout은 AIRun 감사 저장까지만 되고 자동 상담 전환은 `OPEN`; 실제 지연 주입 HTTP도 `NOT_RUN`이다.

완료하려면 PM 승인 Timeout Event를 적용하고 Replay·stale·Guard·History 1건과 실제 지연 주입을 검증한다.

### 2.7 6 전화 문의 등록 — 95%

- 실제 Browser·PostgreSQL 최소 Smoke와 Web Remote 구현 증거가 있다.
- 현재 최종 SHA에서 등록→목록→상세만 짧게 재검증하면 된다.

### 2.8 7 방문기사 P1 처리 — 100%

- 기존 Visit 코드와 Test는 보존했고 오늘 신규 기사 Runtime을 P0에 추가하지 않았다.

### 2.9 8 Blocker 처리 — 95%

- Backend→AI, Guidance Route, 상담사 배정, Web 완료 Blocker가 담당자와 해제 조건으로 중앙 등록됐다.
- 상담사 배정은 코드·PostgreSQL 작성자 검증까지 해제됐고, 중앙 Register 최신화와 실제 Mobile·Web Runtime PASS 회신은 아직 없다.
