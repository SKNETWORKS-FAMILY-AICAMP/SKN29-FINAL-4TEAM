## 2. 절별 평가와 완료 방법

### 2.1 4.1 Remote Mode 기준선 — 85%

- Production Build는 환경변수 누락 시 Mock으로 전환하지 않고 실제 API 경로를 기본으로 사용한다.
- Remote 목록·상세·상담 Write Repository, Token Refresh, `state_version`, `allowed_actions` 소비 코드가 있다.
- 이전 현재 HEAD 검증에서 Web 핵심 표적 **4파일·30 Test PASS**를 확인했고, PM 확인으로 전원이 최신 `main@945cb050ae1d9b9398a011fbfa970e22e09c769c`을 Pull했다.
- 공용 Backend·DB·AI URL과 합성 계정 Runtime은 아직 고정되지 않았다.

완료하려면 현재 후보 SHA의 `.env`에 공용 API URL을 설정하고 상담사 로그인→목록→상세→Action 가능 여부를 Browser Network와 함께 기록한다.

별도 확인: CORS·Token·Seed Inquiry와 Backend 로그 접근이 필요하다.

### 2.2 4.2 상담사 목록·상세 실제 Browser Smoke — 90%

- 8월 12일 실제 PostgreSQL·Browser에서 전화문의 등록→목록→상세→상담 시작→재조회 지속성이 PASS했다.
- Backend 합성 배정 구현에서 Demo 상담사 목록·상세·Start, 타 상담사 404, Replay·Rollback이 Test와 격리 PostgreSQL에서 PASS했다.
- 현재 Mobile 상담 요청에서 만들어진 동일 Inquiry를 실제 Browser로 확인한 것은 아니다.

완료하려면 Mobile이 만든 Inquiry UUID에 준비 명령을 적용한 뒤 해당 ID로 목록·검색·상세·새로고침·403/404·Mock 비혼입을 실제 Browser에서 확인한다.

### 2.3 4.3 실제 AI Guidance·Public Evidence 표시 — 35%

- Remote 상세은 `usage_guidance_status`, 메시지, 제한 기능을 표시하는 Mapper·UI를 갖고 있다.
- 오늘 추가된 Dashboard의 AI 검수 UI는 “상세 API 연동 후 활성화” 상태이며 실제 AI 결과 증거가 아니다.
- Backend 고객 Public Evidence Route는 없고 상담사 상세에도 실제 Evidence 공개 데이터가 준비되지 않았다.
- 최신 PM 승인 문서는 Public Evidence 화면 고도화를 P0에서 제외하고 가짜 근거 대신 안전한 빈 상태를 허용한다.

완료하려면 Backend 실제 Guidance를 상세 DTO에 연결하고 Evidence 미제공 시 `공개 근거 미제공 / 상담 검토 필요`를 표시하며 내부 ID·점수·Prompt·경로 비노출 Test를 유지한다.

### 2.4 4.4 상담 Start→완료 실제 Remote — 70%

- Start·Save·Confirm·Complete Repository와 화면 Hook이 실제 API를 호출하며 409 입력 보존·동일 멱등키 Retry·중복 클릭 Test가 있다.
- 실제 Browser Smoke는 상담 시작까지만 확인됐고 기록·요약 확정·완료·재조회 증거는 없다.

완료하려면 Mock Off에서 동일 Inquiry를 Start→Save→Confirm→Complete하고 새로고침 후 상태·기록·Version이 Backend DB와 일치함을 기록한다.

### 2.5 5 Mobile→AI→Web E2E — 5%

- 합성 상담사 배정의 Backend 전제는 준비됐지만 Mobile Guidance와 실제 공동 Runtime이 막혀 실행되지 않았다.
- 8월 14일 Mobile에서 전달받은 Inquiry ID로 Web 8~12단계를 실제 Browser에서 수행해야 한다.

### 2.6 6 전화 문의 등록 최소 마감 — 95%

- CONS-04 실제 API·Fixture·화면·테스트와 Browser·PostgreSQL Smoke가 있다.
- 현재 SHA에서 등록→목록·상세의 최소 회귀만 필요하다.

### 2.7 7 최소 오류 검증 — 70%

- 409 Draft 보존·중복 클릭과 403/404·AI 빈 상태의 자동 Test가 있다.
- 실제 Backend 오류 응답을 사용하는 Browser 실행은 미완료다.

완료하려면 Happy Path 후 stale Version, 타 상담사 404, 존재하지 않는 Inquiry, AI 결과 없음 각각 한 번을 실제 환경에서 확인한다.

### 2.8 8 조기 완료 시 지원 — 15%

- Web 독립 연결이 끝나지 않아 공동 E2E 지원 단계에 진입하지 않았다.
- 완료 후 Mobile Inquiry ID와 Web 요청·Backend `correlation_id`를 대조해야 한다.

### 2.9 9 보류 업무 준수 — 50%

- Visit 신규 기능은 추가하지 않았다.
- 그러나 오늘 상담사 Dashboard·AI 요약 검수 UI가 대규모로 추가됐다. PM 승인 문서는 이를 동결 대상으로 명시하므로 더 확장하지 않고 실제 Remote 상담 흐름으로 즉시 복귀해야 한다.

### 2.10 10 Blocker 처리 — 85%

- 공용 Runtime·Mobile Guidance·상담사 배정·Web 완료 Blocker가 중앙 Register에 기록됐다.
- 상담사 배정은 Backend 코드·PostgreSQL 검증까지 완료됐지만 Register 최신화와 Web 전용 재현 화면·요청·실제 응답은 아직 없다.

## 3. 코드로 확인할 수 없는 사항

- 현재 Web이 실제 공용 Backend를 보고 있는지
- Backend 배정은 검증됐지만 Mobile이 생성한 Inquiry가 실제 Web 상담사 화면에 표시되는지
- 상담 기록·완료가 실제 PostgreSQL에 유지되는지
- AI Guidance·Fallback이 상담사에게 이해 가능한지와 PII 비노출
