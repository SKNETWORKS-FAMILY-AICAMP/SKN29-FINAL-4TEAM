# E01 전체 50문항 확인표 — Positive 43 + Negative 7

## 0. 먼저 알아둘 점: E01에서는 LLM이 답변을 생성하지 않았음

E01은 **생성형 LLM 답변 실험이 아니라 Retrieval 전용 Baseline 실험**입니다. 따라서 아래 50문항에 대해 GPT 같은 생성형 LLM이 최종 자연어 답변을 만든 기록은 E01에 존재하지 않습니다.

> E01 보고서의 실험 범위: 생성형 LLM 답변 품질은 평가하지 않고, **검색 정확도·제품 격리·No-Evidence 처리·지연시간**만 평가.

즉 아래 표의 `LLM 실제 답변`은 모두 **N/A — E01에서 생성 단계 미실행**입니다.

또한 E01의 Case별 상세 Retrieval 결과는 `.runtime/e01_three_model_baseline/case_results.jsonl`에 저장되도록 설계되었지만, `.runtime`은 Git 추적 대상이 아니므로 현재 GitHub 자료만으로는 각 질문의 실제 Top-1/Top-3 순위를 모두 복원할 수 없습니다. 현재 확인 가능한 확정 집계는 **Positive 43/43 Hit@5, Hit@1 67.44%, Hit@3 100%, Negative 7/7 No-Evidence**입니다.

## 4. 그러면 'LLM이 실제로 뭐라고 답했는지'는 어디서 봐야 하나?

E01에서는 볼 수 없습니다. E01의 파이프라인은 개념적으로 다음 지점에서 평가가 끝납니다.

```text
질문
  ↓
exact_sales_code 제품 필터
  ↓
Embedding / Retrieval
  ↓
Top-K Evidence
  ↓
E01 평가 종료

생성형 LLM 답변
  ↓
E01에서는 평가하지 않음
```

실제 생성형 LLM의 답변 품질을 비교한 실험은 **E04 Generative LLM Comparison**입니다. 다만 E04는 E03에서 GTE Top-5 Retrieval에 성공한 **39개 Answerable Case**를 고정 Evidence로 사용한 별도 실험이므로, 이 E01 50문항과 완전히 동일한 50건 Generation Run은 아닙니다.

따라서 **E01 50문항 모두에 대해 현재 채택 LLM이 실제로 어떻게 답하는지 보고 싶다면 별도의 Generation 확인 Run을 추가로 해야 합니다.** 그 결과는 E01의 기존 Retrieval Metric과 섞지 않고 `E01-보조 확인` 또는 별도 Appendix로 구분하는 것이 맞습니다.

## 5. E01을 이해할 때 핵심 한 문장

> **E01은 'LLM이 답을 잘 쓰는가?'를 본 실험이 아니라, '질문에 맞는 공식 근거를 올바른 제품 안에서 찾아오고, 근거가 없는 질문에는 아무 근거도 내놓지 않는가?'를 먼저 검증한 Retrieval Baseline이다.**
