# 고객 앱 중간 발표 시연 Runbook

## 1. 문서 기준

- 기준 브랜치: `personal/mobile-extension`
- 발표 자료 기준 커밋: `779e1a4`
- 대상 앱: 고객용 Android 앱
- 검증 단말: Samsung SM-F721N / Android 16
- 앱 패키지: `com.skn29.watercare.customer`
- Backend 연결: `http://127.0.0.1:8000`

## 2. 발표에서 설명할 연동 범위

### 실제 Backend 연동

- Backend 상태 확인
- Demo 고객 인증
- 저장 Token 재사용
- 현재 사용자 조회
- 고객 문의 생성
- 고객 문의 취소

### Mock 또는 Blocked

- 고객 제품·구독 홈 데이터
- 문의 상세·타임라인
- AI Guidance 조회
- 상담 요청
- 방문 일정
- QR 제품 조회

Mock 또는 Blocked 기능은 실제 연동 기능처럼 설명하지 않는다.

## 3. 발표 전 준비

### Backend

1. PostgreSQL Docker가 실행 중인지 확인한다.
2. Backend `/health`가 200인지 확인한다.
3. 발표 단말에 `adb reverse tcp:8000 tcp:8000`을 적용한다.
4. 발표 중 사용할 Demo 계정과 데이터 초기화 여부를 Backend 담당자에게 확인한다.

### Android 앱

1. 발표 기준 APK를 설치한다.
2. 앱을 완전히 종료한 후 다시 실행한다.
3. 저장 Token으로 고객 홈이 자동 복원되는지 확인한다.
4. 앱 실행 중 Crash가 없는지 확인한다.
5. 화면 회전, 절전, 알림 팝업을 발표 전에 차단한다.

### 보안

1. UUID, Token, 내부 사용자 ID가 보이는 터미널은 발표 화면에 띄우지 않는다.
2. `mobile/local.properties`를 발표자료나 화면 공유에 노출하지 않는다.
3. 실사용자 정보가 아닌 합성 Demo 데이터만 사용한다.

## 4. 발표 직전 점검 명령

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$package = "com.skn29.watercare.customer"
$apk = ".\mobile\customer-app\build\outputs\apk\debug\customer-app-debug.apk"

& $adb devices
& $adb reverse tcp:8000 tcp:8000
& $adb install -r $apk
& $adb shell am force-stop $package
& $adb shell am start -n "$package/.MainActivity"
```

## 5. 기본 시연 순서

### 1단계: 앱 시작과 저장 세션

- 앱을 실행한다.
- 로그인 화면을 거치지 않고 고객 홈으로 진입하는 것을 보여준다.
- 저장 Token을 이용해 세션이 복원되었다고 설명한다.

발표 설명 예시:

> 고객이 매번 다시 로그인하지 않아도 저장된 인증 정보를 확인해 기존 세션을 복원합니다.

### 2단계: 고객 홈

- 고객용 홈 화면을 보여준다.
- 제품·구독 정보는 현재 Mock 데이터임을 명확히 설명한다.
- `Backend 인증 연결됨 · 홈 데이터 Mock` 표시를 기준으로 실제 인증과 Mock 홈을 구분한다.

발표 설명 예시:

> 고객 인증과 사용자 확인은 실제 Backend에 연결되어 있고, 제품·구독 조회는 Runtime API가 아직 없어 Mock으로 분리했습니다.

### 3단계: 증상 입력

- `문진 시작`을 선택한다.
- 발표 증상으로 `출수량 저하`를 입력한다.
- 작성 중 입력값이 유지되는 화면 구조를 보여준다.

### 4단계: 문의 생성

- 발표용 데이터가 초기화된 경우에만 실제 문의를 제출한다.
- 제출 성공 후 Backend 상태와 허용된 행동을 표시하는 것을 설명한다.
- 이미 발표용 문의가 존재하거나 초기화 여부가 불명확하면 제출하지 않는다.

발표 설명 예시:

> 동일한 제출을 반복해도 중복 문의가 생기지 않도록 요청 식별자를 관리하고, Backend가 반환한 상태와 허용 행동만 사용합니다.

### 5단계: Guidance와 안전 화면

- 일반 안내 화면을 보여준다.
- 위험 안내 화면을 보여준다.
- 근거 없음 또는 네트워크 실패 화면을 보여준다.
- 이 화면들은 현재 명시적인 Mock 또는 Fallback Scenario임을 설명한다.

발표 설명 예시:

> 위험 상태에서는 해결이나 종료 버튼을 노출하지 않고, 안전한 안내만 제공합니다.

### 6단계: 상담 요청 제한

- 상담 요청 Runtime API가 제공되지 않아 실제 요청 버튼이 노출되지 않는 것을 보여준다.
- `상담 요청 준비 중` 안내를 보여준다.

발표 설명 예시:

> API가 없는 기능을 동작하는 것처럼 보이지 않도록 실제 버튼을 차단하고 준비 중 상태로 표시했습니다.

## 6. 문의 생성 없이 진행하는 안전 시연

Backend 데이터 초기화 여부가 확인되지 않으면 다음 순서만 사용한다.

1. 저장 세션으로 고객 홈 진입
2. 고객 홈의 실제 인증·Mock 데이터 구분 설명
3. 문진 입력 화면 확인 후 제출하지 않고 뒤로 이동
4. 개발 검증 도구에서 일반·위험·근거 없음·네트워크 실패 Scenario 확인
5. 상담 요청 Blocked 처리 확인

이 경로에서는 새 문의를 생성하거나 기존 문의 상태를 변경하지 않는다.

## 7. 장애 발생 시 Fallback

### Backend 연결 실패

1. 실시간 시연을 중단한다.
2. Backend 연결 실패 상태를 숨기지 않는다.
3. 명시된 오프라인 미리보기 또는 Mock Scenario로 전환한다.
4. 준비된 화면 캡처 또는 녹화 영상으로 흐름을 이어간다.

발표 설명 예시:

> 현재 발표 네트워크 연결이 불안정해 동일한 화면 흐름을 재현한 Fallback 자료로 이어가겠습니다.

### 앱 Crash

1. 앱을 완전히 종료한다.
2. 한 번만 재실행한다.
3. 재실행 후에도 실패하면 즉시 녹화 영상으로 전환한다.
4. 발표 중 코드 수정이나 재빌드는 하지 않는다.

### 문의 생성 실패

1. 입력값이 보존되는지 보여준다.
2. 오류 안내와 재시도 가능 여부를 설명한다.
3. 연속 재시도로 문의를 여러 개 생성하지 않는다.
4. Mock Guidance 화면으로 전환한다.

## 8. 발표 중 금지 사항

- 발표 당일 새 Dependency 추가
- Backend 또는 계약 파일 수정
- 발표 중 APK 재빌드
- 초기화가 확인되지 않은 상태에서 문의 반복 생성
- UUID, Token, 내부 ID가 포함된 로그 공개
- Mock 기능을 실제 API 연동으로 표현
- 기사 완료, 상담 완료, 방문 완료 기능을 구현 완료로 설명

## 9. 발표 완료 기준

- 앱이 단말에서 정상 실행된다.
- 저장 Token으로 고객 홈에 진입한다.
- 실제 연동과 Mock·Blocked 범위를 구분해 설명한다.
- 일반·위험·근거 없음·실패 화면을 재현한다.
- 상담 요청 미연동 상태가 안전하게 차단된다.
- 장애 발생 시 30초 안에 Fallback 자료로 전환한다.
