# 고객 앱 실연동 수동 검증 가이드

## 1. 목적

고객 앱의 자동 빌드와 설치 성공만으로는 실제 사용자 흐름의 정상 동작을 보장할 수 없다. 이 스크립트는 실제 Android 단말에서 Demo 로그인부터 문의 제출과 앱 재실행까지 직접 확인하고, 각 단계의 화면·메모·앱 로그를 하나의 증거 폴더에 저장한다.

## 2. 사전 조건

- 현재 브랜치: `jeonghyun`
- Backend: `http://127.0.0.1:8000/health` 응답 200
- `mobile/local.properties`
  - `CUSTOMER_CARE_MODE=REMOTE`
  - 유효한 `DEMO_SUBSCRIPTION_ID`
  - `SHOW_DEVELOPER_TOOLS=false`
- Android 단말 USB 연결 및 USB 디버깅 허용

## 3. 실행

저장소 루트에서 실행한다.

```powershell
cd C:\skn29\WaterCare

powershell -ExecutionPolicy Bypass `
  -File ".\mobile\scripts\week4-manual-flow-evidence.ps1" `
  -RepoPath "C:\skn29\WaterCare" `
  -DeviceSerial "R3CT8076D7B" `
  -ResetAppData
```

이미 빌드한 APK를 그대로 사용할 때는 `-SkipBuild`를 추가한다.

```powershell
powershell -ExecutionPolicy Bypass `
  -File ".\mobile\scripts\week4-manual-flow-evidence.ps1" `
  -RepoPath "C:\skn29\WaterCare" `
  -DeviceSerial "R3CT8076D7B" `
  -SkipBuild
```

## 4. 검증 단계

1. Demo 로그인
2. 고객 홈의 Backend 연결·REMOTE 데이터 출처·개발자 도구 숨김 확인
3. 증상 선택 또는 직접 입력
4. 실제 문의 제출
5. 문의 상태와 다음 행동 확인
6. 앱 종료 후 재실행과 상태 유지 확인

각 단계에서 휴대전화 조작을 마치고 Enter를 누르면 화면이 자동 저장된다. 이후 `PASS`, `FAIL`, `SKIP`과 메모를 입력한다.

## 6. 판정 원칙

- Backend 실패가 Fake 성공으로 바뀌면 FAIL이다.
- 미지원 기능이 실제 동작하는 것처럼 표시되면 FAIL이다.
- 실제 문의번호 또는 처리 상태가 확인되지 않으면 FAIL로 기록한다.
- 화면이 정상이어도 Backend 계약과 다른 행동 버튼이 나타나면 FAIL이다.
- 실패 항목은 재현 조건과 사용자 화면 문구를 메모에 남긴다.
