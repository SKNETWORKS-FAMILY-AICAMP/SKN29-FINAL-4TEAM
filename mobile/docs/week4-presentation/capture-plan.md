# 모바일 발표 화면 캡처 계획

## 1. 목적

- 실시간 시연 장애에 대비한 화면 순서 자료를 준비한다.
- 실제 Backend 연동과 Mock·Blocked 기능을 명확히 구분한다.
- 발표자료 제작 담당자가 모바일 구현 범위를 오해하지 않도록 캡처별 설명을 고정한다.

## 2. 캡처 저장 원칙

- 원본 캡처는 저장소에 바로 Commit하지 않는다.
- 검토 전 원본은 `.local-backups/presentation-captures/`에 저장한다.
- 발표자료에 필요한 안전한 이미지 복사본만 별도 전달한다.
- UUID, Token, 내부 사용자 ID, correlation ID가 보이는 화면은 사용하지 않는다.
- Android 상태 표시줄의 개인 알림과 개인정보를 제거한다.
- 합성 Demo 고객 데이터만 사용한다.
- 파일명에는 실제 사용자명, 문의 ID, 구독 UUID를 넣지 않는다.

## 4. 화면별 확인 사항

### 01 고객 로그인

- `고객 Demo 로그인` 버튼이 보인다.
- Backend 연결 상태가 표시된다.
- Token이나 내부 계정 식별자는 표시되지 않는다.

### 02 고객 홈

- 고객용 홈 화면과 빠른 메뉴가 보인다.
- `Backend 인증 연결됨 · 홈 데이터 Mock` 구분이 보인다.
- 제품·구독 정보가 Mock임을 발표자가 설명한다.

### 03 증상 입력

- 증상 입력 영역이 보인다.
- 발표 예시 증상은 `출수량 저하`를 사용한다.
- 제출 전 화면을 우선 캡처해 불필요한 문의 생성을 피한다.

### 04 문의 처리 상태

- 실제 문의 생성이 필요한 경우 Backend 담당자가 데이터 초기화를 확인한 후 한 번만 수행한다.
- 문의 ID나 내부 UUID는 이미지에 포함하지 않는다.
- 상태와 허용 행동 중심으로 캡처한다.

### 05 일반 안내

- 일반 자가조치 안내가 보인다.
- Mock Scenario임을 발표자료에서 표시한다.

### 06 위험 안내

- 위험 또는 사용 제한 안내가 보인다.
- 해결·종료 버튼이 노출되지 않는지 확인한다.

### 07 근거 없음

- 근거 부족 또는 추가 확인 안내가 보인다.
- 확정적인 자가조치나 해결 완료 표현이 없어야 한다.

### 08 네트워크 실패

- 오류 메시지와 재시도 경로가 보인다.
- 입력 내용이 유지되는 흐름을 설명한다.

### 09 상담 요청 Blocked

- 실제 상담 요청 버튼은 보이지 않는다.
- `상담 요청 준비 중` 안내만 표시된다.

## 5. 캡처 전 단말 설정

1. 방해 금지 모드를 활성화한다.
2. 개인 알림을 모두 지운다.
3. 화면 밝기를 일정하게 맞춘다.
4. 자동 회전을 끈다.
5. 화면 배율과 글자 크기를 기본값으로 맞춘다.
6. 배터리 부족 경고가 나타나지 않도록 충전한다.

## 6. 캡처 후 검수

- [ ] UUID가 보이지 않는다.
- [ ] Token 또는 Authorization 값이 보이지 않는다.
- [ ] 내부 사용자 ID가 보이지 않는다.
- [ ] 개인 알림과 연락처 정보가 보이지 않는다.
- [ ] 실제 연동·Mock·Blocked 분류가 설명과 일치한다.
- [ ] 버튼과 안내 문구가 화면 밖으로 잘리지 않는다.
- [ ] 발표 순서대로 파일명이 정렬된다.

## 7. 저장소 반영 원칙

- 원본 PNG와 영상은 기본적으로 Git에 포함하지 않는다.
- 발표자료 담당자에게 전달할 때도 민감정보 검수를 먼저 수행한다.
- 저장소 반영이 꼭 필요한 이미지는 팀 검토 후 최소 파일만 추가한다.
- 영상 파일은 저장소가 아닌 팀 공유 저장소를 사용한다.
