# 첫 번째 검색 실습 — 키워드 겹침

## 목표

사용자 질문과 설명서의 작은 구간(청크)을 비교하여 **겹치는 단어가 많은 순서**로 출력한다. 여기서는 검색 원리만 익힌다. 기존 WaterBridge AI 코드, 벡터 DB, LLM, Pytest는 사용하지 않는다.

## 파일

- `data/mini_corpus.json`: 사용자가 제공한 WPU-JAC104(D) 설명서 **37~38쪽 발췌**로 만든 3개 연습용 청크. **PDF 원본 대조 전**.
- `data/gold/mini3_gold_v0.1.json`: 기존에 작성한 3개 질문과 기대 근거. 검색기 순위 계산에는 사용하지 않는다.
- `src/keyword_search.py`: 간단한 단어 일치 검색. Python 표준 라이브러리만 사용.
- `tests/test_keyword_search.py`: 새로 만든 최소 요구사항을 점검하는 세 개의 작은 테스트.

## 실행 — Windows CMD

프로젝트 루트(`C:\SKN projects\final`)에서 실행:

```cmd
python portfolio_upgrade\src\keyword_search.py --demo
python portfolio_upgrade\src\keyword_search.py "제품 누수 발생"
python -m unittest discover -s portfolio_upgrade\tests -p "test_*.py" -v
```

## 검색 알고리즘을 이해하기

1. 질문을 단어로 분리한다. 예: `"필터 교체" → {"필터", "교체"}`
2. 매뉴얼 청크의 제목과 내용을 같은 방식으로 분리한다.
3. **점수 = 두 집합의 공통 단어 수**. 예: `{"필터", "교체"}` 중 두 단어 모두 있으면 2점.
4. 0점 청크는 반환하지 않고, 점수 내림차순으로 Top-K개를 보여준다. 동점이면 ID순.

**주의:** 이 방식은 한국어 형태소·조사·동의어·문맥을 이해하지 못한다. `"물 새요"`와 `"제품 누수"`처럼 다른 말로 표현하면 검색하지 못할 수 있다. 실패는 숨기거나 정답에 맞춰 코드를 고치지 말고 기록한다. 검색 지표는 다음 단계에서 직접 설계한다.

## 실행 결과를 보고 답해볼 질문

- 왜 `"제품 누수 발생"`은 올바른 절이 1위인데, `"정수기 아래에서 물이 새는 것 같아요"`는 엉뚱한 37쪽이 1위로 나왔을까?
- `"필터 교체"`는 서로 다른 두 청크를 찾아줄 수 있어. 그렇다면 점수만 높다고 정답이라고 할 수 있을까?
- 이 코드가 **유사한 의미를 가진 문장**까지 구분하려면 무엇이 부족할까?

## 성과 주장 제한

- 이 자료는 **3개 청크를 정답 발췌문으로 직접 구성한 교육용 데모**이므로, 그 결과를 실제 RAG 정확도로 보고하거나 포트폴리오에 비교 성과로 사용하지 않는다.
- 원래 사용설명서 PDF 및 모든 원문을 확인한 것이 아니며, 원문 텍스트를 단순 정리한 연습 자료다.
- 이후 10문항과 **더 많은 검색 후보 문단**을 확보해서 독립적인 평가셋을 만든다.
