# WaterBridge 실습 04 — 내 손으로 검색 지표 계산하기

**v3 기준 6일차(계획 날짜: 11/02). 실제 진행 날짜와 관계없이 완료 조건으로 진도를 관리.**  
기존 실습 01·02·03 파일은 **수정하지 않습니다.** 새 실습은 저장된 검색 순위를 다시 채점하므로 모델 다운로드나 GPU가 필요 없습니다.

## 오늘 필요한 이유

직전 실습은 3가지 방법의 `Hit@1`, `Hit@3`, `MRR@3`를 보여주었습니다. 하지만 출력 숫자를 그대로 받아들이기만 하면 1,049개 테스트가 뭔지 모르던 상황이 반복될 수 있습니다. **오늘은 숫자가 어떻게 만들어졌는지 이해하고 간단한 검증기를 직접 실행합니다.** 전체 CLI를 외울 필요는 없고, `score_one()` 함수에서 **첫 정답 순위 → Hit/RR** 계산하는 부분을 읽는 것으로 시작하세요.

### 1) 어떤 정보를 입력하나요?

- 정답지: `data/gold/mini10_gold_step02.json`의 `acceptable_chunk_ids`
- 검색 결과: `experiments/step03/embedding_comparison.json`의 각 질문·방법별 **순위가 지정된** `retrieved`
- 입력 규칙: **검색기의 점수를 절대 정답 판정에 사용하지 않습니다.** 순위와 정답 ID만 사용합니다.

### 2) 세 지표의 차이

| 지표 | 한 질문에서의 계산 | 예시 (정답이 2위) |
|---|---|---|
| `Hit@1` | 1위가 정답이면 1, 아니면 0 | `0` |
| `Hit@3` | 1~3위 중 **어느 하나**라도 정답이면 1 | `1` |
| `RR@3` | 1~3위 중 **첫 정답 순위**의 역수. 없으면 0 | `1/2 = 0.5` |
| `MRR@3` | **질문별 RR@3**를 모든 질문에 대해 평균 | 10개 질문의 RR을 합해 **10으로 나눔** |

두 검색기가 `Hit@3`가 같아도, 정답이 **1위에 더 자주 등장하는 검색기**는 `MRR@3`가 클 수 있습니다.

### 3) 실습 데이터에서 실제로 손 계산해 보기

- `Q002` embedding: 1위는 오답, 정답은 **2위**이므로 `Hit@1=0`, `Hit@3=1`, `RR@3=0.5`.
- `Q009` overlap: 정답은 **3위**이므로 `Hit@1=0`, `Hit@3=1`, `RR@3=1/3 ≈ 0.3333`.
- `Q007` BM25: 정답 검색 실패이므로 세 값이 모두 `0`.
- `Q008` BM25: 1위가 정답이므로 세 값이 모두 `1`.

**연습 질문:** Q002와 Q008은 Hit@3가 둘 다 1이야. 그런데 둘 중 어떤 질문의 RR@3가 더 높고, 왜 그럴까?

### 4) Recall@K는 왜 이번 파일에서 계산하지 않나요?

`Recall@K = 상위 K개에서 검색한 관련 문서 개수 / 전체 관련 문서 개수` 입니다. 전체 정답 문서 목록이 정말 **모든 필수 근거를 빠짐없이** 지정한 경우에 적합합니다.

하지만 Q001의 `acceptable_chunk_ids` 4개는 **대체 가능한 정답 후보(하나만 검색해도 Hit)**로 정의됐습니다. 4개 문서가 모두 필요한 질문이라는 뜻은 아닙니다. 따라서 이 목록만으로 문서 **필수 근거 확보율**이나 완전한 Recall을 확정하면 과장일 수 있습니다. 이번에는 `Hit`와 `MRR`를 먼저 제대로 계산합니다.

## 실행 (Windows CMD, 저장소 루트에서)

ZIP을 프로젝트 최상위 폴더에 압축 해제해 `portfolio_upgrade/scripts/evaluate_mini.py`가 생겼는지 확인합니다.

```cmd
cd /d "C:\SKN projects\final"
python -m unittest discover -s portfolio_upgrade\tests -p "test_mini_evaluation.py" -v
python portfolio_upgrade\scripts\evaluate_mini.py
```

실습 03에서 사용한 모델을 다시 불러오지 않고, **이미 저장한 JSON 결과**로 평가합니다. `embedding_comparison.json`이 없다면 먼저 실습 03 `--demo`를 다시 실행해 결과를 저장하세요.

Q007만 다시 확인하거나 K를 2로 바꾸려면:

```cmd
python portfolio_upgrade\scripts\evaluate_mini.py --case Q007
python portfolio_upgrade\scripts\evaluate_mini.py --k 2 --case Q002
```

**주의:** 실습 03은 상위 3개 결과만 저장했기 때문에 **Hit@5는 계산할 수 없습니다.** 5위를 보려면 먼저 검색을 `--top-k 5`로 다시 실행하고 새 결과를 저장해야 합니다.
