# WaterBridge 검색 실습 02 — 문서·질문 확장과 BM25 비교

## 0. 이번 실습이 필요한 이유

앞선 실습은 **3개 문서(절)·3개 질문**만 있었으므로, 검색 순위를 비교할 수는 있지만 검색 품질의 여러 실패 유형을 보기 어려웠습니다. 이번에는 똑같이 **사용자가 제공한 설명서 37~38쪽 세 증상의 발췌**를 *조건별 문단 8개*로 나누고, *자연어 질문 10개*로 확장합니다. 기존의 **정확히 일치하는 토큰 수**와 **BM25**를 **동일한 8개 문단·10문항**에서 비교합니다.

> **범위 주의:** 새로운 설명서 내용이나 원문을 임의로 만들지 않았습니다. 10문항은 원문 근거의 상황을 바꿔 표현한 **학습용 합성 질문**이며, 일부는 서로 같은 원인·시나리오를 공유합니다(Q003과 Q010). 최종 검색 성능이나 일반화 성과를 주장할 수 있는 평가셋이 아닙니다. 원본 PDF의 37~38쪽 자체는 이 작업에서 직접 대조하지 못했으므로 원문 확인 후 `USER_EXCERPT_ONLY_NOT_PDF_VERIFIED` 상태를 변경하십시오.

## 2. 실행 (Windows CMD)

Git 저장소 최상위인 `C:\SKN projects\final`에서 실행합니다.

```cmd
python portfolio_upgrade\src\compare_search_step02.py --demo
python portfolio_upgrade\src\compare_search_step02.py --query "물이 새는 것 같아요"
python portfolio_upgrade\src\compare_search_step02.py --demo --top-k 3 --out portfolio_upgrade\experiments\step02\comparison_results.json
python -m unittest discover -s portfolio_upgrade\tests -p "test_search_step02.py" -v
```

- **`--demo`**: 동일 질문 10개에 대해 두 검색기의 1위 결과·순위·평가값 출력
- **`--query`**: 단일 자유 질문으로 각 검색기의 결과를 보는 명령 (정답 없음, 성능 계산 없음)
- **`--out`**: 질문별 Top-K, 일치 단어, 평가 결과와 집계 값을 JSON으로 재현·보관
- **unittest**: 1단계 코드 변경 없이 검색기의 기본 조건과 작은 평가식을 확인

### 코드에서 확인할 내용

1. `keyword_search.py`의 `search()`는 공통된 **서로 다른 단어 개수**가 많은 순서로 정렬합니다.
2. `compare_search_step02.py`의 `bm25_search()`는 **문서에서 단어가 나온 횟수(tf)**, **단어가 몇 문서에 등장하는지(df)**, **문서 길이**를 반영합니다. 같은 단어가 많은 문서에서 출현할수록 개별 단어의 정보량이 작아지고, 특정 문서에서만 등장한 단어는 더 큰 가중치를 받는 경향이 있습니다.
3. `evaluate()`는 검색 결과가 나온 **뒤에** Gold ID를 확인합니다. Gold는 검색 점수 계산에 전혀 사용하지 않습니다.
4. **동일한 토큰 분리 방법**을 사용하기 때문에 BM25도 한국어의 조사·활용형·동의어를 해결해주지는 않습니다. `조리수를`↔`조리수`, `새는`↔`누수` 같은 다른 표현은 여전히 어려울 수 있습니다.

## 3. 실제 실행 결과 (실습 8문단·10문항, Top-3)

| 방법 | Hit@1 | Hit@3 | MRR@3 |
|---|---:|---:|---:|
| 단어 겹침 | **4/10 (40%)** | **6/10 (60%)** | **0.4667** |
| BM25 | **6/10 (60%)** | **7/10 (70%)** | **0.6333** |

이 값은 **작성된 10개의 연습 문제를 동일한 8문단 데이터에서 실제 실행한 출력**입니다. 예: Q008(필터 교체 후 출수량 저하)과 Q009(온수 시 출수 속도)가 BM25에서 Top-1 정답으로 바뀌었습니다. 반면 **Q007(조리수를 같이 쓰는데 물줄기가 약함)은 두 방법 모두 검색 결과가 없었습니다**. Q003 누수 역시 Top-1을 찾지 못했습니다.

> **성과 해석 금지:** 이 비교는 새 모델/서비스를 고도화했다는 증거가 아닙니다. 같은 세 원문 절을 나누어 만든 **서로 연관된 합성 질문**이고, 문서도 단 8개입니다. BM25가 독립 데이터나 실제 상담에서도 20%p 개선한다는 의미가 아닙니다. 이전 실습 `1/3` 결과와 이번 `4/10` 결과를 전후 개선으로 비교해서도 안 됩니다. 코퍼스와 질문이 둘 다 달라졌기 때문입니다.

### 지표 이해

- **Hit@1** = 정답으로 허용된 청크가 1위에 있던 질문 수 / 전체 질문 수
- **Hit@3** = 정답으로 허용된 청크가 상위 3개 중 하나 이상 있는 질문 수 / 전체 질문 수
- **MRR@3** = 질문마다 *처음 발견된* 정답의 순위 역수(1위 1, 2위 1/2, 3위 1/3, 미검색 0)를 평균
- **주의**: Q001/Q002는 넓은 질문이라 허용 근거가 각각 4개/3개입니다. **Hit은 '그중 하나를 찾았다'는 뜻**이지, 완전한 안내에 필요한 모든 원인과 조건을 찾았다는 뜻이 아닙니다. 추후 `all_required_evidence@K`로 따로 평가해야 합니다.
