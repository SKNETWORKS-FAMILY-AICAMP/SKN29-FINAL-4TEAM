# S11 독립 가상 시나리오 64건 — 내용 사전 검수

> **판정:** 자동 구조 검사는 통과했고, 질문·가상 근거·정답을 AI가 64건 대조했다. 아래는 **사전 내용 검수**이지 사람의 최종 승인이나 실제 WaterBridge 매뉴얼 학습 허가가 아니다. 원본 데이터와 Probe 정답 파일을 수정하지 않았다.

## 가장 중요한 결과

사용자 PC에서 **구조 테스트 16/16**, Qwen3 토크나이저 **최대 Train 610토큰 / 제한 768토큰**, 질문 영역 마스킹을 통과했다. 이로써 **데이터 파일의 형태와 길이는 적합**하다. 하지만 구조 검사는 답변의 사실·안전·적용 조건까지 보장하지 않는다.

64개 사례의 질문·정답 행동·근거 조합을 대조한 결과 **61건은 사전 검수에서 뚜렷한 불일치를 발견하지 못했고, Train 3건은 수정/재판정이 필요**하다. 이 수치는 실제 모델 성능이나 정답률이 아니다.

## 검증이 통과했어도 남은 근본적인 문제

- **확인한 기존 조건 0/64:** `known_conditions`가 모든 입력에서 빈 배열이다. S12에서 실제 상담의 이전 확인 사항을 활용하도록 학습했다고 주장할 수 없다.
- **근거는 64/64 모두 정확히 2개:** 그중 하나는 정답 관련 근거다. 검색 누락, 관련 근거 0개, 많은 혼동 문서 상황을 테스트하지 못한다.
- **행동별로 같은 틀이 반복됨:** 16개 제품에서 각 4개 행동이 동일 패턴으로 등장한다. 제품군을 분리했더라도 원리 일반화 성능이나 실제 고객 대응 성능을 입증하지 못한다.
- **Probe는 최종 블라인드가 아님:** 이 검수 작업에서 Probe의 정답도 열어보았다. 제품별 그룹은 분리돼 있지만 이후 모델·프롬프트를 튜닝하는 데 Probe 결과를 이용한다면 독립 평가라고 주장하면 안 된다.

## S12 이전 결정

**S12 소형 가상 SFT 기술 실험**은 기존 S10과 달리 48건의 새 행동 균형 데이터를 사용해 파이프라인 비교를 시도할 수 있다. 하지만 위 세 사례를 먼저 정리하고, 기존 조건·근거 부족·조건 충돌을 포함하는 새 데이터/평가 사례를 최소한으로 추가해야 **조건 기반 학습 효과**까지 검증할 수 있다.

사람의 정답 검수 승인 및 매뉴얼 기반 데이터 권한은 아직 확인되지 않았다. **실제 WaterBridge 고객지원 SFT/서비스 품질 개선 성공으로 주장해서는 안 된다.**

## 재현 가능한 증거

- 사용자 제공 터미널: `--check`, `--write`, `--token-check`, 16개 단위 테스트 PASS.
- 기준 원본: `portfolio_upgrade/data/s11_grounded/s11_fictional_train_draft.jsonl`, `s11_fictional_probe_inputs.jsonl`, `s11_fictional_probe_targets_EVAL_ONLY.jsonl`, `s11_fictional_build_summary.json`.
- 본문별 상세 검수: `portfolio_upgrade/experiments/s11_readiness/s11_fictional_content_pre_review.json`의 `case_checks` (64건).
- 검수본은 원본 데이터를 보존하며 **정답과 학습용 승인 상태를 자동 변경하지 않는다**.
