# S11 · P1 실제 근거 재검수 결과

> **상태: 1차 원문·모델 입력 대조 완료 / 학습 승인 아님.** 기존 S07 학습 후보·S09 검색 결과·M2 기록은 수정하지 않았다.

## 0. 한눈에 보기

S11의 `AUDIT PASS`는 파일 사이에 ID·라벨·분할 불일치가 없다는 뜻이다. **검색된 근거가 답변 문장을 모두 뒷받침한다는 뜻이 아니다.**

- 감사 큐의 **P1 원본 4건**과 각각의 BASE/PAR1을 포함한 **8행**을 확인했다.
- 필요한 근거가 검색 모델 입력에 부족한 행 **6/8**, 핵심 누락 근거가 제공된 행 **2/8**. 이는 아래 P1 네 상황에 한정된 검수이며 나머지 전체 18행을 재검수했다는 뜻이 아니다.
- 공식 PDF 실제 페이지를 대조했다: IAC425 **5·27·43·45쪽**, IAC606 **24·29·40·41쪽**.
- 더 중요한 구조 문제: **동일한 `evidence_group_id` 아래에 질문마다 서로 다른 청크 텍스트가 들어온다.** 26행 전체에서 33개의 고유 근거 그룹 ID 중 3개가 둘 이상의 본문 변형을 보였다. 로그상 구조 자체는 가능하지만, 인용 ID만으로 특정 문장을 재현·검증할 수 없다는 위험이 있다.

|---|---|---|---|

## 2. 왜 같은 ID로 다른 문서를 보여주나?

현재 M2 검색 입력 생성 코드 `portfolio_upgrade/scripts/m2_build_train_retrieval_preview.py`의 `pack_record()`는 **상위 검색된 child 청크**들을 `evidence_group_id`로 묶고, 검색 목록에 포함된 청크의 텍스트만 이어 붙인다(코드 93~103행).

따라서 고객 질문 표현이 바뀌어 검색된 child 청크 집합이 달라지면, **같은 EVD 그룹 ID라도 본문과 페이지 집합이 달라진다.** 이것은 그룹 ID를 문서 전체의 유일한 인용 단위처럼 취급할 때 특히 위험하다.

26행 전체에서 확인된 그룹 ID 본문 변형:

| 근거 ID | 발견된 본문 변형 수 | 관련 예시 |
|---|---:|---|
| `EVD-WPUIAC425SNW-LEAK-001` | 2 | IAC425 누수 BASE/PAR1 |
| `EVD-WPUJAC104DWH-INSTANT-HOT-WATER-SAFETY-001` | 6 | JAC104 소음/냉수 등 3개 원본의 BASE/PAR1 |
| `EVD-WPUJAC104DWH-COLD-TEMPERATURE-001` | 2 | JAC104 냉수 관련 원본/재표현 |

**수정 방향은 두 가지 중 하나를 분명히 선택하는 것:** (A) 검색된 **child ID + 실제 청크 본문**을 일관되게 인용하고 그룹 ID는 평가·분류용 메타데이터로만 두기, 또는 (B) 그룹을 인용 단위로 유지한다면 **정규화된 그룹 본문/페이지**를 항상 제공하고 해당 그룹의 모든 필수 문단이 포함되는지 검증하기. **Gold를 검색 결과에 강제로 넣어 100%를 만드는 방식은 금지.**

## 3. 다음 S11 작업 — 순서가 중요한 이유

1. **검색·인용 계약부터 수정:** 지금처럼 같은 ID로 서로 다른 본문을 내보내는 모델 입력을 그대로 학습시키지 않는다. 정확히 어떤 child/그룹 본문을 제공했는지 식별 가능해야 한다.
2. **P1 절차·안전 근거 보완:** 425/606 냉수 잠금 해제 상세 절차를 정식 인덱스의 관련 검색 후보로 추가하는 방안을 검토한다. 425 누수는 기존 PAR1에도 안전문단이 포함된 점을 인정하고 BASE 누락만 해결한다. 606 소음 BASE에서 DEFROST 근거를 확보하지 못하면 해당 설명을 정답에 강제하지 않는다.
3. **독립 학습 사례 설계:** `EXPLAIN_UNSUPPORTED` 학습 원본이 0건이므로, **명시적으로 미지원임을 확인할 수 있는** 허용된 가상 제품 사양을 기반으로 별도 신규 시나리오를 설계한다. 실제 Dev/Holdout 문장을 변형해 Train에 넣지 않는다.
4. **출처·사용 범위 검토:** 공식 사용설명서와 가공 데이터의 학습 가능 범위가 아직 불명확하다. S07 26건의 `training_ready=false`를 유지하고 학습·어댑터 공개에 앞서 이용 근거를 별도로 확정한다.

## 4. 이번 검수의 범위와 근거

- **입력:** `s11_audit_summary.json`, `s11_case_queue.csv`, `s09_train_retrieval_preview.jsonl`(업로드 사본)와 해당 PDF 실제 페이지.
- **원본 코드 확인:** GitHub `seunghyuk` 브랜치의 `m2_build_train_retrieval_preview.py` `pack_record()` (코드 93~103행), 2026-10-31 확인 커밋 `392dfac` 기준.
- **새로 한 것:** 업로드된 JSONL에서 **모델에 실제로 제공된 검색 텍스트**를 추출해 PDF와 대조, BASE/PAR1 차이를 재계산.
- **하지 않은 것:** BGE-M3 재검색, 서비스 DB/운영 코드 수정, S07 정답 수정, 새 SFT 학습, 법적 사용 허락 판정, S08 Holdout 평가.

> **결론:** S11의 P1 작업은 이제 단순한 *데이터 건수 확보*가 아니라 **검색 근거의 정확한 식별·충분성 문제를 먼저 해결**하는 과제로 구체화됐다. `AUDIT PASS`와 `학습 GO`는 다른 상태다.
