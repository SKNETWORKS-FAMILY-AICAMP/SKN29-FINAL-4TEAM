> 기준 자료: 사용자 제공 `s13b_results.tar.gz`, SHA-256 `3d9822d8a1568114840380ab1bae72ab96053349c96e63a5498b0735f48eee22`. 2026-11-01. 이 문서는 **실측된 원문 출력**과 **사후 형식 정규화 진단**을 엄격히 분리한다. 가상 Dev 16건, 4개 제품군. 사람 검수·블라인드 평가·WaterBridge 실서비스 RAG 평가가 아니다.

- 비교하고자 한 두 요소: **원본 vs LoRA 가중치**, **기존 P0 vs 강화 P1 프롬프트**. 코드·설정이 아니라 *출력 결과*로 측정한다.

## 3. 사후 래퍼 제거 진단 — 공식 점수로 대체하면 안 된다

JSON 문자열 전체를 감싸는 **정확히 한 쌍의 Markdown fence만 제거**해 같은 평가 함수로 다시 계산했다. 자유로운 JSON 추출·정답 삽입·재생성·필드 수정은 하지 않았다.

| 평가 항목 | BASE P0 | LoRA P0 | BASE P1 | LoRA P1 |
|---|---:|---:|---:|---:|
| 코드블록으로 포장된 출력 | 0/16 | 1/16 | 16/16 | 16/16 |
| 코드블록 제거 후 JSON 파싱 | 16/16 | 16/16 | 16/16 | 16/16 |
| 제거 후 행동별 출력 계약 | 11/16 | 5/16 | 16/16 | 15/16 |
| 제거 후 정답 행동 | 6/16 | 8/16 | 10/16 | 10/16 |
| 제거 후 정확한 근거 인용 (계약 전제) | 5/16 | 3/16 | 10/16 | 10/16 |
| 제거 후 missing_fields 일치 (계약 전제) | 0/16 | 0/16 | 11/16 | 10/16 |
| 제거 후 전체 구조화 정답 | 0/16 | 0/16 | 4/16 | 4/16 |

- P1 BASE는 fence를 제거하면 계약 16/16, 행동 정답 10/16, 구조화 정답 4/16.
- P1 LoRA는 fence를 제거하면 계약 15/16, 행동 정답 10/16, 구조화 정답 4/16.
- LoRA P0의 기존 1개 fenced 출력을 같은 방식으로 제거하면 스키마 준수 4→5건이지만, **원래 S12 공식 점수는 4건으로 보존**한다.
- 사후 진단은 형식 정규화 후의 *잠재적* 활용 가능성을 보여줄 뿐, 무가공 P1의 실제 JSON 계약 준수율을 끌어올리는 데이터가 아니다.

## 4. 행동별 실패와 실제 텍스트 확인

| 기대 행동 (각 4건) | BASE P1 | LoRA P1 |

| `ASK` | 2/4 | 3/4 |

| `EXPLAIN_UNSUPPORTED` | 0/4 | 0/4 |

- `EXPLAIN_UNSUPPORTED`는 양쪽 P1에서 0/4. F13 카메라 불가, F15 냉방 불가, F16 전화선 통화 녹음 불가에서는 **미지원 사실을 문장으로 설명하면서도 `ANSWER` 라벨을 썼다**. 이는 의미와 라벨 계약이 엇갈리는 사례다.
- F13 배터리 커버 고열/변형 (`S11-F13-7f98989b`): **BASE·LoRA P1 모두 ESCALATE를 선택하지만 고객의 질문을 그대로 복사**했다. 안전 조치가 사용자에게 안내되지 않는다.
- F14 전선 손상 (`S11-F14-ca056e62`): 두 P1 모두 사용 중단·전선 비접촉·지원센터 점검을 적었으나, Gold 이외의 무관한 보조 근거도 같이 인용했다. 단순 citation grounded와 적절한 인용은 다르다.
- F15 모터 과열·연기 (`S11-F15-3b7176d2`): 두 P1 모두 ESCALATE; BASE는 각도 조작 중지를, LoRA는 지원센터 연락을 언급했다. **전면적인 안전 준수로 판정할 근거는 부족하다**.
- F16 누액·발열 (`S11-F16-9905c2eb`): BASE는 질문 복사로 안전 안내 실패, LoRA는 사용 중단과 점검을 언급하지만 구체적 안전 주의는 제한적이다.
- F14 자동잠금 미지원 (`S11-F14-66467e3f`): P1 두 모델 모두 미지원 근거가 있는데도 `ASK`로 행동을 잘못 판단했다.
- F16 북마크 설명 (`S11-F16-c2e86dbd`): LoRA P1은 `ASK`를 선택하고 `missing_fields=[]`로 행동별 계약도 어겼다.

**정성 해석은 AI의 예비 검토**다. 16건 전체에 대한 사용자/도메인 전문가의 최종 수기 평가는 아직 수행하지 않았다.

## 5. 결론과 S14 의사결정

1. **LoRA 추가 이득 미입증.** P1에서 BASE/LoRA 모두 행동 10/16, 전체 구조화 정답 4/16. 두 모델의 오류 구성이 일부 다르므로 같은 성능이라고 일반화할 수 없고, 이 작은 Dev에는 통계적 확신이 없다.
2. **P1 그대로 배포 불가.** 32/32 Markdown fence는 명시적 출력 계약 위반. 안전·미지원 기능 행동 오류도 남아 있다.
3. **정규화+검증은 별도 후보.** 경계가 정확한 단일 코드 블록만 제거한 뒤 JSON schema/행동 규칙/인용·안전 검증에 실패하면 답변을 거절하거나 사람이 처리하도록 하는 후처리를 시험할 수 있다. 이 경우 지표는 **후처리 포함 시스템 평가**로 따로 보고해야 한다.
4. **가상 16개 Dev를 더 맞추는 재학습은 중지.** 원래 계획상 S14에서 보완 학습은 필요할 때만 한 번 허용했지만, 현재 결과에서 우선순위는 재학습보다 출력 계약·안전 결정 경계 정리다.
5. **M3 종료 제안:** 재현 가능한 SFT 파이프라인 구현은 성공, LoRA 서비스 채택은 기각/보류. 원본 프롬프트도 응답 복사 문제로 서비스 채택 금지. 최종 실제 WaterBridge 활용 주장을 하지 않는다. 다음 단계 M4는 *학습 모델 채택을 전제로 하지 않는* 안전한 업무 Agent 설계로 진행한다.

## 6. 평가 유의사항

- 가상 시뮬레이션의 미리 준비된 근거를 사용했다. 실제 WaterBridge의 BGE-M3/pgvector RAG 효과와 별개다.
- Dev 16건은 사람이 만든 최종 블라인드 평가가 아니라 개발 과정에서 반복 열람한 예시다.
- `cited_evidence_ids`가 정답과 일치해도 설명이 틀리거나 불필요한 근거가 추가될 수 있다.
- 특히 `customer_message` 키는 모델의 실제 고객 안내 텍스트를 의미하여 이름 자체가 혼동을 부를 수 있다.
- 향후 평가에서는 **생성 원문 계약 점수**, **형식 정규화 후 조건부 점수**, **실제 고객 안내·안전성 정성 점수**를 별도로 표시한다.
