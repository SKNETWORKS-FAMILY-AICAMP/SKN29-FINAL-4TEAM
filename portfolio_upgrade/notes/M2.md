## S06 — 응대 행동 정답 스키마와 공식 PDF 검수

### 0. 실험 한눈에 보기

- **무엇을 했나?** S04 Train 18건 중 15건의 질문·행동·필수 조치 초안을 선택하고, 공식 사용설명서 3종의 해당 페이지와 직접 대조했다.
- **핵심 결론:** 고객 응답 내용은 15건 모두 매뉴얼 근거를 확보했다. 다만 **`ASK`였던 버튼 명칭 문의 2건은 바로 답할 수 있는 사안인지 다시 검토**해야 한다.
- **실험이 아닌 것:** 모델 학습, 검색 성능 실험, 실제 고객 E2E, 학습 데이터 사용 권한 승인.
- **어디를 보면 되나?** [`s06_review_cards.md`](../data/training/s06_review_cards.md)의 각 고객 질문·원문 페이지·검수 답변을 읽는다.

### 1. 실험 정의 — 무엇을 정답으로 삼는가?

고객 질문 하나를 **입력(`input`) → 올바른 행동과 답변(`target`) → PDF 근거/분할(`provenance`) → 검수 상태(`review`)**로 분리한다.

| 원본 행동 | 의미 | 구체적인 예 |
|---|---|---|
| `ANSWER` | 설명서와 조건이 충분하므로 안내 | 냉수 연속 다량 사용 → 기다린 후 재출수 |
| `ASK` | 결정에 필요한 정보가 부족함 | 소리가 지나치게 큰지, 언제 지속되는지 확인 |
| `ESCALATE` | 안전 또는 지속 이상으로 상담 필요 | 2시간 후에도 냉수 미지근함, 제품 누수 |
| `TOOL_REQUEST` | 정해진 도구 호출 제안 | 향후 상담 접수 전 고객 확인과 업무 계약 필요. **S04의 Train에 없음** |

`forbidden_claims`는 **검수자가 설정한 금지 주장**이며 제조사가 그대로 쓴 문구를 복제한 것이 아니다. `cited_evidence_ids`는 아직 `null`이다. 검색기를 실행해 모델에게 실제로 제공된 문서 목록을 확정하지 않았기 때문이다.

### 2. 실험 목적 — 왜 이 단계를 거치나?

S05에서는 *검색이 정답을 놓치는 경우*와 *정답 근거가 있어도 답변의 적용 조건을 넘는 경우*가 모두 있었다. 서로 다른 실패를 **한 종류의 LLM 학습 오류로 묶으면** 고쳐야 할 부품을 잘못 선택할 위험이 있다.

또한 합성 시나리오에는 **팀 평가용 요약에 없지만 공식 PDF에는 있는 조치**가 있었다. 예를 들어 IAC425에서 조리수 동시 사용 때문에 출수량이 줄어든 문의에 대한 핵심 안내는 '필터 교체'가 아니라 **조리수 사용을 멈추고 다시 출수**하는 것이다.

### 3. 실험 과정 — 어떻게 검수했고 어떤 판단을 했나?

**첫째. 입력을 원본 S04와 연결했다.** 30건을 Train 18 / Dev 6 / Holdout 6으로 나누고 같은 의미 그룹이 분할을 가로지르지 않았던 이전 결과를 그대로 유지했다. S06 대상은 Train만 15건이며 **7개의 의미 그룹**이다. 15개의 완전히 독립된 문제라고 말하지 않는다.

**둘째. 공식 PDF를 직접 확인했다.** 세 설명서의 파일 SHA-256을 S04 검수 기록과 대조했고 전부 일치했다.

| 원문 | 판본 | PDF 페이지 수 | 검수한 대표 위치 |
|---|---|---:|---|
| WPU-IAC425 | REV.02 | 52 | 5, 10·12·15·17, 27, 43~45쪽 |
| WPU-IAC606 | REV.00 | 48 | 5, 10·12·15·18, 24, 40~42쪽 |
| WPU-JAC104(D)/JCC104(D) | REV.00 | 44 | 12~13, 15, 37~38쪽 |

**셋째. 기술적 판단을 기록했다.**

1. **제품별 지침 구분:** IAC425/606의 누수 조건은 물받이 넘침 여부 확인 → 중간 밸브 잠금 → 상담센터 연락이다. JAC104의 누수 지침에는 **원수 밸브 잠금과 플러그 분리**가 명시되어 있어 같은 문장으로 뭉뚱그리지 않는다.
2. **근거 원문 vs 팀 인덱스:** IAC425/606의 버튼 문의에는 PDF에 정답이 있어도 기존 평가용 Gold ID가 비어 있다. **원문에 답 없음**과 **인덱스에 근거 없음**은 다르다.
3. **ANSWER/ASK 라벨 점검:** IAC425·606의 버튼 문의는 제품 코드가 정확하면 설명서로 직접 답할 수 있다. 원본 `ASK`는 **보존**하되 라벨의 타당성은 추가로 검토한다.
4. **필수 조치 우선:** IAC425-102/106, IAC606-102는 기존 요약에서 주 조치 누락이 기록돼 있어 PDF 본문의 안내를 우선한다.
5. **실행 상태를 지어내지 않음:** 냉수가 2시간 후에도 미지근하면 '상담센터에 문의'를 안내하지만, 방문 배정·예약 완료는 보장하지 않는다.

**넷째. 답변을 검수했다.** 15건 모두 `assistant_message`와 `forbidden_claims`를 작성하고 원문 페이지·해시·판단 근거를 기록했다. **원본 `examples_v0.jsonl`은 바꾸지 않았으며**, 검수판을 별도 파일로 만들었다.

### 5. 결과 해석과 결론 — 다음에 무엇을 결정할까?

**S06의 PDF 정답 검수 자체는 끝났다.** 다만 학습을 시작할 준비가 끝났다는 뜻은 아니다. 남은 결정은 (a) 버튼 문의 2건의 `ASK`/`ANSWER` 라벨, (b) Gold가 빠진 문서 근거 보강, (c) 데이터 이용 범위/라이선스 및 학습 텍스트 사용 조건, (d) S08의 모델 입력 근거·인용 계약이다.

**중요한 구분:** 원문 PDF 내용 검수가 완료돼도 **검색으로 그 문서가 실제 제공되는지**는 알 수 없다. `input.evidence=[]`와 `cited_evidence_ids=null`을 유지했으며, Gold ID를 모델의 입력에 섞어 성능이 높아 보이게 하지 않는다.

## S07 — 학습 데이터 소규모 다양화와 검수 (파일럿 내용 검수 완료)

### 0. 실험 한눈에 보기

- **수행한 것:** S06에서 공식 원문과 대조한 Train 15건 중 행동 라벨이 안정적인 13건을 사용해, **원본 13건 + 질문 재표현 13건 = 총 26건**의 검수용 초안을 만들었다.
- **의도적으로 제외:** 버튼 명칭 불일치 때문에 `ASK`인지 `ANSWER`인지 미확정인 `SYN-IAC425-110`, `SYN-IAC606-110` (원본 라벨을 수정한 것이 아님).
- **S07 생성 당시 못 한 것:** 실제 검색 근거 공급, 학습 데이터 사용 범위 확인, 모델 학습, 독립 일반화 평가. 검색 근거 연결 결과는 이 문서의 마지막 M2 후속 검수 절에 반영했다.
- **즉시 확인:** `data/training/review_log_s07_checked.csv`를 Excel로 열어 ‘원본 질문·재표현·검수 상태’를 본다. (생성 직후의 검수 전 로그는 `review_log.csv`로 보존)

### 1. 실험 정의 — 어떤 데이터 변형을 하나?

고객 질문의 **표현만 바꾸되**, 제품 판매코드·이전에 확인한 조건·적용 시간·부정 표현·안전 신호·정답 행동은 바꾸지 않는 *통제된 재표현(controlled paraphrase)* 파일럿이다.

예: IAC425에서 **조리수를 사용하는 동안에만** 출수량이 약해지고 **사용을 멈추면 다시 정상**이라는 조건을 바꾸지 않고 질문 표현만 다듬는다. 조리수 중단 조치를 가리키는 S04 정답도 그대로 유지한다.

### 2. 실험 목적 — 단순 복제보다 무엇이 낫나?

모델이 정확히 같은 고객 문장만 외우지 않고, 같은 조건을 다른 말로 표현한 문의에도 적절한 행동을 선택하도록 *학습 후보*를 다양화하려는 것이다. **하지만 13개 문의를 26문장으로 늘려도 독립 시나리오가 26개가 되는 건 아니다.** 원본의 `semantic_group_id`를 그대로 유지한다.

### 3. 실험 과정 및 기술적 판단

1. **분할 보호:** 기존 `examples_pdf_reviewed_v1.jsonl`만 읽고 `split=train`을 검사한다. Dev 6건과 Holdout 6건은 **읽거나 복제하지 않는다**.
2. **행동 라벨 보수적 선택:** PDF 검수 상태 `consistent_with_manual`인 13건에만 새 문장 1개씩 부여한다. IAC425-110/IAC606-110 두 건은 `s07_label_review_queue.jsonl`에 별도 보관한다. 부정확한 라벨을 억지로 확대하면 잘못된 행동을 학습시킬 수 있기 때문이다.
3. **조건 보존:** `input.known_conditions`, `target`, 제품 코드, 원문 페이지, Gold 근거 목록을 **그대로 복사**한다. 고객 질문 문장만 바꾸며 실험자가 만든 재표현은 `review.status=needs_review`로 처리한다.
4. **안전성:** `ESCALATE`와 누수 사례를 포함해 모든 신규 문장을 검수 대기 대상으로 표시한다. 변형된 문장에서 누수·지속시간·부정 표현 등이 사라졌다면 **기각하거나 다시 작성**한다.
5. **학습/평가 정보 분리:** `input.evidence=[]`, `target.cited_evidence_ids=null`을 유지한다. **정답 Gold를 모델에게 제공되는 실제 검색 결과인 것처럼 주입하지 않는다.** `training_ready=false`도 유지한다.
6. **자동 검증:** `s07_validate_pilot.py`는 건수, 중복, Train 소속, 출처·정답 보존을 확인한다. **의미 보존·PDF 저작물 이용·안전성은 자동 확인하지 못하므로 사람 검토가 필요**하다.

Windows CMD에서 저장소 루트를 기준으로 다음 명령을 실행한다.

```cmd
python portfolio_upgrade\scripts\s07_prepare_pilot.py
python portfolio_upgrade\scripts\s07_prepare_pilot.py --write
python portfolio_upgrade\scripts\s07_validate_pilot.py
```

## S08 — 학습 전후 비교 규칙 고정 (B0/B1 진단 완료)

### 0. 실험 한눈에 보기

**핵심 질문:** ‘SFT 이후 점수가 좋아졌다고 할 때, 그 원인이 학습이라고 말할 수 있으려면 무엇을 같게 해야 할까?’

S05에서 사용한 GPT-4.1-mini의 Dev 행동 일치 6/6은 **Qwen3-1.7B의 SFT 학습 전 성능이 아니다.** 같은 모델의 학습 전/후를 비교해야 한다. S08에서는 기존 S04 분할과 S07 데이터의 누출 위험을 확인하고, 이후 Qwen3를 실행할 평가 입력·정답을 **서로 분리**한다.

**현재 확인:** 사용자 Windows 환경에서 분할·누출 점검과 Dev 입력 6/6 구성 완료. RunPod A40에서 B0 기본 프롬프트와 B1 강화 프롬프트를 각각 6건씩 실행·검수했다. Dev 결과를 여러 번 본 상태이므로 **독립 일반화 성능이 아닌 진단**으로 취급한다.

### 1. 실험 정의

S04 파일럿 데이터 30건을 원래 분할 그대로 유지한다. Train 18건, Dev 6건, Holdout 6건이며 총 16개 의미 그룹이다. S07에서는 Train 가운데 13건을 표현만 달리해 26개 행을 만들었으나 **독립적인 의미 그룹은 6개**다.

- **Train:** 모델의 가중치를 업데이트할 후보 데이터. S07의 26개는 `training_ready=0`이므로 아직 학습하지 않는다.
- **Dev:** 프롬프트·학습 설정 선택용 6건. 결과가 좋더라도 일반화 성능으로 부르지 않는다.
- **Holdout:** 최종 평가 전까지 모델·규칙·학습 설정 선택에 쓰지 않는다. 기존 파일럿 6건은 최종 주장에 비해 적다.

### 2. 실험 목적

학습 후 성능을 비교할 때 기반 모델·검색 근거·답변 형식·디코딩 설정·평가 질문이 달라지면, 좋아진 이유가 SFT인지 검색·프롬프트 차이인지 구분하기 어렵다. 또한 Gold 정답 ID를 검색 전에 제공하면, 모델이 스스로 관련 근거를 찾은 결과가 아니다.

### 3. 실험 과정과 기술적 판단

1. `s08_prepare_eval.py`로 S04의 **30개 사례·16개 의미 그룹·18/6/6 분할**, Train 자료만 사용한 S07 26건을 검사한다.
2. 동일한 그룹이 Train/Dev/Holdout을 가로지르거나 동일 질문이 중복 배정되면 중단한다. 중복 열 `manual_answerable`도 값이 같을 때만 허용한다.
3. **Dev 모델 입력과 Dev 정답을 별도의 파일**로 관리한다. 모델 입력에는 고객 질문, 제품, 이전 확인 사항, **실제 검색된 근거만** 넣는다. 정답 행동·Gold 문서 ID는 모델 입력에 넣지 않는다.
4. S05의 BGE-M3 원본 검색 JSONL을 연결할 수 있을 때 `--retrieval-file` 옵션으로 Dev 6건의 고정 근거를 생성한다. 입력 파일의 SHA가 다르면 실험을 중지하고 다시 검색한다. **원본 BGE 검색과 S05의 안전 라우팅 검색을 섞지 않는다.**
5. 같은 Qwen3 기반 모델을 학습 전/후로 실행하되, 질의·근거·출력 스키마·디코딩 설정을 고정한다. 처음에는 `action_accuracy`, 인용 ID 유효성만 자동 점검하고, **필수 조치·조건 위반·인용의 문맥 적합성은 PDF로 별도 확인**한다.

**기술 선택:** `Hit@5`나 `invalid_cited_ids=0`만으로 최종 답변 안전성은 입증되지 않는다. 같은 Dev에서 튜닝한 구성을 Dev에서 재평가한 값은 개발용 결과다. Holdout을 봐가며 개선하면 독립 보류 데이터가 아니다.

## S09 — 학습할 기반 모델·형식·자원 사전 점검

### 0. 실험 한눈에 보기

**실제로 검증한 후보:** `Qwen/Qwen3-1.7B`, 리비전 `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e` (모델 카드 Apache-2.0). 사용자 PC 토크나이저 20건 점검과 RunPod NVIDIA A40에서 **학습 전 추론** 실행까지 완료. SFT 학습 시 VRAM 사용량은 아직 측정하지 않았다.

### 1. 실험 정의

SFT를 시작하기 전에 모델·토크나이저·대화 템플릿·최대 토큰 길이·LoRA/QLoRA 설정이 학습 데이터와 호환되는지 확인한다. M3에서 모델을 학습하고 평가할 때 재현성을 확보하기 위한 사전 점검이다.

### 2. 실험 목적

7~8B 모델을 바로 학습하면 VRAM/비용 부담이 커질 수 있고, 문서·라벨·출력 포맷 오류를 모델 문제로 착각하기 쉽다. 우선 소형 텍스트 모델 1개에서 데이터 계약과 실험 과정을 안정화하는 것이 이번 프로젝트 목적에 더 맞는다.

### 3. 실험 과정과 기술적 판단

1. 공식 모델 카드를 확인해 텍스트 모델·라이선스·Transformers와 vLLM 사용법을 검토했다. 모델 카드의 Apache-2.0은 **사용설명서의 학습 데이터 이용 권한을 대신하지 않는다.**
2. 모델에서는 **thinking 모드를 끄는 설정(`enable_thinking=False`)**을 우선 검토한다. 고객 응대 결과는 자유 서술보다 `action`, `customer_message`, `cited_evidence_ids`, `missing_fields` 구조의 JSON을 비교할 계획이다.
3. `s09_model_preflight.py --tokenizer-check --write`로 20개 S07 예시를 토큰화한다. 이때 사용하는 `page_evidence.fact_summary`는 **길이 측정용 미리보기**이므로 실제 학습 때의 RAG 검색 근거와 다르며, 여기서 학습 데이터를 확정하지 않는다.
4. 가능한 경우 GPU 모델·VRAM을 로그에 남긴다. LoRA Rank=16, micro-batch=1, grad accumulation=4, 최대 길이 1,536토큰은 **초기 파일럿 초안**이고 실제 학습 파라미터는 토큰 길이와 OOM 실측 후 확정한다.
5. M3에서는 원본 기반 모델과 SFT 어댑터 적용 모델에 **S08에서 고정한 동일한 검색 입력**을 제공해야 한다.

|---|---|---|

## M2 후속 검수 — Train 26건 BGE-M3 검색 근거 적합성 (2026-10-31 실측)

### 0. 실험 한눈에 보기

**이번에는 모델을 새로 학습하지 않았다.** S07 Train 검수본 **26건(원본 13·재표현 13, 6개 의미 그룹)**에 53개 공식 검증 후보 청크를 대상으로 BGE-M3 검색을 적용했다. 그 결과 26건 모두 Top-5에 **Gold 근거 하나 이상**은 들어왔지만, **필요한 Gold 전부**를 포함한 건은 **25/26건**이다. 정확한 인용과 전체 응답 조건까지 자동 검증된 결과는 아니므로 `training_ready=false`를 유지한다.

### 1. 실험 정의

- 검색 모델: `BAAI/bge-m3`, S05와 동일한 후보 문서 집합·제품 코드 필터·코사인 유사도 방식·Top-5·최저 0.4.
- 범위: **Train 26건만**. Dev·Holdout 데이터를 학습 입력에 섞지 않았다.
- 구조: `messages` 3개 (`system`, `user`, `assistant`) 중 `user`에는 고객 발화·이전 답변·검색 근거가 있고, `assistant`에는 올바른 응대 예시가 있다. **추론 성능 평가에서는 `assistant` 정답을 입력에 포함하면 안 된다.** Gold ID는 `audit_only`에 두고 검색 순위 계산에 사용하지 않았다.

### 2. 실험 목적

SFT용 정답 답변이 고객 문의와 실제 **검색 결과에 의해 뒷받침되는지** 확인한다. 정답 문서 ID가 목록에 있는 것과, **답변의 모든 조치·조건을 실제 검색 문서가 뒷받침한다는 것**은 서로 다르다. 검색된 청크가 부족하면 올바른 정답 문장을 학습시키더라도 근거 없는 안내를 학습시키는 모순이 생길 수 있다.

### 3. 실험 과정과 기술적 판단

1. S07 검수본 26개 질문과 제품 코드를 읽고 BGE-M3로 질의별 후보를 검색한다.
2. 검색이 **완료된 뒤에만** `gold_evidence_ids`와 검색 후보를 비교한다. 정답 ID를 검색 후보로 강제 삽입하지 않는다.
3. `system`에는 B1 프롬프트, `user`에는 질의·검색 근거, `assistant`에는 검수한 정답 JSON을 넣는다.
4. 'Gold가 하나라도 있나?', '필수 Gold가 전부 있나?', '정답이 몇 위인가?', '정답 문장의 각 지시를 제공 근거가 지지하나?'를 **서로 다른 검사**로 취급한다.
5. 사용설명서의 정확한 조작 단계는 **관련된 원문 페이지를 확인**한다. 실험에 준 자료의 공개/학습 이용 가능 여부는 별도 조건으로 남긴다.

### 5. 결과 해석 및 결론

이번 실험은 **학습용 질문 26건에 실제 검색 근거를 연결하는 파일럿**을 끝낸 것으로 해석한다. 특히 Gold 존재 여부와 **전체 근거 충분성은 별개**이며, SFT는 검색 근거 부족 문제를 해결하는 대체 수단이 아니다.

**M2 파일럿 완료와 M3 학습 승인(G2)은 구분한다.** 전자는 S06~S09의 작은 정답 설계, 데이터 생성, 기준선, 모델 사전 점검을 마친 상태다. 후자는 **(1) 제3자 문서의 학습·이용 범위 확인, (2) 부족한 검색 근거와 인용을 보완하고 같은 평가 조건 유지, (3) 실제 검색 문맥을 포함한 전체 토큰 길이 점검, (4) 6개 의미 그룹 이상으로 독립 시나리오 확대**가 이뤄지기 전까지 **보류**한다.

**다음 순서:** 추가 GPU 지출보다 **M2 전체 복습을 먼저 진행**한다. 데이터·검색·행동·출력 형식 문제를 분리해 설명할 수 있게 되면 위 미완료 항목을 처리하고 M3의 첫 소형 SFT 파일럿으로 넘어간다.
