# M2 / S08 — Qwen3-1.7B 학습 전 기준선 검수 보고서

> **판정:** 기준선 응답 생성 **완료**, 응답 품질 검수 **완료**, M2 학습 준비 **미완료**. 2026-10-31 단일 Dev 파일럿. 이 보고서는 원본 출력을 **수정하지 않고** 읽어 검수했다.

## 0. 실험 한눈에 보기

- GPU **NVIDIA A40**에서 학습 전 모델 `Qwen/Qwen3-1.7B`을 Dev 6건에 실행했다. **SFT 학습은 하지 않았다.**
- **6/6 응답을 생성**했지만 정상 JSON은 **3/6**, 필수 필드를 모두 갖춘 JSON은 **2/6**이었다.
- 원시 문자열에서 행동을 읽어 기대 라벨과 비교하면 **1/6**, JSON 형식까지 요구하면 **0/6**이었다.
- 제빙 기능이 없는 제품에 가상의 조작법을 안내하는 **중대한 오류**가 있었다.
- **이 결과를 '모델의 일반적 정확도 0%'로 주장하지 않는다.** Dev 6건·단일 실행·일부 검색 실패가 함께 있는 진단용 결과이다.

## 1. 실험 정의

**입력:** 고정된 Dev 고객 질문 6개 + S05의 BGE-M3 오프라인 검색 결과 5/5/2/3/4/1건 (제품별 근거 제공).  
**출력:** `action`, `customer_message`, `cited_evidence_ids`, `missing_fields`의 JSON.  
**비교 기준:** S04에서 공식 매뉴얼과 연결해 검수한 기대 행동/필수 조치.  
**기반 모델:** `Qwen/Qwen3-1.7B` / revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`.  
**생성:** thinking off, `do_sample=False`, `max_new_tokens=512`.  
**입력 해시:** `b52adfb98546eb9d0bc096038ee64bcb7d34bcf571ab16a0e97491943a6f17ee`.

## 2. 실험 목적

모델의 가중치를 바꾸기 전 **현재 응대 품질**을 확보해, 이후 SFT 모델을 **같은 기반 모델·같은 Dev 질문·같은 검색 근거·같은 출력 조건**으로 비교하기 위함이다. 동시에 오류를 **검색/제품 정책/LLM 행동/JSON 형식**으로 나누어 어디를 먼저 개선할지 판단한다.

## 3. 실험 과정과 기술적 판단

1. S04에서 분리해둔 Dev 6건을 이용하고, Train 18건·Holdout 6건은 이 추론에 사용하지 않았다.
2. S05에 저장한 BGE-M3 검색 근거를 **변경하지 않고** 각 질문에 제공했다. 정답(Gold)은 추론 입력에 넣지 않았다.
3. RunPod GPU에서 동일 리비전의 Qwen3-1.7B로 질문마다 출력을 하나 생성했다.
4. **자동 판정:** JSON 문법, 필수 필드 존재, 행동 라벨, 인용 ID가 입력 목록에 있는지 확인했다.
5. **원문 검수:** 모델 답변을 S04 정답 조치와 제품별 공식 PDF 관련 페이지와 대조했다.

**기술적 판단:** 'ID가 제공 목록에 존재한다'는 것은 '그 ID가 답변을 뒷받침한다'와 다르다. JSON 파싱 실패도 실패로 남기고, 끝의 쓸데없는 따옴표를 제거해 점수를 올리지 않았다. 다만 원인 분석을 위해 원시 텍스트의 행동 라벨은 별도로 추출했다.

## 5. 결과 해석과 결론

**오류가 한 종류가 아니다.**

- **검색 후보 누락:** `IAC606-105`, `JAC104-025`는 정답인 전체 무출수 근거가 입력에 없었다. SFT가 문서 검색 실패를 자동으로 고쳐 주는 것은 아니다.
- **모델 행동 오류:** `IAC425-105`는 무출수 근거가 있었는데도 추가 확인 대신 바로 안내했다. `JAC104-029`는 누수 안전 조치는 적절했지만 행동을 `EXPLAIN_UNSUPPORTED`로 잘못 분류했다.
- **근거 적용/조치 누락:** `JAC104-030`은 7일 부재 후 냉수·정수뿐 아니라 **온수도 1L 이상 버리도록** 안내해야 한다. 이는 답변의 완전성 문제다.
- **업무 범위·안전 실패:** `JAC104-033`은 실제로 없는 제빙 기능 조작법을 만들어냈다. 설명서에 없는 기능은 **제품 기능 Gate**로 먼저 차단하고, 무관한 근거를 인용하지 않도록 검증해야 한다.
- **형식 실패:** 세 결과는 문자열 끝의 **추가 `"`** 1개 때문에 파싱되지 않았다. 또 `JAC104-025`는 정상 JSON이지만 `cited_evidence_ids`, `missing_fields`가 빠졌다. **스키마 제약 출력** 또는 강한 프롬프트 기준선을 추가 비교해야 한다.

### 이후의 기술적 결정

1. **이 실험은 최초 기준선(B0)으로 보존한다.** 파싱 오류를 조용히 고치거나 Gold로 답변을 보정하지 않는다.
2. **강한 프롬프트 + 구조화 출력(B1)** 기준선을 별도로 만들어 같은 Dev 자료에서 평가한 뒤, SFT 모델과 **동일한 구성**으로 비교한다. 지금 결과는 '강한 기준선'이 아니라 초기 프롬프트 기준선이다.
3. 검색·제품 기능 정책의 개선은 SFT 효과와 **별도 실험**으로 측정한다. SFT 비교 시 retrieval 근거를 바꾸면 어느 변경이 효과를 냈는지 분리할 수 없다.
4. S07의 학습용 자료는 **training_ready=0** 상태이며, 사용 범위 검토와 학습 입력 근거 연결이 남아 있다. M2 종료 조건은 **기준선 확보만으로 충족하지 않는다**.
5. Dev는 이미 개발/진단에 사용되었으므로 **독립 Holdout 성능처럼 보고하지 않는다**. 최종 평가에서는 제품·증상 다양성이 있는 별도 보류셋이 필요하다.

### 재현성 주의

이번 실행 메타데이터의 `eval_contract_sha256`은 `db1b93f65c646cffda38dfb4789f8c5d209ba525eb03e58fd03c750635f424b1`이며, 대화에서 앞서 공유한 `eval_contract.yaml` 파일의 해시와 일치하지 않는다. S08에서 `--prepare`로 모델 버전을 고정한 뒤 RunPod에서 실행했다면 정상적인 변경일 수 있다. 이후 재현성을 위해 **실제 실행 시 사용한 고정 계약 파일**을 함께 보관한다.
