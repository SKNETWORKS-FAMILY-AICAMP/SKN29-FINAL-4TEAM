## 1. 왜 시작했는가

## 3. 실험 구성과 이해한 원리

| 실습 | 코드를 통해 확인한 것 | 문제의식 |
|---|---|---|
| 01 — Overlap | 단어 집합의 공통 항목 수로 검색 순위 결정 | 단어 표현이 다르면 관련 근거를 놓침 |
| 02 — BM25 | 단어 희귀도(IDF), 문서 내 등장 빈도(TF), 문서 길이 보정 | 단어별 중요도를 달리하면 어떤 오류가 줄어드는가 |
| 03 — E5-small | 질문·문서를 벡터로 표현, 코사인 유사도로 정렬 | 표면 단어가 달라도 의미가 가까운 문서를 찾는가 |
| 04 — 평가기 | Gold 청크 ID와 순위로 Hit@K·RR@K·MRR@K 재계산 | 검색 결과를 숫자로 입증하고 오류 문항을 빼지 않기 |

평가 환경은 **같은 8문단·10문항·Top-3·허용 정답 집합**으로 고정했다. BM25/Overlap은 일치 토큰이 없어 결과가 0건인 경우가 있으나, E5 임베딩은 유사도 임계값 없이 Top-3를 채울 수 있다는 차이도 확인했다.

## 5. 평가 지표와 주장할 수 없는 것

- **Hit@3:** 허용된 정답 청크 중 하나라도 3위 안에 있으면 1, 없으면 0.
- **RR@3:** 첫 정답이 1위이면 1, 2위이면 0.5, 3위이면 약 0.3333, 4위 이하/없음/오류이면 0.
- **MRR@3:** 전체 질문 10개의 RR@3 평균. 오류 문항을 임의로 제외하지 않는다.
- **Recall@K와 구분:** Q001/Q002의 ‘대체 가능한 정답’ 중 하나를 찾는 것과 모든 필수 근거를 확보하는 것은 다르다.
- **측정 범위:** 한 매뉴얼의 세 증상을 분리한 8문단, 관련 표현을 공유하는 10문항이다(Q003과 Q010은 같은 누수 상황). 실서비스 검색 정확도·고객 해결률·신제품 일반화·통계적 우위로 확대하면 안 된다.
- **Top-5 평가 불가:** 저장된 순위가 Top-3까지만 있으므로 Top-5 점수를 계산하거나 추정하지 않는다.
- **학습 vs 공식 결과:** 최초 3문단·3질문 실험과 이번 8문단·10질문 결과를 한 실험의 개선 전후 수치처럼 비교하지 않는다.

## 6. 학습 회고 — 사용자가 직접 설명한 범위

사용자는 Overlap을 ‘단어 일치’, BM25를 ‘희귀도’, Embedding을 ‘유사도’로 구분했고, 대화에서 BM25의 **등장 빈도·문서 길이**와 임베딩의 **벡터 기반 의미 유사도**까지 보완해 이해했다. 또한 **RR이 정답 순위의 역수**이므로 Hit@3가 같아도 1·2·3위에 따라 다른 값을 갖는다고 설명했다. 실습 10문항은 **표본이 적다**는 한계도 인식했다.

아직 확인하지 못한 사항은 더 큰 제품군에서의 재현성, 원문 해시의 로컬 재확인, 전체 검색 파이프라인의 코드 이해, SFT/Agent 단계의 성능이다. 이 부분을 ‘공부 완료’나 ‘검증 완료’라고 쓰지 않는다.

## 7. 기술 선택 결정과 다음 세션

**S01에서 정한 비교 가설:** BM25가 Q008에서, E5가 Q007에서 유리했으므로 RRF 결합을 실험했다. **S02 결론은 아래 통합 결과 절에 기록**했으며, 독립 데이터와 실제 서비스 흐름을 보기 전에는 어떤 검색기도 최종 채택하지 않는다.

- **실험 전 RRF 가설:** BM25와 E5의 순위를 `1/(k+rank)` 방식으로 합산하면 서로 다른 장점을 살릴 수 있다. 원점수가 서로 다르므로 직접 합산하지 않는다.
- **실제 검증:** 동일 후보 Top-3와 RRF 상수 60으로 비교를 수행했다. 수치·실패·퇴행은 아래 S02 절의 원시 결과 JSON을 기준으로 확인한다.
- **다른 후보:** 검색 대상의 제목·증상 코드·모델 조건을 더 정교하게 다루는 방식. 정답을 보고 만든 임시 규칙으로 평가셋에 과적합하지 않는다.
- **기술적 고도화와 연결:** 이 검색 실습은 본격 SFT·Tool-use Agent·서빙의 **근거 제공 기반**이며, 최종 성과로 내세우려면 별도 독립 평가와 서비스 연결이 필요하다.

## S02 — RRF Hybrid Search (저장 순위 결합)

**입력:** S01에서 실제 실행해 저장한 BM25/E5 Top-3 순위, RRF rank constant=60, 출력 Top-3. Gold는 순위 계산에 사용하지 않음.

| 검색기 | Hit@1 | Hit@3 | MRR@3 |
|---|---:|---:|---:|
| BM25 | 6/10 | 7/10 | 0.6333 |
| E5 Embedding | 6/10 | 8/10 | 0.6833 |
| RRF (BM25+E5) | 6/10 | 9/10 | 0.7000 |

**핵심 관찰:** RRF가 상위 1위 정답 개수를 늘린 것은 아니다. Q007은 임베딩의 1위를 유지했고, Q008은 BM25의 1위 정답을 RRF에서는 3위로 밀어냈다. Q002도 임베딩 2위 정답이 RRF에서는 3위가 되었다. Q003은 어느 검색기도 후보에 정답을 넣지 않아 RRF에서도 복구할 수 없었다.

**채택 결론:** 작은 연습 데이터의 Hit@3/MRR@3는 나아졌지만 Q008의 순위가 퇴행했다. 실제 WaterBridge에서 RRF를 채택할지는 더 많은 독립 질문과 실제 검색 파이프라인 분석 후 결정한다.

- 원시 결과: `experiments/step05_rrf/rrf_comparison.json` (Gold 기준으로 직접 재계산).
- 입력 SHA256: 순위 `df8cc1a7e2cc8b739af087e23516d452e02a34c757d32a768654dba3f0bb30ec` / Gold `81fc454e8315bcb2a382a0cd0fe5e92c7bae386f93deaadb9f5cba37a67daa98`.
- 한계: 검색기별 Top-3만 저장돼 있어 그 밖의 청크는 복구할 수 없음. 10문항은 연관된 학습용 데이터이며 실제 고객 해결률이 아님.
- **학습 확인:** RRF가 원점수를 합산하지 않는 이유, Q008의 BM25→RRF 퇴행 이유, Q003 미검색 원인을 내 말로 설명한다.
