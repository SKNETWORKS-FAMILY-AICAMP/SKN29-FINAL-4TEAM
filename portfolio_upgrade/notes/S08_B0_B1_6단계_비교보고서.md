# WaterBridge M2 / S08 — B0·B1 기준선 비교와 기술적 판단
> **상태:** Dev 6건, 학습 전 Qwen3-1.7B 1회씩의 진단 실험. 모델 학습·독립 Holdout 평가 아님.
## 0. 실험 한눈에 보기
**결론:** 시스템 프롬프트 강화로 JSON 형식 성공은 3/6→6/6, 완전 스키마는 2/6→6/6으로 좋아졌지만, 정답 행동 판정은 원시 답변 기준 1/6→1/6으로 변화가 없었다. 누수·제빙·조건별 조치에서 근거와 행동이 계속 어긋나므로 SFT를 시작하기 전에 근거 공급·정답/검증 계약을 고쳐야 한다.
## 1. 실험 정의
- **B0:** 동일 Qwen3-1.7B를 기본 시스템 프롬프트로 실행한 학습 전 기준선.
- **B1:** 모델 가중치와 Dev 질문·검색 근거를 유지하고 시스템 프롬프트만 더 구체적으로 작성한 학습 전 기준선.
- **공통:** Dev 6건, BGE-M3 오프라인 검색 스냅샷, 결정적 생성(`do_sample=False`), 생성 한도 512토큰, Qwen3 thinking 비활성.
## 2. 실험 목적
B0 실패가 단순한 출력 규칙 부족인지, 공식 근거의 적합성·조건 해석·행동 선택 문제인지 나눈다. **프롬프트만 강화해서 해결되는 오류에 SFT를 먼저 적용하지 않는다.**
## 3. 실험 과정 및 기술적 판단
- 모델: `Qwen/Qwen3-1.7B` 리비전 `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`.
- 동일 평가 입력 SHA-256: `b52adfb98546eb9d0bc096038ee64bcb7d34bcf571ab16a0e97491943a6f17ee`.
- 동일 검색 결과 파일 SHA-256: `57836eee9203c9fbecfb37d2b4bbd90f5c7e673ad239c4d8657e453ee7c03913`.
- B1 프롬프트 SHA-256: `48231b33236b0d5791ab5de0525bb0fc5801442abaa24c547d6e46f9fa7ed1c5`.
- 정답(Gold)은 생성 프롬프트에 제공되지 않음. 정답 행동은 **실행 후 S04의 Dev 기준**으로 대조했다.
- **기술적 판단:** 분할 누출과 모델 버전 차이를 피해야 하므로 동일 Dev와 동일 검색 스냅샷으로 비교. 다만 `attention_mask` 경고 및 실행 환경의 완전 동등성은 추가 통제되지 않았으므로 결과는 **진단 파일럿**으로 해석한다.

## 5. 결과 해석 및 결론
**A. 프롬프트가 개선한 것:** JSON 파싱·스키마 준수. 형식 준수와 내용 정답은 서로 다르다.

**B. 프롬프트만으로 해결되지 않은 것:** IAC425 전체 무출수에서 추가 문진 생략; JAC104 누수에서 `ESCALATE` 대신 `ASK`; JAC104 7일 부재의 온수 1L 조치 누락과 조건 없는 전체 필터 교체; JAC104 제빙 문의에 허구의 조작법. 특히 7일 부재의 필터 교체 지시는 B0보다 내용이 나빠졌다.

**C. 검색이 원인에 기여한 것:** IAC606 전체 무출수와 JAC104 전체 무출수는 정답 청크 자체가 Top-5에 없다. 제빙 기능 사례에는 **지원 기능 여부 근거가 없어** `EXPLAIN_UNSUPPORTED` 정답을 인용을 통해 증명하기 어렵다. 이 세 사례를 모두 생성 모델의 순수 판단 오류로 단정해서는 안 된다.

**D. 인용 검사의 함정:** B1에서 `invalid_citation_ids`는 전부 빈 리스트지만, 이는 **보여준 ID가 존재한다는 의미**일 뿐 질문에 적합한 근거라는 뜻이 아니다. IAC606 전체 무출수에 제빙/온수 문단을, JAC104 제빙에 온수 문단을 연결하는 인용은 부적절하다.

**E. 유효성 제약:** Dev 6건만 1회씩 평가했고 이미 여러 번 관찰했다. 시스템 프롬프트 외에 구동 환경까지 완전히 동일하다고 실증하지는 않았다. `attention_mask` 경고를 해결하고 실제 독립 평가에서는 입력/출력 계약을 고정해야 한다.

### 다음 기술적 판단 — GPU를 지금 다시 써야 할까?
**아니오.** 현재 M2에서는 B0/B1 두 결과를 **진단용으로 보존**하는 것이 합리적이다. 동일한 6건을 또 돌리기 전에 **(1) 검색/제품 기능 정보 계약, (2) S07의 학습 사용 권한과 정답 품질, (3) 명시적 attention_mask 및 출력 스키마 강제 방법**을 로컬에서 먼저 정리해야 한다. 그 다음 M3에서 GPU를 재사용하는 편이 낫다. 다만 B0/B1을 공식 비교 수치로 확정하고 싶다면, mask와 실행 환경을 함께 고정한 뒤 **둘 다** 재실행해야 하며 B1만 추가 실행해서는 안 된다.
