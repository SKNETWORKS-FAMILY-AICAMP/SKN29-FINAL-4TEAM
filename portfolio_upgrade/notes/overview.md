> **문서 개편:** 2026-10-30 · **대상 브랜치:** `seunghyuk` · **목적:** 실험을 다시 실행하거나 면접에서 설명할 때, *왜 → 어떻게 → 무엇을 확인했는지* 순서대로 이해하기.
>
> **중요:** 이 문서 개편 자체는 **새로운 성능 실험이 아니다.** 실험 수치와 경로는 기존 `M0.md`, `M1.md` 기록에서 옮겨 왔다. 현재 로컬 저장소의 파일 존재 및 최신 Git 커밋 일치 여부는 이 문서 작성 과정에서 재검증하지 않았다.

## 1. 이 프로젝트에서 풀려는 문제

**WaterBridge**는 정수기 고객 문의를 이해하고 공식 사용설명서의 내용을 검색해 근거 있는 안내를 생성하려는 AI 응대 서비스다. 핵심 어려움은 **문서를 찾아내는 것만으로 안전한 답변이 완성되지 않는다**는 점이다.

예를 들어 고객이 이렇게 질문했다고 하자.

> **Q008:** “필터를 이미 갈았는데도 물이 조금씩만 나와요.”

여기에서 고객의 **현재 증상**은 *출수량 저하*이고, **이미 수행한 조치**는 *필터 교체*다. 설명서에는 ‘출수량이 적을 경우’와 ‘물이 출수되지 않음’이 별도 조건으로 등장할 수 있다. 단어가 비슷하다는 이유로 **완전 무출수** 설명서를 내보내거나, 이미 했던 필터 교체를 무조건 다시 지시하면 문제가 된다.

아래 네 단계를 구분해야 한다.

```text
고객 질문 + 정확한 제품 코드
    ↓
① 질문 이해: 현재 증상 / 이미 한 조치 / 부정·위험 표현 구분
    ↓
② 검색 여부 판단: 위험·미지원 제품/기능·추가 질문 필요 여부
    ↓
③ 공식 근거 검색: 관련 청크 검색 + 제품·증상·적용 조건 검증
    ↓
④ 답변 생성 및 검증: 올바른 행동·필수 조치·인용의 관련성 확인
```

**RAG**(Retrieval-Augmented Generation)는 설명서 등 외부 문서를 *찾아(Retrieval)* LLM 답변을 *생성(Generation)*할 때 참고하게 하는 접근이다. **LangGraph**는 위 과정의 상태와 분기를 관리하는 도구이고, **BGE-M3·E5**는 문장에 대한 벡터 표현을 생성하는 임베딩 모델이다. 이 도구들은 서로 다른 역할을 맡는다.

## 3. 모든 실험을 읽는 공통 규칙 — 6단계

각 실험은 완전히 같은 순서로 서술한다.

| 순서 | 이름 | 이 항목에서 답할 질문 |
|---:|---|---|
| **0** | **실험 한눈에 보기** | 어떤 비교를 했고, 결과와 현재 판단은 무엇인가? |
| **1** | **실험 정의** | 입력·비교 조건·출력·평가 기준은 무엇인가? |
| **2** | **실험 목적** | 왜 이 문제를 지금 검증하는가? 어떤 실패를 줄이려는가? |
| **3** | **실험 과정 + 기술적 판단** | 어떤 개념이 필요하고, 왜 이 방법을 택했고, 실제로 어떻게 수행했는가? |
| **4** | **실험 결과 + 근거 파일** | 실제 관찰된 값/사례는? 원시 파일 어디를 열어 어떤 키를 볼까? |
| **5** | **결과 해석 및 결론** | 왜 그렇게 나왔을 가능성이 있고, 무엇을 채택·보류하며, 무엇은 아직 모르는가? |

**3번의 기술적 판단은 감상문이 아니다.** ① 당시 문제, ② 선택한 방법, ③ 고려할 수 있는 대안, ④ 장단점/실패 위험, ⑤ 그 선택을 검증할 증거를 연결한다. 실제로 채택하지 않은 대안은 반드시 **[후속 제안]**으로 표시한다.

## 4. 자주 나오는 개념 — 필요한 만큼만 먼저

| 용어 | 뜻 | 헷갈리기 쉬운 점 |
|---|---|---|
| **청크(Chunk)** | 설명서의 검색용 부분 문단 | 청크가 맞는 제품·조건에 적용되는지는 별도 확인 필요 |
| **Gold** | 원본 근거와 대조하여 지정한 평가상 정답 ID·조치 | 모델이 높은 점수를 준 문서라는 뜻이 아님 |
| **Overlap** | 질문·문서의 공통 토큰 개수 비교 | 조사·동의어 때문에 의미가 같아도 0이 될 수 있음 |
| **BM25** | 단어의 빈도·희귀도·문서 길이를 고려하는 검색 | 뜻이 비슷해도 단어가 안 겹치면 놓칠 수 있음 |
| **Embedding** | 텍스트를 벡터로 바꾸어 의미상 가까운지 비교 | 코사인이 높아도 해당 조치가 적합하다는 뜻은 아님 |
| **Top-K** | 검색 후보를 최대 K개까지 확인 | `k=60`인 RRF 상수와는 다름 |
| **Hit@K** | 상위 K개 안에 허용 Gold가 하나라도 있는지 | 모든 필수 조치 확보율이 아님 |
| **MRR@K** | 첫 Gold가 얼마나 앞쪽에 나오는지의 평균 | 검색 평가이지 최종 답변 정확도가 아님 |
| **RRF** | 여러 검색기의 점수가 아니라 **순위**를 결합 | 두 검색기가 같은 오답을 높게 평가할 수 있음 |
| **Policy Gate** | 제품·기능·안전·범위에 따라 검색 전 허용/차단 | `PGVECTOR_QUERY`는 검색 성공이 아닌 *검색 허용* |
| **Oracle** | 검수한 정답 근거를 검색 없이 LLM에 직접 제공 | 최종 답변의 정답을 보장하는 장치가 아님 |
| **Train / Dev / Holdout** | 학습용 / 개발 중 조정용 / 설정 고정 후 평가용 | Dev에서 만든 규칙을 Dev로 재평가하면 독립 검증이 아님 |

**파일 형식:** `.json`은 한 데이터 구조를 저장하며, `.jsonl`은 보통 **한 줄에 JSON 객체 하나**, `.csv`는 **표 형태** 데이터다. 결과 Markdown은 원시 증거가 아니라 **그 증거를 설명하는 학습 문서**다.

## 7. 무엇을 실측했다고 말할 수 있는가?

- **[기존 실행 기록]**: 사용자 PC에서 실행했다고 원래 문서에 기록된 결과. 이 개편 작업에서 재실행하지 않았다.
- **[기존 코드 확인]**: 원래 문서가 저장소 코드 경로를 근거로 설명한 구조. 실제 E2E 실행과 다르다.
- **[해석/가설]**: 관찰된 결과의 가능한 이유. 검증 전에는 확정 원인으로 말하지 않는다.
- **[후속 제안]**: 아직 구현·평가하지 않은 대안. 성과로 쓰지 않는다.

가장 중요한 문장은 이것이다.

> **검색할 수 있음 ≠ 정답 근거를 찾음 ≠ 적절한 최종 답변을 생성함 ≠ 운영 환경에서 안전하게 동작함**

M0에서는 앞의 검색을, M1에서는 분류·평가 데이터·응답 품질을 차례로 검증한다. 이후 M2~M6에서는 학습 데이터 설계 → 소형 LLM SFT/QLoRA → Tool-use Agent → vLLM 서빙 → 독립 평가·포트폴리오를 진행할 계획이며, **이 계획을 이미 달성한 성과로 적지 않는다.**
