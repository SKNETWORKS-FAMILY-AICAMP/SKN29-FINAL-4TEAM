## 1. 우리가 풀려는 문제를 먼저 이해하기

WaterBridge의 고객이 “필터를 갈았는데도 물이 조금씩 나와요”라고 물었다고 하자. 고객의 **현재 증상은 저출수**이고 **이미 한 행동은 필터 교체**다. '필터'라는 단어가 있다는 이유만으로 필터 교체 방법을 다시 안내하거나, 물이 *전혀* 나오지 않는 경우의 절차를 적용하면 잘못된 답변이 될 수 있다.

```text
고객 질문·제품 코드·이미 확인한 상태
    ↓ ① 질문·위험·적용 조건 이해
검색 허용 여부·추가 질문 필요 여부 판단
    ↓ ② 관련 공식 근거를 검색
정답과 관계된 문단이 검색 결과에 있는가?
    ↓ ③ 문단의 조건을 이번 고객에게 적용할 수 있는가?
답변(ANSWER) / 추가 질문(ASK) / 상담 이관(ESCALATE) / 미지원 설명(EXPLAIN_UNSUPPORTED)
    ↓ ④ 고객 답변·인용·위험 조치 검증
```

**이 흐름 전체가 이번 실험에서 실제 운영 환경으로 통과한 것은 아니다.** M0는 독립 미니 검색, M1의 S03은 팀 코드 추적·일부 함수 실행, S05는 오프라인 검색/LLM, M2는 합성 학습 데이터 준비와 GPU 기반 소형 모델 진단이다.

**RAG**는 문서를 찾아 답변 생성에 제공하는 접근이고, **임베딩 모델(E5·BGE-M3)**은 질문·문서를 벡터로 바꾼다. **pgvector**는 PostgreSQL에서 벡터 검색을 지원하고, **LangGraph**는 질문 처리 단계의 상태·분기를 관리한다. 서로 같은 기술이 아니다.

## 4. 문서 한 실험을 읽는 공통 6단계

| 순서 | 읽는 항목 | 확인할 질문 |
|---:|---|---|
| 0 | 실험 한눈에 보기 | 이번에 한 일과 가장 중요한 결과는? |
| 1 | 실험 정의 | 입력·비교 조건·출력·정답은 무엇인가? |
| 2 | 실험 목적 | 왜 지금 이 실험이 필요한가? |
| 3 | 실험 과정 + 기술적 판단 | 어떻게 했나? 다른 선택지는 무엇이고 왜 이 방식을 택했나? |
| 4 | 실험 결과 + 증거 위치 | 몇 건 중 몇 건? 어느 파일의 어떤 값을 볼까? |
| 5 | 결과 해석 및 결론 | 무엇을 알게 됐고, 무엇은 아직 말할 수 없나? |

**추천 공부 방식:** 1회독에는 실험마다 **0→1→2→5**만 읽어 이야기를 연결한다. 2회독에는 **3번의 기술·코드**, 3회독에는 **4번의 실제 JSON/CSV와 결과 수치**를 확인한다. 실험을 새로 실행할 필요는 없다.

## 5. 자주 헷갈리는 개념

| 개념 | 가장 짧은 뜻 | 주의할 점 |
|---|---|---|
| 청크 / Gold | 검색할 문단 조각 / PDF와 대조해 정한 정답 근거·행동 | 높은 검색 점수 = Gold가 아님 |
| BM25 / 임베딩 | 단어 기반 검색 / 문장 벡터 기반 검색 | 의미가 비슷해도 조건이 틀릴 수 있음 |
| RRF / Top-K | 검색기 간 순위 결합 / 살펴볼 상위 문서 개수 | RRF의 `k=60`은 Top-60이 아님 |
| Hit@K / MRR@K | Gold가 상위 K개 중 하나라도 있는가 / 첫 Gold가 얼마나 앞에 있는가 | 모든 필수 근거·최종 답변의 정확도를 뜻하지 않음 |
| Oracle | 검색 없이 지정 Gold 문서를 바로 제공한 비교 조건 | LLM이 그 문서를 바르게 적용할지는 별도 문제 |
| Train / Dev / Holdout | 학습 / 개발 중 조정 / 마지막 독립 확인 | 같은 의미의 문장이 분할을 넘어가면 누출 위험 |
| `action` / `customer_message` | AI가 선택한 응대 종류 / 고객에게 보여줄 내용 | `ANSWER`를 골랐어도 내용이 틀릴 수 있음 |
| SFT / LoRA | 정답 예시로 LLM을 추가 학습 / 일부 어댑터 가중치만 학습하는 방법 | 현재 M2에서는 **SFT 학습을 하지 않았음** |
| `training_ready` | 이 데이터가 학습에 투입될 조건을 충족했는가 | 검색 성공만으로 `true`가 되지 않음 |

## 7. 어디까지 말할 수 있는가?

- **실행/실측:** 원시 결과 파일로 확인한 수치. 전체 운영 성능이나 독립 일반화를 의미하지는 않는다.
- **코드 확인/부분 실행:** 코드의 흐름 또는 일부 함수의 출력. 운영 E2E 성공을 뜻하지 않는다.
- **해석/가설:** 어떤 오류의 원인일지 설명한 추론. 후속 실험 전에는 확정 원인으로 말하지 않는다.
- **후속 계획:** M3 SFT·Agent·vLLM 서빙 등 실제 구현 전 항목을 이미 이룬 성과처럼 말하지 않는다.

> **검색 허용 ≠ Gold 근거 검색 ≠ 정답 조치의 충분한 근거 ≠ 안전한 고객 응답 ≠ 실제 서비스 성공.**
