## 1. WaterBridge는 무엇을 하는가?

**WaterBridge**는 고객의 정수기 문제를 이해하고 **공식 사용설명서의 근거**를 찾아 안전한 안내를 제공하려는 AI 응대 프로젝트다. 고객은 “필터를 갈았는데도 물이 조금씩 나와요”처럼 자연스럽게 말하지만, 설명서는 “출수량이 적을 경우” 같은 표현을 쓴다. 질문과 설명서의 표현이 다르더라도 올바른 근거를 찾아야 하고, **다른 제품의 조치나 다른 증상의 조치를 섞어서는 안 된다.**

전체 흐름을 먼저 이렇게 기억하자.

```text
고객 질문 + 제품 코드
       ↓
① 질문 이해: 어떤 증상인지 파악
       ↓
② 검색 여부 판단: 위험한가? 추가 확인이 필요한가? 설명서 범위인가?
       ↓  (통과한 경우)
③ 공식 근거 검색: 맞는 제품·증상·조건의 설명서 내용 찾기
       ↓
④ 답변 생성·검증: 확인한 근거로 안내하고 오류 검사
```

이 흐름의 **③ 검색**을 이해하기 위해 M0에서 작은 검색기를 만들었고, **①·②·③·④의 연결**을 이해하기 위해 M1의 S03에서 기존 코드를 분석했다.

### RAG는 어떤 기술인가?

**RAG(Retrieval-Augmented Generation, 검색 증강 생성)**는 LLM이 답을 만들기 전에 관련 문서를 *검색(Retrieval)*하여 근거로 제공하는 방법이다.

- **검색기:** 설명서에서 관련된 부분을 골라 가져온다.
- **LLM:** 가져온 근거를 해석해 고객에게 보여줄 문장을 만든다.
- **검증·업무 규칙:** 제품·안전 조건이 맞는지 확인하고, 근거가 부족하면 추가 질문·안내 보류·상담 경로를 선택한다.

**검색에서 맞는 문서를 찾았다는 것과 최종 답변이 맞다는 것은 다르다.** 검색이 틀릴 수도 있고, 정답 문서가 있어도 LLM이 적용 조건을 잘못 해석할 수 있다. 그래서 각각 따로 평가한다.

## 3. 핵심 용어는 여기서부터

| 용어 | 쉬운 뜻 | 예시 |
|---|---|---|
| **매뉴얼** | 제조사의 사용설명서 원본 | WPU-JAC104(D) 설명서 37~38쪽 |
| **청크(Chunk)** | 설명서에서 떼어낸 검색용 내용 조각 | “필터 교체 후에도 출수량이 적으면 상담” |
| **질문(Query)** | 고객이 알고 싶은 내용 | “물이 조금씩만 나와요” |
| **Gold / 정답 근거** | 원문을 확인해 답에 적합하다고 표시한 문서 ID | Q008의 실습 정답 `WB-S02-006` |
| **검색(Retrieval)** | 질문에 맞는 청크를 찾고 순서를 매김 | BM25는 정답을 1위로 찾음 |
| **임베딩(Embedding)** | 문장을 숫자 벡터로 나타냄 | E5-small, BGE-M3 |
| **Top-K** | 검색기가 많아야 몇 개를 돌려줄지 | Top-3: 최대 3개, Top-5: 최대 5개 |
| **RRF** | 서로 다른 검색기의 **순위**를 합쳐 재정렬 | BM25 3위 + E5 2위인 문서 |
| **LangGraph** | 질문 처리 단계의 실행 순서와 분기 관리 | 추가 질문이 필요하면 검색을 기다림 |
| **pgvector** | PostgreSQL에서 벡터 유사도 검색을 하는 확장 기능 | WaterBridge의 실제 벡터 검색 |
| **Policy Gate** | 검색 전에 진행 가능/차단 여부를 판정 | 지원하지 않는 제품 문의 차단 |
| **Oracle 근거** | 실험에서 정답 문서를 **미리 알고 직접** LLM에 주는 방식 | S05에서 검색 문제와 생성 문제 분리 |
| **기준선(Baseline)** | 개선 전 비교 대상이 되는 고정된 방법·점수 | 강한 프롬프트 + 기존 RAG |

## 4. 이번에 사용한 대표 질문: Q008

> **“필터를 이미 갈았는데도 물이 조금씩만 나와요.”**

- 고객이 **겪는 증상**은 *출수량 저하*이다.
- “필터를 갈았다”는 고객이 **이미 했다고 말한 조치**다. ‘필터 관리 방법을 알려 달라’는 요청이 아니다.
- **M0:** BM25는 정답을 찾았지만 E5에서는 놓쳤고, RRF에서는 정답이 3위로 밀렸다.
- **M1/S03:** 실제 WaterBridge 규칙 기반 증상 분류기도 이 문장을 `필터/관리 문의`로 분류했다. 그 결과 근거 필터와 추가 질문 조건이 달라지는 **부분 실험**을 확인했다.

**주의:** 미니 검색기와 실제 WaterBridge의 청크 ID·검색 모델·실행 조건은 서로 다르다. S03에서 실제 고객에게 틀린 답변을 제공했다는 증거까지 확보한 것은 아니다.

### 반드시 구분할 세 가지

**[실측]** 사용자의 Windows 환경에서 실제 실행한 결과. **[코드 확인]** 저장소 코드만 살펴 확인한 설계. **[예정]** 앞으로 구현·실험할 일. 세 가지를 서로 바꿔 쓰지 않는다.

현재 수치는 **한 제품의 작은 설명서 발췌(8청크)와 서로 관련 있는 연습 질문(10개)**에서 나온 결과다. 실제 고객센터의 성능, 다른 제품 일반화, 모델 학습 성능이라고 주장하지 않는다. 새 제품 자료와 보류 평가셋이 필요한 이유가 바로 여기에 있다.
