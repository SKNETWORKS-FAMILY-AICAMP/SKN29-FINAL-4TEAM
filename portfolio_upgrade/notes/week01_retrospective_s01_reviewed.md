**기존 팀 프로젝트의 복잡한 코드를 무조건 실행하는 대신, 처음부터 원리를 이해할 수 있는 작은 검색기를 만들고 검색 방식의 선택 이유를 설명하는 것.** 공식 사용설명서에 근거해 정답을 정하고, 검색 방식 세 가지를 같은 질문·문단으로 비교한다.

## 2. 실제 진행한 일

- `seunghyuk` 브랜치를 사용하기로 결정하고 팀 프로젝트는 보존, 개인 고도화는 `portfolio_upgrade/`에서 분리.

- 발췌 내용에서 세부 조건별 **8개 문단**과 서로 관련 있는 **10개 질문**으로 학습용 데이터 확장. 이 10문항을 각각 독립 현장 사례라고 주장하지 않음.
- ChatGPT가 제공한 예제 코드로 **Overlap → BM25 → Embedding** 검색을 로컬 실행하고 같은 질문으로 결과를 비교.
- ChatGPT가 제공한 평가기 코드의 출력을 로컬에서 생성·업로드하고, Hit@1/Hit@3/MRR@3 값을 검산.
- 기존 단위 테스트 1,049개를 전부 이해하거나 삭제하지 않고, 새로운 요구사항을 중심으로 학습하기로 결정.

## 3. 정량 결과(학습용)

| 방식 | Hit@1 | Hit@3 | MRR@3 |
|---|---:|---:|---:|
| Overlap | 4/10 | 6/10 | 0.4667 |
| BM25 | 6/10 | 7/10 | 0.6333 |
| Embedding | 6/10 | 8/10 | 0.6833 |

**이 숫자로 주장할 수 있는 것:** 동일한 8문단·10문항 학습 자료에서는 BM25가 Overlap보다 1위 정답을 두 건 더 찾았고, Embedding은 BM25보다 Top-3에 정답이 한 건 더 포함됐다.  
**주장할 수 없는 것:** 실제 WaterBridge 검색 정확도, 고객 문제 해결률, 문서가 늘어났을 때의 일반화, 성능 개선의 통계적 유의성.

## 4. 가장 기억에 남는 실패와 배움

| 사례 | 관찰한 결과 | 배운 점·남은 가설 |
|---|---|---|
| **Q007** 다른 표현으로 저출수 질문 | BM25 검색 없음, Embedding 정답 1위 | 단어가 달라도 검색할 수 있는 임베딩의 장점이 나타남. 다만 다른 문장에서도 일관적인지는 미확인 |
| **Q008** 필터 교체 후 '조금씩' 나옴 | BM25 정답 1위, Embedding Top-3 실패 | 의미 유사도만으로 세부 조건을 올바르게 구별하지 못할 수 있음 |
| **Q003** 누수 의심 | 모두 Top-3 실패 | 검색 방식 변경 외에 문서 제목/증상 표현·청크 구성 문제도 확인 필요 |
| **Q010** 누수 + 밸브/전원 조치 | 모두 정답 3위 | 동일한 안전 조치 표현이 서로 다른 증상 문서에 포함돼 혼동 가능 |

### 이해 확인: 실제 대화에서 확인한 내용

- 이번 S01에서 확인된 **원문 근거 8/8개 일치**는 학습용 검색 실험의 정답 출처를 강화하지만, 실제 서비스 정확도를 보장하지 않는다.

- **RR(Reciprocal Rank):** 정답이 1위면 1, 2위면 1/2, 3위면 1/3. 같은 Hit@3=1이어도 정답 순위가 높을수록 RR이 높다고 사용자가 직접 설명함.
- BM25의 희귀도/빈도, 임베딩의 의미 검색, 서로 다른 결과에 대한 설명은 함께 학습했으나 **혼자서 3분간 설명할 수 있는지는 아직 확인하지 않았다.**

## 5. 의도적으로 바꾼 작업 방식

**기존:** 이해하지 못한 상태에서 기존 코드를 수정하거나 대량 테스트 통과를 최종 목표로 삼았다.  
**이번:** 실패 예제 → 방법의 원리 → 같은 질문으로 비교 → 평가 지표 계산 → 차이의 원인 가설 → 새 실험 선택.  
**앞으로 지킬 규칙:** 필요한 개념을 설명할 수 있고, 실험 결과의 한계를 말할 수 있어야 다음 기술을 무작정 추가하지 않는다.
