## 1. 고도화 목표와 원칙

- 브랜치: `seunghyuk` (`main`을 복사해 시작했다고 사용자 설명).
- WaterBridge에서 **문제 → 원인 가설 → 대안 비교 → 선택 이유 → 정량 성과**를 설명하는 고도화와 6페이지 포트폴리오 제작이 목표.
- 기존 대량 단위 테스트는 삭제하지 않고 보관한다. 전체 테스트를 이해·통과하는 것을 새 개발의 선행조건으로 삼지 않는다.
- 별도 `portfolio_upgrade/` 영역에서 최소 검색기를 구현하며, 개념·구현·검증·본인 설명을 묶어 진행한다.
- 정해진 날짜까지 기다릴 필요 없이 이해·검증이 완료되면 다음 단계로 진도를 앞당긴다.
- 11/03로 표시된 **1주차 마지막 과정까지 완료한 뒤** 회고를 작성한다(달력상 11/03 도래만을 기준으로 하지 않음).

## 2. 지금까지 한 작업 (확인됨)

### 기준점·작업 방식
- 과거 단위 테스트 실행 결과: **1,024 passed, 25 setup errors**. 25개는 pytest 임시 디렉터리 접근 권한 문제로 테스트 본문 전에 중단된 것으로 분석. 프로젝트 전체 검색 품질의 증거로 사용하지 않는다.
- 복잡한 기존 테스트를 무조건 통과시키는 방식 대신, 요구사항이 이해되는 작은 검색기부터 시작하기로 결정.
- `portfolio_upgrade/` 분리 구조를 추천함. 실제 로컬 폴더 생성·파일 복사 여부는 추후 확인 필요.

### 공식 매뉴얼에서 찾은 근거 (사용자 발췌 기준)
- **Q001 / NO_WATER:** 37쪽 「물이 출수되지 않음」 — 필터 교체 상태, 수돗물 단수, 호스 꺾임 등 조건 확인.
- **Q002 / LOW_FLOW:** 38쪽 「출수량이 적을 경우」 — 다른 수전 동시 사용, 필터 교체, 해당 제품의 순간 온수 조건.
- **Q003 / LEAK:** 38쪽 「제품 누수 발생」 — 원수 밸브 잠금, 전원 플러그 분리, 고객상담센터 문의. 조립 부위 불량이라고 실제 원인을 단정하지 않는다.
- `WaterBridge_mini3_gold_v0.1.json` 작성. **PDF 원본을 직접 대조한 최종 검수본은 아님**; 실제 청크 ID 미지정.

### 미니 키워드 검색기 — 사용자 실행 출력
- 실습 자료: 설명서 발췌에서 만든 3개 검색 문서(청크), 3개 질문.
- 검색 방식: 단어 집합 간 정확히 겹치는 토큰 개수로 점수 계산; 임베딩·의미 이해 없음.
- 매뉴얼 소제목을 그대로 입력한 [A]: **3/3** 정답 1위.
- 고객 자연어 질문 [B]: **1/3** 정답 1위(Top-1 **33.3%**, 3문항 한정).

| 문항 | 올바른 청크 | 검색 1위 | 판정 | 관찰된 겹치는 토큰 |
|---|---|---|---|---|
| Q001 완전 미출수 | `WB-DEMO-001` / 37쪽 | `WB-DEMO-001` | 성공 | `때`, `물이` |
| Q002 출수량 저하 | `WB-DEMO-002` / 38쪽 | `WB-DEMO-001` | 실패 | `나올`, `때`, `물이` |
| Q003 누수 | `WB-DEMO-003` / 38쪽 | `WB-DEMO-001` | 실패 | `물이` |

**분석:** 고객 표현 「물이 새는 것」과 매뉴얼 「누수」가 표면적으로 다르며, 완전 미출수와 출수량 저하가 공통 단어를 사용한다. 따라서 토큰이 겹친다고 정답이라는 보장은 없다. **이 결과는 학습용 소규모 실습이며 포트폴리오의 실제 서비스 검색 성능으로 사용하지 않는다.** 문서 3개뿐이라 Top-5 지표는 변별력이 거의 없다.
