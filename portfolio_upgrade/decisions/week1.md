# ADR-W01 — 검색 기준선과 다음 실험의 선정

> 작성: 2026-10-29 / 실습 7일차 / `portfolio_upgrade/decisions/week1.md`  
> **상태:** 관찰 결과는 확인, 다음 실험은 *가설* / 최종 기술 확정 아님.

## 의사결정 질문

**왜 Overlap을 넘어 BM25·Embedding을 비교했으며, 다음에는 무엇을 시험할 것인가?**

### 확인된 문제와 증거

- 단어 겹침(Overlap) 검색은 동일한 표면 단어의 개수만 고려한다. 고객 표현이 매뉴얼과 다르면 1위가 틀릴 수 있다.
- BM25는 희귀도·빈도·길이 보정으로 Overlap이 틀린 Q008·Q009를 1위 정답으로 바꿨다.
- Embedding은 Q007의 다른 표현을 1위 정답으로 연결하고 Q002 정답을 2위에서 찾았지만, BM25가 맞힌 Q008을 놓쳤다.
- Q003은 모두 Top-3에서 누수 근거를 누락했고, Q010은 모두 정답을 3위에 뒀다.

### 최소 대안 비교

| 후보 | 이번 실습에서 드러난 장점 | 남는 문제 | 판단 |
|---|---|---|---|
| **Overlap** | 원리 간단하고 실행 저렴 | 다른 표현과 중요 단어 구분에 취약 | 학습용 기준선 유지 |
| **BM25** | Q008/Q009 정답 1위, Overlap 대비 개선 | Q007에서 결과 없음, Q003/Q010 약점 | 강한 키워드 기준선 유지 |
| **Embedding(E5)** | Q007 정답 1위, Q002 정답을 Top-3 확보 | Q008 퇴행, Q003/Q010 증상·조치 구별 실패 | 의미 검색 기준선 유지 |
| **Hybrid(RRF)** | BM25/Embedding의 상보성을 활용할 가능성 | 오답까지 합쳐서 오히려 뒤집힐 수 있음 | **다음 가설로만 제안** |
| **증상/조건 메타데이터** | 공통 조치보다 증상·제품 조건을 우선할 가능성 | 증상 분류 오류가 생기면 올바른 정답까지 제거 | Q003/Q008/Q010 사례를 확인한 뒤 실험 |

### 결정

1. **현재 한 방식을 최종 채택하지 않는다.** 데이터 규모가 작고 독립적이지 않다.
2. 다음 주에는 기존 WaterBridge의 검색 경로(질문 → 검색 전 검사 → 질의 확장 → 임베딩 → DB → 결과 필터)를 **요청 하나 기준으로 이해**한다.
3. 우선 검토할 신기술 실험은 **RRF 하이브리드 검색**이다. 단, BM25/Embedding이 못 찾는 Q003 같은 사례는 합친다고 반드시 해결되지 않는다.
4. 검색 전에 적용되는 **제품·증상·조건 필터**가 제대로 작동하는지 먼저 확인한다. 정답 라벨을 보고 만든 전용 규칙을 평가 데이터에 되돌려 적용해서는 안 된다.
5. 하이브리드·증상 구분·청크 구조 보존 중 **어느 방법이 가장 큰 실패를 줄이는지** 비교한 뒤 다음 모델 학습 투자 여부를 결정한다.

### 검증 계획 (2주차 이후)

- 동일한 독립 질문·원문·청크 분할에서 BM25, Embedding, RRF를 실행하고 Hit@1/3, MRR@3, 증상별 오류와 비용을 비교한다.
- **RRF는 각 방법에서 검색된 문서의 순위**를 결합한다(예: `1/(k+rank)` 합). BM25와 코사인 점수를 직접 더하지 않는다.
- 미검색·검색 실패·잘못된 조건 적용·근거 부족 질문도 기록한다. 무조건 3개를 뽑는 Dense 검색의 낮은 유사도를 '정답 있음'으로 오해하지 않는다.
- 제품·설명서·표현 변형에 따른 데이터 누수 방지와 원본 PDF 대조는 확장 평가 전 필수.

### 아직 확정할 수 없는 사실

- Embedding이 실제로 '물줄기가 약하다=출수량 저하'라는 의미를 학습했기 때문에 Q007을 맞혔다는 것은 **출력만으로 증명되지 않는다**.
- RRF가 BM25 또는 Embedding을 넘을지, 어떤 `k`가 적절할지 아직 검증되지 않았다.
- 세 방식의 실제 고객센터 성능·정책 준수·비용 절감은 이 실험에서 측정하지 않았다.
