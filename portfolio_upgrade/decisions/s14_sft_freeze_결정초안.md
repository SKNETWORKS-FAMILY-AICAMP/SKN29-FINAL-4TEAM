# S14 SFT 모델 채택·동결 결정 — 예비안

**상태:** 가상 Dev 진단에 근거한 **엔지니어링 의사결정 초안**. 최종 블라인드/사람 검수 및 실제 WaterBridge 시스템 성능 평가는 아니다.

## 관찰한 증거

- S10: LoRA 학습·어댑터 저장·재로드 성공, 가상 파일럿에서 schema 저하.
- S12: 48개 가상 Train, 12 step, Qwen3-1.7B LoRA. Dev 16건에서 BASE P0의 계약 11/16 vs LoRA P0 4/16. 구조화 정답 양쪽 0/16.
- S13b: 강화 프롬프트 P1 양쪽 **16/16 Markdown fenced JSON**이어서 원문 JSON 계약 0/16. 단일 fence를 제거하는 사후 진단에서는 BASE P1 계약 16/16, LoRA P1 15/16; 행동 10/16 vs 10/16; 구조화 정답 4/16 vs 4/16.
- 둘 다 P1 `EXPLAIN_UNSUPPORTED` 0/4이며 안전 상황에서 `ESCALATE` 라벨만 맞고 사용자 안내가 누락된 예시 존재.

## 결정 초안

1. **LoRA를 서비스 모델로 채택하지 않는다.** 추가 파라미터·추론 복잡도를 정당화할 독립적 응답 품질 개선이 확인되지 않았다. 유효한 기술적 성과는 재현 가능한 SFT 파이프라인 구축이다.
2. **BASE P1도 그대로 채택하지 않는다.** 원문 Markdown fenced 출력 계약 위반 16/16 및 의미·안전 오류가 남아 있다.
3. 추후 통합 시스템 후보는 `원본 모델 + 강한 지시 + 제한적 fence 제거 + JSON/행동/근거 검증 + 미확신 시 ASK/인계`다. **이 조합은 설계 대안일 뿐 실험으로 입증되지 않았다.** 안전 판정은 단순 키워드가 아닌 서버 측 규칙·전문가 검수에 의존한다.
4. 추가 SFT 재학습은 지금 시행하지 않는다. 16개 Dev에 맞춘 과적합을 피하고, 안전한 Agent 업무 흐름을 만드는 M4에서 실패한 모델 출력을 제어하는 법을 검증한다.
