# S11 — 새로운 독립 시나리오 설계안 (아직 학습 데이터 아님)

> **상태: DESIGN_ONLY.** S07의 26행을 그대로 두고, S08 Dev 6건·Holdout 6건의 질문·정답을 복제하지 않는다. 아래 표는 **다음에 어떤 신규 데이터를 만들지** 정하는 설계안이다. 신규 학습 자료나 Gold 확정본을 생성한 것이 아니다.

## 지금 학습 데이터를 늘리기 전에 확인할 것

S07 Train은 26행이지만 원본 문의는 13개, 선언된 의미 그룹은 6개다. 행동 라벨은 `ANSWER` 12행(원본 6개), `ASK` 4행(원본 2개), `ESCALATE` 10행(원본 5개), **`EXPLAIN_UNSUPPORTED` 0행**이다. 따라서 ‘26개나 있으니 10개만 더 만들자’는 접근은 불균형과 근거 문제를 그대로 확대할 수 있다.

특히 **`sg-ef6b56fea3f1`**은 비슷한 냉수 온도 문의 안에서 정상적인 대기 안내(`ANSWER`)와 지속 이상 상담 안내(`ESCALATE`)가 함께 등장한다. *표현*이 아니라 **조건·경과 시간·이미 수행한 조치가 라벨을 바꾸는 이유**를 제대로 보존해야 한다.

## 신규로 설계할 사례 유형

| 유형 | 판단을 나누는 핵심 조건 | 검수 항목 |
|---|---|---|
| `ANSWER` vs `ASK` | 문제 해결에 필요한 정보가 이미 주어졌는가? | 필요한 질문만 추가하고 이미 확인한 사실을 반복하지 않는가 |
| `ANSWER` vs `ESCALATE` | 정상적 일시 현상인가, 특정 조건을 충족한 지속 이상인가? | 원문 조건을 바꾸지 않고 위험 신호 우선 처리 |
| `EXPLAIN_UNSUPPORTED` | **허용된 기능 목록이 명시적으로 미지원을 증명**하는가? | 단순 미검색을 미지원이라고 주장하지 않기 |
| 검색 오답 선순위 | 비슷해 보이는 다른 기능/제품 근거가 1위인가? | 잘못된 Top-1에도 관련 조건과 인용을 검사 |
| 근거 불충분 | 정답 절차가 RAG 검색에 없거나 일부만 있는가? | 정답을 외우게 하지 말고 추측 보류·추가 질문·근거 개선 |
| JSON 필드 누락 | `missing_fields`가 빈 배열이어도 빠지지 않는가? | 4개 필드 포함, JSON 객체 **정확히 1개** 출력 |

**하드 디스트랙터(hard distractor)**는 질문과 단어·문맥은 비슷하지만 *지금 고객에게 적용할 수 없는* 근거다. 예를 들어 가상 제품에서 정상적인 일시적 경고등 설명과 지속 위험 경고등 설명이 동시에 검색될 수 있다. 학습 후보는 둘 중 어떤 문서가 적용되는지 *조건*에 근거해 정답을 정해야 한다.

## 새로운 데이터 1건의 최소 검수 계약

1. 자료의 출처와 **학습 목적 사용 근거**를 기록한다. 가상 자료라면 본인이 새로 작성했다는 기록을 남긴다.
2. 질문에 나타난 제품·기능·상태·시간 조건·이미 한 조치를 보존한다.
3. 모델이 실제로 볼 근거(검색 후보 목록)를 **Gold로 교체하거나 보강하지 않는다**. 필요한 근거가 없으면 학습 후보에서 보류한다.
4. 정답은 행동 라벨만이 아니라 고객 안내·필수 조치·금지 주장·적절한 인용까지 검수한다.
5. `semantic_group_id` 단위로 Train/Dev/Holdout 교차를 막는다. **신규 Train은 기존 Dev/Holdout 문항을 약간만 바꾼 변형으로 생성하지 않는다.**
6. 구조화 출력의 필수 4필드와 정답 영역 Loss 마스킹, 응답의 종료까지 확인한다.

**이 문서 자체는 새로운 독립 데이터 확보나 학습 이용 승인을 뜻하지 않는다.** 먼저 S11 우선순위 검수에서 기존 근거·권리 문제를 확정하고, 신규 자료를 독립적으로 작성·검수한 후에만 S12의 학습셋으로 승격한다.
