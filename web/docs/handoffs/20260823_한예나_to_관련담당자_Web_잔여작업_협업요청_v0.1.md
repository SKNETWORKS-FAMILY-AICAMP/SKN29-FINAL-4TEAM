## 한 줄 요약

기본 상담 Web과 Playwright G4는 확인됐고, 남은 Handoff·HITL·제품별 테스트는 API와 공식 합성 Fixture가 준비돼야 진행할 수 있습니다.

## Web에서 먼저 확인한 내용

- 최신 `main`이 반영된 `yena` 브랜치에서 확인했습니다.
- 기본 Playwright G4는 상담 시작 → 저장 → 요약 확정 → 완료 → 새로고침 복구와 404·409까지 `2 passed / 0 failed`입니다.
- 실제 API가 내려준 제품 모델 `SYN-WEB-WP-001`, `002`, `003`이 상담 상세에 그대로 표시됩니다.
- 1920×1080과 노트북 크기 1366×768에서 가로 넘침이 없었습니다.
- 긴 증상 문장도 잘리지 않고 화면 폭 안에 표시됐습니다.
- Web Test `219 passed / 4 skipped`, Lint·TypeCheck·E2E TypeCheck·Production Build가 모두 통과했습니다.

## 현재 Web에서 바로 완료할 수 없는 이유

- 계획서 대상 모델은 `WPU-JAC104`, `WPU-JCC104`, `WPU-IAC425`, `WPU-IAC606`이지만, 현재 실행 DB의 상담 문의에는 `SYN-WEB-WP-001~003`만 연결돼 있습니다.
- 상담사 화면용 AI Handoff 조회 API와 공개 Evidence 데이터가 현재 Web 계약에 없습니다.
- HITL 승인·수정 승인·거절 API가 없어서 Web은 임의 성공 처리 없이 비활성 상태를 유지하고 있습니다.
- 401·403·5xx Browser Smoke에 사용할 공식 계정·Fixture·오류 재현 조건이 고정돼 있지 않습니다.

## 담당자별 요청 사항

### 최지용 / Backend·DB

1. 제품별 공식 합성 Fixture를 부탁드립니다.
   - 대상: `WPU-JAC104`, `WPU-JCC104`, `WPU-IAC425`, `WPU-IAC606`
   - 각 모델의 Product·Subscription·신규 Inquiry와 대표 `inquiry_id`
   - 실제 고객정보가 아닌 `data_classification=synthetic` 데이터
   - 기존 완료 Inquiry, 공용 DB, RDS를 재사용하지 않는 실행 방법
2. 상담사 전용 Consultation Handoff 조회 API·DTO·OpenAPI 등록 여부를 알려주세요.
   - 증상, 제품 모델/제품군, 고객 답변, Evidence, Safety, 전환 사유, 우선 확인 항목
   - Handoff 없음·생성 실패·권한 없음 응답 규칙
   - Prompt, Raw PII, 내부 오류정보는 응답에서 제외
3. 상담사에게 공개 가능한 Evidence 필드와 Inquiry 상세 응답 계약을 부탁드립니다.
4. HITL이 이번 범위라면 Review 목록·상세·결정·Resume API를 부탁드립니다.
   - `approve / modify / reject`, `allowed_actions`, `state_version`, 409 규칙 포함
   - 이번 범위가 아니라면 공식 보류 여부만 확인 부탁드립니다.
5. 401·403·5xx Browser Smoke용 합성 계정·Fixture·재현 절차를 부탁드립니다.

### 윤승혁·이동윤 / PM·AI

1. Consultation Handoff 최종 Schema와 Web 공개 필드를 확정해 주세요.
2. 네 모델별 Evidence·Safety·제품 불일치 판단이 포함된 대표 합성 Handoff Case를 부탁드립니다.
3. HITL과 `AI → ESCALATE → Handoff → 상담사 확인`이 이번 발표·릴리스 필수인지 우선순위를 확정해 주세요.
4. G2·G3의 공식 판정명, 실행 담당자, PASS 기준을 공유해 주세요.

### 김은진 / QA·CI/CD

1. 작업 예정인 `web/Dockerfile`, `web/nginx.conf`의 반영 PR 또는 SHA를 공유해 주세요.
2. 반영 후 Web Production Container, SPA 새로고침, `/api/v1/**` Proxy를 함께 Smoke Test하고 싶습니다.
3. 안정적인 합성 Fixture가 준비되면 Playwright를 GitHub Actions Gate로 넣을지 결정해 주세요.
   - 실패 시 Screenshot·Trace 보존 기간과 업로드 규칙 포함
4. 제품별 Fixture와 Handoff/Evidence에서 다른 모델 정보가 섞이지 않는지 QA를 부탁드립니다.

### 양정현 / Mobile

1. 같은 신규 합성 Inquiry에서 제품 모델이 정상 표시되는지 확인해 주세요.
2. Web 상담 완료 후 Mobile 재조회에서 같은 Inquiry의 최신 상태가 보이는지 확인해 주세요.
