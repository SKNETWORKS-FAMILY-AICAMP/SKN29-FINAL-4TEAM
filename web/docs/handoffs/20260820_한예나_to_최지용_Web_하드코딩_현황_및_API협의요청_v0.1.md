# Web 하드코딩 현황 및 API 협의 요청

- 작성일: 2026-08-20
- 작성자: 한예나 (Web Frontend)
- 전달 대상: 최지용 (Backend)
- 목적: Web 화면에 직접 입력된 가짜·고정 데이터를 제거하고 실제 Backend 응답으로 교체하기 위한 현황 공유 및 API 협의

## 1. 요약

현재 Web에는 실제 데이터처럼 보이지만 프론트 코드에 직접 작성된 값이 일부 남아 있습니다.

- Web에서 자체적으로 제거할 수 있는 값은 제거하겠습니다.
- 이미 Backend API가 제공하는 값은 API 응답으로 교체하겠습니다.
- 아직 API 계약이 없는 기능은 다른 가짜 값으로 대체하지 않고 빈 상태 또는 비활성 상태로 처리할 예정입니다.
- Backend·Migration·공용 계약 파일은 Web에서 수정하지 않습니다.

## 2. 현재 확인된 하드코딩 현황

| 우선순위 | 영역 | 현재 Web 하드코딩 | 현재 문제 | 처리 방향 |
|---|---|---|---|---|
| P0 | 상담사 이름 | `합성 상담사 001`을 `한예나`로 강제 변경 | 실제 로그인 사용자와 다른 이름이 표시될 수 있음 | 로그인 응답의 `display_name`을 그대로 사용 |
| P0 | 상담사 사번 | 모든 상담사에게 `2026-001-256` 표시 | 다른 상담사도 같은 사번으로 표시됨 | API 필드가 없으면 숨김 처리 |
| P0 | 직원 연락처 | 부서 4개와 직원 8명의 이름·내선·이메일 고정 | 실제 조직 정보처럼 보이는 가짜 데이터 | Dashboard API의 `consultants` 사용 |
| P0 | 방문기사 연락처 | 기사 4명의 이름·전화·이메일 고정 | 실제 기사 정보처럼 보이는 가짜 데이터 | Dashboard API의 `technicians` 사용 |
| P0 | 자동 Mock 전환 | API 오류·빈 목록을 디자인용 문의로 자동 교체 | Backend 오류가 정상 데이터처럼 숨겨짐 | 오류·빈 상태를 그대로 표시하고 자동 전환 제거 |
| P0 | AI 검수 | 승인·반려 시 API 저장 없이 화면 데이터만 변경 | 실제 저장되지 않았는데 성공한 것처럼 보임 | API 계약 전까지 기능 숨김 또는 비활성화 |
| P0 | 운영 관리자 | 지표와 문의 목록 전체가 합성 문의 기반 | 실제 운영 현황처럼 오해할 수 있음 | 운영 API 전까지 연동 대기 상태 표시 |
| P1 | 공지사항 | 공지 6개의 제목·내용·부서·날짜 고정 | 실제 공지와 무관한 내용이 노출됨 | Dashboard API의 `notices` 사용 |
| P1 | 공지 요약 건수 | `전체 90 / 신규 30 / 진행 30 / 완료 30` 고정 | 실제 문의 건수와 달라질 수 있음 | Dashboard API의 `summary` 사용 |
| P1 | 전날 대비 수치 | `+8`, `+5`, `-2`, `+3` 고정 | 계산 근거가 없는 수치 | 비교 API가 없으면 UI에서 삭제 |
| P1 | 문의 카테고리 | 대·중·소분류와 키워드 판정을 Web에서 수행 | 현재 페이지 데이터만으로 오분류될 수 있음 | Backend 분류 결과를 받아 표시 |
| P1 | 운영 예외 기준 | `120분 이상 대기` 등을 Web에서 직접 판단 | 실제 SLA 정책과 다를 수 있음 | Backend가 예외 코드와 사유 제공 |
| P1 | 알림 | 특정 문의번호와 `방금 전` 문구 고정 | 실제 알림처럼 보이는 가짜 데이터 | 알림 API 전까지 삭제 또는 빈 상태 처리 |
| P2 | 화면 상태 테스트 | URL의 `mockState`, `mockFailure`로 오류·빈 화면 강제 | 일반 실행 화면에서도 테스트 상태 접근 가능 | 테스트 환경으로만 분리 |

## 3. 현재 확인된 Dashboard API

Backend 구현을 기준으로 다음 API가 확인됩니다.

```http
GET /api/v1/consultant/dashboard
```

확인된 응답 영역:

```text
summary
notices
consultants
technicians
inquiries
```

현재 Web 공지 API는 아래의 잘못된 경로를 호출하고 있습니다.

```text
현재 Web: /api/v1/operations/consultant/dashboard
실제 확인 경로: /api/v1/consultant/dashboard
```

이 경로 수정과 공지·직원·기사 데이터 연결은 Web에서 진행할 수 있습니다.

## 4. Web에서 자체 진행할 작업

1. 상담사 이름 강제 치환을 제거하고 로그인 사용자명을 그대로 표시
2. 사번 API가 없을 때 고정 사번을 표시하지 않도록 처리
3. 공지·직원·방문기사 연락처를 Dashboard API 응답으로 교체
4. 전날 대비 고정 수치 삭제
5. Remote 모드에서 자동으로 디자인 Mock으로 바뀌는 처리 제거
6. API 저장 없이 성공 처리되는 AI 승인·반려 동작 제거 또는 비활성화
7. `mockState`, `mockFailure`를 제품 실행 화면에서 분리
8. 합성 데이터는 명시적인 Mock·테스트 환경에서만 사용

## 5. Backend 확인 및 협의 요청

| 요청 항목 | 확인이 필요한 내용 | API가 없을 때 Web 처리 |
|---|---|---|
| Dashboard API | `/api/v1/consultant/dashboard`의 정식 사용 가능 여부와 응답 계약 | 공지·연락처 패널을 오류 또는 빈 상태로 표시 |
| 상담사 사번 | 로그인 또는 `/me` 응답에 `employee_no` 제공 가능 여부 | 사번 영역 숨김 |
| 전일 비교 지표 | 전체·신규·진행·AI 검토의 전일 대비 증감값 제공 여부 | 증감 문구 삭제 |
| AI 요약 검수 | 승인·반려 API, `allowed_actions`, `state_version` 계약 | 버튼 숨김 또는 비활성화 |
| 문의 카테고리 | 대분류·중분류·소분류 필드와 목록 필터 파라미터 제공 여부 | 카테고리 필터 비활성화 검토 |
| 운영 관리자 집계 | 실제 운영 지표·예외·문의 목록 API 제공 계획 | 관리자 데이터 영역을 연동 대기 상태로 표시 |
| 알림 | 상담사 알림 목록 API 제공 계획 | 고정 알림 삭제 후 빈 상태 표시 |
| 방문기사 배정 목록 | 방문 전환 시 선택 가능한 기사 조회·배정 계약 | 신규 기사 선택 기능 비활성화 |

- 대상: 상담사 Web, 운영 관리자 Web, Web 공통 사용자 헤더
