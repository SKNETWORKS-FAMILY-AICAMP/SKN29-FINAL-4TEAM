DEC-001: REVIEWED
- 단계별 연결 가능 여부: 가능하다. 문의 목록 → 문의 상세 → 상담 4 Action과 저장 후 상세 재조회 → 방문 Action → 공통 오류 복구 순서로 Repository·Adapter를 단계별 교체하고, 실제 API 성공 증거와 Mock 검증 결과를 단계별로 분리할 수 있다. DEC-008이 보류돼도 공식 근거를 독립 영역으로 두고 기본 상세·상담·방문 연결을 진행할 수 있다.
- Mock/실제 API 분리 조건: 실제 API 실패를 숨기고 전체 Mock으로 자동 전환하지 않는다. 실제 실패는 Loading·Empty·오류·BACKEND_BLOCKED 상태로 표시하고, Mock은 명시적으로 선택한 환경이나 Fallback 시연에서만 사용한다.
- 필수 수정: PM 최종 승인과 Active 계약 확정 뒤 현재 단일 Mock Repository를 Remote·Mock 구현으로 분리하고 DTO → Mapper → View Model 경계를 유지한다.

DEC-004: REVIEWED
- 공통 응답·visit null: 동일 Wrapper는 공통 Mapper에서 소비할 수 있다. visit은 응답 Key가 항상 존재하는 required·nullable 필드로 정의하고, visit: null은 Visit 미생성, Key 누락은 계약 불일치로 처리한다.
- 날짜·기사 상태: preferred_date와 confirmed_date, 기사 미배정 ASSIGNING·기사 필수 SCHEDULING·기사와 확정일 필수 CONFIRMED를 화면에서 구분할 수 있다. 현재 Mock Form은 승인된 계약에 맞춰 날짜 단위 입력과 상태별 필수 조건으로 변경해야 한다.
- 409 복구: 입력을 화면 메모리에 유지하고 최신 상태·state_version·allowed_actions·visit을 반영한 뒤 가능한 행동을 다시 판단할 수 있다. 자동 덮어쓰기와 자동 재제출은 하지 않는다.
- 필수 수정: Active OpenAPI에 visit의 required·nullable 여부, 상태별 필수 필드, 상태 충돌 409와 멱등 Payload 충돌의 서로 다른 Error Code와 응답 Schema를 명시해야 한다.

DEC-009: REVIEWED
- returnTo·Draft 복구: 안전한 내부 returnTo를 유지하고, 최종 401 전에 최소 Draft를 Token과 분리된 같은 탭 메모리에 저장한 뒤 최신 상세 조회 → 충돌 판정 → 경로 복귀 → Draft 복구 순서로 구현할 수 있다.
- 동일 사용자·역할 확인: Draft의 사용자 ID·역할·문의 ID·저장 시각·기준 state_version을 재로그인 정보와 비교하고 모두 같을 때만 복구한다. 최신 state_version이 다르면 자동 복구·제출하지 않고 충돌을 안내한다.
- 15분 TTL·새로고침 손실: P0 UX로 수용 가능하다. 15분 만료, 새로고침·탭 종료 시 손실 가능성, 자동 제출하지 않음을 화면에 안내한다.
- 필수 수정: Web에서 최종 401과 명시적 로그아웃을 구분하는 종료 사유, 메모리 Draft Store·TTL·폐기 규칙, 재로그인 복구 안내와 회귀 테스트를 추가한다. Token과 Draft는 URL·Router State·Web Storage에 저장하지 않는다.
